# design-sync notes

## Setup: no package build of its own

`design-system/` is raw shadcn source living inside the Next.js app (`web/`)
— no `package.json`, no `dist/`, no shipped `.d.ts`, no compiled CSS. It is
not a publishable package and never will be (see `web/design-system/design-system.md`).

To get real fidelity (accurate CVA variant unions in props, real compiled
Tailwind CSS) instead of the converter's synth-entry last resort, this sync
builds a **scratch package** under `.ds-sync/pkgscratch/` before running the
converter:

- `.design-sync/build-design-system-package.mjs` (committed, durable) does
  the work: glob `design-system/ui/*.tsx` → write a scratch `package.json` +
  JS entry (`index.mjs`, re-exporting each file) → run `tsc
  --declaration --emitDeclarationOnly` (via a generated
  `.ds-sync/dts.tsconfig.json`) for a real `.d.ts` tree → hand-write a
  `types/index.d.ts` barrel → compile `app/globals.css` through
  `postcss` + `@tailwindcss/postcss` (pure content-scan, does NOT require
  `next build`/`tsc --noEmit` on the whole app to succeed) into
  `compiled.css`.
- Everything under `.ds-sync/` (including `pkgscratch/`) is gitignored and
  fully regenerated by that one script — never hand-edit it.
- `cfg.entry` points at `./.ds-sync/pkgscratch/index.mjs`, `cfg.cssEntry` at
  `./.ds-sync/pkgscratch/compiled.css`, `cfg.tsconfig` at the repo's own
  `tsconfig.json` (for esbuild's `@/*` alias resolution during bundling —
  the scratch entry re-exports from `design-system/ui/*.tsx`, which imports
  `@/lib/utils` etc).
- **Re-sync**: `cfg.buildCmd` (`node .design-sync/build-design-system-package.mjs`)
  regenerates the scratch package from whatever's currently in
  `design-system/ui/`. Run it before every converter build/re-sync — it
  auto-discovers files, so adding a new shadcn primitive to `ui/` needs no
  script changes.

## Preview-authoring scope (this sync)

User chose: author real previews for all 9 root components (Badge, Button,
Card, Input, Pagination, Select, Table, Toggle, ToggleGroup). The ~29
subcomponents (CardHeader, TableRow, SelectItem, PaginationLink, etc.) are
composed inside their parent's story and left on the floor card individually
— shadcn here uses flat named exports (not `Card.Header` dotted namespacing)
so the converter's automatic subcomponent-nesting can't detect the
parent/child relationship; they still render fine standalone (plain styled
`div`/`tr`/`td` wrappers, no required context), so the floor card is honest
and harmless for them.

## Fonts: OS-only by design, not a missing asset

`[FONT_MISSING]` flags ヒラギノ角ゴシック / ヒラギノ角ゴ ProN W3 / メイリオ (Hiragino,
Meiryo). This is not an oversight: the site deliberately ships **zero**
webfonts and relies entirely on OS-installed Japanese fonts (see
`design-system/design-system.md` "フォント" and the root CLAUDE.md — dropping
`next/font` saved 52KB/2 requests per page, and Hiragino/Meiryo are
proprietary Apple/Microsoft fonts that couldn't be redistributed even if we
wanted to). Recorded via `cfg.runtimeFontPrefixes` so the warning doesn't
recur — these families really do only ever come from the visitor's OS, never
from this bundle or any font service.

## Found while authoring the Select preview: a real production bug

Authoring `Select.tsx` with `defaultValue="all"` (no `defaultOpen`) rendered
the trigger's visible text as the literal string `"all"` instead of the
matching item's label. Investigated against the running dev server: the
real 業種 (industry) filter on the production ranking page has the exact
same bug right now — it shows `__all__` (the internal sentinel value from
`FilterSelect.tsx`'s `const ALL = "__all__"`) instead of "すべて" until the
dropdown is opened once. Confirmed via `mcp__playwright__browser_navigate`
+ screenshot against `next dev` (2026-08-20).

Root cause: base-ui's `<Select.Root>` needs an `items` prop to resolve a
value to its label before the popup has ever mounted (see
`node_modules/@base-ui/react/select/root/SelectRoot.d.ts`:
"When specified, `<Select.Value>` renders the label of the selected item
instead of the raw value."). `features/ranking/components/FilterSelect.tsx`
passes `value`/`onValueChange` but never `items`, so it hits exactly this
gap. Only the 業種 filter uses `Select` — the other three filters
(従業員数/在籍年数/平均年齢) use `ToggleGroup`, unaffected.

This sync's own `Select.tsx` preview was fixed to pass `items` (the correct
usage) rather than reproducing the bug — see the comment there. The app fix
itself is out of scope for design-sync; the user asked for it to be applied
as a follow-up after this sync finishes (a one-line addition, no Issue
needed per CLAUDE.md's 1-commit-fix carve-out).

## Re-sync risks

- The scratch package's shape (which files are "components") is
  auto-discovered from `design-system/ui/*.tsx` — if a future primitive
  needs excluding (e.g. it exports a non-component helper as PascalCase),
  use `cfg.componentSrcMap.<Name>: null`, don't hand-edit the scratch script.
- `compiled.css` is a snapshot of whatever Tailwind classes exist in the
  *entire* repo at build time (content-scan has no allowlist) — this is
  intentional (matches production exactly) but means an unrelated large
  refactor elsewhere in the app could theoretically shift which utilities
  get generated. Not expected to cause visible drift in practice.
- No Storybook, no docs/ tree for these components — `.prompt.md` files are
  synthesized from the `.d.ts` + authored preview only. If `docs/guides/`
  content is ever added under `design-system/`, revisit `cfg.docsDir`.

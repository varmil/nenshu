# 現在地: ランキング（`/`）・表示基準・推定式・URL 同期

> CLAUDE.md の「現在地」節から移した（2026-10-07・トークン消費の削減。移しただけで、本文は1字も書き換えていない）。
> 文中の「上の」「下の」は、CLAUDE.md の「現在地」に並んでいた当時の位置を指す。対応する項は `docs/status/` のどれかにある（索引は CLAUDE.md）。
> **新しく分かったことはここに書く。CLAUDE.md には書かない**（CLAUDE.md は全セッション・全サブエージェントが毎回読むので、伸ばすとそのまま消費量になる）。

年齢・4フィルタ・検索語・ページ番号は`?age=&ind=&emp=&ten=&aage=&q=&page=`としてURLに同期済み（`page`は1始まり、既定値は省略）。

**推定式はADR-0005の2点モデル**（`web/features/ranking/lib/salary.ts`）。目標年齢が平均年齢より下では、その会社の賃金カーブが「22歳＝業種平均の水準」と「平均年齢＝実測の平均年間給与」の2点を通ると置いて間を業種カーブの形で結ぶ。平均年齢より上はADR-0003の倍率一定のまま。Issue #42（若年側の過大推定）はこれで解消した（キーエンス25歳 1,642万→788万）。**カーブは`curves.json`に千円で入っているので、`curveValuesInYen`で円に揃えてから`estimateSalary`に渡すこと**——旧式は比しか取らないので揃えなくても合っていた。経緯と却下案（標準労働者カーブは効果が小さく60歳側が悪化する）は`docs/ranking/estimation-model/design.md`とADR-0005にある。

**Python側（`pipeline/salary/curves.py`の`estimate_salary`）も同じ式で、CSVの`salary35`列はこれで計算してある。** 両者が一致することは`pipeline/scripts/build-data.test.ts`がweb の`estimateSalary`を直接importして全社で固定している。**推定式を変えたらPython・TypeScriptの両方を直し、`cd pipeline/salary && python3 unified.py --from-csv ../data/ranking_unified.csv` でCSVの派生列を作り直してから`npm run build:data -- --out ../web/public/data`を回すこと**（EDINETから取り直す必要は無い）。Pythonの`round()`は偶数丸めでJSの`Math.round`と違うので、Python側は`floor(x+0.5)`を使う。

**既定の表示基準は「実測値」＝有報の平均年間給与そのまま（ADR-0007・U11・Issue #71）。** 年齢補正は「年齢そろえ」として読者が明示的に選ぶモードになった。ランキングと企業詳細の両方に同じ2モードがある。

- **ランキングのモードは `age` の有無で表す。`basis` のようなパラメータは無い。** `/` = 実測値、`/?age=35` = 年齢そろえ。状態は `RankingState.targetAge: TargetAge | null` の1つの値で持ち、`null` が実測値。分けると「実測値なのに年齢がある」矛盾した状態が表現できてしまうため。**企業詳細ページは違う——あちらは URL に出さず、クライアントの状態としてだけ持つ**（R1・ADR-0012）
- **年齢そろえなら35歳でも `age=35` を出す。** 35歳を既定として省略していた頃とは違う——省くと実測値のURLと区別が付かない
- **`stats.json` の `population`/`rankAll`/`rankIndustry` は `bases = [null, 25, 30, ..., 60]` の9列**（先頭が実測値）。**行がずれると別の会社、列がずれると別の表示基準の順位を出す。** `view.ts` は `stats.bases` を回して並びの正を1か所に寄せている
- **母集団は基準ごとに別物。** 実測値は平均719万円・標準偏差200万円、35歳そろえは629万円・155万円。キーエンスは平均年齢がちょうど35.0歳なので金額は両モードで同じ2,178万円だが、偏差値は122.9と150.0で違う
- **実測値では「推定」の語を1つも出さない**（バッジも断り書きも）。有報そのままの数字に推定の体裁を被せない
- **年齢そろえのときも「推定」の語は1画面に1回だけ置く**（Issue #128）。見出し（`推定年収（35歳）`／`35歳時点の推定年収`）とその隣のバッジのように**同じ語を重ねない**し、1ページ30件ぶん繰り返されるランキングの行にも置かない。AC-9 が求めるのは「推定値であることを示す表記が画面上に存在する」ことなので、見出し・帯のヒント・脚注のいずれかで足りる
- 実測値のとき年齢スイッチは**消さずに `disabled` にする**——消すと切り替えて何が増えるのか分からないため
- 経緯と実測値は `docs/ranking/salary-basis/design.md` と ADR-0007 にある

**年収偏差値は100を超える。** 35歳時点のキーエンスで150.0（全体平均629万・標準偏差155万に対して2,178万）。年収分布が右に強く裾を引くためで、対数変換しても107.4。**画面には数字だけを出し、水準は順位で読ませる**——「上位◯%」の併記は2026-08-20に運営者の判断で外した（モックに無いものを足さないため）。100を超えうる理由の注記は**ランキングの表・カードの脚注と `/about`** に残す（企業詳細ページの注記は2026-08-20に外した）。**偏差値だけが単独で置かれた画面を作らない**線は変わっていない（glossary参照）。

**ランキングは U12（`docs/ranking/ranking-refresh/`、Issue #80）でレイアウトを刷新し、U13（`docs/ranking/ranking-mock-alignment/`、Issue #88）でモックに合わせ直した。**

- **表は3列**（順位・会社名 / 金額＋バー / 偏差値）。**順位はロゴ左上のホームベース型バッジ**（`RankBadge`、アートボード 3e・4d）で、独立した列は無い——固定20px弱のレーンに3〜4桁が入ると数字がロゴ画像に重なっていた。バッジは `min-width` を下限に**右へだけ伸びる**ので1桁でも4桁でも左端・上端が動かない。**色は `--rank-badge`。モックの `oklch(0.62 …)` は白文字に対して 3.57:1 で AA を割る**（10.5〜12px なので大きな文字の緩和は使えない）ため `0.56` にしてある（4.56:1、`tokens.test.ts` が両モードで見張る）。平均年齢・在籍年数・従業員数は社名の下の meta 行にある（`CompanyMetaLine`）。**業種は meta 行に出さない**（公開後の指摘で外した。行が長くなって末尾が見切れていた）。**U12 の7列では社名が省略記号で切れていた**（「三菱商事…」）。`truncate` は `block` にしないとインラインのまま溢れる（360px で横スクロールが出た）
- **表示基準と年齢は `ControlBand`（ラベル＋ヒントを持つ帯）に入っている。** 実測値のとき年齢の帯は破線＋減光で残る（AC-11）
- **並び替えチップの見えている文字は軸だけ**で、方向は選択中かつ `sm` 以上でだけ出す（390px で「絞り込み」と並ばないため）。`aria-label` は常に `${軸} ${方向}`
- **モバイルの行は3カラム**（順位つきロゴ / 社名＋meta / 金額ブロック。アートボード 2a・3e）。**年収バーは金額ブロックの中**で、金額は**左寄せ**でバーと左端が揃う。**幅は `w-20`＝80px**（4桁で金額とバーの幅が揃う値）。**`whitespace-nowrap` を外さないこと**——webfont を持たずOSのフォントで組むので幅が環境で変わり、`nowrap` の無い80pxでは実機で「円」だけが2行目に落ちた。`nowrap` があれば2行にはならず、収まらない環境では右へわずかにはみ出す（`p-4` の16pxに収まる範囲）。バーの幅は全行で同じでないと長さを見比べられないので、`w-fit` で逃げられない。**バーはモバイルだけ3px**（`SalaryBar` の `size="row"`。PCの表は6pxのまま）——88pxの器で6pxだとバーが金額より強く目に入る。5c の頃は社名・meta・バーを右の1列に縦積みしており、**バーだけが行の全幅に伸びてどの社名の帯か読めなかった**。社名は1行で切る。**縮むのは社名と平均年齢だけ**——金額と偏差値は `shrink-0` で360pxでも全部見える。**従業員数はモバイルの行に出さない**（PCの表にはある）。**「本社のみ」バッジは PC の表にも出さない**（2026-09-28 に外した。下の「年収に関するQ&A」の項）。行の高さはロゴの48pxが決めるので社名の長さによらず等間隔
- **モバイルで長い文は「1文目＋`hidden md:inline` の2文目」で縮める。** 同じ文言を2つ書いて出し分けない
- **「適用中」は PC ではサイドバーの先頭。** モバイルでも `aside` は消えず、中身のうち絞り込みだけがシートに移る——同じ解除ボタンを2つ描かないため
- 業種チップは本文カラムの中の muted の帯で、社数を併記する（`industryCounts` が描画時に数える）
- トップページの HTML は gzip 72,232 B → **71,671 B**。`/company/[id]` は 12,873 B → **13,283 B**（共通ヘッダに検索ボタンが増えたぶん）。その後 Issue #103 で1ページ30件にして **70,283 B → 62,563 B**（同一手法で `next start` に対して再計測した前後。`/company/[id]` は変わらない）。Issue #119 のモバイル行で raw 371,849 B → **355,341 B**（−4.4%）。順位バッジで raw 355,766 B → **373,821 B**（バッジ1つあたり約300Bの `class` と `style` が PC・モバイル合わせて60個並ぶ。同じ文字列の繰り返しなので gzip 後は +364 B（63,287 → 63,651））。**gzip 後の値は同じビルドでも `next start` の起動ごとに揺れるので、前後を比べるときは raw で見る**

- **ページ送りは押した後にページ最上部へ戻す**（`lib/scroll.ts`、Issue #96）。ボタンは表1ページぶん下（1ページ100件だった頃の実測で `scrollY = 5,653`。30件でも1画面は超える）にあるので、位置を保つと入れ替わった行が視界に入らない。`goTo` の中＝実際にページが変わるときだけ呼ぶ。**`behavior` は付けない**（一瞬で戻す）
- **行の中の強弱は 社名（太字）＞ 順位（バッジ）＞ 金額（16px）**（Issue #96）。金額を20pxにすると社名より先に目に入り、「どの会社の数字か」を読む順序が逆になる。**順位はロゴ左上のバッジ**なので、大きさで社名と競らない（PC 12px・モバイル 10.5px の文字を塗りの上に載せる）
- **ページ番号は先頭・末尾と前後2ページまで**（U17・Issue #813・親 #811。`docs/ranking/pagination-reach/`）。当初は前後1ページ。**3にしない**——並びは中央寄せで、本文の幅を超えると左端の「前へ」が画面の外に出て押せなくなる（横スクロールにも出ない）。前後2ページで最長 324px、360px の本文は 328px。**`sm` 未満だけ省略記号を 16px・隙間を 0 に詰めて収めている**（数字の器 32px は削らない）。詰めは `RankingPagination` から class で渡し、`design-system/ui/pagination.tsx` は触らない。E2E は横スクロールではなく並びの左右の端を本文の器と突き合わせる
- **1ページは30件**（`PAGE_SIZE`、Issue #103。当初100件。1,867社で63ページ）。**この値はペイロードを決めない**——全件は表示件数に関わらず初回HTMLに埋まっている（Issue #22）ので、減って軽くなるのは描画する行数ぶんだけ。**行数を「絞り込みが効いたか」の判定に使わない**（`PAGE_SIZE` で頭打ちなので絞り込みが壊れても通る）。件数表示（`82社 中 1〜30社目`）で見る
- **並び替えは3軸×2方向の6通り**（年収／平均年齢／従業員数 × 既定の向きと逆向き。U15・Issue #106）を `?sort=` で同期。**並び替えても順位の列は振り直さない**——順位は「金額で何位か」の意味なので、平均年齢順に並べたら `1,204位 / 87位 / …` と飛ぶのが正しい
  - **選択中のチップをもう一度押すと向きが反転する。** その合図は `ToggleGroup` が寄こす**空配列**（単一選択の `@base-ui/react` は選択中を押すと `onValueChange([])` を呼ぶ）。項目ごとの `onClick` で拾うと同じクリックで状態が2回動く。規則は `features/ranking/lib/sort.ts` の `nextSortSelection` の1か所
  - **軸と向きは `RankingState.sort` の1つの値**（`SortSelection = { key, order }`）。`sort` と `sortOrder` に分けると `Partial<RankingState>` の差分で片方だけ当たり、「平均年齢を降順で」という誰も選んでいない並びになる（実際にそう書いてテストが落ちた）
  - **既定の向きは3軸とも降順（大きい順）に揃えてある。** U15 の初版は `age` だけ昇順（若い順）だったが、**1つの軸だけ向きが違うと押したときに何が起きるかを軸ごとに覚えることになる**ので揃えた（運営者の指摘）。代償として、初版の直後に配った `?sort=age` は若い順ではなく高い順で開く（sitemap にも検索インデックスにも無いので影響は共有リンクだけ）
  - **URLは `sort` 1本のまま。`dir=` を足さない。** 既定の向きなら軸だけ（`sort=age`）、逆向きなら向きを足す（`sort=age-asc`・`sort=salary-asc`・`sort=emp-asc`）。3軸とも既定が降順なので**書き出す綴りに `-desc` は現れない**が、`splitSortParam` は読める側に残してある（落とすと `?sort=age-desc` が既定の並びに倒れる）
  - **canonical の判定は軸だけでなく向きも見る**（`lib/seo/ranking.ts`）。`?sort=salary-asc` は軸が既定と同じなので、向きを見ないと「効いていない」と誤判定して自己canonicalになる
  - **矢印は向きを表す**（下＝大きい順・上＝小さい順）。モバイルは向きの語を出さないので矢印だけが手がかり。経緯は `docs/ranking/sort-direction/design.md`
- **順位は2つある。** `rank`（絞り込み後・1から振り直す）と `populationRank`（全1,867社の中）。**上位◯%は画面から外したが `populationRank` は残してある**——絞り込み後の順位を母集団の位置として使わない、という区別自体は生きている
- **偏差値だけが単独で置かれた画面を作らない**（glossary）。表では順位の列と、企業詳細では位置バーと同じ視界に並べる
- **`/` は `stats.json` から母集団統計（`count`/`bases`/`population`）だけを抜いて渡す。** `rankAll`/`rankIndustry` は1,867×9の配列2本で、クライアントに直列化するとページの予算を超える。抜いた結果は1KB未満（`population.test.ts` が固定）
- **業種チップ33件は `<a href="/?ind=…">` の実体を持つが、左クリックは横取りして状態更新にする。** 実体はクロール経路（ADR-0006 で `/industry/[x]` を作らないと決めたため）、横取りはAC-7（操作でネットワークを起こさない）のため。修飾キー付きはブラウザに任せる。**これで U8 のリンクハブは不要になった**
- **検索は共通ヘッダに移した**（`features/navigation/components/HeaderSearch.tsx`）。ヘッダは `RankingApp` の祖先ではなく兄弟なので、URLを経路にして `pushState` ＋ `RANKING_STATE_CHANGED_EVENT` で届ける。`/` 以外では素の `<form action="/">` として遷移する
- **`ToggleGroup` の既定は折り返さない**（`w-fit flex-row`）。216pxのサイドバーで3択がはみ出し、本文の表に重なってクリックが吸われた。表は `table-fixed` にしないと社名の列が枠を超える（978px / 枠752px）。どちらもE2Eが検出した
- **トップページの HTML は gzip 66.5KB → 72.2KB になった**（+8.7%）。増えたのは行あたりの情報量と業種チップで、母集団統計は1KB未満

**年収バーは「そのページの1位を100%」で正規化する**（デザイン案の「上限2,500万円」は採らない）。ページ・フィルタ・並び替え・**表示基準**が変わるたびに基準が変わるので、最大値は `rankedCompanies`（ページ切り出し済み）から導く（`pageMaxSalary`）。全体平均の縦線はページ最大を超える場合は描かない。**表示基準の切替で棒だけ元の縮尺で残るのが一番気づきにくい壊れ方**なので、単体・E2Eの両方で固定してある。**全体平均の縦線は棒の上下に3pxずつはみ出させ、不透明の `--foreground` で引く**——棒の中に `--foreground` の40%で引いていた頃は、平均を上回る行で塗りに重なりライトではほとんど見えなかった（2026-09-29・`docs/ranking/ranking-refresh/design.md`）。**表の脚注（`lib/footnote.ts`）には表示基準の断りを置かない**——出典はリード文、補正と「推定」は並べ方の帯が持っていて、実測値では同じ断りが1画面に3回あった。

**戻る/進むは `web/lib/history/useLocationSyncedState.ts` の3規則が正**（U14・`docs/ranking/back-navigation/`、親 Issue #108・Issue #121）。ページを跨いで戻ると絞り込み・ページ番号・表示基準が消えていたのを直した。

- **マウント時は URL が正。** 戻ったときにサーバーが渡した `initialState` で URL を上書きすると `?page=2` が `/` に戻り、**進む先の履歴まで消える**。Next.js の頃はルーターキャッシュの RSC ツリーがそのまま返って `initialState` が「そのツリーを作ったときのURL」の値になっていた。**Astro でも規則は変えない**——ブラウザのキャッシュから返った HTML も、それが作られたときのURLのものになる
- **URL へ書くのは、アプリ側の操作で値が変わったときだけ**（setter を包んで印を付けている）。**「マウント後の1回目だけ飛ばす」という数え方にしない**——開発サーバーの StrictMode は effect を2回走らせるので2回目が漏れる（実際に漏れていた）
- **自分のパスを離れたら書かない・読まない。** Next.js は `pushState` を浅い遷移として扱うので、抜けていくページが行き先のURLを書くと**URLだけ次のページ・画面は前のページ**の行き止まりになっていた（企業詳細 → ランキングの戻るで実際に起きた）。**Astro では文書ごと入れ替わるのでこの経路は無い**が、規則は残してある——コストがほぼ無く、外すと「なぜ外したか」を次に読む人が確かめ直すことになる
- **検索語だけはフックを通さない。** `q` が付く／外れる境目だけ `push`、打ち替えは `replace`（`queryBroadcast.ts` の `buildQueryLocation`）。以前は1文字ごとに `pushState` していて「トヨタ自動車」で履歴が6件増えていた
- **スクロール位置は自前で復元しない。** ブラウザが正しく戻している。E2E で戻らないように見えたのは、**Playwright の `click()` がクリック前に対象をビューポートへスクロールする**ため——戻る/進むの位置を測るときは画面内にある要素を押すこと

**稼ぐ力（一人当たり経常利益）は `performance` 施策**（`docs/performance/`）。**レーダーチャートの軸を決める親 Issue #154 が「賃金差を外し、稼ぐ力を入れる」と決めた**ので、その軸のためのデータを作る施策として新しく立てた（`market-data`（#55）に寄せない理由は intent.md）。**P0（取り込み・Issue #155）・P1（レーダー表示・Issue #167）は実装済み**（`docs/performance/profit-per-employee/`・`docs/performance/company-radar/`）。**P2（稼ぐ力の推移・Issue #168）も実装済み**（`docs/performance/profit-trend/`）。**E6（#182）で母集団の拡大に追随させた**（1,865社 → 2,959社 = 99.9%）。

- **`稼ぐ力 ＝ 連結の経常利益（直近5期の中央値） ÷ 連結の従業員数`。連結で組む**（#154 の決定）。単体だと分子が実質的に子会社からの配当になる会社が173社あり、**軸の上位が持株会社で埋まって「本社のみ」バッジと役割が重なる**。実測でも**上位20社に「本社のみ」バッジは1社も無い**
- **1書類に5期ぶんの経常利益がタグ付けされている**（`jpcrp_cor:OrdinaryIncomeLossSummaryOfBusinessResults` が `Prior4YearDuration` 〜 `CurrentYearDuration`）ので、**中央値は最新年の書類1件で出せる。追加のダウンロードは要らなかった**。**従業員数だけは当期しか無い**（5期ぶんは本文の中にしかない）ので、10年ぶんの棒を描く P2 は書類の取り直しが要る
- **実測: 2,959社（99.9%）。赤字（中央値が0以下）が136社、連結の従業員数が無くて単体で代用したのが371社。** 銀行業82社・保険業17社・その他金融業40社とも欠損なし（営業利益が無いことを理由に欠ける会社は出ない）。~~取れない2社（弘電社・キクカワエンタープライズ。最後の開示が8年前）~~ → **#911 で、開示が古いのではなく経常利益を「経常収益」の要素（`OrdinaryIncomeSummaryOfBusinessResults`）でタグ付けしていたと分かった。** 当期の値が損益計算書の経常利益と一致するときだけ読み替える（`performance/extract.py`。ディーブイエックスを入れて3社14書類）
- **連結の従業員数は `NumberOfEmployees` だけでなく、IFRS 用の要素（`NumberOfEmployeesIFRSSummaryOfBusinessResults`。会社独自の名前空間で書く会社もある）にもある**（#905）。取りこぼすと「連結が無い」と見なして単体の人数で割り、桁で外れる（ソフトバンクグループ 2017年 144億円/人 → 4,197万円/人。16社24行）。要素名の表は `edinet.EMPLOYEES_CONSOLIDATED_FALLBACK_LOCAL_NAMES` の1か所で、ランキング側と推移側が共有する。**連結の経常利益が無い会社（IFRS・米国基準の240社）は、稼ぐ力を出さない**（#911。下の項）
- **最新年の経常利益が単体だけで、連結の従業員数がある会社（IFRS・米国基準の240社）は、稼ぐ力を出さない**（#911）。単体の経常利益は連結の値の代わりにならない（最新年の実測で、連結の税引前利益に対する比の中央値 0.59・±25% に収まるのは21%・符号が逆が15社。連結の経常利益がある J-GAAP でも単体 ÷ 連結は中央値 0.85）。**レーダーの稼ぐ力は「掲載なし」・業種中央値の母集団から外し、推移は `profit-history.json` にキーを作らない**——企業詳細では「稼ぐ力の推移」の節が節ごと出ず、出典の計算値にも稼ぐ力を挙げない。**判定は `pipeline/scripts/lib/profitBasis.ts` の1か所**（レーダーと推移が同じ関数を通る）。旧年だけ単体の会社（連結決算を後から作り始めた155社）と、連結の従業員数が無い会社は対象にしない。**逆向き（連結の経常利益 ÷ 単体の従業員数）も出さない**（クラサスケミカル1社。最新の書類が有価証券届出書の様式で、連結の従業員数が取れていない）。**元データの連結・単体の取り違えは全社の最新の書類で確かめて0件**（連結＝単体の4件は損益計算書でも同じ値の偶然の一致）。**業種中央値は母集団が変わって27業種で動いた**（鉱業 −42%・医薬品 −41%・保険業 +24%）。**この変更と一緒に196社の分析を直した**（67社は全文を書き直し、129社は倍率を言う1文だけを新しい倍率に合わせた）。数字の書類が同じなので定期実行の差分生成には選ばれない。**業種中央値が動くと、倍率の言い方だけでなく、見送り条件①④（基準の食い違い・またぎ）に新たに当たる会社が出る**——当たった会社は倍率を書けないので全文を書き直す（`docs/performance/profit-per-employee/design.md`）。**業種中央値は毎日の差分更新でも動くので、倍率を書いた分析文は本人が有報を出さなくても外れていく**（2026-09-29 の D4 の1回目で20社。直したが、止める仕組みはまだ無い・#916）
- **赤字は負のまま持つ。** 捨てると「データが無い」と区別できなくなる
- **業種差が30.7倍ある**（鉱業3,846万円・陸運業125万円）ので**業種中央値を数字として併記する**。**どの業種が端に来るかは母集団で入れ替わる**——E6 の前は 海運業2,524万・輸送用機器131万 の19倍だった。**業種名を決め打ちして倍率を書くと母集団が変わったときに嘘になる**ので、テストは端そのもの（最大 ÷ 最小）を見る。**平均ではなく中央値**——電気機器はキーエンスが業種中央値の18.9倍で、平均だと業種の代表値がキーエンスに引きずられる

**レーダーチャート「公開資料による全体像」は P1**（`docs/performance/company-radar/`・Issue #167）。企業詳細ページの平均年収カードの直後に5軸（平均年収・有給の取得・定着（在籍）・稼ぐ力・残業時間）を出す（P1 から C14 までは本文の先頭だった。下の C15）。**男女の賃金の差異は軸にしない**（#154。数値は W1 の節に残る）。

- **位置は順位で決める。金額を線形に当てない。** 稼ぐ力は業種中央値に対する倍率が 5%tile 0.08 / 95%tile 4.46 で、線形だと上位が振り切れて下位が中心に潰れる。**順位なら5軸を同じ規則で置ける**——1軸だけ別の目盛りにすると1枚の図の中で位置の意味が2種類になる

- **欠測軸は頂点を打たず、飛ばして多角形を閉じる**（AC-7）。中心まで引き込むと「掲載なし」と書いてあっても最低評価と同じ形に見える。**ラベルは残す**（軸ごと消すと5角形が4角形になり、何が公表されていないかが図から消える）。キーエンスは4点、三菱UFJは3点で閉じる。**描き方の断り（「公表の無い指標は…」）は欠けた軸がある会社（1,803社）にだけ出す**（`missingAxisNote`。W3 の後の指摘で `unitPickNote` とそろえた）
- **最下位でも中心には置かない**（`MIN_POSITION = 0.1`）。中心に貼り付けると**頂点を打たない軸と見分けがつかない**
- **雇用管理区分が2つ以上ある会社は、先頭の区分の値で軸に乗せる**（W3・#802・`docs/worklife/first-unit/`）。**全体値 → 無ければ値のある区分のうち先頭**（会社が登録した順＝節の先頭の行）。~~乗せずに「区分別」と書く~~（W2・#215）は、有給222社・残業112社の図から軸が1本欠けたうえ、その断りが全社のページに出ていて冗長だった（運営者の指摘）。**区分名で振り分けない**——先頭が管理職・男性・部門の会社（有給54社・残業31社）もそのまま使う。名前で飛ばす判定は spec 2.2b が禁じた「区分名を分類する」ことになる。**代わりにどの区分の値かを図の下に書く**（`unitPickNote`）。**断りは先頭を選んだ軸がある会社にだけ出す**（区分がちょうど1つの会社は選んでいないので出さない）。**全体値があれば区分がいくつあっても全体値で打ち、断りは出さない**（残業で503社。ソフトバンクグループ・住友商事）——全社の成果物で「図の値＝節の先頭の行」を突き合わせて不一致0件。**区分名はリストの行に入れない**（値の列は76px 固定）。**文はビューに持たせない**——props に載るのは `pickedUnit`（区分名）だけで、**選んでいない軸ではキーごと持たない**。先頭の区分と全体値のずれは、両方持つ会社で有給 −1.5pt・残業 +0.2h（中央値）

- **モックの「上位◯%」は採らない。** `上位82%` は上から82%の位置の意味だが、日本語としては上位＝良いに読める（キーエンスの有給は実データで1,461/1,486位）。**`1,486社中1,461位` と順位で出す**——偏差値の隣の「上位◯%」を外したのと同じ線

- **`@container` を `<svg>` 自身に置かない**（Issue #191）。`container-type: inline-size` は**その要素の縦横比を無かったことにする**ので、`height: auto` が置換要素の既定（150px）に落ち、`preserveAspectRatio` が図を**倍率0.5まで縮める**（実測 314×150）。幅は正しいので**縦だけが潰れ、型もUnitテストも既存のE2Eも全部通る**。器のクエリは包む要素に置く（`SalaryCurveChart` は `<figure>` に置いている）

# 現在地: 企業ロゴ

**企業ロゴは `logo` 施策**（`docs/logo/`・親 Issue #23・ADR-0008）。**L0（調達、#109）・L1（器と表示、#110）とも実装済み。** **2,961社中2,536社（85.6%）にロゴが出る**（E3・#175 で母集団の拡大に追随させ、W2 と同じ日の #221 で2社が頭文字に戻った）。

- **出典は Commons と各社の公式サイトの2つだけ。** 優先順は `commons` → `jsonld`（`Organization.logo`）→ `header`（ヘッダの `logo` を含む `<img>`）→ `icon`。**「先に取れたものを採る」であって「一番大きいものを採る」ではない**——出典の確からしさを解像度より優先する
- **`header` の候補は、名前に `logo` があるかではなく囲む `<a>` の行き先で仕分ける**（2026-08-23。`docs/logo/logo-pipeline/design.md`「公開後に直したもの」）。SNSへ行くものは捨て、いま見ているページ自身かトップらしいパスへ行くものを先に試す。**クレスコ（4674）の企業ページにXのロゴが出ていた**のは、SNSリンクのアイコンのファイル名が `logo-black1.png` だったため。**「自サイトではない」を捨てる理由にしない**——別ホストのトップへリンクする本物のロゴが実在する（コニカミノルタ）。**公式サイトのURLが `…/english/` のように深いことがある**ので、パスの形だけでトップを判定しない（KDDI で povo のロゴが1位に来ていた）
- **器の中でファビコンとして出ていた46社を `og:image` に差し替えた**（2026-08-26・運営者の指摘）。`img` は原寸で描かれ拡大しないので、16×16 の favicon は器の中に点として出る。**原因はサイトからロゴが1枚も取れないこと**——ヘッダのロゴが CSS の背景画像・JS で後から差し込まれる・インライン SVG のいずれかで `<img>` として無く、候補の最後の favicon まで落ちていた。**`og:image` を自動の候補にはしない**——共有用の絵はロゴとは限らず、実測した56件に写真・バナー・画面写真が10件混ざっていた（#220 の豊田通商もこの型）。**機械的に切る線は引けなかった**：最頻2色の占有率で測ると、ロゴでないアイル（3854）0.599 とロゴのアイドマ（9466）0.259 が逆転する。**1枚ずつ見て46件を `PINNED` に書いた。** `LogoSource` の `ogp` は出典を記録するためのもので、`extractCandidates` は1件も作らない。**`og:image` が無い3社（1893・4828・9621）は運営者が目視で見つけ、個別に直した**——原因は3社とも違う（ヘッダの `img` の選び方／**公式サイトのURLが `/` で中身が `/jp/` にある**／ヘッダを JS が差し込む）ので、**経路を1つ足しても揃わない**
- **公式サイトの取得が失敗したら `https://` に上げて1回だけやり直す**（`fetchSite`）。**Wikidata の P856 は古い `http://` のまま登録されていることが多い**（オービックは `http://` が 503・`https://` が 200）。ロゴが無かった454社に当てて +24社。**上げるのは失敗したときだけ**——先に `https` を試すと `https` を持たないサイトで余計な1往復が全社に掛かる。**逆向きはしない**
- **ロゴが出ない454社の内訳は「URLがどこにも無い271社」と「URLはあるが取れない183社」。** 後者の壁は**サイトに届かないこと**で、`og:image` の手当てを159社に回しても通ったのは5件だけだった（HTMLが取れない116社・`og:image` が無い36社）。**gBizINFO は社名を返すのに `company_url` が null** のことが多い（キオクシアHD・日本オラクル・グロービングとも空）。**URLさえ人が見つければヘッダのロゴは取れる**ので、分かった会社から `PINNED` に足す
- **ブラウザの UA への偽装とヘッドレスブラウザでの取得はしない**（ADR-0008 決定1）。403・503 の多くは明示的な拒否で、「ブラウザUAなら通る11社」もこの線の内側に置く——1社ずつ `PINNED` で足せるので規則を緩める理由にならない
- **その会社では別のURLを使う、と決めたら `candidates.ts` の `PINNED` に書く**（2026-08-26・豊田通商）。`prioritize()` が優先順の先頭に置く。**画像を手で差し替えない**——取り直した瞬間に元へ戻る。豊田通商（8015）は Wikidata の公式サイト（P856）が**英語版**を指しており、そこの `Organization.logo` が 1200×630 の共有用の絵（ロゴは上端の帯だけで残りはグラデーションの余白。`trim` は単色の縁しか落とせない）、英語版ヘッダのロゴは 19.9:1 で器に入らない。**余白の割合で機械的に落とす線は引けなかった**——「インクの外接矩形が画像の半分未満」は2,509枚中52枚あり、その大半は薄い色のワードマークを持つ正しいロゴだった（`docs/logo/logo-pipeline/design.md`）。**同種の見えにくい画像は #221 で片付けた**（下の `mostlyHiddenOnLight`）。**`PINNED` に足してよいのは「同じ意匠の濃淡2版があり、濃いほうを名指しできる」とき**——日本コークス工業（3315）は `logo_w.png` と `logo_b.png` が同じディレクトリに並んでおり、白いほうを落とすと次は 32×32 の favicon になる
- **運営者が画像で渡したロゴは `pipeline/data/logo-assets/<企業ID>.png` に置き、`candidates.ts` の `PINNED` に `source: "supplied"`・`url: "data/logo-assets/<企業ID>.png"` で指定する**（2026-09-30。日本オラクル・グロービング・高砂熱学工業・メルカリの4社）。あとは `npm run build:logos -- --only <ID,…>` で `web/public/logos/` と `logos.json` に入る。`web/public/logos/` へ直接置かない（次の全周で元へ戻る）。`logos.json` の `from` はURLではなくこのパスになる。`/about` の企業ロゴの出典の数え方では `commons` 以外の側に入る
- **1社だけ取り直すときは `npm run build:logos -- --only <ID,…>`。** `--limit` を使うと `pruneOrphans` が対象外の画像を全部消す。`--only` は既存の `logos.json` に上書きし、掃除もしない
- **白いロゴは明るい器（`--logo-surface`）で落とす**（Issue #156・`blankOnLight`）。ライトもダークも地は明るいので、白抜き版はどちらでも空白のマス目になる。**判定は `normalize` を通した後＝配る画像そのものを、白に重ねてから見る**——`reject` の24×24走査に相乗りさせると縮小の平均化とアルファを戻す計算で取りこぼす（同じ50枚を24×24で数えると23枚しか挙がらない）。実測で1,636枚中50枚（3.1%、うち49枚がサイトのヘッダの `logo_w.svg` 系）が該当し、39社は色付きの候補に替わり11社は頭文字に戻した。**`--only` は「取り直した結果で置き換える」——前回の記録を残すのは、いま配っている画像がいまの判定を通るときだけ**（残す規則のままだと、直しに来た当の白いロゴを置いて帰る）。**配ってしまったものは判定では消えないので、`build-logos.test.ts` が `web/public/logos/` の全画像を毎コミット走査する**
- **シンボルだけが見えて残りが白く沈んでいるロゴも落とす**（Issue #221・`mostlyHiddenOnLight`）。**`blankOnLight` はインクが1%あれば通す**ので、濃いシンボル＋白いワードマークは素通りしていた。見るのは2つで、**描かれている図（インクまたは不透明の外接矩形）に対して見えている図（インクの外接矩形）が半分未満**、かつ**その外側の4割以上が透明**であること。**2つめが要る**——白地のカードに載ったアイコンは1つめだけだと落ちるが、白は地であって沈んだ図ではない。**分母を画像ではなく描かれている図にする**のも要点で、画像の寸法は正規化の都合で決まる。**白い縁取り・色の中の白抜きは1つめで残る**（実測22枚）。配っている2,509枚に当てると目視で決めた31枚と一致した（誤検出0）。**呼ぶ側は `unusableOnLight` の1つから引く**——`pick`・`--only` の記録を残す判断・全画像走査の3か所が同じものを見ないと、次の全周で落とすはずの画像を配り続ける
- **仕分けは目で見るしかなかった**（#221）。「外接矩形の面積比が小さい」で切り出した51枚のうち、沈んでいるのは31枚で、19枚は余白があるだけの正方形アイコン。**濃い地と明るい器に並べて描くと一目で分かる**——濃い地に置くと明るい器で消えているものがそのまま現れる。Issue が見立てていた「淡いグレーで読みにくい」は0枚（隠れている画素の輝度は平均251〜255でほぼ純白）
- **OpenWork・OpenMoney は採れない。** 運営者の指示で試したが、OpenWork は9社ぶんで画像認証に切り替わり、OpenMoney は AWS WAF の JS チャレンジで本文が返らない。**アクセス制御の回避になるので作らない**（ADR-0008 決定1に実測）
- **解像度の下限は無い**（ADR-0008 決定3）。取れたものは一旦すべて載せ、**明らかにおかしいものを見てから頭文字に戻す**。そのために `logos.json` に**元画像の実寸**を持たせてある。短辺48px未満が429件・32px未満が146件
- **器は正方形にしない**（ADR-0008 決定4）。実測した縦横比の中央値は3.69で、正方形付近は230件しかない。**器に `contain` で収め、拡大しない。器の縦横比は表示箇所ごとに変えてよい**が、収め方は4箇所（表・カード・企業詳細の見出し・近傍の会社）で共通にする
- **`sharp` は ICO を読めない。** `favicon.ico` をそのまま渡すと「画像でない」に落ちる。`icoToImage` で中の最大エントリを開いてから渡すこと。**ICO の DIB は AND マスクを含むので高さが2倍で入っており、行は下から上**
- **「単色だから空の画像」と判定してはいけない。** 1色のワードマークは Commons の大半で、これで522社中332社を落としていた。空と見なすのは**全面が不透明で、かつ1色**のときだけ
- **gBizINFO のトークンは `pipeline/salary/.gbiz_key`**（gitignore 済み。`.edinet_key`・`.estat_key` と同じ形）。Wikidata に公式サイトが無い263社のうち147社をこれで埋めた。**トークンが無い環境でもその工程だけ飛ばして動く**
- 取得の失敗はキャッシュしないので、`npm run build:logos` を**走らせ直すたびに数十社ぶん回収される**（429と一時的な失敗）。**ただし回収は先細る**——E3 では1巡目（1,336社）で +875社、2巡目（461社）で +9社だった。到達率 2,536/2,961 = 85.6%、画像は合計13.29MB（1枚平均5.2KB・最大18.4KB）、`logos.json` は gzip 64.2KB
- **`meta.count` は母集団の社数（＝CSV の行数）で、今回叩いた社数ではない。** `--only` のとき前回の値を引き継ぐ実装だったため、**E2 で母集団が変わったときに到達率が `2500/1867 = 133.9%` と出た**（E3 で直した）。`missReasons`・`rejectReasons` は**回した社数に対する内訳**で、`partialOf` がその分母を示す
- **新しく入った会社のほうが取りにくい。** 決算期が3月でない会社には非上場・新規上場が多く、**Wikidata に項目が無い**（2巡目の461社のうち271社が「公式サイトURLが無い」）
- **`/` に `logos.json` を丸ごと渡さない**（gzip 41.5KB）。渡すのは**ロゴの有無だけ**——`companies.rows` と同じ並びの1,867文字の文字列（gzip 約250B）。**縦横比は渡さない**——器の寸法が固定で中身は `object-contain` なので、画像が届いてもレイアウトは動かない。企業詳細ページはマスクではなくその画面に出る46社ぶんのIDだけを渡す
- **器は横長。** 表 88×50／近傍の会社 48×38／モバイルのランキング行 68×48（`size="row"`）／企業詳細 128×62。**高さはモック由来で、幅だけ広げてある**（`features/logo/components/CompanyLogo.tsx`）。**表（PC）だけは高さもモックの40pxから50pxに上げた**（運営者の指示・Issue #128。この行は器が行の高さを決めているので隣の列を削らない）。**モバイルは 48×38 に留めていた**——56px以上にすると meta 行の従業員数が丸ごと消えたため（実測）。**Issue #119 で行を4カラムにして meta から従業員数を落としたので、この制約は外れた**（削られる相手が無くなった）
- **ダークで濃いロゴが沈むので、器に `--logo-surface` の明るい面を敷く。** 色を反転させる加工はしない（商標をそのままの形で出す）。**ダークだけ少し落としてある**——白のままだと1ページに30枚並んで眩しい。E2E は `getComputedStyle` が `lab()` を返すので、**キャンバスに描いて sRGB に開いてから**明るさを測っている
- **E2E の「リクエスト数0」は画像とファビコンだけ緩めた**（`e2e/network.ts` の `collectPageRequests`）。ランキングの操作はすべて `e2e/ranking-url-sync.spec.ts` の1本の流れ（操作を続けて1手ごとに0件を見る）で数えている。素の `page.on("request")` を書き足さないこと——見たいのは「操作で HTML を取り直さない」ことで、`loading="lazy"` の画像も、ブラウザが `pushState` のたびに取り直す `/favicon.ico` もこれに反しない。**ファビコンはブラウザのバージョン差**——Chromium 141 は `pushState` で取り直し、Playwright 1.62 同梱の 151 は取り直さない。緩める前は、古い Chromium しか無い環境（Claude Code web のコンテナ等）で走らせるとこの9件が毎回落ちていた
- **`/about` の帰属表示は `attr: true` の44社だけ。** パブリックドメインの397社は並べない（本当に帰属が要るものが埋もれる）

# 現在地: 平均年収・在籍年数の10年推移

> CLAUDE.md の「現在地」節から移した（2026-10-07・トークン消費の削減。移しただけで、本文は1字も書き換えていない）。
> 文中の「上の」「下の」は、CLAUDE.md の「現在地」に並んでいた当時の位置を指す。対応する項は `docs/status/` のどれかにある（索引は CLAUDE.md）。
> **新しく分かったことはここに書く。CLAUDE.md には書かない**（CLAUDE.md は全セッション・全サブエージェントが毎回読むので、伸ばすとそのまま消費量になる）。

**平均年収の10年推移は `timeseries` 施策**（`docs/timeseries/`）。T0（Issue #74）で `web/public/data/history.json`（**2,961社×10年・gzip 187.0KB**。E4・#176 で母集団に追随させ、T3 で平均年齢、T4 で在籍年数を足した）を出し、表示（T1）は C2（#83）に同梱して実装済み。**T2（Issue #138）でグラフの上に数表を足した**（`docs/timeseries/history-table/`）。**T3（Issue #827・親 #826）で表の前年比の列を平均年齢に置き換えた**（`docs/timeseries/history-age/`）。**T4（Issue #835・親 #829）で「在籍年数推移（過去10年間）」の節を平均年収推移と稼ぐ力の推移の間に足した**（`docs/timeseries/tenure-history/`・Claude Design `在籍年数推移.dc.html` の 1b）。

- **表の列は 年度 / 平均年収 / 平均年齢 / `<基準年>年比`。前年比は無い**（T3）。有報の平均年間給与は会社の平均なので、年齢構成が変わるだけでも動く。前年比は動いた幅しか言えないが、平均年齢が隣にあれば、伸びが年齢の上昇と一緒に起きたか（ベースアップとは限らない）を読者が読める
- **平均年齢は `history.json` の `ageById`**。`byId` と同じ CSV の同じ行から同じループで組むので、キーと null の位置は `byId` と同じ。**別のファイルに分けない。** 値は有報の桁のまま（`42.49` もある）で、丸めは描画の `formatDecimal1`——**カードの平均年齢と同じ関数を通すので、最新年の行とカードは同じ文字列になる**（E2E の AC-16）。パイプラインで丸めると2回丸めることになる
- **`history.json` の gzip 上限は 224KB**（T3 で 150KB → 180KB、T4 で 224KB に上げた）。150KB は Worker バンドルに同梱されていた頃の予算で、F1 以降はビルド時に読まれるだけ（`dist/server` に中身が無いことを確かめた）
- **平均年齢の飛びを均さない。** 隣の年と3歳以上動く組が222組あるが、大半は持株会社化で単体の従業員数が桁で変わった年（オープンアップグループ 35.7→50.5歳）。平均年収と同じく「浮いて見えるだけでは直さない」。本文由来の年（2017・2018）の小数第2位は、多くが「35歳2ヶ月」を年に直した12分の1刻みの値で、読み違いではない

- **在籍年数（T4）は `history.json` の `tenureById` と `tenureIndustryMedian`。** 抜き出す処理（`edinet.to_record` の `avg_tenure`）は T0 からあり、`salary_history.csv` に書き出していなかっただけ——**書き出すには書類の ZIP（gitignore）が要り、空のコンテナでは約2.7万件を EDINET から取り直すことになる**（T4 では2本並走で約2時間10分・失敗0。`pipeline/performance/fetch.py` は `salary_history.csv` の `doc_id` を落とすので書類一覧が要らない）。**`history.py` を回し直すときは、書類一覧を取得の窓の終わり（`universe.json` の `filingWindow.to`）までに絞る**——その後の提出を混ぜると、ランキングより新しい年の値が推移にだけ入る。作り直した CSV は在籍年数の列を除いて1文字も変わらなかった
- **在籍年数は平均年齢と違い、平均年収のある年に空欄がありうる**（1行。給与と年齢のタグはあって勤続のタグだけが無い書類で、本文へ降りるのは給与か年齢のタグが無いときだけ）。画面ではその年が「データなし」になる
- **読みが割れた書類は、給与を選び直したら同じ読みの年齢・勤続もそろえる**（`edinet.adopt_salary`。`history.resolve_candidates` と `unified.resolve_ambiguous_salary` の両方が使う）。それまでは給与だけを選び直し、勤続は選ばなかった読みのまま残っていた（22件。差はどれも 0.01〜0.02年で、年齢が変わった行は無かった）
- **業種の中央値は、いまの業種で、その年に値を持つ会社だけで数える。同業が3社未満の年は `null`**（空運業の2017・2018年だけ。1社なら中央値はその会社の値そのもの）。33業種×10年をビルド時に1回数えるだけで、リクエスト時には何も数えない
- **描き方は折れ線で、縦軸は0起点にしない**（棒にすると差が潰れる）。各点に値、最新年だけ塗る、欠損年で線を切る。**中央値のラベルは会社の線と反対側に、左へ伸びる幅ぶん点線の高さを見て置く**——右端の1点だけで上下を決めると、右肩上がりの点線がラベルを横切る。**値のラベルは全部中央揃え**（両端を内側へ寄せると390pxで隣と接する）。目盛は整数の年（`niceTicks` に刻みの候補 `[1, 2, 5]` を渡す）。文字の大きさは年齢別の折れ線と共有（`features/company/components/chartText.ts`）
- **表は 年度 / 在籍年数 / `<基準年>年との差`。差は比ではなく年**で、画面に出ている小数第1位の値どうしで引く。業種の中央値の列は置かない（モックの表は3列）。**在籍年数の列が半分を取る**（`w-1/2`。幅を指定しないと見出しの長い差の列のほうが広くなる。`table-fixed` の等分は375pxで差の見出しがはみ出すので使わない）
- **説明文の1文目に時点を書かない。** モックは「（2026年3月時点）」だったが、企業詳細で決算期を出すのは Q&A・要約・給与の決定方針の各節の説明の先頭だけ。**年（「2026年の」）も付けない**（運営者の指示。無くても意味が通じる）——「◯◯の平均勤続年数は、単体（提出会社）で11.3年です。」
- **「誰も辞めず誰も入らなければ毎年1年ずつ伸びる」読み違いへの手当て（モックの 1c・1e）は入れていない。** 運営者が選んだのは 1b で、業種の中央値が同業の水準を示す
- `/company/[id]` の HTML は raw 約 +17KB・gzip 約 +1.2KB（6861 で 145,226 → 162,594 B）。`/` は ±0

- **節は チャート → 表 → 説明文**（運営者の指示。**年齢別の推定年収も #846 で同じ順にそろえた**——C3 から表が先だった）。増減の1文は図と表の両方を受けた締めなので末尾に置く。**読み上げは表が担う**ので、グラフが持っていた `sr-only` の10件は落とした——同じ中身を読み上げる経路を2つ置かない
- **累積の基準年は会社ごとに違う。** 2017年の値を持たない会社が230社あるので、固定の2017年基準にするとその230社の累積が丸ごと空になる。**その会社で最初に値のある年**を基準にし、列の見出しに書く（`2018年比`）
- **累積は飛び年があっても出す**（内部欠損が33社。例: 2117 は2023・2024が欠損）。基準年からの比なので、間が飛んでいても意味が変わらない
- **「昇給率」とは呼ばない。** 有報の平均年間給与の差は個人の昇給ではなく採用・退職による構成の変化を含む。列は「`<基準年>年比`」、節の説明で「2017年比は会社の平均が動いた幅で、個人の昇給率ではありません」と断る。**基準年は `historyBaseYear` の1か所で求める**——列の見出しと説明が同じ年を名乗るように
- ~~**右端が空く会社が349社ある**（E4・#176）~~ → **refresh の D5（#875）で窓を会社ごとにしたので、右端は空かない。** 決算期が3月でない会社の最新の有報は前の年の提出になり（取得の窓は直近12か月・ADR-0011）、その会社の窓は1年前に寄る（2016〜2025年。2016年は値が無いので左端が「データなし」）。途中が欠ける（2117）のとは別の欠け方
- **桁は1行では決まらない。** `run.fix_salary_typos` はあり得る帯に入る10の冪を小さいほうから採るので、**帯が広いぶん間違った桁で止まる**（トスネット2019は提出側の26億円が÷100 の 2,624万円で止まっていた）。10年ぶんを並べればその会社の他の年が正しい桁を指すので、`history.resolve_scale` が選び直す。**浮いて見えるというだけでは直さない**——ホットリンク2018の320万円は有報が「（千円）3,205」と書いている実額
- **帯の上限3,000万円は実在の会社を切る。** Ｍ＆Ａキャピタルパートナーズの2019・2022年（3,109万・3,161万）が÷10 されていた。推移は他の年を基準に戻せるが、**1年ぶんしか持たないランキング側（`run.py`・`unified.py`）は直していない**（いまの実測値は帯の中なので影響は出ていない）

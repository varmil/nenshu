# 現在地: 掲載企業数の拡大・データの時点の幅

> CLAUDE.md の「現在地」節から移した（2026-10-07・トークン消費の削減。移しただけで、本文は1字も書き換えていない）。
> 文中の「上の」「下の」は、CLAUDE.md の「現在地」に並んでいた当時の位置を指す。対応する項は `docs/status/` のどれかにある（索引は CLAUDE.md）。
> **新しく分かったことはここに書く。CLAUDE.md には書かない**（CLAUDE.md は全セッション・全サブエージェントが毎回読むので、伸ばすとそのまま消費量になる）。

**掲載企業数の拡大は `expansion` 施策**（`docs/expansion/`・親 Issue #22）。取得の窓を直近12か月に広げて母集団を広げる（ADR-0011）と、全件embed をやめる（ADR-0013）の2つが決まっている。Unit は E0〜E6（Issue #172〜#177・#182）で、**E0〜E6 すべて実装済み**（`docs/expansion/initial-payload/`・`period-range/`・`universe/`。E3・E4・E5・E6 は既存の Unit のデータを作り直しただけなので docs は元の Unit の側にある）。**Unit の ID に `P` は使えない**（`performance` 施策が使っている）。

**母集団は 1,867社 → 2,961社になった**（E2・Issue #173・ADR-0011）。**それまで載っていた1,867社は1社も落ちず、金額も採用書類も1つも変わっていない**（実測）。

- **窓は回す日から遡って12か月**（`run.twelve_month_window`）。**日付を直書きしない。** 以前の 6/1〜7/10 は3月期決算の提出ピークに貼り付いた窓で、キヤノン・JT・楽天・イオン・ファーストリテイリングなど1,095社が落ちていた。作ったデータの窓は `pipeline/data/universe.json` に残る（今回は 2025-08-25〜2026-08-25）
- **1社1件に寄せるキーは EDINETコードで、期末が新しいほう（同じなら `docID` が大きいほう）を採る**（`edinet.doc_rank`）。**「後に見つかったものが勝つ」だと走査順で決まり、同じ年に有報を複数出す会社が消える**——りそな銀行・三井住友信託銀行は窓の中に4件ずつ持ち、従業員の状況を持たない書類が残って実際に消えていた
- **証券コードの有無で経路を分けない。** `run.unlisted_docs()` は消した。**提出者種別（内国法人・組合）の絞り込みは上場側にも当たる**——以前は非上場側の経路だけが持っていた
- **`pipeline/data/universe.json` は「CSV の行からは出せないもの」だけを持つ。** 取得の窓（行に残らない）と、掲載条件で落とした社数（そもそも行にならない）。`build-data.ts` が `companies.meta.filingWindow`・`meta.excluded` に写す
- ~~**`/about` に「単体従業員100人未満で省いた社数」を出す**（1,047社。運営者の指示・2026-08-24）~~ → **2026-09-29 に外した**（運営者の判断）。差分更新（refresh の D4）では省いた会社の一覧を持たず、数が動かなくなったため。`/about` は線とその理由だけを書く。`companies.meta.excluded` には `minEmployees` だけが残り、`universe.json` の `excludedByEmployees` は全件の組み直しの記録としてだけ残る（ビルドは読まない）
- **読み方が割れた平均年間給与は2段で絞る**（`unified.resolve_ambiguous_salary`）。①候補のうち「あり得る帯」（`run.plausible_salary_range`＝桁ズレ補正と同じ線）に入るものが1つだけならそれ、②帯で決まらなければ10年推移の中央値に近いほう、③どちらでも決まらなければ落とす。**実測で11社のうち7社が帯で決まり4社が落ちた。** サントリーHD `[1,176万, 176万]`・竹中工務店 `[1,153万, 153万]` は①で決まる。**`fix_salary_typos` より先に走らせること**——あちらは帯の外の値を10の冪で戻すので、先に当てると候補のどれとも一致しない値になる
- **1位が入れ替わった。** 実測値は ヒューリック 2,295万 → Ｍ＆Ａキャピタルパートナーズ 2,266万 → **キーエンス 2,178万（3位）**、35歳そろえは Ｍ＆Ａ 2,330万 → キーエンス 2,178万。**母集団の統計も動く**（実測値 平均719万→693万・sd 200万→199万、35歳 629万→616万・155万→157万）。キーエンスの偏差値は 122.9→124.8（実測値）・150.0→149.5（35歳）
- **`/` の HTML は gzip 63,856 B → 92,797 B**（予算100KBの90.6%）。**余白は 7.6KB。** 1行あたりの情報を増やす変更がそのまま予算にぶつかる（E0・ADR-0013）
- **派生データの充足率をビルドのサマリーに出す**（AC-8）。E2 の時点では 10年推移63.1%・働きやすさ52.3%・稼ぐ力63.0%・ロゴ54.9%。**画面は壊れない**（どれも「掲載なし」を持つ）ので、**数を出さないと気づけない**。追随は E3〜E6

**データの時点は幅で出す**（E1・Issue #172。S3 の「最頻の1つを代表として出す」を改訂した）。**`companies.meta.fiscalPeriodRange`（最古と最新）と `companies.periods`／`rows[9]`（会社ごと）の2種類があり、混ぜない。**

- **母集団の時点は幅**（`/` の title 末尾・`/`・`/?age=N`・`/?ind=X`・`/about` の description・`/` のリード文・`/about`「対象範囲」）。**1社ぶんを出せる場所（`/company/[id]`）はその会社の決算期**——幅を出すと3月期の会社のページに「〜4月期」が付き、その数字がいつのものかぼやける
- **同じ年なら後ろの年を省く**（`2026年3月期〜4月期`）が、**年が違えば省かない**——`2025年3月期〜5月期` は2025年5月期と読めてしまう。拡大後の実データは `2025年3月期〜2026年5月期`
- **最頻を代表にするのをやめた理由。** 母集団を広げると3月期は 63.5% で、**「代表が過半に届かなければ落とす」という旧ガードは通ってしまう**（1,081社の決算期が違うまま代表を名乗る）。**落ちないほうが危ない。** 代わりのガードは**幅が上限を超えたら落とす**（`fiscalPeriodRange`）。上限は D2（#872）で24か月 → **36か月**にした——出る条件を最後の有報から24か月にした（ADR-0018）ので、猶予中の会社が混ざると24か月を超えうる。幅は毎回ビルドのサマリーに出る
- **会社ごとの決算期は文字列プールの添字**（`periods`）。`YYYY-MM` をそのまま並べると `/` の HTML が4倍以上増える。実測で `/` は gzip +301 B（2種類しか無かった頃は圧縮が極端に効いた。**拡大後は14種類**）
- **`/about` だけは幅と最頻の両方を出す。** 幅だけだと端（`2025年3月期` の1社）が全体を代表しているように読める。「3月期が中心」の直書きはやめ、`buildAboutFacts` の `fiscalPeriodTop` から引く。E2E の「1画面に1回」は**幅のほう**を数える

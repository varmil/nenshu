**働きやすさ指標は `worklife` 施策**（`docs/worklife/`）。厚生労働省「女性の活躍推進企業データベース」から**平均残業時間・年次有給休暇の取得率・男女の賃金の差異**を取り込み、企業詳細ページに出す。**W0（取り込み・Issue #149）・W1（表示・Issue #150）・W2（異常値の除去・Issue #215）・W3（区分だけの会社をレーダーに載せる・Issue #802）とも実装済み**（`docs/worklife/data-ingest/`・`company-section/`・`outlier-handling/`・`first-unit/`）。親 Issue #148。**E5（#177）で母集団の拡大に追随させた**（1,548社 → 2,369社 = 80.0%。**W2 で 2,367社 = 79.9%**）。

- **画面の見出しは「残業・有給・男女の賃金の差異」。「働きやすさ」の語は出さない**（W1 で spec 5. の未決事項を決めた）。3指標がそれを代表しているわけではなく（残業と有給は労働時間、賃金の差異は処遇の話）、束ねる名前を付けると、ランキングもスコアも作らないと決めているのに見出しだけが総合評価を名乗ることになる。**施策名とドキュメントの表題は「働きやすさ指標」のまま**
- **節は「年齢別の推定年収」の後ろ**（2026-09-28 に移した。W1 では年齢別の前だった）。この節は雇用管理区分の数で高さが倍以上変わるので、前に置くと年齢別の位置が会社ごとにずれる
- **`CompanyView.byBasis` の中に入れない。** 推移と同じく別の prop で渡す——`byBasis` に置くと「年齢そろえにしたら残業時間が変わる」を型の上で作れてしまう（AC-11）
- **「データが無い」が主要な状態**（全2,961社中592社）。`buildWorklifeView(null)` が3指標ぶんの**空の器**を返し、呼び出し側に分岐を作らせない。**節ごとも項目ごとも消さない**——消すと「残業が少ない会社」と見分けがつかない。**「掲載なし」に添える1文は29文字まで**（Issue #192。390pxの本文幅358px・12px の字で1行に収まる上限）——指標名は隣の見出しが持っているので繰り返さない（`有給休暇の取得率` → `取得率`、`男女の賃金の差異` → `差異`）
- **平均残業時間には定義の注記を1つ置く。数値は補正しない**（Issue #224）。女性活躍DBの算式は**法定労働時間**（1日8時間・週40時間）を起点に数え、**管理監督者・事業場外みなし労働の適用者を除外する**。会社が自社サイトに出すのは**所定労働時間**を起点にした所定外労働であることが多く、所定が8時間より短いぶんが構造的に落ちる——三菱商事は所定が1日7時間15分で、自社公表 31.0時間／月 に対してDBは全体10.5時間・総合職14.1時間（0.75時間／日 × 月20日 ≒ 15時間／月）。三井物産も同じ構図。**補正しないのは所定労働時間がどの一次情報にも無いから**で、埋めれば推定値になる。**注記は値の並びの下に1つ。区分ごとに繰り返さない**（同じ3文が5回並ぶうえ、区分ごとに定義が違うように見える）。**「掲載なし」の会社には出さない**
  - **`WorklifeMetricView` に持たせない。** 島の props は HTML の属性に直列化されるので、固定の110字をビューに載せると**同じ文が props と本文の2か所に出る**（実測で `/company/8058` が +942 B。うち490 B が props ぶんで、残業を登録していない592社ではその490 B だけが残る）。描画側で `metricFootnote(key)` から引くと本文ぶんだけになり、**注記の出ない会社は±0**（`/company/8058`・`/company/7203`・`/company/9104` が +451〜452 B、`/company/6861`・`/company/8306` が ±0）
- **単位は3指標とも値の隣**（残業 `20.1h`・有給 `90.3%`・賃金の差異 `47.6%`。運営者の指示）。~~見出しに1回だけ置く~~ → **区分が5件並ぶと、見出しの単位から5行離れた数字を読むことになり、残業の `20.1` と有給の `90.3` が同じ尺度に見える。** 見出しには**単位では表せない情報だけ**を残す——残業は `月あたり`、有給は空、賃金の差異は定義（`女性の平均賃金 ÷ 男性の平均賃金 × 100`。spec 2.4「数字だけを単独で置かない」）。`時間 / 月` のままだと `h` と「時間」が2か所に出る。**値の列は `min-w-14` の固定幅なので、単位を足しても器の右端は動かない**
- **バーは「器＋塗り＋区切り線」の3枚**（Issue #191 で組み替えた）。グレーの器（`--muted`・高さ7px・`flex:1`）に `width: 値%` の塗りを重ね、地の色で10等分に抜く。1メモリ＝10時間/10%で上限100、**値そのものは丸めない**（有給103.0 はそのまま）。~~塗られていないメモリは描かない~~ → **下敷きが無いと目盛りの基準が消え、10.5 と 26.0 が「何のうちの差か」読めない**（運営者の指摘）。**左右を固定幅で挟む**——区分名は `w-24`、値は `min-w-14` で右寄せ。**値を固定しないと `10.5` と `3.3` で器の右端が9pxずれ、棒を見比べられない**（実測）。**賃金の差異にバーは描かない**（100を基準に上下する値で「長いほど良い」の向きが揃わない）
- **賃金の差異は「全労働者」だけ太字**（Issue #191）。`うち正規`/`うち非正規` はラベルを muted に、値を 16px 太字 → 14px 通常体に落とす（`WorklifeValueRow.subordinate`）。**太字が3つ並ぶとどれが会社全体の値か読み取れない。** 残業・有給の行には強弱を付けない——あちらの全体値と区分別は対等で、片方を弱めるのは「代表を選ぶ」に近づく
- **残業の全体値の行は `全体`。公表する範囲（`対象正社員`・`その他`・`基幹的な職種`）は下に小さく添える**（`WorklifeValueRow.scope`。W3 の後の運営者の指摘）。以前は範囲そのものを行の名前にしていて、`その他 9.9h` が「その他」という区分の値に読めた。**区分名に `全体` を登録している会社が残業で5社ある**ので、範囲の有無で見分け、行の key も区分名だけにしない
- **長い区分名は字を一段落として収める。省略しない**（`契約社員(フルタイム)` のような16文字級が実在する）
- **左カラムの `justify-between` を PC まで効かせない。** 縦積みで左カラムが区分5件ぶんの高さになると、**単位が5行下の行末に落ちる**（実測。`sm:justify-start` で止めている）
- **`web/lib/data/worklife.ts` は `pipeline/worklife/json.ts` の写し。** `pipeline/` は web から import できないので同じ規則が2か所にある。**変えるときは両側を直す。** 写し違いは合成データでは見つからない（両側が同じ勘違いをすれば通る）ので、`lib/data/worklife.test.ts` は**実物の `worklife.json`** を、取り込み元の `pipeline/data/worklife.csv` と列の名前で突き合わせている（D0・#870 で、spec が名指しする7社の値の書き写しから改めた）
- **時点は `lib/data/period.ts` に相乗りさせない。** 決算期（`2026年3月期`）は有報の時点で、データ集計時点（`2026年3月時点`）とは別物。会社ごとに違う（三菱商事は `2026年4月時点`、みずほ銀行は `2025年3月時点`）
- **トップページの HTML は raw 373,821 B のまま±0**（`src/pages/index.astro` から読まない）。`/company/6861` は 97,889 B → 103,281 B、区分4件＋注釈のある `/company/8058` は 110,254 B。**Issue #191 のバーの組み替えで、区分の多い会社ほど軽くなった**（1本あたり 10 `<span>` → 3 `<span>`。`/company/8058` は 133,477 → 131,266 B）

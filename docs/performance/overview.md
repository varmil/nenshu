## 実施順序

```
（T0 → C0 →）P0 ─┬─→ P1（W1 の3指標が要る）
                 └─→ P2（年次の従業員数の取り直しが要る）
```

**P1 は W1 に依存する。** レーダー5軸のうち2軸（有給の取得・残業時間）は女性活躍データベースの値で、W1 が読み手（`web/lib/data/worklife.ts`）を作っている。**同じ規則を2か所に書かない。**

**P2 だけが追加のダウンロードを要する。** 経常利益は1書類に5期ぶん入っているが、**従業員数は当期しかタグ付けされていない**ので、10年ぶんの棒を描くには10年ぶんの書類が要る（17,684件・実測で並列3で約150分）。P0・P1 には要らない。

## P0 一人当たり経常利益の取り込み

spec.md の 1.（データ）すべて。**表示に影響しない Unit である**（AC-5）。W0・T0・C0・L0 と同じ形。

### 事前に確認済みの数値

着手前に実物の有報1,867件から抜いて測った（`intent.md`「前提の確認」）。

- 経常利益を取れた会社 **1,864社（99.8%）**。5期そろうのが1,855社（**着手前の値。P2 で10年ぶんを取り直したあとは1,865社**）
- 連結の従業員数で割れたのが1,675社、単体で代用したのが189社
- **5期の中央値が0以下（赤字）が59社**
- 銀行業82社・保険業13社・その他金融業33社とも欠損なし（AC-2）
- **一人当たり経常利益の上位20社に「本社のみ」バッジが1社も無い**（連結で組んだ結果。#154 の狙い）
- 業種中央値は 海運業2,524万円 〜 輸送用機器131万円で **19倍**開く

### この Unit で決めたこと

**実装は完了した。決めた内容は `docs/performance/profit-per-employee/design.md` にある。**

- ~~T0 のキャッシュで足りるか~~ → **足りた。**「主要な経営指標等の推移」に5期ぶんがタグ付けされており、最新年の書類1件で中央値が出せる。**従業員数だけは当期しか無い**ので、10年ぶんの棒を描く P2 は書類の取り直しが要る
- ~~`performance.json` の gzip 上限~~ → **32KB に置いた**（実測 7.2KB）。数値の配列2本しか持たないので、桁が変わったら中身が変わったということ
- ~~赤字の会社を JSON でどう持つか~~ → **負の値のまま。** 捨てると「データが無い」と区別できなくなる（59社）

## P1 レーダーチャート「公開資料による全体像」

spec.md の 2.1・2.2。**この Unit の要点は「欠測軸をどう描かないか」**（AC-7）。

**5軸のうち2軸は掲載率が6割前後**なので、欠ける会社が常にある。中心まで引き込むと「掲載なし」と書いてあっても最低評価に見える。

**相対位置の決め方が未決**（spec 5.）。倍率の分布が 5%tile 0.08 / 95%tile 4.46 と広いので、線形では上位が振り切れる。

**依存を足さずインライン SVG で描く**（`SalaryCurveChart` と同じ。recharts は使わない）。

## P2 稼ぐ力の推移（過去10年間）

spec.md の 2.3。**実装は完了した。決めた内容は `docs/performance/profit-trend/design.md` にある。**

- ~~年次の従業員数が取れるか~~ → **取れた。** 2017年でも連結91.4%・単体100%で、T0 が踏んだ「2019年以前はタグが無い」問題は従業員数と経常利益には当たらなかった
- 10年ぶんの書類17,684件を取り直した（並列3で74分）。**10年すべて埋まる会社が1,602社（85.8%）**
- ~~`performance.json` に年次を足すか別ファイルか~~ → **別ファイル（`profit-history.json`・gzip 187.0KB）。** `performance.json` は5期の中央値だけを持つ（gzip 上限32KB）ので、10年×3本を足すと超える
- ~~経常利益の単位~~ → **億円**（spec 5.）
- **取り込みで P0 のデータの誤りが2つ出た**（要素名の名前空間・`OrdinaryIncome` が経常収益であること）。`design.md` の「取り込みで直したもの」にある

~~**軸の名前も向きに合わせる。**「残業時間」ではなく「残業の少なさ」~~ → **3巡目で「残業時間」に戻した**（運営者の指示）。**位置の決め方は変えていない**（`ascendingIsBetter` のまま少ないほど外側）——向きは図の説明文（`外側ほど上位`）と、隣に出る順位が担う。`974社中749位` は「公表している974社の中で下から226番目」と読める。

## 位置は順位で決める

**その指標を公表している会社の中での順位**を 0〜1 に写す。**母集団は軸ごとに違う。**

| 軸 | 母集団 |
| --- | ---: |
| 平均年収・定着 | 2,961社 |
| 稼ぐ力 | 2,959社（E6・#182 で 1,865社から追随させた） |
| 有給の取得 | 895社 |
| 残業時間 | 974社 |

**欠測を最下位として数えない。** 掲載率6割の軸で、公表している会社が軒並み上位に寄ってしまう。図の上に「その指標を公表している会社の中での相対位置」と書いてあるのはこの意味になる。

**金額そのものを線形に当てない。** 稼ぐ力は業種中央値に対する倍率が 5%tile 0.08 / 95%tile 4.46 / 99%tile 11.47 で（P0 の実測）、線形だと上位が振り切れて下位が中心に潰れる。**順位なら5軸を同じ規則で置ける**——1軸だけ別の目盛りにすると、1枚の図の中で位置の意味が2種類になる（#154）。

**最下位でも中心には置かない**（`MIN_POSITION = 0.1`）。中心に貼り付けると、**頂点を打たない軸（掲載なし）と見分けがつかなくなる。**「掲載なし」を最低評価に見せないという判断は、逆側からも要る。

## 欠測軸は頂点を打たない

**中心まで引き込んで破線でつながない**（#154・AC-7）。「掲載なし」と書いてあっても、形としては最低評価と同じに見える。

- 頂点を打たない軸を**飛ばして**多角形を閉じる。掲載なしがあっても面積が広がらない
- **軸のラベルは残す**（グレー）。軸ごと消すと5角形が4角形になり、何が公表されていないのかが図から消える
- 頂点が2つの会社は多角形にならないので線だけを引く

キーエンス（残業なし）は4点、三菱UFJフィナンシャル・グループ（有給・残業なし）は3点で閉じる。**#154 が「最悪でも三角形が残る」と書いたとおりになった。**

## 雇用管理区分が2つ以上ある会社は軸に乗せない

**節の表示（W1）は「代表を選ばない」**——区分をそのまま全部並べる（spec 2.2b）。だが**レーダーは1軸に1点しか打てない。**

そこで `representativeValue` は次の順で決める。

1. 全体値があればそれ
2. 無ければ、**区分がちょうど1つのときだけ**その値
3. それ以外は掲載なし

**区分が2つ以上ある会社で1つを選ぶことは、spec 2.2b が禁じた「代表の1区分を選んで残りを捨てる」ことそのものになる。** 平均もしない（spec 1.4）。

キーエンスの有給（区分「正社員」1件・38.8%）はこの規則で軸に出る——アートボード 6a・6b がそう描いている。新日本空調（営業・管理系 67.4 / 技術系 60.8）は掲載なしになる。

## 平均年収の軸だけが表示基準に追随する

**`radar.json` に平均年収は入っていない。** 表示基準（実測値 / 年齢そろえ）で変わるので、`CompanyDetail` が `stats.json` 由来の `current.rankAll` から5軸目を組む（AC-11）。

`radar.json` に入れると、表示基準ごとに9通りの順位を持つことになり、しかも同じものが `stats.json` に既にある。

残り4軸は年齢補正を通さない値なので、サーバーが確定した値のまま渡る。

## `radar.json` は順位だけを持つ

**初版は軸の値も一緒に持っていた。落とした。**

4軸の値はすべて、その画面が既に読んでいる別のファイルから引ける。

| 軸 | 値の出どころ |
| --- | --- |
| 有給の取得・残業時間 | `worklife.json` ＋ `representativeValue()` |
| 定着（在籍） | `companies.json`（`rows[i][5]`） |
| 稼ぐ力・業種中央値 | `performance.json` |

**同じ数字を2か所に置くと、`radar.json` の `JSON.parse` が倍になる**——`import` したファイルは1バイトしか使わなくても丸ごと解析され、しかも isolate の初回リクエストに課金される。

| | raw | `JSON.parse` |
| --- | ---: | ---: |
| 値を持っていた初版 | 84KB | 0.524ms |
| **順位だけ** | **29KB** | **0.161ms** |

`performance.json` を読む側に足したぶん（+0.043ms）を引いても **0.32ms** 減る。

**表示側は、ビルド時に順位を決めたときと同じ `representativeValue()` を通す。** 別の規約で選ぶと**図の頂点と、その隣に出る値が食い違う**——「区分が2つ以上ある会社は軸に乗せない」という規則が片側にしか効かない状態になる。

## モックに合わせ直したもの（2巡目・[Issue #191](https://github.com/varmil/nenshu/issues/191)）

`DesignSync` でアートボード 6a・6b の**実際のマークアップを読めた**ので、それに合わせて直した。初版は画像から起こしている。

### 図が半分に縮んでいた（`@container` を `<svg>` 自身に置いていた）

**`container-type: inline-size` は、その要素の縦横比を無かったことにする。** 置換要素である `<svg>` に付けると `height: auto` が既定の 150px に落ち、`preserveAspectRatio` が図全体を器に収めようとして**倍率 0.5 まで縮める。**

実測では PC で `314×150`（本来 `314×262`）になっており、**R=105 の5角形が半径 52px で描かれていた。** 型チェックも単体テストも E2E も全部通る——`w-full` は効いているので幅は正しく、**縦だけが潰れる。**

**器のクエリは包む要素に置く**（`SalaryCurveChart` が `<figure>` に置いているのと同じ形）。ここでは**クエリ自体を無くした**——器の幅が 340px 固定になったので、刻む必要が無い。

`e2e/company-radar.spec.ts` が `height / width` を viewBox の比と突き合わせて見張る。

### viewBox と器の幅をモックの値にした

| | 初版 | 2巡目（＝アートボード 6a・6b） |
| --- | --- | --- |
| viewBox | `360×300` | **`300×232`** |
| 中心 / R | `(180,150)` / 105 | **`(150,136)` / 70** |
| グリッド | 0.4 / 0.7 / 1 | **1/3 / 2/3 / 1** |
| PC の器 | `1fr 1fr`（実測 314px） | **`340px 1fr`** |
| モバイルの器 | 本文幅 | **本文幅・`max-w-[370px]`** |
| 文字 | 器のクエリで 15〜20 user unit | **11 / 12 user unit** |

**2カラムは `lg` から。** この画面は 768px でサイドバーが出るので、`md` の時点では本文が **396px しかない**（1024px から 652px。実測）。`md:` で `340px 1fr` に割ると右カラムが 32px になり、ラベルが1文字ずつ折れる。

**器の幅が固定になったので、実効の文字サイズがモックと同じになる。** 倍率は PC 1.13・モバイル 1.19 の範囲に収まり、11 / 12 user unit が実効 12.5〜14.8px になる。

### 掲載なしの軸は軸線も破線にする

アートボード 6a・6b・6d がそう描いている。**頂点を打たないことは図から読み取りにくい**ので、線の側にも印を残す。多角形は実線のまま（`polygon[stroke-dasharray]` が0であることは AC-7 の E2E が見張っている）。

### 「掲載なし」は実数より一段小さい（3巡目）

軸ラベルの下に出す値は 12px だが、**「掲載なし」だけ 10px にした**（運営者の指示）。実数と同じ大きさで並ぶと、**無い軸のほうが読む順で先に来る**——値の大きさは軸の重みではない。

**`dy` は user unit で指定する。** `1.35em` は tspan 自身の font-size 基準なので、10px にすると行間まで縮み、**その軸だけラベルとの間隔が狭くなる。**

### 指標リスト（アートボード 6b）

- **並びは 年収 → 残業 → 有給 → 定着 → 稼ぐ力。図の時計回りとは別**（`RADAR_LIST_ORDER`）。**稼ぐ力だけが2行ぶんの高さを持つ**（下に「1人あたり経常利益」と業種中央値が付く）ので、途中に挟むとそこで行間が崩れる。**末尾なら下に続く行が無い**（運営者の指摘。初版は「図と同じ時計回り」にしていた）
- **縦を2本そろえる。** 値は `min-w-[4.75rem]`（76px）、順位は `w-[5.75rem]`（92px）の固定幅で、**どちらも右寄せ**（3巡目・運営者の指示。当初は順位だけ左寄せだった）。**掲載なしの行も同じ幅の空きを残す**——詰めるとその行だけ値の右端が右へ寄る
- **固定幅は最長の文字列より1文字ぶん広く取る。** 右寄せの文字が器を超えると**左へはみ出して隣のラベルを押す**ので、右端はそろったまま崩れる。順位を 84px にしていたとき、`1,867社中1,468位`（実測83px）が**1pxしか余らず**、フォントの違う環境で実際に崩れた（運営者の指摘）。**このサイトは webfont を持たずOSのフォントで組むので、同じ文字列の幅が環境で変わる**——モバイルの行で「円」だけが実機で2行目に落ちたのと同じ理由。右カラム296pxの内訳は ラベル104 ＋ 8 ＋ 値76 ＋ 8 ＋ 順位92 ＝ 288px（実測。最長は `平均年収（有報）` 104px・`11,000万円` 65px・`1,867社中1,867位` 83px）
- **業種中央値は値の下に右寄せ**（`電気機器の中央値 191万円`）。初版は行の全幅に左寄せで敷いていた。**4巡目で値と順位の `dd` から出した**——業種名が長い会社で列を押していたため（下の「公開後に直したもの」）
- ~~有給・残業には、その値がどの雇用管理区分のものかを添える~~ → **3巡目で落とした**（運営者の指示）。`対象とする労働者すべて` のような長い区分名で**行が2行になり、そのぶんの情報量に見合わない。** 区分名は W1 の節が行ごとに出しているので、この画面から消えるわけではない。**2行ぶんの高さを持つのは稼ぐ力の行だけ**という状態に戻った
- **「上位◯%」は採らないまま**（理由は上の対照表）。`上位0.1%` より順位のほうが幅を食う（`1,867社中1,867位` で実測83px）ぶん、器の余裕を測って決める必要がある——上の1つ前の項目がその内訳

## 公開後に直したもの（4巡目・業種名の長い会社）

### 業種中央値が値と順位の列を押していた

運営者の指摘（`/company/8601`・大和証券グループ本社）。**稼ぐ力の行だけ、値と順位が右へずれて器からはみ出していた。**

原因は**業種中央値の注記が、値と順位を包む `dd` の中に入っていた**こと。行は `flex justify-between` で、`dd` は `shrink-0`＋`whitespace-nowrap`。注記の幅は**業種名の長さで決まる**ので、`証券、商品先物取引業の中央値 598万円`（実測 **201px**）が `dd` を押し広げ、中の値（76px）＋順位（92px）＝176px の並びが**9.3px 右へずれて**右カラム（296px）からはみ出した。

**電気機器（`電気機器の中央値 214万円`）では 176px に収まるので、既存の E2E は全部通っていた。** 33業種のうち崩れるのは一番長い1業種だけで、**その業種の会社を1社も見ていない限り気づけない。**

**列は grid で固定した。**

| | 前 | 後 |
| --- | --- | --- |
| 行 | `flex justify-between`（`dt` ＋ `dd` 1つ） | **`grid-cols-[minmax(0,1fr)_4.75rem_5.75rem]`** |
| 値・順位 | 1つの `dd` の中の `span`（`min-w-`/`w-` で固定） | **それぞれ `dd`＝grid の列** |
| 副題・業種中央値 | `dt` と `dd` にそれぞれ内包 | **2行目の `dd`（`col-span-3`）に左右で並べる** |

**2行目は行の全幅（296px）を使い、収まらなければ業種中央値だけが次の行へ落ちる**（`flex-wrap`）。`1人当たり経常利益`（96px）＋ 中央値（201px）は 296px に入らないので、証券では中央値が独立した行になる。**電気機器のような短い業種名では今までどおり1行に並ぶ**（見た目は変わらない）。

~~**業種名は略さない。**~~ → **5巡目で略称にした**（運営者の指示。下の節）。落ちた行が独立して残るのは、**列がそろっていないように見える**ためで、器の側だけでは解けなかった。

**列が中身で動かないことを E2E で固定した**（`業種名が長くても値と順位の列が動かない`）。全行の値・順位の右端が一致すること**と、行そのものが `dl` の右端を超えないこと**の両方を見る——**右端がそろっていても器からはみ出せる**（既存の「全行の右端がそろう」は `dd` 同士を比べるので、行ごと右へずれると通ってしまう）。

## 公開後に直したもの（5巡目・業種名の略称）

### 収まらない業種名は略す

4巡目で列のずれ自体は消えたが、**`証券、商品先物取引業` では中央値だけが3行目に落ちて、その会社の行だけ高くなっていた**（実測 69px。他社は 52px）。運営者の指摘は「**行が揃っていないのが気になる**」。折り返しは崩れではないが、**5行のうち1行だけ形が違う**ことは、指標リストを縦に読むときの引っかかりになる。

**略称は `web/lib/data/industry.ts` の1か所に置く。** `lib/data/period.ts`（決算期を文字列にするのはここだけ）と同じ位置づけで、**データの値を画面用の表記に直す場所**をまとめる。

| | |
| --- | --- |
| 表 | `証券、商品先物取引業` → **`証券・商品先物`**（実測 201px → 167.5px） |
| 既定 | **原文のまま。** 表に無い業種は1文字も変えない |
| 上限 | **8文字**（`MAX_INDUSTRY_LABEL_LENGTH`） |
| 使う場所 | レーダーの指標リストの注記だけ |

**落とすのは「取引業」の3文字だけ。** `証券・商品` まで縮めると「商品」が何を指すか原文から離れる——東証の業種名は「商品先物取引業」で一続きの語で、「証券・商品」は我々が切った切り方になる。読点を中黒に替えたのは、`証券` と `商品先物` が並列であることを見せるため。

**上限8文字は器から決めた。** 2行目は 296px で、左の `1人当たり経常利益` が 96.3px、間が 8px なので注記に使えるのは **191.8px**。33業種を実測すると `ガラス・土石製品の中央値 318万円`（8文字・179.5px）までが収まり、`証券、商品先物取引業の中央値 598万円`（10文字・201px）だけが溢れる。

**器（grid）は4巡目のまま残す。** 略称で収まるようになっても、**列が文字列の長さで動く作りに戻さない**——次に長い業種名が入ったときに、また列がずれるところからやり直すことになる。`flex-wrap` も残す（表を直し忘れたときに、文字を重ねずに折る）。

**原文は同じ画面に残る。** パンくず（`ランキング / 証券、商品先物取引業 / 会社名`）と上部カードの業界内順位が原文なので、**読者は略称と原文を同じ画面で突き合わせられる**。`/?ind=` のリンクも原文のまま。

### 固定の仕方

- **単体テスト**（`lib/data/industry.test.ts`）——**実物の `companies.json` の33業種**に対して「略称のあと8文字以下」を見る。データ側に9文字以上の業種名が増えたらここが落ちる。**落ちなければ、その業種の会社を1社も見ないまま行が折れる**（4巡目で起きたのがそれ）。表の鍵が実在する綴りであることも見る——綴りがずれると `??` で原文に落ちるだけなので、**画面は壊れずに元の長さへ戻る**
- **E2E**（`e2e/company-radar.spec.ts`）——`/company/8601` で、列がそろうこと・**2行目が1行に収まること**（`secondLines === 1`）・略称で出ていること・**原文がページのどこかに残っていること**を見る

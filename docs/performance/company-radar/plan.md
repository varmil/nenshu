## 段取り

1. **先に「欠測軸をどう描かないか」を決める**（AC-7）。5軸のうち2軸は掲載率6割前後で、**欠ける会社が常にある。** 値がある場合の見た目から作ると、欠測が後付けの分岐になる
   → 検証: 頂点を打たない軸があっても多角形が閉じ、面積が広がらない

2. **相対位置の決め方を決める**（spec 5. の未決事項）。P0 の実測では業種中央値に対する倍率が 5%tile 0.08 / 95%tile 4.46 と広く、線形では上位が振り切れる
   → 検証: 5軸すべてが同じ規則で位置を決めていること

3. **`web/features/company/lib/radar.ts` に規則を置く。** 代表値の選び方・順位・位置。**`pipeline/scripts/build-data.ts` も import する**ので alias（`@/`）を使わない
   → 検証: 単体テストで、代表を選ばないこと・残業が反転すること・最下位が中心に来ないこと

4. **`build-data.ts` に `buildRadar()` を足す。** 4軸の順位をビルド時に確定させる。**平均年収の軸は入れない**——表示基準で変わる（AC-11）
   → 検証: `npm run build:data` が通り、`radar.json` が出る。gzip 上限

5. **`OverviewRadar.tsx` を書く。** 依存を足さずインライン SVG。文字は `@container` で器の幅から決める
   → 検証: 390px と PC の両方でラベルが viewBox の外へ出ない

6. **`OverviewSection.tsx` を書く。** 図と、PC だけの指標リスト。図の外にも値を出す（AC-9）
   → 検証: JS実行前のHTMLに軸の値が入っている

7. **`CompanyDetail` の先頭に置き、平均年収の軸をここで組む。** `current`（表示基準の統計）から作って5軸目に足す
   → 検証: 年齢そろえに切り替えると平均年収の軸だけが動き、残り4軸が動かない

8. **E2E を書く**（`e2e/company-radar.spec.ts`）。AC-6〜AC-9・AC-11

9. **スクリーンショットをアートボード 6a・6b・6d と突き合わせる。** ブラウザ操作ツールが無いセッションなので、節だけを撮って目で比べる

10. **`design.md` を書く。** 決めた規則と、モックに合わせなかった点を残す

## リスク

- **代表値の選び方が spec 2.2b とぶつかる。** 節の表示は「代表を選ばない」だが、レーダーは1軸に1点しか打てない。**区分が2つ以上ある会社は軸に乗せない**ことで、選ばずに済ませる
- **モックの「上位◯%」は誤読を招く。** `上位82%` は上から82%の位置の意味だが、日本語としては上位＝良いに読める。順位に替える判断が要る
- **ラベルが viewBox の外に出ると切れる。** 「残業の少なさ」は6文字あり、左右の軸に `start`/`end` で置くと器の外へ出る
- **平均年収の軸を `radar.json` に入れると AC-11 が壊れる。** 表示基準ごとに9通りの順位を持つことになり、しかも `stats.json` に同じものが既にある

# design.md — P2 稼ぐ力の推移（過去10年間）

Issue: [#168](https://github.com/varmil/nenshu/issues/168) ／ 親 [#154](https://github.com/varmil/nenshu/issues/154)
参照: `docs/performance/spec.md` 2.3・AC-10・AC-11、アートボード 6e

出来上がった内部構造。段取りは `plan.md`。

## 年ごとに割る

```
その年の稼ぐ力 ＝ その年の経常利益 ÷ その年の連結従業員数
```

**P0 の「5期の中央値 ÷ 当期の従業員数」とは分母が違う。** あちらは1点の代表値で、こちらは各年の実績になる。キーエンスは従業員が10年で 5,673人 → 12,784人と倍以上になっており、当期の分母で2017年を割ると実態と合わない。

**従業員数はその年の書類の当期からしか取れない。** 経常利益は1書類に5期ぶんタグ付けされているが、従業員数は当期だけで、5期ぶんは本文（`BusinessResultsOfGroupTextBlock`）の中にしかない。**だからこの Unit だけが10年ぶんの書類を要した**（17,684件・並列3で74分）。

**内挿しない。** 経常利益はあっても従業員数が無い年は「データなし」と出す（推移の既存の扱いと同じ）。

## 年の範囲は平均年収の推移に合わせる

CSV には**2013年まで**入っている——2017年の書類が5期ぶんの経常利益を持つため。だが `profit-history.json` は `history.json` と同じ **2017〜2026年の10年**にそろえてある。

**この節は平均年収推移の直後に置いて同じ10年を見比べるためのもの**（アートボード 6e）で、片方だけ14本の棒になると横軸が揃わない。2016年以前は分母（従業員数）も無い。

## 棒グラフは平均年収の推移と共用

`SalaryHistoryChart` を **`YearlyBarChart` に改名**して両方から使う。どちらも「10年ぶんの金額を万円で並べた棒」で、違うのは値の出どころと figcaption だけになる。

**同じ図を2つ書くと、片方だけ直したときに並んだ2枚の見た目がずれる。** この2つは縦に隣り合って出るので、ずれるとすぐ分かる形で目に入る。

**共用にしたことで既存の E2E が1件落ちた。** `figure` を figcaption の文言（`横軸は報告書の提出年です。`）だけで引いていたテストが2枚に当たるようになったので、**節（`平均年収推移（過去10年間）`）で絞ってから figure を取る**ように直した。同じ図が2枚並ぶ以上、図そのものを名指しできる手がかりは節しかない。

表は別（`ProfitHistoryTable`）——**列が違う**。平均年収は1つの金額の前年比・累積で、こちらは割り算の分子と分母を並べる。**分母が10年で倍になった会社では「利益は増えたのに稼ぐ力は横ばい」が起きる**ので、内訳を見せないと値が動いた理由を読者が確かめられない。

## 書式（spec 5. の未決事項に対する答え）

- **経常利益は億円。** 万円だとキーエンスが `63,575,600万円` になり、**桁を数えないと大きさが読めない**。隣の「稼ぐ力」の列が1人当たりの万円なので混ざらない。10億円未満は小数第1位まで（`0億円` だと値が無いのと見分けがつかない）
- **赤字は全角のマイナス**（`−240億円`）。画面の他の増減——全体平均との差（`formatDiffFromMean`）・推移の前年比（`formatRate`）——が `＋` / `−` を使っており、ここだけ ASCII の `-` にすると**同じページに2種類のマイナスが並ぶ**

## 取り込みで直したもの（P0 のデータの誤り）

**10年ぶんを取ったことで、P0 の時点では見えていなかった誤りが2つ出た。**

### 1. 経常利益の要素名は名前空間で決め打ちできない

東京製鐵は `jpcrp030000-asr_E01261-000:OrdinaryProfitSummaryOfBusinessResults` という**会社独自の名前空間の要素**を使っている。`jpcrp_cor:` で決め打ちしていた P0 では2018年以降が取れず、**5期ぶんを遡る性質上、2013〜2017年だけが残って「10年前の数字が最新」になっていた**（P0 の時点では最新年の書類しか読んでおらず、この会社は「データ無し」に落ちていたので気づけなかった）。

**名前空間を外したローカル名で見る。**

### 2. `OrdinaryIncome`（`Loss` が付かない綴り）は経常利益ではない

**あれは「経常収益」で、売上に相当する別の指標。** 三菱UFJフィナンシャル・グループは両方を持つ。

| 要素 | ラベル | 値 |
| --- | --- | ---: |
| `OrdinaryIncomeSummaryOfBusinessResults` | 経常収益、経営指標等 | 14.6兆円 |
| `OrdinaryIncomeLossSummaryOfBusinessResults` | 経常利益又は経常損失（△）、経営指標等 | 3.4兆円 |

**取り違えると業種中央値が桁で変わる**——実際に足してみたところ 保険業 889万円 → **10,995万円**、銀行業 772万円 → 4,332万円になった。この2業種は経常収益（保険料収入・資金運用収益）が経常利益の10倍以上あるので、**間違いが数字の顔つきに出た**。

拾うのは2つの綴りだけにし、**ラベルに「経常収益」を含む行は二重に弾く**（独自拡張の要素はラベルが空になるので、「空でなく、かつ経常収益」のときだけ落とす）。

### 3. 最後の開示が古すぎる会社は落とす

「直近5期」は最新年から遡って数えるので、最後に経常利益を開示したのが8年前の会社では **2014〜2018年の中央値が「稼ぐ力」として画面に出る。** 古い数字を最新のものとして見せない。

該当は2社で、そこはレーダーの稼ぐ力の軸も「掲載なし」になる。

## P0 の実測値が変わった

| | P0（最新年の書類だけ） | P2（10年ぶん） |
| --- | ---: | ---: |
| 一人当たり経常利益が出る会社 | 1,864社 | **1,865社** |
| 電気機器の業種中央値 | 181万円 | **191万円** |
| 赤字（中央値が0以下） | 59社 | 59社 |

**54社で値が変わった。** 10年ぶんが揃ったことで `extract.py` の「遡りの少ないほう＝その年の書類の当期を優先する」が効くようになったため——**遡った値は会計基準の変更で組み替えられていることがあり、当期のほうが一次の記載になる。** 京三製作所 165万円 → 199万円、フォースタートアップス 195万円 → 233万円など。

**精度が上がった変更なので、P0 の design.md の実測値もこちらに更新した。**

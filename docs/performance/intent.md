# intent.md — 稼ぐ力（一人当たり経常利益）

親 Issue: [#154](https://github.com/varmil/nenshu/issues/154)

## なぜ作るか

**企業詳細ページのレーダーチャートに、有価証券報告書だけで埋まる軸をもう1本足すため。**

Claude Design の `改善案.dc.html`（アートボード 6a・6b・6d）が置いたレーダーは5軸ある。出どころは有報が2本（平均年収・定着＝在籍年数）、厚生労働省「女性の活躍推進企業データベース」が3本（有給・残業・男女の賃金の差異）。**データベース側は突合率90.5%に記入率6割程度が乗るので、5軸のうち3軸が欠ける会社が出る。** 図が線に潰れる。

賃金の差異をレーダーから降ろし（理由は #154。数値そのものは W1 の節に残る）、代わりに**一人当たり経常利益**を置く。**有報3本・データベース2本になり、最悪でも三角形が残る。**

もう1つ、読者に対する意味がある。いま出しているのは「その会社がいくら払うか」だけで、**その原資がどこから来ているか**に何も答えていない。一人当たりいくら稼いでいる会社なのかは、年収の持続性を読者が自分で判断する材料になる。

## 成功指標

- レーダーの5軸のうち**3軸（平均年収・定着・稼ぐ力）が全社で埋まる**
- 軸の上位が持株会社で埋まらない——「本社のみ」バッジと役割が重ならないこと
- 追加のデータ調達を発生させない（T0 が取得済みの有報から出す）

## 前提の確認（実測）

着手前に、EDINET の有報1,867件から実際に抜いて測った。

| 項目 | 実測値 |
| --- | ---: |
| 経常利益を取れた会社 | **1,864社（99.8%）** |
| うち直近5期がそろう | 1,855社 |
| 連結の従業員数で割れた | 1,675社 |
| 単体の従業員数で代用した | 189社（連結財務諸表を作っていない会社） |
| **5期の中央値が0以下（赤字）** | **59社** |
| 取れなかった会社 | 3社 |

**「主要な経営指標等の推移」に5期ぶんがタグ付けされている**（`jpcrp_cor:OrdinaryIncomeLossSummaryOfBusinessResults` が `Prior4YearDuration` 〜 `CurrentYearDuration`）ので、**直近5期の中央値は最新年の書類1件だけで出せる。** 追加のダウンロードは1件も要らない。

### 業種差が大きい（中央値の併記が要る）

| 業種 | 中央値 | | 業種 | 中央値 |
| --- | ---: | --- | --- | ---: |
| 海運業 | 2,524万円 | | 電気機器 | 181万円 |
| その他金融業 | 1,278万円 | | 情報・通信業 | 181万円 |
| 銀行業 | 772万円 | | サービス業 | 165万円 |
| 不動産業 | 808万円 | | 輸送用機器 | 131万円 |

**上と下で19倍開く。** 全社を一列に並べると、レーダーの稼ぐ力は業種の当たり外れを表示するだけになる。**業種（tse33）の中央値を数字として併記する**（#154 の判断）。

業種中央値に対する倍率の分布は 5%tile 0.08 / 中央値 1.00 / 95%tile 4.46 / 99%tile 11.47。**10倍超が25社、0.1倍未満が97社、負が59社。**

### 持株会社は上位に来ない（連結で組んだ結果）

一人当たり経常利益の上位20社に「本社のみ」バッジは**1社も無い**。全国保証（1億1,000万円）・国際協力銀行・任天堂・キーエンス（4,062万円）のように、**少人数で高収益の事業会社**が並ぶ。

単体で組むと分子が実質的に子会社からの配当になり、上位が持株会社で埋まる——**連結で組むという #154 の判断は、例外処理を1つも足さずにこれを避けている。**

### 臨時雇用人員は従業員数に入らない

有報の従業員数は正社員等の数で、パート・アルバイトは年間平均人員の外書きになる。小売業の上位はワークマン（5,660万円）・ZOZO・セリアで、**フランチャイズ型・EC型で正社員が少ない業態**が並ぶ。値そのものは正しいが、店頭の人手を含まない数字であることは画面に断る。

## 作らないもの

- **稼ぐ力のランキング・順位表・スコア・総合評価。** レーダーの1軸と企業詳細の1節に留める
- **労働分配率・一人当たり付加価値。** 人件費総額が有報から安定して取れない
- **株価・信用格付け**（#55 の market-data）。外部調達の可否から始まる別の話
- **業績の予測・見通し。** 過去の開示値だけを出す
- **「実力」「効率」のような語。** 「想定年収」を退けたのと同じ線（`docs/product/glossary.md`）

## 施策をどこに置くか（#154 の決めること）

**新規に `performance` 施策を立てる**（#154 の既定案）。

`market-data`（#55）に寄せない理由は、あちらが株価・信用格付けの**外部調達の可否**から止まっており、EDINET だけで完結する経常利益を混ぜると Unit が調達の不確実性を引き継ぐため。稼ぐ力は今後、労働分配率や一人当たり付加価値へ伸ばせる筋があり、独立させておくと後が楽になる。

`docs/product/product.md` の施策マップに行を足した。

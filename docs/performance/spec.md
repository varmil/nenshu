# spec.md — 稼ぐ力（一人当たり経常利益）

対象面: user-web（ユーザー画面）

親 Issue: [#154](https://github.com/varmil/nenshu/issues/154) ／ Unit: P0 [#155](https://github.com/varmil/nenshu/issues/155)・P1・P2

有価証券報告書の「主要な経営指標等の推移」から連結の経常利益を取り、**一人当たり経常利益＝稼ぐ力**として企業詳細ページに出す。用語は `docs/product/glossary.md` に従う。

数値はすべて 2026年提出の有報1,867件での実測値。

---

## 1. データ

### 1.1 出典と取得

金融庁 EDINET の有価証券報告書。**T0（#74）が10年ぶんをキャッシュ済みで、追加の取得先は無い。**

**「主要な経営指標等の推移」には5期ぶんがタグ付けされている**（`jpcrp_cor:OrdinaryIncomeLossSummaryOfBusinessResults` の `Prior4YearDuration` 〜 `CurrentYearDuration`）。**直近5期の中央値は最新年の書類1件だけで出せる。**

**従業員数は当期しかタグ付けされていない。** 5期ぶんは本文（`BusinessResultsOfGroupTextBlock`）の中にしかないので、**年次の従業員数が要るならその年の書類を読む**（P2）。

### 1.2 計算

```
稼ぐ力 ＝ 連結の経常利益（直近5期の中央値） ÷ 連結の従業員数
```

**連結で組む**（ADR は立てない。理由は #154 と `intent.md` にある）。単体で組むと、単体従業員が連結の10%未満の会社173社で分子が実質的に子会社からの配当になり、軸の上位が持株会社で埋まる。そうなるとこの軸は稼ぐ力ではなく「本社に人を置いていないか」を測ることになり、**「本社のみ」バッジと役割が重なる。**

- **中央値を採る。** 1期の減損や特別要因で順位が決まらないようにするため
- **連結の従業員数が無い会社（191社）は単体で代用する。** 連結財務諸表を作っていない会社なので、単体がグループ全体でもある
- **連結の経常利益が無い年は単体で埋める。** 銀行業・保険業でも経常利益は共通して開示される（営業利益が無いことを理由に欠損にしない）
- **赤字（中央値が0以下）はそのまま負の値で持つ。** 59社ある

### 1.3 比較の相手

**業種（tse33）の中央値。** 一人当たり利益は海運業2,524万円・輸送用機器131万円と**19倍開く**ので、全社を一列に並べるとレーダーが業種の当たり外れを表示するだけになる。

**中央値を採るのは1社の外れ値に引きずられないため**——電気機器はキーエンスが桁で外れる（業種中央値181万円に対して4,062万円）。

業種は tse33（`docs/company/spec.md` 1.7 の業界内順位と同じ切り方）。

### 1.4 出力

`pipeline/data/performance_history.csv`（1社1年1行）を中間成果物としてコミットし、`build-data.ts` が `web/public/data/performance.json` を作る。

**`performance.json` が持つのは会社ごとの金額と業種ごとの中央値だけ。** 相対位置（レーダーの頂点をどこに打つか）の算出は表示側に置く——目盛りの決め方を後で変えてもデータを作り直さずに済む。

**`/company/[id]` だけが import する。`app/page.tsx` からは読まない**（Issue #22）。

## 2. 表示

### 2.1 レーダーチャート「公開資料による全体像」（P1）

企業詳細ページの先頭に置く（アートボード 6a・6b・6d）。**5軸。**

| 軸 | 値 | 出どころ | 向き |
| --- | --- | --- | --- |
| 平均年収（有報） | 円 | 有報 | 高いほど外側 |
| 有給の取得 | % | 女性活躍DB | 高いほど外側 |
| 定着（在籍） | 年 | 有報 | 長いほど外側 |
| 稼ぐ力 | 円 | 有報 | 高いほど外側 |
| 残業の少なさ | 時間/月 | 女性活躍DB | **少ないほど外側** |

**ラベルに実数を出し、頂点の位置だけが相対位置になる**（既存のレーダーの作りに合わせる。`平均年収（有報） 2,178万円`・`定着（在籍） 11.3年`）。

**位置の決め方は5軸で揃える。** 1軸だけ別の目盛り（業種中央値を中心にした対数など）にすると、1枚の図の中で位置の意味が2種類になる。業種の文脈は**数字として添える**（`稼ぐ力は、従業員1人当たりの経常利益です（電気機器の中央値 310万円）`）。

**各軸は「その指標を公表している会社の中での相対位置（外側ほど上位）」**である旨を図の上に書く。

### 2.2 欠測軸は頂点を打たない

**中心まで引き込んで破線でつながない。** 「掲載なし」と書いてあっても、形としては最低評価と同じに見える（#154）。

**頂点を打たずに残りの点で多角形を閉じ、その軸のラベルはグレーで残す。** 残業・有給の2軸が欠けても面積が広がらないこと（アートボード 6d）。

### 2.3 稼ぐ力の推移（過去10年間）（P2）

**「平均年収推移（過去10年間）」の直後に置く**（アートボード 6e）。同じ10年の縦棒を並べて置ける。

**チャート → 表**の順。表の列は 年度・稼ぐ力・従業員数・経常利益。

**その年の値を持たない年は棒を描かず「データなし」と書く**（推移の既存の扱いと同じ。内挿しない）。

### 2.4 語彙

**画面に出す語は「稼ぐ力」、その定義として「1人当たり経常利益」を添える**（アートボード 6b）。

- **「実力」「効率」「生産性」のような語を足さない**（`docs/product/glossary.md`。「想定年収」を退けたのと同じ線）
- 経常利益は監査を経た法定開示なので**「実測値」の側**に入る。「推定」の語は使わない
- **分子と分母の範囲が年収と食い違う。** 年収は提出会社単体、稼ぐ力はグループ全体になる。`/about` に1行書く
- **臨時雇用人員は従業員数に入らない。** パート・アルバイトが多い業態では一人当たりが大きく出ることを断る

## 3. 非機能要件

**配信** — 企業詳細ページと同じフルSSR（ADR-0004）。

**データ量** — `performance.json` の gzip サイズに上限を置き、超過したらビルドを落とす（`companies.json`・`worklife.json` と同じ扱い）。**トップページのペイロードは1バイトも増やさない。**

**計算量** — リクエスト時の処理は当該1社ぶんの引き当てだけ。

**対応環境** — モバイルを主とする。横スクロールを発生させない。

**SEO** — 数値はすべて初期HTMLに含める。

**アクセシビリティ** — レーダーの値は図の外に**表または箇条書きとして**出す。図だけが情報源にならないこと。

## 5. 未決事項

- ~~**レーダーの相対位置をどう出すか。**~~ **P1 で決めた。順位で置く**（`docs/performance/company-radar/design.md`）。金額を線形に当てると、業種中央値に対する倍率が 95%tile 4.46 / 99%tile 11.47 と広いために上位が振り切れる。**母集団は軸ごとに、その指標を公表している会社だけ**にする。
- ~~**「上位◯%」を軸のラベルに併記するか**~~ → **採らなかった。** `上位82%` は上から82%の位置の意味だが、日本語としては上位＝良いに読める（キーエンスの有給は実データで895社中883位で、モックの書き方だと「上位99%」になる）。**`895社中883位` と順位で出す**——「画面には数字だけを出し、水準は順位で読ませる」という既存の判断に揃えた。**運営者が「上位◯%」を望む場合はここを戻す。**
- ~~**赤字の会社の書式。**~~ **P2 で決めた。全角のマイナスを付けて `−240億円` と出す**（`web/features/company/lib/profitHistory.ts`）。画面の他の増減——全体平均との差・推移の前年比——が `＋` / `−` を使っており、ここだけ ASCII の `-` にすると同じページに2種類のマイナスが並ぶ。**捨てて「データなし」にはしない**（59社）。
- **中央値の期間。** 5期で始める。10期取れるが、10年前と今では事業構成が変わっている会社がある。
- **経常利益の単位は億円**（P2 で決めた）。サイトの他の金額は万円で通しているが、経常利益はキーエンスで 6,358億円になり、万円にすると8桁が並んで**桁を数えないと大きさが読めない**。隣の「稼ぐ力」の列が1人当たりの万円なので、混ざる心配はない。

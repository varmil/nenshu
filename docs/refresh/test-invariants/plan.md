# plan.md — D0 テストをいまのデータの値から切り離す

Issue: [#870](https://github.com/varmil/nenshu/issues/870)
spec: `docs/refresh/spec.md` 1.12・AC-13 ／ overview: `docs/refresh/overview.md`「D0」

毎日の更新で社数・金額・順位・決算期の幅が動いても、テストとビルドが落ちないようにする。**いまのデータの値を書き写したテストは、データが1社ぶん動いただけで落ちる。** 着手時に数えると、値を書き写したテスト（B）が162件、名指しした会社の状態を前提にしたテスト（C）が109件あった（内訳は design.md）。

---

## 段取り

### 1. 揺らしたデータを作る道具を先に作る

**書き直しより先に、書き直しが正しいかを確かめる手段を持つ。** 棚卸しは読んで仕分けただけなので、見落としがあってもわからない。データを実際に揺らしてテストを回せば、値に縛られたテストはそこで落ちる。

揺らし方は、毎日の更新で実際に起きることに寄せる。

- 実測値の1位の会社を消す（「1位は◯◯」を書き写したテストが落ちる）
- 全社の平均年収を会社ごとに ±1〜9% 動かす（金額・順位・偏差値・母集団の統計を書き写したテストが落ちる）
- 新しい会社を2社足す。派生データ（ロゴ・働きやすさ・文章）は持たせない（社数と「全社に◯◯がある」を前提にしたテストが落ちる）
- 1社の決算期を新しくする（決算期の幅を書き写したテストが落ちる）

**作業ツリーのデータをその場で書き換え、終わったら必ず戻す。** CI（D1）で回すときもチェックアウトは使い捨てなので、同じ手順がそのまま使える。

### 2. いまのデータで一度回し、落ちるテストを数える

揺らす道具ができた時点で、書き直す前のテストを揺らしたデータで回す。**落ちたものが直す対象の実物で、棚卸しの B・C と突き合わせる。** 棚卸しに無いものが落ちたら足し、棚卸しにあって落ちなかったものは、揺らし方が足りないのか、そもそも落ちないのかを見る（C は揺らしても落ちないものが多い——その会社の状態が変わったときにだけ落ちる）。

### 3. ビルドの社数の決め打ちを外す

`pipeline/scripts/build-data.ts` と `pipeline/scripts/build-logos.ts` の `EXPECTED_ROW_COUNT`（2,961）を外す。代わりの線は design.md で決める。

**毎日の差分で落ちるガードのうち、D0 で外すのは社数だけにする。** 給与の決定方針の書類 ID の一致（D3）、掲載から外れた会社の行が横持ちデータに残ると落ちるもの（D9）は、それぞれの Unit が扱う。揺らし方もそれらに触れない形にする。

### 4. ユニットテストを書き直す（pipeline → web の順）

直し方は次の3通り。どれを当てたかは design.md の一覧に残す。

- **データから引く**: 社数は `companies.rows.length`、その会社の平均年収は行の値、というように、期待値をテスト対象と同じ入力から取る
- **関係を見る**: 順位は「自分より高い会社の数＋1」、偏差値は母集団の平均と標準偏差から、のように、値ではなく値どうしの関係を見る
- **会社を選び直す**: 「給与の決定方針が無い会社」のように状態を前提にしたテストは、名指しをやめ、その状態の会社をデータから探す。**名指しを残してよいのは、存在だけを前提にしたものに限る**（企業 ID は ADR-0017 で変わらない）

**書き写した値を別の書き写しで置き換えない。** 合成データに移すのは、規則そのものを見たいテストだけにする。

### 5. E2E を書き直す

ユニットと同じ3通りで直す。**E2E が確かめるのは「データから決まる値が画面に届くこと」なので、期待値はデータと画面の組み立ての関数から作る。** 文言や金額を書き写さない（CLAUDE.md「メタデータの E2E は文言を書き写さない」と同じ考え方）。

データを読む手段と、状態で会社を選ぶ手段は E2E の共通のヘルパーに1か所で持つ。spec ごとに JSON を読みに行かない。

### 6. 揺らしたデータで全部回す

2. と同じ揺らし方で、ビルド・pipeline のテスト・web のユニット・E2E を回し、**全部通ること**を確かめる（Issue の完了条件）。揺らさないデータでも全部通ることを確かめる。

### 7. docs

- design.md に、仕分けの一覧・直し方・揺らす道具の使い方・残したガードを書く
- CLAUDE.md の「開発上の約束」のテストの項に、「実データの値を書き写さない」を足す（次に書くテストが同じ形に戻らないように）
- CLAUDE.md の「現在地」を更新する

## 検証の順序

1. 揺らす道具を、書き直す前のテストに当てて、落ちるものが出ることを確かめる（道具が働いていることの確認）
2. 書き直したファイルごとに、揺らさないデータで通ることを確かめる
3. 最後に、揺らしたデータと揺らさないデータの両方で全部を回す

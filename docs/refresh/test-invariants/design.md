# design.md — D0 テストをいまのデータの値から切り離す

Issue: [#870](https://github.com/varmil/nenshu/issues/870)
spec: `docs/refresh/spec.md` 1.12・AC-13 ／ 段取り: `plan.md`

毎日の更新で社数・金額・順位・決算期の幅が動いても、テストとビルドが落ちない形にした。**確かめ方は、データを実際に揺らしてテストを回すこと**（`tools/perturb/`）。書き直す前のテストは、揺らしたデータで pipeline 10件・web のユニット42件・E2E 43件が落ちた。

---

## テストの2つの型

| 型 | 見ているもの | 扱い |
| --- | --- | --- |
| **規則のテスト** | 計算・整形・選び方の規則。合成データで見るもの、または実データを読んでも値どうしの関係を見るもの（「Python と TypeScript の推定式が全社で一致する」） | そのまま |
| **いまのデータのテスト** | 特定の会社の金額・順位・偏差値、社数、決算期の幅、業種の社数、説明文や原文の文言、書類 ID を書き写したもの | 不変条件に書き直す |

**名指しした会社の「状態」を前提にするテストも、いまのデータのテストに含める。** 「キーエンスには給与の決定方針が無い」「キーエンスは平均年齢がちょうど35.0歳」「みずほ銀行は業界で17位」は、値を書き写していなくても、その会社の次の有報で崩れる。揺らしたデータでは落ちないことが多い（揺らし方がその状態に触れない）ので、棚卸しで拾った。

## 直し方

| 直し方 | 何をするか | 例 |
| --- | --- | --- |
| (a) データから引く | 期待値を、テスト対象と同じ入力から取る | 社数は `companies.rows.length`、その会社の全体順位は `stats.rankAll[行][表示基準]` |
| (b) 関係を見る | 値ではなく値どうしの関係を見る | 全体順位は「自分より金額が高い会社の数＋1」、業界内順位 ≤ 全体順位 |
| (c) 会社を選び直す | 状態を前提にするなら、名指しをやめ、その状態の会社をデータから選ぶ | `pickCompany("給与の決定方針が無い会社", …)` |
| (d) 合成データに移す | 規則そのものを見たいが、実データでは条件を作れないもの | — |
| (e) 消す | 値を書き写しているだけで、同じ性質を別のテストが見ているもの | — |

**表示の文字列は、データから引いた値をアプリの整形関数・組み立て関数に通して作る。** 整形の規則（`formatManYen` 等）はそれぞれの単体テストが見ている。E2E はアプリのデータ組み立て（`companyPageData`・`rankingPageData`）の出力と画面を突き合わせる——**E2E が見るのは「データから決まる値が画面に届くこと」**で、値の計算の正しさはユニットが見る。

**名指しを残してよいのは、その会社が「居る」ことだけを前提にするとき。** 企業 ID は一度振ったら変えない（ADR-0017）ので、居ることは崩れない。

**条件に合う会社が無ければ落とす。** `pickCompany` は、条件に合う会社がデータから消えたとき空振りして通るのではなく、前提が崩れたことを失敗で知らせる。

## 実データの入口 — `web/testing/realData.ts`

ユニットと E2E が実データを読む1か所。`public/data/*.json` を読み、会社を引く・選ぶ関数を持つ。

| 名前 | 役割 |
| --- | --- |
| `companies`・`stats`・`curves`・`history`・`worklife`・`radar`・`performance`・`profitHistory`・`logos`・`summaries`・`analyses`・`filings`・`payPolicies` | 各 JSON を型付きで |
| `rowIndexOf(id)`・`rowOf(id)`・`industryOf(id)` | ID から行・添字・業種を引く。無ければ落とす |
| `pickCompany(what, pred)`・`pickCompanies(what, pred, n)` | 条件に合う会社を `companies.rows` の順に選ぶ。足りなければ落とす |

**JSON の import には `with { type: "json" }` を付けている。** Playwright は Node の ESM でテストを読むので、付けないと JSON を import できない。**アプリの `features/company/lib/pageData.ts`・`features/ranking/lib/pageData.ts` にも同じ指定を付けた**——E2E が画面の組み立てを import するため。Vite・Astro の出力は変わらない。**それ以外で JSON を import するアプリのモジュール（`AboutPage.tsx` 等）は、E2E から import すると落ちる。**

## 揺らす道具 — `tools/perturb/`

```
tools/perturb/check.sh          ビルド・pipeline のテスト・web のユニット
tools/perturb/check.sh --e2e    ＋ E2E（dev サーバーに向けて）
```

**作業ツリーのデータをその場で書き換え、終わったら（失敗しても）git で戻す。** データに未コミットの変更があると戻せなくなるので、そのときは始めずに止まる。テストはどれかが落ちても残りを回す——どこが値に縛られているかを1回で全部見るため。

揺らし方は、毎日の更新で実際に起きることに寄せている（`tools/perturb/perturb.py`）。

| 揺らし方 | 落とすテスト |
| --- | --- |
| 実測値の1位の会社を、全部のデータから消す | 「1位は◯◯」 |
| 全社の平均年収を、会社ごとに ±1〜9% 動かす（倍率は EDINETコードから決まり、1.0 にはならない。その書類の10年推移の行も同じだけ） | 金額・順位・偏差値・母集団の統計の書き写し |
| 新しい会社を2社足す（上場1社・非上場1社。10年推移はその年の1行だけで、ロゴ・働きやすさ・稼ぐ力・文章を持たない） | 社数の書き写しと、「全社に◯◯がある」 |
| 1社を、いまのいちばん新しい決算期の翌月の決算期の、新しい書類に替える | 決算期の幅の書き写し |

**揺らさないもの。** 給与の決定方針のある会社の書類 ID（替えると D3 が外すガードでビルドが落ちる）と、掲載から外れた会社の横持ちデータの行（D9 が扱う）。どちらも D0 の外で、触るとそちらの失敗が混ざる。

## ビルドのガード

**外したのは社数の決め打ちだけ。**

| ガード | 扱い |
| --- | --- |
| `build-data.ts`・`build-logos.ts` の `EXPECTED_ROW_COUNT = 2961` | **外した。** 1社動いただけで落ちた。`build-data.ts` は代わりに `checkCountDrop`——**前回のビルド（書き出し先にいまある `companies.json`）から社数が5%を超えて減ったら落とす**。見たいのは取得の失敗で会社が静かに消えることなので、減り方だけを見る。増えるほうは見ない。`build-logos.ts` は社数を見ない（ID が `companies.json` に居ることは `validate` が見る） |
| `pipeline/worklife/extract.ts` の `EXPECTED_COMPANY_COUNT = 2961`（働きやすさの取り込み） | **外した。** 空の CSV だけを止める |
| 各 JSON の gzip の上限 | 残した。気づくための線で、毎日の差分では動かない程度の余白がある |
| 決算期の幅が24か月を超えたら落とす | 残した。値ではなく幅の上限 |
| ロゴを持つ会社が2,300社を下回ったら落とす（`MIN_WITH_LOGO`） | 残した。いま2,536社で、毎日の差分では割らない。全周で取り直したときの大量の失敗を見る線 |
| 給与の決定方針の書類 ID が採用中の書類と違うと落ちる | **D3 が外す。** 新しい有報が出た会社があるたびに落ちる |
| 横持ちデータ（説明文・分析・給与の決定方針・働きやすさ・ロゴ）の行が掲載社に当たらないと落ちる | **D9 が扱う。** 掲載から外れた会社の行が残ると落ちる |
| `DATA_VERSION = "2026-06"` | **D2 が外す。** 古い HTML が新しい JSON を受け入れてよいかの判断に使っており、毎日行が動くのに版が同じだと判断が働かない |

**5%は「止める線の閾値」**（spec 1.11 の A）で、spec 1.12 の「通る基準」に当たる。D4 がこの線に台帳の扱い（その日の数字を出さず、台帳を進めない）を足す。**線 B（その会社の前の期から ±50%）も同じ形で `checkCountDrop` の隣に置ける**——どちらも「前回のビルドの出力と今回の行を比べる」線で、前回の出力は書き出し先にいまある JSON として手元にある。

## アプリ側で直した依存

**`/about` の実例（みずほFG・みずほ銀行）を、社名ではなく企業 ID（`8411`・`E03532`）で引く**（`features/ranking/lib/aboutFacts.ts`）。社名で引いていたので、社名が変わると `/about` のビルドが落ちた。U7 で社名にしたのはみずほ銀行の ID が書類 ID 由来で毎年変わったためで、その理由は ADR-0006・ADR-0017 で無くなっている。

## 見つけたが D0 では直していないもの

- **「適用中」のチップが長い検索語で横スクロールを出す**（`features/ranking/components/ActiveFilterChips.tsx`）。`Badge` が `shrink-0 whitespace-nowrap` で縮まないため、社名がいちばん長い会社の全名で `?q=` を開くと 390px で 66px・360px で 96px はみ出す。ランキングの横スクロールのループは `?q=` を使わずに避けている（コメントに時点付きで書いた）
- **企業詳細の description の順位に桁区切りが無い**（`lib/seo/company.ts` の `${rankAll}位`）。1,000位以上で `全2,961社中1234位` と出る
- **推移の「連続した10年」の検査**（`build-data.test.ts`）は、2027年の有報が入り始めた時点で落ちる。D5（#875）で年の範囲を会社ごとにするときに直す
- spec の本文に、いまの値や会社名が残っている（`docs/ranking/spec.md` の AC-2・AC-3・1.5 の件数表、`docs/timeseries/spec.md` の AC-2、`docs/company/spec.md` の AC-35・AC-36）。**テストはもうこれらの値を見ていない**

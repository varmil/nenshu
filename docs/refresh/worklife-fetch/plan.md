# plan.md — D7 女性活躍DB の自動取得

Issue: [#877](https://github.com/varmil/nenshu/issues/877)
spec: `docs/refresh/spec.md` 1.15・AC-17 ／ overview: `docs/refresh/overview.md`「D7」 ／ 依存: D0（#870） ／ ADR: ADR-0008 の追記（2026-09-29）・ADR-0009 ／ 共有: worklife の W0・W2

厚生労働省「女性の活躍推進企業データベース」の全件版を、オープンデータのページからリンクを拾って落とし、取り込む。取り込みの規則（法人番号での突合・異常値の除去・236列の検証）は W0・W2 のまま変えない。

---

## 段取り

### 1. ページの形を確かめる

- オープンデータのページ（`https://positive-ryouritsu.mhlw.go.jp/positivedb/opendata/`）を、まず自サイト名を名乗る User-Agent で1回、403 ならブラウザの User-Agent で1回だけ取る
- 全件版のリンクがどこにあるかを確かめる。ページには BOM 有りと BOM 無しの2つの表があり、どちらにも「全体版」の行がある。**BOM 無しの表の「全体版」の行のリンクを拾う**（`docs/worklife/spec.md` 1.1 は BOM 無しを読むと決めている）
- リンク先が ZIP をそのまま返すか、ファイル名がどこから来るかを確かめる

### 2. 取得と取り込みの道筋を決める

- 日付は日本時間で数える（D4 の「昨日まで」と同じ）
- **取りに行くのは1日1回まで。** 取得した日を manifest に残し、同じ日の2回目は取りに行かない
- **版が変わっていなくても毎日取り込む。** 取り込みは同じ ZIP なら同じ値を返すので、毎日回しても既存の会社の値は動かない。一方で、数字の差分更新（D4）がその日に足した会社は、取り込み直さないと働きやすさが空のまま残る（spec 1.15 が防ぎたい状態そのもの）
- **検証に落ちた版は取り込まない。** `worklife.csv` と manifest の取り込んだ版は前のまま残し、落ちた版と理由を manifest に書く。知らせるのは D8
- 値が大きく動いた会社を1社ずつ止める線は置かない。自己申告値で、動いたときに正しいほうを決める根拠が無い（W2 が 0 と 100 ちょうどしか落とさないのと同じ理由）。代わりに**版全体の壊れ方**（突合できた社数が前の版から大きく減る）で止める——列がそろっていても、中身の半分が欠けた版を取り込むと「データベースに登録していません」が大量に事実と違う文になる

### 3. 実装

- リンクの拾い方・User-Agent の順・ファイル名・日本時間の日付を、ネットワークに触れない関数に切り出してテストで固定する
- 取り込みの本体（`extract.ts`）は ZIP のパスを引数で受け、社数の減りの線をそこで見る。手で ZIP を置いて回す道筋（`npm run extract:worklife`）は残す
- 定期実行が呼ぶ入口を1つ作る（取得 → 検証 → 取り込み → manifest）

### 4. 取り込みの規則が変わっていないことを確かめる

- 手元の ZIP（2026-09-29 版）を、main の `extract.ts` と新しい道筋の両方で取り込み、`worklife.csv` が1バイトも違わないことを見る

### 5. 実データで1回回す

- 入口を1回回し、その日の全件版を取り込む（D4 の1回目で足した17社にも働きやすさが付く）
- `build:data` → `check:data` → 全テスト。`worklife.json` の大きさを上限と比べる

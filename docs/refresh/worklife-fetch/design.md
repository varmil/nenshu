# design.md — D7 女性活躍DB の自動取得

Issue: [#877](https://github.com/varmil/nenshu/issues/877)
spec: `docs/refresh/spec.md` 1.15・AC-17 ／ 段取り: `plan.md` ／ ADR: ADR-0008 の追記（2026-09-29）・ADR-0009 ／ 触る Unit: W0（`docs/worklife/data-ingest/`）・W2（`docs/worklife/outlier-handling/`）

厚生労働省「女性の活躍推進企業データベース」の全件版を、定期実行が毎日1回落として取り込む。取り込みの規則（法人番号での突合・異常値の除去・236列の検証）は W0・W2 のまま。

---

## 構成

```
pipeline/worklife/
  download.ts        ページのリンクの拾い方・名乗りの順・ファイル名・日本時間の日付・curl での取得
  download.test.ts   上をネットワーク無しで固定する
  update.ts          入口（npm run update:worklife）。1日1回の判定 → 取得 → 取り込み → 置き場と manifest
  update.test.ts     取得から取り込みまで（ページと ZIP を返す fetch を渡す）
  extract.ts         取り込みの本体（W0）。ZIP のパスと読み書きする場所を引数で受ける。社数の減りの線
  manifest.json      取り込んだ版（と、最後に落とした版）
  source/            取り込んだ ZIP（gitignore）。extract:worklife が読む
```

**入口は2つ。** 定期実行は `update:worklife`（落として取り込む）、取り込みの規則だけを変えて回し直すときは `extract:worklife`（`source/` の ZIP を読む）。どちらも同じ `extract()` を通る。

## 取得

| 手順 | 中身 |
| --- | --- |
| 1日1回の判定 | 日本時間の今日が manifest の `fetchedAt` か `rejected.fetchedAt` と同じなら、何もせずに終わる |
| ページ | `https://positive-ryouritsu.mhlw.go.jp/positivedb/opendata/` を自サイト名（`OpenReport-bot/1.0 (+https://openreport.net/about)`）で取り、**403 のときだけ**ブラウザの名乗りで1回だけ取り直す。403 以外の失敗では名乗りを変えない |
| リンク | **BOM 無しの表（`id="download_nb"`）の「全体版」の行のリンク**。相対パスをページの URL で解決する |
| ZIP | ページで通った名乗りで取る。先頭が `PK` でなければ落とす。ファイル名は `Content-Disposition`（無ければ URL の最後の部分） |

- **ZIP の URL を決め打ちしない。** いまは `download_nb.html?w=99` が ZIP をそのまま返すが、W0 の頃は UUID の入った URL だった。行で拾えば形が変わっても追える
- **「全体版」の行が見つからなければ落とす。** 同じ表に企業規模別・業種別の ZIP が同じ形のリンクで並んでいる。取り違えると一部の会社だけの版を全件として取り込み、残りの会社の働きやすさが消える
- **BOM 無しを採る**（`docs/worklife/spec.md` 1.1）。E5 の頃は BOM 有りを手で落としていた。2026-09-29 版で両方を取り込み、`worklife.csv` が1バイトも違わないことを確かめた（CSV の読み手が BOM を落とすため）
- **取得は curl で行う**（`curlFetcher`）。Node の `fetch`（undici）では、ブラウザの名乗りでも 403 が返った。curl は同じ名乗りで 200。undici が足す見出しで弾かれているとみられるが、弾かれ方を探るためにデータベースへ試しに行くのは1日1回の約束に反するので探っていない。**送る見出しは名乗りだけ**で、通ることを確かめた形のまま
- 日付は日本時間で数える（D4 の「昨日まで」と同じ）
- **取得そのものの失敗**（ページが開けない・リンクが無い・ZIP でない）は例外で止まり、何も書かない。1日1回の判定にも数えないので、次の回がそのままやり直す

## 取り込み

- **版が変わっていなくても毎日取り込む。** `extract()` は同じ ZIP なら同じ値を返すので、既存の会社の値は動かない。一方で、数字の差分更新（D4）がその日に足した会社は、取り込み直さないと働きやすさが空のまま残り、「この会社は残業時間をデータベースに登録していません。」が事実と違う文になる（spec 1.15）。**定期実行では D4 の後に回す**
- 版が変わったかどうかは sha256 で見分け、結果（`changed`）として出す。判断には使わない

### 取り込まない版

| 検証 | 例外 | 中身 |
| --- | --- | --- |
| 236列の見出し | `HeaderMismatchError`（W0） | 列数か、どれか1列の名前が想定と違う。**列がずれたまま取り込むと、別の指標を残業時間として公開することになる** |
| 突合できた社数 | `RejectedSourceError` | 前の版の `matched` から5%を超えて減った。割合はビルドの社数の線（`MAX_COUNT_DROP_RATIO`）と同じ。列がそろっていても中身の欠けた版を止める |

**どちらも `worklife.csv` を書く前に投げる。** `update.ts` はこの2つを受けて、manifest に落とした版を足して終わる（終了コード 0）。取り込んだ版の記録と `worklife.csv` は前のまま。

```json
"rejected": { "file": "99_20261001_utf8.zip", "sha256": "…", "fetchedAt": "2026-10-01", "reason": "女性活躍DBの101列目が想定と違います: …" }
```

- **知らせるのは D8。** 定期実行は `rejected` の有無を見て Issue を立てる。次に取り込めた版で `rejected` は消える（`extract()` が manifest を書き直す）
- 落とした版は `source/` に置かない
- 前の版が無い（manifest が無い）ときは「前の版のまま」にできないので、例外で止める

**1社ずつ値の動きで止める線は置かない。** 自己申告値で、動いたときにどちらが正しいかを決める根拠が無い（W2 が 0 と 100 ちょうどしか落とさないのと同じ理由）。値にはその会社の集計時点（`as_of`）が付いており、画面はそれを出している。

## manifest.json

```json
{
  "source": "厚生労働省 女性の活躍推進企業データベース オープンデータ（全件版）",
  "url": "https://positive-ryouritsu.mhlw.go.jp/positivedb/opendata/",
  "file": "99_20260929_utf8.zip",
  "sha256": "f560960e…",
  "bytes": 11255734,
  "fetchedAt": "2026-09-30",
  "sourceRows": 65720,
  "matched": 2655,
  "written": 2390
}
```

- `fetchedAt` は ZIP を落とした日（日本時間）。`extract:worklife` で手で回し直したときは、同じ版なら前の日付を引き継ぎ、違えば ZIP の更新時刻の日付にする
- `url` はページ。ZIP の URL は毎回ページから拾うので持たない

## 1回目の結果（2026-09-30）

2026-08-25 版 → 2026-09-29 版（BOM 無し）。ページは自サイト名で 403、ブラウザの名乗りで 200。

| | 前 | 後 |
| --- | --- | --- |
| 全件版の行数 | 64,963 | 65,720 |
| 突合できた社数 | 2,641 | 2,655 |
| `worklife.csv` の行数 | 2,367 | 2,390 |
| `worklife.json`（gzip） | 186.3KB | 188.5KB（上限 220KB） |

- 増えた23社のうち9社は、D4 の1回目で新しく載った17社（三菱ＵＦＪ信託銀行・クラサスケミカルほか）。残り14社は、この1か月で新たにデータベースに登録した既存の会社
- 数値（区分名を含む）が動いた会社は176社。最終更新日・集計時点・注釈だけが動いた会社を含めると268社
- 行が消えた会社は無い

## テスト

- `download.test.ts`: リンクは BOM 無しの表の「全体版」の行から拾う（形が変わっても行で拾う・行が無ければ落とす・表が無ければ落とす）、ファイル名、日本時間の日付、名乗りの順（自サイト名で通れば1回・403 のときだけブラウザ・403 以外では変えない）、ZIP でない中身を落とす、curl の見出しの束の読み方
- `update.test.ts`（実データの先頭3社と合成した全件版）: 取り込んで manifest に残す、1日1回、同じ版でも取り込んで値は変わらない、列がずれた版は取り込まず `rejected` に残す（その日は取りに行かない・次の版で消える）、社数が大きく減った版は取り込まない、前の版が無ければ何も書かずに止める
- **取り込みの規則が変わっていないこと**: 2026-09-29 版（BOM 有り）を main の `extract.ts` と新しい `extract.ts` の両方で取り込み、`worklife.csv` が1バイトも違わないことを確かめた

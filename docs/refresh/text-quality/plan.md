## 段取り

### 1. 物差しを起こす

- C9 の版3で数えた「主観の語・事実の語・外部の資料を使った割合」は、語の並びがコードに残っていない（機械ゲートに入ったのは「逃げの語」だけ）。語の並びを起こしてコードに置く
- **起こした物差しが、C9 で実際に起きた劣化を見分けられるかを確かめる。** git の履歴に、要約に戻っていた頃の版2の分析（2026-09-06 時点の676社）が残っている。版2と版5の分布が、C9 の記録と同じ向きに開くこと
- 版5の中のぶれ（書いた時期ごと）も見て、線を決める材料にする

### 2. 版5の分布を固定する

- いま載っている分析（C9 が書いた全社ぶん）を一度数え、分布をファイルに固定する。以後の月はこれと比べる
- 物差しの語を変えたら数え直す（ファイルに物差しの版を持たせ、食い違えば止める）

### 3. 月の集計と線

- その月（日本時間）に書いた分析を数え、版5と比べる。書いたモデルごとの内訳も出す
- 「ずれが大きい」の線を決め、閾値は `pipeline/refresh/thresholds.json` に置く（基準のファイル）。社数が少ない月は判定しない
- 集計は月ごとのファイルに残す（前の月と並べて読めるように）

### 4. 知らせと定期実行

- 最新の月の集計がずれていれば、知らせ（`alerts.py`）が Issue を1つ立てる。次の月がずれていなければ閉じる
- 定期実行の手順に「前の月の集計が無ければ作る」を足す
- 機械ゲートには入れない（1社ずつの下限を課すと分析が単調になる。`gate.py` の注記）
- 物差しと固定した分布も基準のファイル（`criteria.txt`）に入れる——定期実行が物差しを書き換えて知らせを消せないように

### 5. 確かめる

- 合成データのユニットテスト（数え方・月の切り方・線・モデルの内訳・知らせ）
- 実データで9月の集計を作る

# plan.md — D5 10年推移を会社ごとの直近10年に

Issue: [#875](https://github.com/varmil/nenshu/issues/875)
spec: `docs/refresh/spec.md` 1.10・AC-9 ／ overview: `docs/refresh/overview.md`「D5」 ／ 依存: D2（#872） ／ 触る Unit: T0〜T4（`docs/timeseries/`）・P2（`docs/performance/profit-trend/`）

平均年収・在籍年数・稼ぐ力の3つの推移を、全社共通の年の範囲（いまは2017〜2026年）から、会社ごとにその会社の直近10年へ変える。有報が出た日に、その会社の推移だけが1年ずれる。

**期限は2027年1月。** 10〜11月期の会社が、推移の年で「2027年」になる有報を出しはじめる（年は提出した暦年）。全社共通の範囲のままだと、その年の値が捨てられるか、全社の横軸が11年に伸びる。

---

## 段取り

### 1. 窓の右端を確かめる

- 右端は**その会社の推移で値のある最新の年**。D4 の1回目の後のデータで、全2,978社について「台帳の提出日の年」「数字の書類の行の年」と一致することを確かめた（2026年が2,744社・2025年が234社）
- 右端が2025年の234社は、いまは左端2017年・右端2026年（空き）で出ている。窓を会社ごとにすると左端2016年（データなし）・右端2025年になる。この変わり方を design に書く

### 2. データの形を変える

- `history.json` の平均年収・平均年齢・在籍年数を、会社ごとの10年ぶんの配列と右端の年にする
- `profit-history.json` の稼ぐ力・経常利益・従業員数を、**同じ会社の平均年収の窓にそろえる**（P2 の「同じ10年を見比べる」）
- 在籍年数の業種の中央値は、年ごとに「その年に値を持つ会社」で数える（いまと同じ）。全社の窓を合わせた年の範囲で持つ
- 右端の年の行が数字の書類の行でなければビルドを落とす（推移にだけ新しい書類の値が入る事故を止める）
- 2つのファイルが gzip の上限に収まるかを測る

### 3. 画面の側を合わせる

- `pageData.ts` が会社の窓の年を作って、3つの推移に同じ年を渡す。図・表・説明文は受け取った `years` で描いているので、その先は変えずに済むかを確かめる
- 「推移の範囲」を全社共通の年で名乗っている箇所が無いかを洗う（見出しは「過去10年間」、基準年は `historyBaseYear` が会社ごとに決めている）

### 4. テスト

- 合成データのユニットテスト（AC-9）: ある会社に新しい年の行が来ると、その会社の窓は新しい年を右端にし、ほかの会社の窓は変わらない。3つの推移の窓がそろう。中央値は年ごとに値を持つ会社で数える
- `build-data.test.ts`・web のユニットの推移の検査を、全社共通の `years` から会社ごとの窓に書き直す（値は書き写さない）
- E2E: 3つの推移の節の年が、その会社の窓（右端＝値のある最新の年から10年）と一致し、互いにそろうこと。右端の違う会社どうしで見る
- `tools/perturb/check.sh --e2e`。揺らし方に「ある会社が翌年の有報を出す」を足す（いまの4つ目は同じ年の書類の差し替えで、窓がずれない）

# design.md — D5 10年推移を会社ごとの直近10年に

Issue: [#875](https://github.com/varmil/nenshu/issues/875)
spec: `docs/refresh/spec.md` 1.10・AC-9 ／ 段取り: `plan.md` ／ 触る Unit: T0〜T4（`docs/timeseries/`）・P2（`docs/performance/profit-trend/`）

平均年収・在籍年数・稼ぐ力の3つの推移は、**会社ごとにその会社の直近10年**を出す。窓の右端はその会社の推移で値のある最新の年で、有報が出た日にその会社の窓だけが1年ずれる。全社共通の年の並び（`history.json` の `years`）は無くした。

---

## 構成

```
web/features/company/lib/
  historyWindow.ts          HISTORY_SPAN（10）・historyWindowYears（右端から窓の年を振る）・JSON の型
  historyWindow.test.ts     画面に渡す年がデータの窓とそろうこと（実データ）
  pageData.ts               3つの推移に同じ窓の年を渡す（historyYearsFor）
pipeline/scripts/
  lib/historyWindow.ts      windowEnds（会社ごとの右端）・indexInWindow・coveringYears
  lib/historyWindow.test.ts 窓の規則（合成データ・AC-9）
  build-data.ts             buildHistory・buildProfitHistory を窓に詰める。checkWindowEnds
web/testing/realData.ts     historyYearsOf（テストが会社の窓の年を引く）
tools/perturb/perturb.py    5つ目の揺らし方: 1社が翌年の有報を出す
```

**窓の年を振る関数は web に1つだけ置き、pipeline がそれを import する**（`radar.ts` と同じ形。alias を使わない）。データを窓に詰める側と、画面で年を振る側が別々の式を持つと、1年ずれても気づけない。

## 窓の決め方

- **右端＝その会社の推移で値のある最新の年**（`windowEnds`）。`salary_history.csv` は値のある年にしか行を作らないので、行の最新の年がそのまま右端になる。年は有報を提出した暦年（T0 のまま）
- **窓＝右端から数えた10年**（`historyWindowYears(end)` ＝ `end-9 … end`）。窓より古い行は出さない
- **右端の年には必ず値がある。** D5 の前は全社共通の右端（2026年）で、最新の有報が2025年の会社は右端の枠が空いていた。いまは空かない
- **右端の行は数字の書類の行でなければビルドが落ちる**（`checkWindowEnds`）。推移にだけ新しい書類の行が入ると（`history.py` を取得の窓の終わりより後の書類一覧で回した等）、ランキングより新しい年が推移の右端に出る。D4 の1回目の後のデータで、全2,978社の右端が「台帳の提出日の年」「数字の書類の行の年」と一致することを確かめた

**「右端の年」を台帳の提出日から取らない。** 推移の側だけで決まる値にしておくと、`build-data.ts` の中で台帳と推移を突き合わせる経路が1本（`checkWindowEnds`）で済む。

## データの形

### `history.json`

```
{
  "endById": { "<企業ID>": 2026, … },                 // 窓の右端
  "byId": { "<企業ID>": [値 or null, …（10件）] },    // 窓の年の並び
  "ageById": { … }, "tenureById": { … },               // byId と同じ会社・同じ窓
  "medianYears": [2016, …, 2026],                      // 全社の窓を覆う連続した年
  "tenureIndustryMedian": [[年 or null, …], …]         // companies.industries の並び。各配列は medianYears にそろう
}
```

- **全社共通の `years` は持たない。** 残すと、会社の配列を共通の年で引く書き方が型の上で通ってしまう（実際にテストの半分がそう書いていた）
- **業種の中央値は年ごとに、その年に値を持つ会社で数える**（T4 のまま）。**会社の窓ではなく CSV の行から数える**——中央値はその年の性質で、右端が新しい年に進んだ会社の古い年の値も、その年の中央値に入る。並べる年は全社の窓を覆う範囲（`coveringYears`）で、画面は会社の窓の年だけを**年で**引く（添字で引くと、右端が全社の最新の年でない会社で1年ずれる）
- gzip **187.8KB → 196.2KB**（上限 224KB）。増えたのは `endById`（2,978社ぶん）。配列の長さは10のままなので、年がたっても伸びない

### `profit-history.json`

```
{ "profit": { "<企業ID>": [円 or null, …（10件）] }, "income": { … }, "employees": { … } }
```

- **窓は `history.json` の同じ会社の窓**。右端は `history.json` の `endById` だけが持つ——2つのファイルに右端を書くと、片方だけ古い右端になりうる
- CSV には窓より古い年も入っている（1書類が5期ぶんの経常利益を持つ）が、出さない
- gzip 290.9KB → 291.1KB（上限 384KB）

## 画面

- `pageData.ts` の `historyYearsFor(id)` が窓の年を作り、**平均年収・在籍年数・稼ぐ力の3つに同じ年を渡す**。図・表・説明文は受け取った `years` で描いているので、その先は変えていない
- **推移の範囲を全社共通の年で名乗っている箇所は無かった。** 見出しは「過去10年間」、表と図はその会社の年を並べ、累積の基準年（`historyBaseYear`）と在籍年数の差の基準年は会社ごとに最初に値のある年で決まる

## いまのデータで画面が変わる会社

**右端が2025年の234社**（D4 の1回目の後。E4 の時点では349社だった）。決算期が3月でない会社で、2026年の有報をまだ出していない。

| | D5 の前 | D5 の後 |
| --- | --- | --- |
| 窓 | 2017〜2026年 | 2016〜2025年 |
| 右端 | 2026年が「データなし」 | 2025年（値がある） |
| 左端 | 2017年（値がある） | 2016年が「データなし」 |

**2016年の値はどの会社も持っていない**（10年推移は2017年の書類から取っている）ので、この234社は左端が空いて9年ぶんの値が並ぶ。値の数は D5 の前と同じで、空く枠が右端から左端へ移る。**2026年の有報を出した日に、その会社の窓は2017〜2026年になり、左端も埋まる。**

右端が2026年の2,744社は何も変わらない。

## テスト

- **窓の規則は合成データで見る**（`pipeline/scripts/lib/historyWindow.test.ts`）。ある会社に新しい年の行が来ると、その会社の窓だけが新しい年を右端にし、ほかの会社は変わらない（AC-9）。窓より古い年と先の年は窓の外。中央値の年は全社の窓を覆う
- **実データは値を書き写さずに見る**（`build-data.test.ts`）。全社について、配列が10件で右端に値があること、右端の年の平均年収・平均年齢・在籍年数がランキングの値と同じこと、埋まっている年が CSV の行の年（窓の中）と同じこと（内挿しない）、稼ぐ力の経常利益が窓の年の CSV の値と同じこと
- **画面に渡す年**（`web/features/company/lib/historyWindow.test.ts`）。右端がいちばん新しい会社と古い会社で、3つの推移に同じ窓の年が渡り、在籍年数の中央値が年で引かれること
- **E2E**（`e2e/company-refresh.spec.ts` の「D5 AC-9 推移の窓」）。同じ2社で、3つの推移の表の年がその会社の窓と一致し、右端の年に値があること。T3 AC-16・T4 AC-21 の「右端が空いている会社」は、D5 で状態ごと無くなったので「右端がいちばん新しい会社と古い会社」に置き換えた
- **揺らしたデータ**（`tools/perturb/check.sh`）。5つ目の揺らし方で1社が翌年の有報を出し、その会社だけ窓が1年進む。取得の窓の終わりもその提出日まで進める

# plan.md — D3 文章の節が自分の期を名乗る

Issue: [#873](https://github.com/varmil/nenshu/issues/873)
spec: `docs/refresh/spec.md` 1.5・AC-3、`docs/site-chrome/spec.md` 5.1 ／ overview: `docs/refresh/overview.md`「D3」 ／ 依存: D2（#872）

数字は新しい書類、文章は前の書類、という会社でも、文章の節がそれぞれ自分の中身を作った書類の期を名乗り、その書類を指すようにする。給与の決定方針の書類が数字の書類と違うとビルドが落ちるガードをやめる。**D4 より先に入れる**——無いまま数字だけ替えると、要約の節が新しい決算期を名乗り、給与の決定方針はビルドが落ちる。

**いまの全社は数字と文章の書類がそろっている**（D2 の台帳で確かめた）ので、画面はほぼ変わらない。変わるものは design.md に書く。

---

## 段取り

### 1. 文章の節が、いまどこから期と書類を引いているかを洗い出す

- 要約の節の説明（`digestNote`）の決算期
- 給与の決定方針の節の引用の `cite` と下辺の EDINET の帯
- 「このページの出典」の各行のリンク
- 説明文（C7）の出典の1行

どれも数字の側（`companies.json` の決算期・`filings.json` の書類）を借りているはず。借りていない箇所があれば、それは直さずに残す。

### 2. 文章の記録に、自分の書類と期を持たせる

ビルド（`build-data.ts`）で、各成果物が持っている書類 ID と決算期を、web に渡す記録へ写す。**どこから引くかは各成果物の列**（`source_doc_id`・`source_period_end`・`doc_id`・`period_end`）にする。台帳は同じ値を持っているが、D2 でビルドが両者の一致を検めているので、記録の中身を作った成果物から取るほうが近い。

- 要約と分析（`analyses.json`）
- 給与の決定方針（`pay-policies.json`）
- 説明文（`summaries.json`）

合成データのテストで、書類と期が記録に写ることを固定する。

### 3. C18 のガードを外す

`buildPayPolicies` の「原文の書類がいまの数字の書類と違えば落とす」をやめる。代わりに、何社の文章が数字より前の書類のままかをビルドのサマリーに出す（D6 が追いついているかが毎回目に入るように）。

### 4. 節と出典が自分の書類を使うようにする

- 要約の節は、要約の原文の決算期を名乗る
- 給与の決定方針の節は、原文の書類へリンクする。**期は数字の期とずれたときだけ出す**（理由は design.md）
- 「このページの出典」は、行ごとにその行の中身を作った書類へリンクする。説明文と要約の書類が違えば行を分ける
- site-chrome の spec 5.1（企業詳細で決算期を出すのは2か所）に、給与の決定方針の例外を書き足す

純関数（`buildSourceRows`・`digestNote`・給与の決定方針の見せ方）に、ずれた会社の合成データでユニットテストを書く。

### 5. ずれた会社で画面を確かめる

いまのデータには数字と文章がずれた会社がいないので、**揺らしの道具（`tools/perturb/perturb.py`）で作る。** 書類を新しくする1社を、給与の決定方針を持つ会社から選ぶようにする（いまは C18 のガードを避けて持たない会社を選んでいる）。

E2E は、ずれた会社をデータから選び（`pickCompany`）、要約の節・給与の決定方針・出典の行がそれぞれ文章の書類の期とリンクを出すことを見る。**いまのデータではその会社がいないので skip になり、`tools/perturb/check.sh --e2e` で走る。** D4 が入って実データにずれた会社が出れば、ふだんの E2E でも走る。

### 6. 検証する

1. いまのデータで `build:data` の成果物を比べ、変わったのが記録に足した書類と期だけであることを見る
2. いまの全社で、画面に出る決算期が変わらないこと（`e2e/data-period.spec.ts`）
3. pipeline・web のユニットテストと E2E
4. `tools/perturb/check.sh --e2e`（ずれた会社の E2E がここで走る）

### 7. docs

design.md を書き、`docs/site-chrome/spec.md` 5.1、`docs/company/` の該当する design（C10・C12・C19）と CLAUDE.md を直す。

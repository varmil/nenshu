# plan.md — D11 掲載の条件を割った会社をランキングから外し、ページを残す

Issue: [#903](https://github.com/varmil/nenshu/issues/903)
spec: `docs/refresh/spec.md` 1.3・1.16・AC-7 ／ ADR: `docs/adr/0018-universe-entry-exit.md`（2026-09-30 の追記） ／ overview: `docs/refresh/overview.md`「D11」 ／ 依存: D4（#874）・D9（#879）

載っている会社の次の有報が、単体従業員の線（100人）を割ったとき、その有報の数字で反映し、ランキングと母集団から外す。企業ページは残し、ランキングにいない理由を社名の直下で断る。次の有報で線に戻ればランキングに戻る。

きっかけはサイバーステップＨＤ（#893）。2026年5月期に持株会社へ移り、単体の従業員が40人（全員が管理部門）になった。

---

## 段取り

### 1. いまの振る舞いを確かめる

- 差分更新（`update_numbers.py`）で、載っている会社が条件を割ると何が残るかを見る。いまは数字も台帳も替えず、待ち行列に `not_eligible` を残して知らせる。台帳の提出日が進まないので、24か月後に D9 の「提出が途切れた会社」になる
- 条件のうちどれを割ったときに外すかを決める。**単体従業員の線だけ**にする。平均年齢（20〜65歳）と平均年間給与（100万円超）は妥当性の検査で、割ったら読み違いを先に疑う（#892・#895 はどちらも読み違いだった）

### 2. 状態の持ち方を決める

- 「線を割った」を台帳の列にするか、行の従業員数からビルドが決めるかを比べる。行から決めれば、線に戻ったときに何も書き換えずにランキングへ戻る
- 提出が途切れた会社と同じ画面を使うので、D9 の名前（`lapsed`）を「ランキングの外の会社」の名前に改める範囲を決める

### 3. 差分更新を直す

- 載っている会社で、割ったのが単体従業員の線だけなら、ほかの会社と同じく反映する（線 B の読み直しもふつうに掛かる）
- 載っていない会社が線を割っているのは、いまのまま載せない
- 反映した数と社名を、定期実行の PR 本文に書けるよう標準出力に出す

### 4. ビルドと画面

- ビルドの振り分けに「線を割った」を足す。提出が途切れた会社の判定を先にする（数字が古いほうの断りを出す）
- ランキングの外の会社のデータに、理由と連結の従業員数を足す
- 画面は D9 の画面を使い、断り・カードの1文・title と description を理由で出し分ける。決算期を出すのは2か所のまま
- `/about` の「対象範囲」に、一度載った会社が線を割ったときの扱いを1文足す

### 5. 文章の差分生成

- ランキングの外の会社は分析「現状と今後」を画面に出さないので、分析の工程を選ばない。説明文と給与の決定方針は書き直す

### 6. 確かめる

- ユニットテスト: 差分更新の判定（線だけを割った・ほかの条件も割った・載っていない会社）、ビルドの振り分け（理由・順序）、断りの文とメタ、文章の工程の選び方
- 揺らし方（`tools/perturb/`）に「1社の単体従業員を線の下にする」を足し、揺らしたデータでビルドと全テストを回す
- E2E は理由ごとに1本。線を割った会社はサイバーステップＨＤを拾い直した後の実データで走る（名指しはしない）
- dev サーバーでページを 390px・1280px で見る

### 7. サイバーステップＨＤを拾い直す

- `collect --through <読んだ日> --doc S100YZC8:2026-08-28` → `apply` → `build:data` → `build:brand`。待ち行列から消え、#893 が閉じる

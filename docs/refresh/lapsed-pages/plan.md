# plan.md — D9 提出が途切れた会社のページ

Issue: [#879](https://github.com/varmil/nenshu/issues/879)
spec: `docs/refresh/spec.md` 1.3・1.16・AC-7（ページの側） ／ ADR: `docs/adr/0018-universe-entry-exit.md` ／ overview: `docs/refresh/overview.md`「D9」 ／ 依存: D2（#872）

最後の有報から24か月を過ぎた会社を、ランキングと母集団から外したまま、企業ページは残す。ページでは最後の有報の決算期と、提出が途切れていることが読める。順位・偏差値は出さない。いまの台帳で最初に外れうるのは 2027-08-26。

---

## 段取り

### 1. 外れた会社がいるとどこが壊れるかを確かめる

- 台帳の1社の提出日を24か月より前にずらしてビルドを回す。いまは母集団（`companies.json`）から丸ごと落ちるので、企業ページが消え、横持ちデータの突合（働きやすさ・説明文 等の「全件が掲載社に当たる」）でビルドが落ちる

### 2. 残す節と外す節を決める

- 母集団に依存する節（順位・偏差値・位置と分布・レーダー・水準が近い会社・ランキングで比べる）は外す
- 表示基準（年齢そろえ）と年齢別の推定年収も外す。順位の無い推定値だけを残す理由が無い
- 分析「現状と今後」は外す。書いた時点の見立てで、提出が途切れた後に「今後」として読ませると誤る。要約は分析と対なので一緒に外す（C10 の決まり）
- 残すのは、最後の有報の実測値（金額・平均年齢・平均勤続年数・従業員数）、推移3つ、働きやすさ、説明文、給与の決定方針、Q&A、出典
- sitemap には載せる（ページは正規のページで、消えるほうが痛手。spec 1.3 の運営者の判断）

### 3. ビルドで、外れた会社のページのデータを作る

- 外れた会社の行を、母集団とは別のファイルに書く（ランキングの全件データに混ぜない——トップページの読み込みが増え、母集団の計算に紛れる）
- 会社ごとのデータ（推移・稼ぐ力の推移・説明文・給与の決定方針・書類 ID・働きやすさ）は、外れた会社のぶんも作る。業種の中央値など母集団で数えるものは、母集団の会社だけで数える
- 横持ちデータの突合（全件が当たる）は、母集団と外れた会社を合わせて見る

### 4. 画面

- 同じ URL（`/company/[id]`）で、外れた会社は別の画面を描く。操作が無いので島（JS）は持たない
- 企業詳細の画面から、使い回す節を部品に切り出す（パンくず・説明文・平均年収推移）。同じ見た目を2か所に書かない
- 提出が途切れていることの断りは、社名の直下に置く
- タイトル・description・パンくずの構造化データ・sitemap

### 5. 確かめる

- ユニットテスト（ビルドの振り分けと突合・ページのデータ・断りの文・メタ）
- 揺らし方（`tools/perturb/`）に「1社を24か月より前の提出にする」を足し、E2E はその会社で見る。外れた会社がいないとき（いまのデータ）は skip
- 外れた会社が、ランキング・ほかの会社の「水準が近い会社」・母集団の統計に入っていないこと

### 6. docs

design.md、CLAUDE.md、`docs/refresh/ledger/design.md`（「ページを残すのは D9」の記述）。

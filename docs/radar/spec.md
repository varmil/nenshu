# spec.md — レーダーに「平均年収の伸び」を足す（6軸）

対象面: user-web（ユーザー画面）。変わるのは企業詳細ページのレーダー「公開資料による全体像」と `/about`・「このページの出典」だけ。

親 Issue: [#912](https://github.com/varmil/nenshu/issues/912)

企業詳細ページのレーダーに6本目の軸「平均年収の伸び」を足す。値は10年推移（timeseries 施策）の平均年収から出す年率で、稼ぐ力の軸は残す。用語は `docs/product/glossary.md` に従う。

なぜ足すのか・置き換えにしなかった理由・線の引き方の実測は `intent.md` にある。ここにはその結果だけを書く。数値は 2026-09-30 のデータ（ランキング内 2,978社）での実測で、#911（稼ぐ力を240社で掲載しない）を当てた後の状態で数えている。

---

## 1. 何を作るか（WHAT）

### 1.1 レーダーを6軸にする

| 軸 | 値 | 出どころ | 向き |
| --- | --- | --- | --- |
| 平均年収（有報） | 円 | 有報 | 高いほど外側 |
| **平均年収の伸び** | **%/年** | **有報（10年推移）** | **高いほど外側** |
| 有給の取得 | % | 女性活躍DB | 高いほど外側 |
| 定着（在籍） | 年 | 有報 | 長いほど外側 |
| 稼ぐ力 | 円 | 有報 | 高いほど外側 |
| 残業時間 | 時間/月 | 女性活躍DB | 少ないほど外側 |

**既存の5軸の決まりは変えない**（`docs/performance/spec.md` 2.1・2.2、`docs/performance/company-radar/design.md`）。位置は順位で決める・欠測軸は頂点を打たずに残りの点で閉じる・最下位でも中心に置かない・平均年収の軸だけが表示基準に追随する、のすべてがそのまま6軸に広がる。

**軸の並び（時計回りの位置）と指標の一覧の並びは A0 の design.md で決める。**

### 1.2 平均年収の伸びの定義

```
平均年収の伸び ＝（最新年の平均年収 ÷ 基準年の平均年収）^（1 ÷（最新年 − 基準年））− 1
```

- **基準年と最新年は「平均年収推移（過去10年間）」の節と同じもの。** 窓はその会社の直近10年（refresh の D5）。基準年は窓の中で最初に値のある年で、推移の表の `<基準年>年比` の列の見出しと同じ年（`historyBaseYear`）。最新年は窓の右端で、数字の書類の年（必ず値がある）
- **途中の年の欠けは問わない。** 推移の表の累積の比と同じ扱い（`docs/timeseries/spec.md` 2.5）
- **推移の表から読者が計算し直せる。** 最後の行の `<基準年>年比` を r とすると、伸び ＝（1 ＋ r）^（1 ÷ 年数）− 1。表の r は小数第1位に丸めてあるので、端の値では小数第1位が1つずれることがある
- **計算値の区分**（glossary）。実測値から機械的に出す。**「推定」の語を使わない**

### 1.3 伸びを出さない会社

次のどちらかに当たる会社は、この軸を**掲載なし**にする（頂点を打たない）。

**(a) 基準年から最新年までが5年に満たない**（269社）。幅が短いほど1年の動きで年率が大きく振れ、軸の上下の端に集まる。

**(b) 提出会社の範囲が期間中に大きく変わった**（82社）。基準年と最新年を比べて、次の両方を満たす会社。

1. 単体の従業員数が3倍を超えて増えたか、3分の1未満に減った
2. 単体の従業員数 ÷ 連結の従業員数 の比も、3倍を超えて動いた

持株会社化（オープンアップグループ・パナソニックHD）や、持株会社と事業会社の合併（LIXIL）がここに入る。前後で平均年収が別の集団の平均になるため。

- **1だけでは外さない。** グループごと大きくなった会社（KIYOラーニング・アトラエ）が落ちる
- **2だけでは外さない。** M&A で連結だけが増えた会社（ウィルグループ・ペプチドリーム）が落ちる
- **連結の従業員数が無い年は、比を1とみなす。** 連結財務諸表を作っていない会社で、単体がグループ全体でもある（`docs/performance/spec.md` 1.2 の代用と同じ考え方）
- 年次の従業員数は、P2（#168）が年ごとの書類から取った `pipeline/data/performance_history.csv` と、`salary_history.csv` の単体の従業員数から引く。**追加の取得はしない**

**(a)(b) とも「公表していない」わけではない。** 掲載なしにした理由を図の下で読めるようにする（1.6）。

### 1.4 位置

- **順位で置く。** 母集団は伸びを持つ会社（2,627社・ランキング内の88.2%）
- **伸びが大きいほど外側。** 下がった会社（221社）も負の値のまま順位に入る
- 同率の扱い・`MIN_POSITION`・掲載なしの描き方は既存の軸と同じ
- **業種の中央値は添えない。** 業種の中の散らばりのほうが業種どうしの差より大きい（`intent.md`）

### 1.5 同じ期間の平均年齢の動きを添える

**PC の指標の一覧で、伸びの行に基準年・最新年と、その間の平均年齢の差を添える。** 平均年収は年齢構成が変わるだけでも動くので、読者が「年齢が上がったぶんではないか」を自分で読めるようにする（T3・#827 と同じ理由）。

- 平均年齢は `history.json` の `ageById`（推移の表の平均年齢の列と同じ値）
- **補正はしない。** 年齢の動きで伸びを割り引くと推定値になる
- モバイルは指標の一覧を出さない（いまのまま）。平均年齢の動きは同じページの推移の表で読める
- 基準年か最新年の平均年齢が無ければ、年齢の差は出さずに年だけを添える

### 1.6 語と断り

- **軸の名前は「平均年収の伸び」。「昇給率」とは呼ばない**（`intent.md`「「昇給率」とは呼ばない」）
- **値は年率の%を小数第1位で、符号を付けて出す。** 書式は推移の表の基準年比と同じ（`formatRate`。全角の `＋`／`−`、0 は `±`）で、年あたりの値であることが値の表記から読めること
- **図の下に、会社の平均の動きであって個人の昇給率ではない旨を1回書く。** 伸びを出している会社だけ
- **伸びを出していない会社には、その理由を図の下に書く**（(a) 推移が5年に満たない／(b) 持株会社化などで提出会社の範囲が変わった）。**既存の欠測の断り（「公表の無い指標は…」）に混ぜない。** 伸びは会社が公表していないのではなく、このサイトが出していない
  - #911 で掲載なしになる稼ぐ力も同じ性質を持つ。欠測の断りの文言は A0 の design.md で、6軸すべての欠け方に対して正しくなるように決め直す
- 断りの文を島の props に載せない（固定の文言は描画側で引く。C7・W2 と同じ）

### 1.7 計算方法を見える場所に置く

- **`/about` に「平均年収の伸びの出し方」の節を足す。** 式・基準年と最新年・5年の線・提出会社の範囲が変わった会社を外す線・個人の昇給率ではないこと
- **企業詳細の「このページの出典」の計算値の行に「平均年収の伸び」を挙げる。** 伸びを出している会社だけ（行と文言は `buildSourceRows` が節の有無から決める。C12）

### 1.8 毎日の更新との関係

**何も足さない。** 伸びはビルドのたびに `history.json` と同じ窓から作り直すので、有報が出てその会社の窓が1年ずれた日に、値も順位も変わる（refresh の D5・D8）。

### 1.9 ランキングの外の会社

**変わらない。** ランキングの外の会社（D9・D11）のページはレーダーを出さない。

## 2. 非機能要件

**配信** — いまのまま（`/company/[id]` はビルド時に生成する静的アセット。ADR-0014）。

**データ量** — `radar.json` に伸びの順位が1軸ぶん増える。gzip の上限（48KB）の中に収める。**トップページ（`/`）の HTML は1バイトも増やさない**（`radar.json`・`history.json` を `src/pages/index.astro` から読まない）。

**表示側で値を持ち直さない。** `radar.json` は順位だけを持つ（`docs/performance/company-radar/design.md`「`radar.json` は順位だけを持つ」）。伸びの値と年齢の差は、そのページが読んでいる `history.json` から、順位を決めたのと同じ関数で出す。**別の規約で出すと、図の頂点と隣の値が食い違う。**

**対応環境** — モバイルを主とする。360px・390px で横スクロールを出さない。6本のラベルが切れず、重ならない。

**SEO** — 値と断りはすべて初期 HTML に含める。

**アクセシビリティ** — 6軸の値が図の外にも文字として出る（PC の一覧。モバイルは図の中のラベルが DOM のテキスト）。

**テスト** — 実データの値を書き写さない（CLAUDE.md「開発上の約束」）。(a)(b) の会社・伸びが負の会社などは状態で `pickCompany` から選び、`tools/perturb/check.sh` の揺らしたデータで回す。

## 3. 受け入れ基準

### AC-1 6軸

```gherkin
Given 伸びを持つ会社の企業詳細ページ
Then 「公開資料による全体像」の図に6軸が出る
And 平均年収の伸びの軸のラベルに年率の%が符号付きで出る
And 既存の5軸のラベルと値は6軸にする前と同じである
```

### AC-2 値の定義

```gherkin
Given 伸びを持つ会社
Then 伸びの値は、推移の節と同じ窓の基準年と最新年の平均年収（history.json）から 1.2 の式で出し、小数第1位に丸めた値である
And 基準年と最新年は、推移の表の基準年比の列の見出しと最後の行の年度と同じである
```

### AC-3 幅が5年に満たない会社

```gherkin
Given 基準年から最新年までが5年に満たない会社
Then 平均年収の伸びの軸に頂点が打たれない
And その軸のラベルが「掲載なし」としてグレーで残る
And 図の下に、推移が5年に満たないため伸びを出していない旨が出る
And 「公表の無い指標」の断りに伸びが数えられない
```

### AC-4 提出会社の範囲が変わった会社

```gherkin
Given 基準年と最新年で、単体の従業員数が3倍超／3分の1未満に動き、かつ単体÷連結の比も3倍超動いた会社
Then 平均年収の伸びの軸に頂点が打たれない
And 図の下に、持株会社化などで提出会社の範囲が変わったため伸びを出していない旨が出る
```

```gherkin
Given 単体の従業員数は3倍超に増えたが、単体÷連結の比の動きが3倍以内の会社
Then 平均年収の伸びの軸に頂点が打たれる
```

```gherkin
Given 単体÷連結の比は3倍超動いたが、単体の従業員数の動きが3倍以内の会社
Then 平均年収の伸びの軸に頂点が打たれる
```

```gherkin
Given 期間中に連結の従業員数が無い年がある会社
Then その年の比は1として判定される
```

### AC-5 位置

```gherkin
Given 伸びを持つ2社
When 片方の伸びがもう片方より大きい
Then 大きいほうの頂点が外側にある
```

```gherkin
Given 伸びが負の会社
Then 頂点が打たれる
And 中心には置かれない
```

### AC-6 平均年齢の動き（PC）

```gherkin
Given 伸びを持つ会社を PC の幅で開く
Then 指標の一覧の伸びの行に、基準年・最新年と、その間の平均年齢の差が出る
And 平均年齢の差は推移の表の基準年と最新年の平均年齢から出した値である
```

### AC-7 語

```gherkin
Given 企業詳細ページと /about
Then 「昇給率」の語が伸びの名前として出ない
And 伸びの軸・一覧・断りに「推定」の語が出ない
```

```gherkin
Given 伸びを持つ会社
Then 図の下に、会社の平均の動きであって個人の昇給率ではない旨が1回だけ出る
```

### AC-8 表示基準と独立

```gherkin
Given 伸びを持つ会社の企業詳細ページ
When 「見せ方」を「年齢そろえ」に切り替える
Then 平均年収の伸びの値と頂点の位置が変わらない
And 平均年収（有報）の軸だけが表示基準に追随する
```

### AC-9 図だけが情報源にならない

```gherkin
Given PC の幅の「公開資料による全体像」の節
Then 6軸の値が図の外の一覧にも文字として出る
And 6行の値の列と順位の列の右端がそろう
```

### AC-10 モバイル

```gherkin
Given 360px と 390px の幅
When 伸びを持つ会社と、伸びが掲載なしの会社を開く
Then 横スクロールが出ない
And 6本の軸のラベルと値が図の器からはみ出さず、互いに重ならない
```

### AC-11 計算方法と出典

```gherkin
Given /about
Then 平均年収の伸びの出し方の節があり、式・5年の線・提出会社の範囲が変わった会社を外す線・個人の昇給率ではないことが読める
```

```gherkin
Given 伸びを持つ会社の「このページの出典」
Then 計算値の行に平均年収の伸びが挙がる
```

```gherkin
Given 伸びが掲載なしの会社の「このページの出典」
Then 計算値の行に平均年収の伸びが挙がらない
```

### AC-12 データ

```gherkin
Given npm run build:data を実行する
Then radar.json に平均年収の伸びの順位が入る
And 伸びを持つ会社の数と、(a)(b) それぞれで外した会社の数がビルドのサマリーに出る
And radar.json の gzip サイズが上限以内である
And トップページの HTML のサイズが変わらない
```

## 4. 未決事項

- **軸の並びと指標の一覧の並び。** A0 の design.md で決める。一覧は、2行ぶんの高さを持つ行（稼ぐ力・平均年収の伸び）を末尾にまとめるのが既存の考え方（`RADAR_LIST_ORDER`）
- **6角形の寸法とラベルの置き場所。** いまの viewBox（300×232）は5軸の配置で決めてある。6軸で上下に頂点を置くと、下のラベルの分だけ縦に要る。モックを Claude Design で起こすか、いまの寸法から組むかは運営者が決める
- **欠測の断りの文言。** 1.6 のとおり、#911 の稼ぐ力・伸びの (a)(b)・女性活躍DB の未登録で理由が3通りになる。1文にまとめるか、理由ごとに書くか

## 5. 作らないもの

`intent.md`「作らないもの」を参照。平均年収の伸びのランキング・並び替え・フィルタ、年齢構成で補正した伸び、稼ぐ力の軸を外すこと、窓の途中の形の変化を見つけること、分析の材料に足すこと。

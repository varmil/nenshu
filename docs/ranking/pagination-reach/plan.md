# U17 ページ番号の到達範囲 — plan.md

Issue: [#813](https://github.com/varmil/nenshu/issues/813)（親 [#811](https://github.com/varmil/nenshu/issues/811)）
仕様: `docs/ranking/spec.md` 1.8・AC-17 ／ 分解: `docs/ranking/overview.md` U17 ／ 前提: `docs/ranking/ranking-pagination/`（U6）

着手前の段取り。出来上がりの構造は design.md に書く。

## 手順

1. **いまのページ送りを幅ごとに測る。** 360・375・390・640・768・1280px で、1ページ目・中ほど・最終ページの並びと、並び全体の幅・本文の幅を取る。**前後2ページに広げたときに収まらない幅がどこかを、コードを書く前に数字で押さえる**のがこの手順の目的。
2. **収まらない幅の詰め方を決める。** 押せる大きさ（32px）を削る案・「前へ」「次へ」を消す案・省略記号を狭める案を、1. の数字に当てて比べる。決めた根拠と採らなかった案は design.md に残す。
3. **`getPaginationRange` の前後のページ数を2にする。** 並びを決めるのはこの純粋関数1つなので、表示側に分岐を足さない。
4. `pagination.test.ts` を前後2ページの並びに書き換える。**先に書いて落ちることを見てから** 3. を当てる。先頭付近・末尾付近・中ほど・隙間が1ページだけの位置（5ページ目）を固定する。
5. `RankingPagination` から、狭い画面での省略記号の幅と項目の隙間を class で渡す。**`design-system/ui/pagination.tsx` は触らない。**
6. E2E を `e2e/ranking-pagination.spec.ts` に追記する（新しいファイルを増やさない）。2ページ先を押して移れること・その操作でネットワークが起きないこと・360px で並びが本文からはみ出さないこと。
7. 型・lint・Unit テスト・E2E をすべて通す。**dev サーバーを立て、360px と 1280px で並びを目で見る**（省略記号を狭めても隣の数字と見分けられるか）。
8. 決めたことを design.md に、仕様の変更を spec.md 1.8・AC-17 に残す。
9. PR を出してマージする。

## 検証の順序

- Unit テスト（並びの純粋関数）→ E2E（実ブラウザでの幅と操作）→ dev サーバーでの目視、の順。
- **幅の検証は、並びが一番長くなるページで行う。** 前後2ページの両側に省略記号が出る位置（5ページ目〜最終ページの4つ前）が最大で、1ページ目や最終ページで見ても意味がない。
- 既存の E2E 全件が緑であること。とくに U6 の `?page=N` の直接表示・範囲外の丸め・押すと最上部へ戻ること。

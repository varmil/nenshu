# U17 ページ番号の到達範囲 — design.md

Issue: [#813](https://github.com/varmil/nenshu/issues/813)（親 [#811](https://github.com/varmil/nenshu/issues/811)）
仕様: `docs/ranking/spec.md` 1.8・AC-17 ／ 分解: `docs/ranking/overview.md` U17 ／ 段取り: `plan.md` ／ 前提: `docs/ranking/ranking-pagination/design.md`（U6）

出来上がりの内部構造。**ページ番号は先頭・末尾と、いま見ているページの前後2ページまでを並べる。** 狭い画面でも1行に収まるよう、`sm` 未満だけ省略記号と隙間を詰める。

## 構成

```
web/features/ranking/lib/pagination.ts              # getPaginationRange の前後のページ数 1 → 2
web/features/ranking/lib/pagination.test.ts         # 99ページで並びを固定
web/features/ranking/components/RankingPagination.tsx  # sm 未満の詰め方を class で渡す
web/e2e/ranking-pagination.spec.ts                  # AC-17（2ページ先への移動・360px の幅）
```

`design-system/ui/pagination.tsx`（shadcn のプリミティブ）は変えていない。

## 並びの規則

`getPaginationRange(currentPage, totalPages)` が並びの正で、表示側に分岐は無い。先頭・末尾・`currentPage ± 2` を集め、番号が飛ぶ箇所に `"ellipsis"` を挟む（U6 から集め方は同じで、前後のページ数だけが変わった）。

2,961社＝99ページでの並び:

| いまのページ | 並び | 項目数（前へ・次へ込み） |
| --- | --- | --- |
| 1 | 1 2 3 … 99 | 7 |
| 3 | 1 2 3 4 5 … 99 | 9 |
| 4 | 1 2 3 4 5 6 … 99 | 10 |
| 5 | 1 … 3 4 5 6 7 … 99 | 11 |
| 10 | 1 … 8 9 10 11 12 … 99 | 11 |
| 95 | 1 … 93 94 95 96 97 … 99 | 11 |
| 97 | 1 … 95 96 97 98 99 | 9 |
| 99 | 1 … 97 98 99 | 7 |

**最長は数字7つ・省略記号2つ**で、5ページ目から最終ページの4つ前（95ページ目）までがこの形になる。幅の検証はこの区間で行う。

**隠すのが1ページだけの隙間も省略記号にする**（5ページ目の `1 … 3` の `…` は2だけを隠している）。数字にすると次の「幅の予算」を超える。

## 幅の予算

並びは中央寄せ（`Pagination` の `justify-center`）なので、本文の幅を超えると**左右の両側へ**はみ出す。左へ出た「前へ」は画面の外になり、横スクロールでも戻せない（`scrollWidth` は増えない）。だから収まることが条件になる。

項目ごとの幅（実測）:

| 項目 | `sm` 未満 | `sm` 以上 |
| --- | --- | --- |
| 数字（`size-8`） | 32px | 32px |
| 「前へ」「次へ」 | 34px（文字は `hidden sm:block` で隠れ、矢印だけ） | 約68px |
| 省略記号 | **16px**（`w-4`） | 32px（`size-8`） |
| 項目の隙間 | **0**（`gap-0`） | 2px（`gap-0.5`） |

最長の並び（前へ・数字7・省略記号2・次へ）:

| 画面幅 | 本文の幅 | 並びの幅 |
| --- | --- | --- |
| 360px | 328px | **324px** |
| 390px | 358px | 324px |
| 768px（サイドバーが出る） | 496px | 445px |
| 1280px | 752px | 445px |

詰めずに前後2ページを並べると、`sm` 未満で 376px になる（360px でも 390px でも収まらない）。**`sm` 以上は詰めていない**——本文が最も狭い 768px でも 51px 余る。

### 詰め方

`RankingPagination` から class を渡す。

- `PaginationContent` に `gap-0 sm:gap-0.5`。数字の器は `ghost`（地と同じ色）なので、隙間が 0 でも隣と接して見えない。枠線を持つのは選択中のページ（`outline`）だけ。
- `PaginationEllipsis` に `w-4 sm:w-8`。省略記号は押せないので狭めてよい。中のアイコンが 16px なので `w-4` でちょうど入る。
  - **プリミティブ側は `size-8`。** tailwind-merge は `size-8 w-4` の両方を残す（`size-*` は後ろに来た `w-*` を消さない）ので、どちらが効くかは CSS の順で決まる。Tailwind v4 は一括指定の `size-*` を個別指定の `w-*` より前に出すので `w-4` が勝つ。実測 16px で、E2E が並び全体の幅として固定している。
- **数字の器（32px）は削らない。** 押せる大きさを残すほうを採った。

**プリミティブに入れないのは、この幅の事情が ranking のページ送りのものだから。** shadcn の既定のまま置いておけば、取り直したときに差分が出ない（`design-system/tableContainer.ts` の器と同じ考え方）。

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| 前後3ページ | `sm` 未満で 388px。360px の本文に収まらない |
| 狭い画面で「前へ」「次へ」を消す | 前後2ページの数字が並ぶので操作としては足りるが、U6 から置いている操作を消すことになる。消さなくても収まる |
| 数字の器を 28px（`size-7`）に縮める | 収まるが、押せる大きさを削る |
| 並ぶ項目の数を一定にする（1ページ目でも 1〜7 を並べる） | 押すたびに並びの幅が変わらない利点はあるが、省略記号を狭めた状態では数字が1つ増えて 340px になり、360px に収まらない |
| 隠すのが1ページだけの隙間を数字にする（5ページ目の `…` を `2` に） | 同じく 340px |

**残る揺れ。** 並びの幅はページによって 212px〜324px（`sm` 未満）で変わり、中央寄せなので「次へ」の位置は1〜5ページ目で押すたびに最大 16px 右へ動く。U6（前後1ページ）の頃からある揺れで、この Unit では直していない——止めるには上の「項目の数を一定にする」が要り、幅の予算を超える。

## ペイロード

`/` の HTML は raw 325,184 → 326,090 B（+906 B）。1ページ目で数字が1つ増える（`1 2 … 99` → `1 2 3 … 99`）ぶんと、`sm` 未満の class のぶん。同じ dev サーバーで前後を続けて取った値（本番の HTML は dev の開発用スクリプトを含まないので絶対値は違う）。

## テスト

- `pagination.test.ts`: 99ページで、先頭（`1 2 3 … 99`）・末尾（`1 … 97 98 99`）・中ほど（`1 … 8 9 10 11 12 … 99`）・先頭と2ページ前が隣り合う位置（3・4ページ目）・隙間が1ページだけの位置（5・95ページ目）を固定する。**全99ページで項目が9つ以下・省略記号が2つ以下**であることも回す——幅の予算はこの上限の上に立っている。
- E2E（`e2e/ranking-pagination.spec.ts` に追記）:
  - 10ページ目で 8・9・11・12 が並び、7・13 は並ばない。12を押すと `?page=12`・`331〜360社目` になり、その操作でネットワークは発生しない。
  - 1ページ目で 2・3、最終ページで 97・98 が並ぶ。
  - 360px で 5・10・95ページ目の並び（`ul`）が本文の器（`nav`）の左右の端に収まり、「前へ」「次へ」が丸ごと画面に入っている。数字の器は 32px 以上。**横スクロールの有無では見ない**——はみ出しは左右に割れて左は `scrollWidth` に出ない。詰めを外すと並びの左端が −8px になって落ちることを確かめてある。

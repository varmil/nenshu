# U12 ランキングのレイアウト刷新 — plan.md

参照: Issue #80（親: #21）, `docs/ranking/spec.md` 1.10〜1.13・AC-7・AC-12〜AC-14, ADR-0007, ADR-0006
依存: #71（U11 実測値モードと既定化）, #79（design-system に sheet）

## Context

U11 で**中身**を入れ替えた（既定が有報の実測値になった）。U12 は**器**を入れ替える。Claude Design `改善案.dc.html` のアートボード 4a（PC）/ 2a（モバイル）/ 5a・5c（実測値モード）に合わせ、PC を2カラムに組み替え、行を高密度化し、読み取りの手がかり（並び替え・年収バー・偏差値）を足す。Issue #41（高密度化）と #24（年収バー）はここで解消する。

**この Unit で最も壊れやすいのは「操作でネットワークが発生しない」という性質**（AC-7・U5 で踏んだ）と、**表示基準ごとに基準が変わるもの**（バーの正規化と偏差値の母集団）の2つである。作業の順序はこの2つを最後まで確かめられるように組む。

## 進め方

1. **先に在庫を確かめる。** `sheet` が入っていること（#79）を確認し、それ以外に在庫に無いものを使おうとしていないかを、着手前に一度見る。足りなければ起票してから進む。
2. **偏差値に要る統計をページに渡す道を作る。** `stats.json` から**表示基準ごとの母集団（平均・標準偏差）だけ**を抜く経路を用意し、渡す前と後でトップページの gzip サイズを測る。**ここで増分が読めない状態のまま先に進まない**——Issue #22 の 64KB は既に予算の圧迫要因で、全体を渡すと悪化する。
3. **状態に並び替えを足す。** URL との往復（parse → state → buildSearchParams → parse）が同値に戻ることを単体テストで固めてから、画面に出す。既定はURLに出さない・変更したら `page` を1に戻す、の2点は既存のフィルタと同じ規則に揃える。
4. **正規化の基準を導く。** ページ切り出し後の配列から最大値を出し、**表示基準・並び替え・ページ・フィルタのどれを変えても取り直される**ことを単体テストで固める。全体平均の縦線がページ最大を超える場合に描かれないことも同時に固める。
5. **器を組み替える。** PC の2カラム（左に sticky な絞り込み）から先に作り、モバイルのシートを後に回す。**モバイルは横スクロールが出ないことを毎回確かめる**——U3 で実際にこれを踏んでいる。
6. **検索を共通ヘッダへ移す。** ranking 施策から site-chrome 施策のコンポーネントを触ることになるので、`/` 上では状態更新・それ以外のページでは `/?q=` への遷移、という2つの振る舞いを分けて確かめる。
7. **業種チップを出す。** U8 が予定しているリンクハブと出すものが同じなので、**U8 の範囲を canonical・sitemap・robots に狭める**ことを overview.md に反映する（着手前に反映済み）。
8. **固める。** ロジックは単体テストで、描画とキーボード操作・モバイル幅は E2E で固定する。既存の `e2e/ranking-filters.spec.ts` に載るものはそこに足し、並び替え・サイドバー・シートは新規に分ける。
9. **測る。** `npm run measure:prefetch` を本番ビルドに対して回し、`<Link>` を増やしたぶんのプリフェッチが0件のままであることを確認する。トップページの HTML gzip サイズを測り直し、64KB からの増減を記録する。
10. **出す。** ビルド・単体・E2E・実操作の結果を PR にまとめ、問題が無ければマージする。

## 着手前に見えている判断

**並び替えたときに順位の列をどうするか。** 振り直さない。順位は「表示基準の金額で何位か」を意味するので、平均年齢順に並べたら上から `1,204位 / 87位 / …` と飛ぶのが正しい。spec 1.10 に書いた。

**年収バーの基準。** そのページの1位を100%とする。固定上限（2,500万円）を採らない理由と、表示基準ごとに取り直す理由は spec 1.11 にある。**表示基準を切り替えたときに棒だけ元の縮尺で残るのが最も気づきにくい壊れ方**なので、手順4でここを単体テストに落としてから画面を作る。

**偏差値に渡すもの。** `stats.json` 全体ではなく母集団統計だけ。手順2で増分を測ったうえで確定させる。

## 検証

```bash
cd web && npm run typecheck && npm run lint && npm test && npm run test:e2e
cd web && npm run build            # / が ƒ (Dynamic)、/about が ○ (Static) のまま
cd web && npm run measure:prefetch # 動的ルートへの <Link> を増やすので必ず回す
```

- dev server を起動し、ブラウザで実際に触る（並び替え・サイドバー・シート・戻る/進む・モバイル幅で横スクロールが出ないこと）。ブラウザ操作ツールが使えなければ E2E の結果で代替する
- トップページの HTML gzip サイズを測り、design.md に記録する

# U15 並び替えの向きの切替 — plan.md

Issue: [#132](https://github.com/varmil/nenshu/issues/132)（親 [#106](https://github.com/varmil/nenshu/issues/106)）
仕様: `docs/ranking/spec.md` 1.10・AC-12 ／ 分解: `docs/ranking/overview.md` U15

着手前の段取り。出来上がりの構造は design.md に書く。

## 手順

1. **いまの並び替えが通っている経路をひととおり辿る。** 状態（`RankingState.sort`）・URL（`?sort=`）・並べ替え（`applySort`）・チップ（`SortSwitch`）・canonical（`rankingCanonical`）の5か所を、1つの値が通る順に読む。**向きを足すときに触り漏れる場所を先に数え上げる**のがこの手順の目的で、読み終えるまでコードを書かない。
2. **URL の載せ方を先に決める。** 既に配ってある `?sort=age`・`?sort=emp` の意味を変えないことが制約なので、ここが決まらないと state の形も決まらない。決めた根拠は design.md に残す。
3. **軸と向きを決める規則を純粋関数に切り出す。** チップを押したときに次に何になるかは「同じ軸なら反転・別の軸ならその軸の既定の向き」の1行で、コンポーネントの中に書くと Unit テストから触れなくなる。
4. 規則・URL の往復・並べ替えの3つに Unit テストを書く。**先に書いて落ちることを見てから**実装する。
5. `SortSwitch` に向きを出す。**読み上げの名前（`aria-label`）と見えている文字の関係を崩さない**——見えている文字は必ず `aria-label` の部分文字列であること（WCAG 2.5.3）を目で確かめる。
6. E2E を `e2e/ranking-refresh.spec.ts` の「AC-12 並び替え」に追記する。**新しいファイルを増やさない**（CLAUDE.md「開発上の約束」）。向きの反転・軸の乗り換え・直接URL・`page` のリセット・ネットワーク0件を見る。
7. 型・lint・Unit テスト・E2E をすべて通す。**dev サーバーを立てて実際にチップを押し、モバイル幅（390px）でも軸が1行に収まっているかを見る**（向きの語は `sm` 未満では出さない規則があるので、押した結果が矢印だけで読めるか）。
8. トップページのHTMLサイズを前後で測る（raw で比較する。gzip は起動ごとに揺れる）。
9. 決めたこと・採らなかった案を design.md に残す。spec.md は 1.10 と AC-12 を先に改訂してあるので、実装で食い違いが出たらここで直す。
10. PR を出してマージする。

## 検証の順序

- Unit テスト（規則の純粋関数 → URL の往復 → 並べ替えの結果）→ E2E（実ブラウザでのチップ操作と直接URL）→ dev サーバーでの手動確認、の順。
- **既存の `?sort=age`・`?sort=emp` が同じ意味のままであることを、URL の往復テストと E2E の両方で見る。** ここが壊れると、外に出ているリンクの指す並びが変わる。
- 既存の E2E 全件が緑であること。とくに「操作でネットワークリクエストが発生しない」（AC-7）と、並び替えで順位が振り直されないこと（AC-12）。

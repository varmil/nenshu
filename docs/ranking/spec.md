# spec.md — 年齢補正ランキング

対象面: user-web（ユーザー画面）

MVP はランキング1ページと計算方法ページの2枚で構成する。企業詳細ページ・業種ページ・年齢別ページは Bolt 2 以降に回す。
用語は `docs/product/glossary.md` に従う。

---

## 1. ランキングページ（`/`）

### 1.1 何を出すか（WHAT）

1,867社を1つの表に並べる。並び順は選択中の目標年齢における推定年収の降順。

初期状態は目標年齢35歳、フィルタなし、検索語なし。

### 1.2 なぜ（WHY）

読者が知りたいのは順位ではなく、自分の年齢でその会社に入るといくらかという金額になる。既存のランキングはこの問いに答えていない。

### 1.3 表の列

| 列 | 内容 | 備考 |
| --- | --- | --- |
| 順位 | 現在の絞り込み・目標年齢での順位 | フィルタ適用後に振り直す |
| 会社名 | `name` | 「本社のみ」バッジをこの列に添える |
| 業種 | `tse33` | |
| **推定年収** | 目標年齢での補正後の金額 | **視覚的に最も強い列にする** |
| 平均年齢 | `avg_age` | |
| 平均年収 | `avg_salary` | 補正前の実額 |
| 在籍年数 | `avg_tenure` | |
| 従業員数 | `employees_nonconsolidated` | 単体 |

金額は万円単位・カンマ区切りの整数で表示する（例: 2,178万円）。年齢と在籍年数は小数第1位まで。

推定年収の列見出しには目標年齢を含める（例: 「35歳時点の推定年収」）。列見出しか直下に、この値が推定であることを示す注記を常時置く。

### 1.4 年齢スイッチ

25 / 30 / 35 / 40 / 45 / 50 / 55 / 60 歳の8段。単一選択。

操作すると推定年収の列と順位が更新される。ページ遷移も再取得も発生させない。

### 1.5 フィルタ

4種すべて絞り込み方向に働く。複数指定は AND で結合する。

**業種** — 東証33業種から単一選択（プルダウン）。

**従業員数（単体）** — 単一選択。

| 区分 | 条件 | 該当社数 |
| --- | --- | ---: |
| 〜300人 | < 300 | 517 |
| 300〜1,000人 | 300 以上 1,000 未満 | 734 |
| 1,000人以上 | 1,000 以上 | 616 |

**在籍年数** — 単一選択。

| 区分 | 条件 | 該当社数 |
| --- | --- | ---: |
| 〜13年 | < 13 | 545 |
| 13〜17年 | 13 以上 17 未満 | 732 |
| 17年以上 | 17 以上 | 590 |

**平均年齢** — 単一選択。

| 区分 | 条件 | 該当社数 |
| --- | --- | ---: |
| 〜40歳 | < 40 | 450 |
| 40〜43歳 | 40 以上 43 未満 | 709 |
| 43歳以上 | 43 以上 | 708 |

境界値は三分位に寄せている。実データの平均年齢は中央値42.0歳・四分位40.0〜44.0歳に固まっており、「30歳未満」のような一般的な区切りでは該当が6社しかなく機能しない。

### 1.6 フリーワード検索

会社名に対する部分一致。以下を正規化してから照合する。

- 全角英数 → 半角
- 半角カナ → 全角カナ
- 英字 → 小文字
- 空白（半角・全角）の除去
- 法人格の除去（株式会社・(株)・㈱・有限会社・合同会社）

「商船三井」で「株式会社　商船三井」が引ける必要がある。社名に全角スペースを含むものが74件ある。

### 1.7 URLへの反映

年齢・フィルタ・検索語・ページ番号をクエリパラメータに載せる。

```
/?age=35&ind=情報・通信業&emp=1000-&ten=-13&aage=40-43&q=商船&page=2
```

並び替え（1.10）を足したので `sort` も同じ扱いで載せる。

初期値と同じ項目はクエリに出さない（初期状態の URL を `/` に保つ）。
ブラウザの戻る・進むで状態が復元される。URL を共有すれば同じ絞り込みが再現される。

### 1.8 空・端の状態

- 絞り込み結果が0件のとき、条件を緩める案内を出す。エラー表示にはしない。
- 表示件数が多いため、1ページ30件のページネーションで区切る。全件を一度に描画しない。
- ページネーション: 1ページ30件（Issue #103。当初は100件だったが、1画面のスクロール量として多すぎるという指摘を受けて減らした）。URLクエリ`page`（1始まり）で管理し、`page=1`（既定値）はURLに出さない。フィルタ・検索語を変更したら`page`は1に戻る。不正な値（範囲外・非数値）は1として扱う。クライアント側で完結し（`pushState`、ネットワークアクセスを伴わない）、直接URLを開いた場合はSSRで該当ページの内容が返る。

### 1.9 対象外（MVP）

企業詳細ページ、業種別ページ、年齢別の静的ページ、複数選択フィルタ、任意の列でのソート、CSVダウンロード、広告枠。

企業詳細ページは company 施策として作った（C1）。並び替えは 1.10 として Bolt 2 で入れる。残りは対象外のまま。

## 1B. ランキングページ（Bolt 2 の追加）

Issue #21（UI改善）で足す。1. の内容を置き換えるのではなく、読み取りの手がかりを足す。

### 1.10 並び替え

3つの軸。単一選択で、既定は「年収が高い順」。**どの軸も両方向から読める**（Issue #106）。

| 軸 | 既定の向き | 逆向き |
| --- | --- | --- |
| 年収（既定の軸） | 高い順＝表示基準の金額の降順 | 低い順＝同じ金額の昇順 |
| 平均年齢 | 高い順＝`avg_age` の降順 | 若い順＝`avg_age` の昇順 |
| 従業員数 | 多い順＝`employees` の降順 | 少ない順＝`employees` の昇順 |

**既定の向きは3軸とも降順＝大きい順で揃える。** 平均年齢だけを若い順から始めていた時期があるが、**1つの軸だけ向きが違うと、チップを押したときに何が起きるかを軸ごとに覚えることになる**（矢印もその軸だけ上を向く）。若い会社から見たい読み方は、もう一度押して逆向きにすることで足りる。

**選択中の軸をもう一度押すと向きが反転する。** 別の軸を押したときは、その軸の既定の向きから始まる（前の軸の向きを引き継がない）。軸と向きの組は常にどれか1つで、「並び替え無し」の状態は無い。

**並び替えても順位の列は動かない。** 順位は「表示基準の金額で何位か」の意味を持つので、並べ方を変えたら1から振り直す、という扱いにはしない。平均年齢の若い順に並べたとき、上から `1,204位 / 87位 / 1,533位` のように飛ぶのが正しい姿になる。

`?sort=` に同期する。既定（年収が高い順）はURLに出さない。**向きも同じ1つのパラメータに載せる**——既定の向きなら軸だけ（`sort=age`）、逆向きなら向きを足す（`sort=age-asc`・`sort=salary-asc`・`sort=emp-asc`）。3軸とも既定が降順なので、URLに向きが出るのは昇順のときだけになる。フィルタ・検索語と同じく、軸・向きのどちらを変えても `page` は1に戻る。

**なぜ** — この表の主題は年収なので既定は年収でよい。ただし「若い会社」「規模の大きい会社」から見たいという読み方があり、1.5 のフィルタは3区分しかなく粗い。

**なぜ両方向か**（Issue #106）— 片方向しか無いと、絞り込んだ集団の「下の端」が最終ページまで送らないと見えない。絞り込みと組み合わせて初めて意味を持つ読み方（「銀行業でいちばん若い会社は」「この業種で年収が低いのはどこか」）が、3軸それぞれの逆向きにある。軸を増やすのとは別の話で、増えるのは操作であって列ではない。

### 1.11 年収バー

各行の金額に、横棒を添える。

**そのページの1位を100%として正規化する。** 上限を固定額（2,500万円など）に置かない。1ページ目の先頭が1,456万円ならそれが基準で、2ページ目に移って先頭が876万円になればそれが基準になる。**ページ・フィルタ・並び替え・表示基準のどれが変わっても基準は取り直す。**

**表示基準ごとに基準が変わる。** 実測値なら実測値の最大、年齢そろえならその年齢の推定値の最大を100%とする。片方の基準で両方を描くと、年齢そろえに切り替えたときに棒だけが元の縮尺で残る。

全体平均の位置に細い縦線を引く。**全体平均がそのページの最大を超える場合は線を引かない**（枠の外に描かない）。

基準がページ内で閉じていることは読者に見えないので、表の脚注に明示する。

**なぜ** — 金額の列だけでは、1位と50位が2倍違うのか1割違うのかが読み取れない。固定上限にすると、下位ページでは棒がすべて短くなって差が潰れる。

### 1.12 偏差値の列

表示基準ごとの母集団（1,867社）に対する偏差値を出す。**100を超えうる**（35歳そろえのキーエンスで150.0）。年収の分布が右に強く裾を引くためで、企業詳細ページと同じ扱いにする——**数字だけを出し**、100を超えうる理由を表の脚注と `/about` に書く（`docs/product/glossary.md`）。

**母集団は絞り込み後の集団ではなく全1,867社。** 順位の列は絞り込むと1から振り直される（AC-3）が、偏差値は母集団の分布に対する値でなければ意味を持たない。海運業7社の中で偏差値を計算し直したら、1位が50.0付近になって水準が消える。

**「上位◯%」は画面に出さない**（2026-08-20、運営者の判断。モックに無いものを足さない）。100を超えうることは表の脚注に置き、水準は順位の列で読ませる（`docs/product/glossary.md`）。

### 1.13 対象外（Bolt 2 でも作らない）

複数選択フィルタ、任意の列でのソート（1.10 の3軸以外。**同じ軸の逆向きは 1.10 に含む**）、CSVダウンロード、広告枠、保存した絞り込みの共有以外の会員機能。

## 2. 計算方法ページ（`/about`）

装飾ではなく必須とする。既存サイトの弱点は根拠が見えないことにあり、方法の公開そのものが差別化になる。

載せるもの。

- 補正の式と、賃金カーブをどこから作ったか
- 対象範囲（2026年6〜7月提出の有報、単体従業員100人以上、1,867社）
- 「本社のみ」バッジの意味と、持株会社と事業会社で数百万円ずれる実例
- 限界の明示。平均値であること、単体の数字であること、カーブが会社間の差から作られていること、22歳の水準を業種平均と置いていること、平均年齢より上は倍率を一定と置いていること
- **年齢スイッチで順位がほとんど動かないこと**と、その理由・実測値
- 出典（EDINET / 賃金構造基本統計調査）

## 3. 非機能要件

**配信** — 完全な静的配信。サーバーサイドの実行環境を持たない。

**データ量** — 初期ロードのペイロードは gzip 後 100KB 以内に収める。1,867社ぶんで概算60KBを見込む。

**応答** — 年齢スイッチ・フィルタ・検索の操作から表の更新まで、通常の端末で100ms以内。ネットワークアクセスを伴わない。

**対応環境** — モバイルを主とする。1,867行の表を狭い画面で読ませるため、モバイルではカード状の表示に切り替える。

**SEO** — トップページの初期表示（絞り込みなしの上位30社）はHTMLに含める。クライアント側の描画待ちにしない。

**アクセシビリティ** — 年齢スイッチとフィルタはキーボードで操作できる。表にはヘッダーの対応付けを持たせる。

## 4. 受け入れ基準

### AC-1 初期表示

既定の表示基準は**実測値**（有報の平均年間給与そのまま）。ADR-0007。

```gherkin
Given トップページをクエリ無しで開く
When 何も操作しない
Then 有価証券報告書の平均年間給与そのままのランキングが上位30件表示される
And 1位に「株式会社キーエンス」が2,178万円で表示される
And 金額の列見出しが「平均年収（有報）」になっている
And 画面に「推定」の語が存在しない
```

### AC-2 表示基準の切替と年齢スイッチ

```gherkin
Given トップページをクエリ無しで開いている
When 「年齢そろえ」に切り替える
Then 35歳時点の推定年収に変わる
And 見出しが「35歳年収ランキング」になる
And ページ遷移が発生しない
And URLに age=35 が反映される
```

```gherkin
Given 「年齢そろえ」で35歳を選んでいる
When 年齢スイッチで25歳を選ぶ
Then 1位のキーエンスの推定年収が788万円に変わる
And ページ遷移が発生しない
And URLに age=25 が反映される
```

```gherkin
Given 年齢スイッチで60歳を選んでいる
When ランキング上位50社を見る
Then 35歳時点の上位50社のうち35社以上が含まれる
```

年齢スイッチで順位がほとんど動かないことを、この基準で固定する。挙動が変わったら計算が壊れている。

推定式は ADR-0005 の2点モデル（平均年齢より下は22歳を業種平均に固定して結ぶ）。同じ業種で平均年齢も同じ2社なら順序は目標年齢によらず不変で、平均年齢が違えば入れ替わりうる（同業種ペアの1.7%）。

### AC-9 推定であることの明示



### AC-13 年収バー

```gherkin
Given トップページをクエリ無しで開いている
Then 1位の行のバーが最大の長さで描かれている
And 各行のバーの長さが「その行の金額 ÷ 1位の金額」の比率になっている
And バーの基準がそのページ内であることが脚注に書かれている
```

```gherkin
Given 2ページ目を見ている
Then そのページの先頭の行のバーが最大の長さで描かれている
```

全体平均の縦線は、そのページの最大を超えるときは描かない。

```gherkin
Given 表示基準が「実測値」で、バーの基準がその最大値になっている
When 「年齢そろえ」に切り替える
Then バーの基準がその年齢の推定値の最大値に取り直される
```

### AC-14 偏差値

```gherkin
Given 表示基準が「年齢そろえ」で35歳を選んでいる
Then 1位のキーエンスの偏差値が150.0と表示される
And 偏差値の列には数字だけが出る（「上位◯%」は出さない）
```

```gherkin
Given 表示基準が「実測値」
Then 1位のキーエンスの偏差値が122.9と表示される
```

```gherkin
Given 業種で「海運業」を選んでいる
Then 順位の列は1から7まで振り直されている
And 偏差値は全1,867社の分布に対する値のまま（1位が50.0付近にならない）
```

同じ会社・同じ金額でも表示基準が変われば偏差値は変わる。母集団が別物であることをこの基準で固定する。

消さずに無効化するのは、消すと「年齢そろえ」で何が使えるようになるかが事前に分からないため（ADR-0007）。

### AC-15 ページを跨いだ戻る/進む

読者は一覧と個別ページを往復する。**行きで作った絞り込みは、帰りに残っていなければならない**（Issue #108）。

```gherkin
Given ランキングの2ページ目を見ている
When 一覧の会社をタップして企業詳細ページへ移り、ブラウザの戻るを押す
Then 2ページ目に戻る（1ページ目にならない）
And 直前に見ていた位置に戻る
```

```gherkin
Given /?age=35&ind=銀行業 で企業詳細ページへ移った後
When ブラウザの戻るを押す
Then 銀行業82社の35歳そろえの一覧に戻る
And 画面が企業詳細ページのまま残らない
```

```gherkin
Given 企業詳細ページで「年齢そろえ」に切り替えた後
When ランキングへ移り、ブラウザの戻るを押す
Then 企業詳細ページが年齢そろえのまま復元される
```

```gherkin
Given ランキングを見ている
When 共通ヘッダの検索欄に6文字入力する
Then 履歴に増えるのは1件だけ（1文字ごとに増えない）
And 戻るを1回押すと検索前の一覧に戻る
```

**戻るは1回で1つ前の景色に戻る。** 同じ画面のまま URL だけが変わる履歴（クエリの並びを書き直すだけの書き換えなど）を積まない。

## ページの実装方針

`web/app/about/page.tsx` は Server Component。`searchParams` を読まないので Next.js が静的プリレンダーする（トップページ `/` が `ƒ (Dynamic)` なのに対し `○ (Static)` になる）。

**文章が本体なので、コンポーネントに刻まずこのファイルに直接書く。** 見出し・段落・リストの素のHTMLに Tailwind を当てる。`design-system/ui/` から持ってくるのは実例を囲う `Card` 程度に留める（在庫に無いものは作らない、というレジストリ方針を守りつつ、文章ページのために新しい合成物を増やさない）。

## 数値の出どころ — データから引くものと直書きするもの

CLAUDE.md「数値の出典と計算方法は必ずユーザーから見える場所に置く」に加え、**年1回のデータ更新で /about の数字だけが静かに古くなる事故を防ぐ**ため、算出可能な数値は実データから引く。

**`companies.json` / `curves.json` から算出する**（`lib/aboutFacts.ts`）:

| 本文の記述 | 算出元 |
| --- | --- |
| 掲載社数 1,867社 | `companies.rows.length` |
| 「本社のみ」173社 | `rows.filter(r => r[8] === 1).length` |
| 東証33業種 | `companies.industries.length` |
| 産業大分類17系列 | `companies.curveKeys.length` |
| 代表年齢 22,27,…,67 | `curves.agePoints` |
| みずほFG / みずほ銀行の実例（平均年間給与・平均年齢・単体従業員数・バッジ有無） | `rows` から**会社名で**引く |

実例2社を `id` ではなく**会社名で引く**理由: みずほ銀行は非上場で `id` が `doc_id` 由来（`s100yfah`）のため、データ更新で変わる。会社名のほうが安定する。

**見つからなければ throw する。** Server Component なのでビルド時に落ち、静かに壊れた本文が公開されるのを防ぐ。`pipeline/scripts/build-data.ts` がデータ異常で落とすのと同じ方針。

**本文に直書きする**（データから出ない、パイプライン側の定数のため）:

| 記述 | 出どころ |
| --- | --- |
| 2026年6月1日〜7月10日提出 | `pipeline/salary35/unified.py` の `run.build(..., date(2026,6,1), date(2026,7,10), ...)` |
| 単体従業員100人以上 | 同 `MIN_EMPLOYEES = 100` |
| 平均年齢20〜65歳・平均年間給与100万円超 | 同 `ok` のフィルタ条件 |
| 令和5年賃金構造基本統計調査・年収の定義・男女計/学歴計/企業規模計/民営事業所 | `pipeline/salary35/fetch_estat.py` |

これらはデータ更新時に人が見直す前提。design.md にこの線引きを残すのはそのため。

### 金額の書式

既存の `lib/format.ts` の `formatManYen`（四捨五入）を使い、ランキング表と書式を揃える。**Issue #8 の本文は「みずほFG 1,166万」だが、`formatManYen` では 1,167万円になる**（11,665,000 → 1166.5 → 四捨五入で1167）。ランキング表の表示と食い違うほうが読者を混乱させるので、実装側の値を正とする。

## 賃金カーブの出典 — 実態を書く

`pipeline/salary35/curves.py` の先頭 docstring は「令和6年賃金構造基本統計調査 結果の概況／第4表・第5-1表／所定内給与額（月額・千円）」と書いているが、**これは現在フォールバック扱いの旧定数 `INDUSTRY_CURVES` 向けの記述**で、実際に出荷されているカーブとは別物。

実際に使われているのは `annual_curves.json` の `ANNUAL_INDUSTRY` で、`fetch_estat.py` が e-Stat API から取得している:

- statsDataId `0003425893`、`cdTime=2023000000` → **令和5年（2023年）**賃金構造基本統計調査
- **年収 = きまって支給する現金給与額 × 12 ＋ 年間賞与その他特別給与額**（賞与・時間外を含む。有報の平均年間給与と定義が揃う）
- 男女計（`cdCat03=01`）・学歴計（`cdCat05=01`）・企業規模計（`cdCat01=01`）・民営事業所（`cdCat06=02`）・一般労働者

/about には**この実態のほうを書く**（ユーザー確認済み）。あわせて `curves.py` の docstring も、旧定数向けの記述であることが分かる形に直す。放置すると同じ混乱が再発する。

## 産業大分類を開示する

`docs/product/glossary.md` は産業大分類（17系列）を「ユーザーには見せない」と規定しているが、**/about ではこれを開示する**（ユーザー確認済み）。理由:

- /about の目的は計算方法の全公開（intent.md の差別化要因）で、式に登場する内部区分を伏せると目的と矛盾する
- 「東証33業種が17カーブに集約されている」ことは推定精度の実際の限界であり、Issue #8 の完了条件「限界の明示」に該当する

glossary.md の該当箇所に、この例外を明記する。規定の趣旨は「ランキングUIの表示・フィルタ軸に使わない」ことだと解釈する。

## 年齢スイッチが同業種内の順位を動かさないこと

Issue #8 が明記を求めている項目。**理由まで書く**:

推定年収の比を取ると、同じカーブを引く2社では分子の `カーブ[産業](目標年齢)` が共通なので約分され、目標年齢に依存しない項だけが残る。

```
推定年収A(目標年齢)     平均給与A ÷ カーブ(平均年齢A)
──────────────────  =  ────────────────────────────   ← 目標年齢が消える
推定年収B(目標年齢)     平均給与B ÷ カーブ(平均年齢B)
```

東証33業種はいずれも産業大分類に多対一で写像されるので、同じ東証業種の2社は必ず同じカーブを引く。したがって**同業種内の並び順は目標年齢によらず不変**。8つの目標年齢 × 33業種すべてで並び順に変化が無いことを実データで確認した（0件）。順位が動くのは業種をまたぐ比較だけで、TOP50は25歳時点と60歳時点で41社が重なる。

## 限界の明示 — 若年側の過大推定を含める

Issue #8 の完了条件は「平均値であること・単体の数字であること・カーブが会社間の差から作られていること」を挙げているが、**計画中に発見した構造的な偏りもここに書く**（`docs/ranking/about-page/plan.md` に定量結果、別Issueに改良方針）。

式は実質「その会社の産業平均に対する倍率は何歳でも同じ」と仮定している。倍率の実測分布は中央値1.22倍・p90 1.64倍・最大4.32倍で、2倍超が49社ある。産業計の25歳は382万円なので、倍率をそのまま掛けると高倍率の会社は25歳時点が実感より大幅に高く出る。現実には新卒初任給が業界横断で圧縮され、企業間の差は年次・等級を重ねて開くため、**倍率一定と置くと高倍率企業ほど若年側が過大**になる。

会社の平均年齢からの外挿距離も書く（平均年齢の中央値は42歳。目標25歳では平均16.8歳、45歳では3.7歳、60歳では18.2歳）。**平均年齢から離れた年齢ほど不確実**であることが読者に伝わる形にする。

この開示は自社プロダクトの弱点を自ら書くことになるが、H3（方法の全公開が信頼につながる）と CLAUDE.md「根拠を隠した推定値を表示しない」に照らせば書かない選択肢は無い。

## リンク（AC-10）

`RankingApp.tsx` のヘッダーに `next/link` の `<Link href="/about">計算方法</Link>` を置く。/about 側にもランキングへ戻るリンクを置く。

**ページ間の離散的なナビゲーションなので `<Link>` を使ってよい。** CLAUDE.md が `useRouter()`/`router.push()` を禁じているのはフィルタ操作のような高頻度なクライアント側状態変更が対象で（RSCペイロード再フェッチによるネットワーク発生・競合状態、U5で実際に踏んだ）、別ページへの遷移はその対象外。

## テスト方針

- `aboutFacts.test.ts`: 実データに対する値を固定する（1,867 / 173 / 33 / 17 / 代表年齢10点 / みずほ2社の平均年間給与・平均年齢・単体従業員数・バッジ有無）。会社名で引けなくなったら throw することも固定する。データ更新でこれらが変わればテストが落ちて気づける。
- E2E（`web/e2e/about.spec.ts`）:
  - **AC-10**: ランキングページの「計算方法」リンクをたどって `/about` に着き、式・出典・対象範囲・限界が読める
  - 年齢スイッチが同業種内の順位を動かさないことが書かれている（AC-10 の後半）
  - `/about` への生HTTPリクエスト（JS実行なし）で本文が返る（静的プリレンダーの確認。クローラーが読める形になっていること）
  - `/about` からランキングへ戻れる

## エッジキャッシュの当て先（実測して確定）

`_next/static/*` は Worker を経由せず Assets バインディングから配信されるため `next.config.ts` の `headers()` が効かず、`public/_headers` に書く必要があった（U6直前のフォローアップ）。`/about` は静的プリレンダーされるので同じ経路になる可能性があり、実測で確かめた。

**結果、`/about` は Assets には出ず（`.open-next/assets/` に `about` を含むファイルは無い）、Worker 経由で配信される。** したがって `next.config.ts` の `headers()` が効く。`source: "/about"` を追加し、`wrangler dev` で確認した:

```
Cache-Control: public, max-age=3600
cloudflare-cdn-cache-control: public, s-maxage=86400, stale-while-revalidate=604800
```

`/` と `/about` はどちらもデータがビルド時に確定し実行中は変わらない（更新は年1回）ので、同じ方針にした。`next.config.ts` ではヘッダー配列を定数に括り出して両方に当てている。

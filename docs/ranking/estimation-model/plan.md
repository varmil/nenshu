# Issue #42 推定モデルの改良（22歳アンカーの2点モデル） — plan.md

## Context

推定式 `平均年間給与 × カーブ(目標年齢) ÷ カーブ(平均年齢)` は実質「その会社の産業平均に対する倍率は何歳でも同じ」と仮定している。倍率の実測分布は中央値1.22倍・最大4.32倍（キーエンス）で、**倍率の大きい会社ほど若年側が過大**に出る。キーエンス25歳1,642万円、三菱商事25歳1,491万円、トヨタ25歳694万円。実装のバグではなくモデルの仮定の問題。

intent.md H1 が「知りたいのは順位ではなく金額」と置いている以上、金額が2倍ずれるのは軽くない。U7 では `/about` の限界セクションに定量的に開示して当面をしのいだが、本体を直す。

**この調査で Issue #42 の「本命候補」だった標準労働者カーブは否定された**（下記）。採るのは新しいデータ源を必要としない2点モデル。

## 事前検証で確定した事実（すべて実データで計測済み）

### 標準労働者カーブは解にならない

e-Stat の令和7年 標準労働者 第1表（`statInfId=000040421138`、17産業 × 学歴 × 年齢各歳 15〜65、Excel）を実際に取得して全17産業のカーブを組み、1,867社を再計算した。

| | 25歳 | 60歳 |
| --- | ---: | ---: |
| キーエンス 現行 → 標準労働者 | 1,642万 → **1,505万** | 2,213万 → **2,849万** |
| 三菱商事 現行 → 標準労働者 | 1,491万 → 1,213万 | 1,962万 → 2,686万 |
| 中央値 現行 → 標準労働者 | 469万 → 380万 | 640万 → 722万 |

**若年側の改善はわずかで、60歳側は大幅に悪化する。** 標準労働者（同一企業に継続勤務している大卒）は57歳まで上がり続け（産業計 22歳311万 → 57歳1,057万）、そこに4倍の倍率を掛けるため破綻する。倍率一定の仮定が残る限りカーブの差し替えでは直らない。

副次的に判明: **API（DB）で取れるのは2023年（令和5年）まで**。統計表 `0003425893`・`0003447178` とも時間軸は2020〜2023で、令和6年・令和7年はファイル（Excel）にしか無い。「令和7年への更新」はExcelパースを新たに書く話になる。

### 22歳アンカーの2点モデルは公知の値と合う

平均年齢より下では、その会社の賃金カーブが **(22歳, 業種平均の22歳水準)** と **(平均年齢, 実測の平均年間給与)** の2点を通ると置き、業種カーブの形で間を結ぶ。

```
C(a) = 業種カーブ(a)
est(t) = C(22) + (平均給与 − C(22)) × (C(t) − C(22)) / (C(平均年齢) − C(22))   … t ≤ 平均年齢
est(t) = 平均給与 × C(t) / C(平均年齢)                                       … t > 平均年齢（現行のまま）
```

| 会社 | 平均給与/平均年齢 | 25歳 現行→新 | 30歳 現行→新 |
| --- | ---: | ---: | ---: |
| キーエンス | 2,178万/35.0歳 | 1,642 → **788** | 1,912 → 1,487 |
| 三菱商事 | 2,113万/42.3歳 | 1,491 → **711** | 1,707 → 1,199 |
| トヨタ自動車 | 1,006万/40.5歳 | 694 → **466** | 809 → 664 |
| ソニーグループ | 1,155万/42.7歳 | 779 → **486** | 907 → 713 |
| リクルートHD | 1,162万/40.2歳 | 891 → **534** | 1,013 → 817 |
| 全社中央値 | | 469 → 410 | 549 → 513 |

中央値の動きは小さく、**歪みが集中していた高給企業だけが大きく下がる**。診断（倍率一定の誤差は高倍率企業に集中）と一致する。標準労働者カーブを組み合わせても25歳中央値は410万 vs 402万でほぼ変わらず、Excelパースのコストに見合わない。

### 波及する数値（実測済み）

- 平均年齢の最小は27.1歳。`C(平均年齢) − C(22)` がゼロ割れする会社は無い。平均給与が業種の22歳水準を下回るのは**1社**だけで、この社は倍率一定にフォールバックさせる
- **同業種内の順位不変が崩れる。** 目標年齢で順序が入れ替わる同業種ペアは 1,685/96,469（**1.7%**）。平均年齢が同じ2社なら不変のまま
- TOP50の重なり: 35歳 vs 60歳 **37社**（現行40）、25歳 vs 60歳 **39社**（現行41）
- 35歳の1位はキーエンス2,178万円で不変（平均年齢35.0＝目標年齢のため）。2位以下は入れ替わる（ディスコ1,666万 → 三菱商事1,578万 → 三井物産1,555万）
- 35歳の101位（2ページ目の先頭）は 岩谷産業 → **戸田建設株式会社**（882万円）
- みずほ銀行の35歳推定 767万 → **755万円**

### 残す限界（今回スコープ外・ユーザー確認済み）

- **平均年齢より上は倍率一定のまま。** キーエンス60歳は2,213万のまま。「初任給は圧縮されている」に相当する根拠が高年齢側には無く、手を入れると任意のパラメータを発明することになる
- **22歳アンカーは業種平均。** 初任給が業種平均より高い会社（商社・キーエンス等）では若年側が今度は控えめに出る。逆方向のズレだが絶対値ははるかに小さい

## 変更するもの

### 計算の本体

- `web/features/ranking/lib/salary.ts` — `estimateSalary` を2点モデルにする。22歳の値は既に引数にある `curveValues[0]` / `agePoints[0]` から取れるので**シグネチャは変えない**。`avgSalary <= C(22)` と `C(平均年齢) − C(22)` がゼロ近傍のときは現行式にフォールバック
- `web/features/ranking/lib/curve.ts` の `interpolate` はそのまま再利用する

### `/about`（このページの正確さがプロダクトの差別化そのもの）

- `web/features/ranking/lib/aboutFacts.ts` — `FormulaExample` に22歳アンカーの値を持たせ、`buildModelBiasFacts` を「倍率一定が壊れていた話」から「2点モデルで何を仮定しているか・どこが残った限界か」に組み替える。数値は引き続きデータから算出し、ハードコードしない
- `web/app/about/page.tsx` — 補正の式のセクションを2式に書き直し、みずほ銀行の実例をたどり直す。**「年齢スイッチは同業種内の順位を動かしません」のセクションを書き換える**（平均年齢が同じなら動かない／違えば入れ替わりうる、同業種ペアの1.7%）。限界セクションに上記2点を残す

### 仕様・用語・記録

- `docs/adr/0005-two-point-anchor-estimation.md`（新規） — ADR-0003 の式を supersede する。却下案として標準労働者カーブ差し替えの実測結果を残す

### パイプライン（今回は式を変えない）

CSV の `salary35` / `factor` / `rank_adj` 列は旧モデルの派生値。web側はこれらを読んでおらず（`build-data.ts` は `avgSalary` / `avgAge` / `industry` だけ使う）、EDINETキーが無い環境ではCSVを再生成できない。

- `pipeline/scripts/build-data.test.ts` の「カーブから再計算した35歳時点の推定年収がCSVのsalary35と全1,867社で一致する」テストは**旧式のまま残す**。役割は「avgSalary・avgAge・industry の取り込みとカーブの対応が正しい」ことの固定であって表示式の検証ではない、とテスト名とコメントで明示する

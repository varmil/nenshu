# U13 ランキングのモック合わせ — design.md

参照: Issue #88（親: #84）, `docs/ranking/spec.md` AC-7・AC-12〜AC-14, `docs/site-chrome/spec.md` 2, ADR-0007
依存: #80（U12）

## 出来上がりの構造

### ページの骨格（`RankingApp`）

```
SiteHeader（site-chrome）          ブランド / 検索 / 表示モード＋計算方法
─────────────────────────────────
h1 + 説明文
ControlBand「並べ方」    BasisSwitch      + 説明文
ControlBand「年齢」      AgeSwitch        + ヒント（実測値のときは破線＋減光）
─────────────────────────────────
grid [13.5rem | 1fr]
  aside                       本文カラム
   ActiveFilterChips           件数 ／ 並び替え＋絞り込み（1行）
   RankingFilters（PCのみ）     RankingTable（md以上）／ RankingCardList（md未満）
                               RankingPagination
                               IndustryChips（muted の帯）
```

`aside` は `md:sticky`。**モバイルでも `aside` は消えない**——中身のうち `ActiveFilterChips` だけが残り、`RankingFilters` が `hidden md:block` でシートに移る。効いている絞り込みを2か所に描いて出し分けると、同じ解除ボタンが2つ存在することになり、読み上げからもテストからも曖昧になる。

### 表（`RankingTable`）

| 列 | 幅 | 中身 |
| --- | --- | --- |
| 順位 | `w-11` | `rank`（`text-lg font-bold`） |
| 会社名・業種 | 残り | ロゴマーク＋社名＋「本社のみ」＋`CompanyMetaLine` |
| 平均年収（有報）／推定年収（◯歳） | `w-44` | 金額＋`SalaryBar` |
| 偏差値 | `w-20` | 偏差値／上位◯%（2行） |

`table-fixed` のまま。**U12 の7列から4列に減らした。** 平均年齢・在籍年数・従業員数は `CompanyMetaLine`（社名の下の1行）に移っている。7列では社名の列に 200px 弱しか残らず、`truncate` が効いて「三菱商事…」のように**一覧で最も重要な情報が省略記号で切れていた**。移した3つはどれも「その会社がどんな会社か」を言う属性で、行どうしを見比べるために縦に揃える必要が無い。

`CompanyMetaLine` は `block truncate`。`truncate` は `overflow: hidden` を効かせるが、インライン要素のままでは溢れた文字がそのまま外へ出る（360px でページに横スクロールが出た）。

**年齢そろえのときだけ meta 行の末尾に「実績 ◯万円」が付く**（アートボード 4a）。補正後の数字だけを見せると、元がいくらだったのかを確かめる手段がページから消える。

### 帯（`ControlBand`）

ラベル・中身・ヒントを持つ器。`tone="solid"` は `bg-muted` の塗り、`tone="dashed"` は破線＋減光で「いまは使えない」を表す。**実測値のとき年齢スイッチを消さずに残す**（AC-11）ための無効の見た目をここに持たせている。

ラベルは `aria-hidden`。中のスイッチが `aria-label` で自分を名乗っているので、読み上げに同じ語を二度載せない。

### 並び替え（`SortSwitch`）

見えている文字は軸（平均年収／平均年齢／従業員数）だけで、**方向（高い順／若い順／多い順）は選択中かつ `sm` 以上でだけ**添える。3つとも方向まで書くと 390px で「絞り込み」と並ばず横スクロールが出る。

`aria-label` は常に `${軸} ${方向}`。見えている文字は必ずその部分文字列になっている（WCAG 2.5.3 Label in Name）。

### 業種チップ（`IndustryChips`）

本文カラムの中の `bg-muted` の帯に入れ、**社数を併記する**（`industryCounts`）。`<a href="/?ind=…">` の実体と左クリックの横取りは U12 のまま——実体はクロール経路（ADR-0006）、横取りは AC-7。

社数は `companies.json` に持たせず**描画時に数える**。1,867回のインクリメントで、`buildRankedCompanies` が同じ配列に対してやっている仕事より軽い。並びはデータの順のまま（社数の降順にしない）——チップの位置が固定されているほうが、何度も来る読者には探しやすい。

### 共通ヘッダ（site-chrome に触る）

`grid-cols-[auto_minmax(0,1fr)_auto]` の3カラムで、中央の検索だけが伸び縮みする。検索は入力欄と虫めがねボタンを突き合わせた1つの丸い帯（`sm` 未満ではボタンを落として入力欄だけ）。振る舞い（`/` では `pushState`、それ以外では `/?q=` へ遷移）は U12 のまま変えていない。

## モックに合わせなかったもの

**先に決めた約束のほうが強い箇所。** 直し忘れではないことを残す。

| モック（`改善案.dc.html`） | この実装 | 理由 |
| --- | --- | --- |
| 偏差値の数字だけを出す | **モックに合わせた**（当初は上位◯%を併記していたが、公開後に外した。下記） | — |
| 脚注「帯は…上限2,500万円で伸ばしたもの」 | そのページの1位を100% | spec.md 1.11。固定上限だと下位ページで棒が全部短くなる |
| モバイルでは年齢スイッチを出さない（5c） | 破線＋減光で残す | AC-11。消すと「年齢そろえ」で何が増えるのかが分からない |
| 表の脚注をページ末尾（業種チップの下）に置く | 表の `<caption>` のまま | `<caption>` は `<table>` の中にしか置けない。外に出すと表と注記の対応が読み上げから切れる。位置は表の直下・ページネーションの上 |
| h1 直下に会社の紹介文（4b・2b） | 出さない | 企業詳細ページ側の話（#89）。データを持っていない |

## 実測値

| | U12 | U13 |
| --- | --- | --- |
| `/` の初期HTML（gzip） | 72,232 B | **71,671 B**（−561 B） |
| `/company/[id]` の初期HTML（gzip） | 12,873 B | **13,283 B**（+410 B） |
| `/company/` へのプリフェッチ | 0件 | 0件 |

`/` が減ったのは、行あたりのセルが7つから4つになり `<td>` の繰り返しが減ったため（meta 行の文字と業種チップの社数を足してもなお減る）。**`/company/[id]` が増えたぶんは共通ヘッダの検索ボタン**で、全ページに等しく乗る。

## 公開後に直したもの（2026-08-20）

本番を見た運営者からの指摘。**どれもモックとの差を埋める向きの修正**で、機能は変えていない。

| 指摘 | 直したもの |
| --- | --- |
| 表にスクロールバーが出る | `Table` の器は `overflow-x-auto` だけを持つが、**CSS の仕様で片方が `visible` でないと `visible` は `auto` に計算される**（CSS Overflow 3）。つまり縦も `auto` で、端数で1pxはみ出すと表だけが縦スクロールする小窓になっていた。`design-system/tableContainer.ts` のクラスで器の overflow を打ち消す（プリミティブは触らない） |
| 偏差値の「上位◯%」が要らない | ランキング表・モバイルの行・企業詳細のカード・要点・h1 直下から外した。**モックに無いものを足さない**（運営者の指示）。100を超えうることは脚注に残し、水準は順位で読ませる（`docs/product/glossary.md` を改訂） |
| サイト名を押してもフィルタが解けない | `<Link href="/">` は同じルートへの遷移なので `RankingApp` が作り直されず、URL だけ `/` になっていた。`BrandLink` が `/` の上ではクリックを横取りし、`pushRankingReset()` で URL を書いて合図を投げる |
| meta 行の業種が要らない | 行が長くなって末尾の従業員数が見切れていた。業種は左のサイドバーで選ぶものなので、列見出しも「会社名」に戻した |

### 2巡目（モバイルの行）

1巡目のあと、**SP のランキングがアートボード 5c と違う**という指摘が続いた。5c の行のマークアップを読み直して合わせた。

| 指摘 | 直したもの |
| --- | --- |
| バーの位置が違う | 5c ではバーは**右側の列の中**にあり、社名の左端から始まる。行の全幅に伸ばすと順位とロゴの下まで届き、どの社名の帯なのかが読み取りにくい |
| 順位の位置が違う | 行を `items-center` にして縦中央へ。幅 20px・中央寄せ・15px 太字（5c と同じ） |
| 社名は1行で切る | `truncate`。**「本社のみ」バッジは meta 行へ移した**——社名の隣に置くとバッジのぶん社名が先に切れる |
| 見出しが大きい | モバイル 20px / PC 30px（`text-xl md:text-3xl`） |
| 説明文が長い | **文を2つに割り、2文目を `hidden md:inline` にした。** 同じ文言を2つ書いて出し分けない（片方だけ直す事故を作らない） |
| 並べ方の説明文も1行に | 同じ手当て。実測値は「有価証券報告書の数値のまま。」＋PCで「年齢の違いは補正していません。」 |

**行に出す「推定」から年齢を落とした。** `35歳・推定` は 360px で meta 側の幅を食い、平均年齢と従業員数が省略記号に飲まれていた。年齢は見出しと帯に出ている。AC-9 が求めるのは「推定値であることを示す表記が画面上に存在する」ことで、行ごとの年齢表示ではない。

**モバイルの meta 行は在籍年数と「実績」を落とす**（`CompanyMetaLine` の `compact`）。

### 3巡目（行の中の強弱、Issue #96）

行の中で「どれを先に読ませるか」の指摘。**PC・モバイルの両方に同じ手当てを入れる**（片方だけ直すと、同じ行の見え方が幅で割れる）。

| 指摘 | 直したもの |
| --- | --- |
| 社名を太字に | `font-medium` → `font-bold`。一覧で最初に読むのは社名で、リンクでもある。ロゴマークと合わせて行の起点になる |
| 金額を小さく | PC `text-xl`（20px）・モバイル `text-lg`（18px）→ どちらも `text-base`（16px）。**20px だと金額のほうが社名より先に目に入り、「どの会社の数字か」を読む順序が逆になっていた**。順位（18px）より小さくなるので、行の目印は順位のまま |
| 説明文の「そのまま」が重複 | 「有価証券報告書の平均年間給与（単体）**そのままで**1,867社。」→「（単体）で1,867社。」。同じ段落の帯のヒントに「有価証券報告書の数値のまま。」があり、一度の視界に同じ断りが2つ並んでいた |

**金額を 16px に落としたぶん社名の幅が広がる。** 390px では「株式会社大和証券グループ本社」が切れなくなったため、切り詰めを見る E2E は長い社名（`?q=ジャパンエレベーター`）で引き直した。

HTML の大きさは実質変わらない（raw 608,757 B → 608,745 B）。**gzip 後の値は `next start` に対して測ると同じビルドでも起動ごとに 66.5KB〜70.3KB の幅で動いた**ので、ここは raw で比べている。

### 4巡目（モバイルの行を4カラムにする、Issue #119）

アートボード 2a。**モバイルの行だけを直す**——PC の表（`RankingTable`）と、順位・金額・
偏差値の算出（`lib/rank`・`lib/format`・`features/company/lib/stats`）は触っていない。

2巡目で「バーは右の列の中」まで寄せたが、右の列は社名・meta・バーを縦積みしたまま
だったので、**バーは依然として社名の左端から行の右端まで**伸びていた。2a はここを
割って、行を **順位 / ロゴ / 社名＋meta / 金額ブロック** の4カラムにする。

| 直したもの | 理由 |
| --- | --- |
| バーを金額ブロックの中へ | 金額の直下にあれば「この数字の帯」と読める。社名の幅いっぱいに伸びていると、隣の会社の帯と長さだけが並んで見え、どの数字に対する比なのかが曖昧になる |
| 金額ブロックは `w-20`（80px）・左寄せ・`whitespace-nowrap` | 下の「金額の幅と `nowrap`」を参照。**金額とバーの左端が揃う。** バーの意味（ページの1位を100%・細い縦線が全体平均）は変えていない |
| 年収バーはモバイルだけ3px（`SalaryBar` の `size="row"`） | PC の表では金額のセルが1列を占めるので6pxが釣り合うが、88pxの器の中では**バーのほうが金額より強く目に入る**（運営者の指摘）。行の中の強弱は 社名 ＞ 金額 ＞ 順位 で、バーは金額に添える補助なのでそこに割り込ませない |
| meta 行は `justify-between` をやめて `gap-2` | 両端に振ると、社名が短い行で平均年齢と偏差値が離れて別々の情報に見える。隣り合わせたので `CompanyMetaLine` に `min-w-0` が要る——flex アイテムの最小幅は既定で中身の幅で、これが無いと年齢が縮まず偏差値を押し出す |
| 順位を 12px に（`text-[0.95rem]` → `text-xs`） | 3巡目で金額を16pxに落として社名を一番強くしたが、順位が18pxのまま残っていて社名と同じ強さで目に入っていた。行の中の強弱は 社名 ＞ 金額 ＞ 順位 になる |
| ロゴの器をこの行だけ 48×68 に | `CompanyLogo` に `size="row"` を足す。既存の `sm`/`default`/`lg` の寸法は変えない（近傍5社と表と企業詳細に波及させない） |
| 「本社のみ」バッジをモバイル行から外す | PC の表には残る。2巡目で社名の行から meta 行へ逃がしたが、4カラムで社名の列が 390px で 160px 前後になり、逃げ場が無くなった |
| モバイルの meta を**平均年齢だけ**に | 従業員数を残すと `平均42.3歳 ・ 4,456人` ＋ `推定 偏差値 122.9` が 160px に入らず、**省略記号が偏差値側に届く**。金額と偏差値はこの行で唯一「他社と見比べる」数値なので、削るのは属性側にする（`CompanyMetaLine` の `compact`） |

**縮むのは社名と平均年齢だけ。** 金額ブロックと偏差値の `shrink-0` が受け入れ条件
（360px でも偏差値と金額が全部見える）を担保する。

### 金額の幅と `nowrap`

最初は「2,178万円」の実測幅そのままの `w-20`（80px）に `text-right` で置き、**実機で「円」
だけが2行目に落ちた**（報告あり）。**このサイトは webfont を持たず OS のフォントで組む**
（Issue #67）ので、同じ文字列でも幅が読者の環境で変わる。**自分の環境で測った値をそのまま
器の幅にすると、他の環境では収まらない。**

**器は `w-20`（80px）で、`whitespace-nowrap` が付いている。** 幅は「4桁（`2,178万円`）で
金額とバーの幅が揃う」ことを狙った値で、運営者が選んでいる（96px → 88px → 80px と詰めた）。
`nowrap` が付いている以上、収まらない環境でも2行にはならず、**右へわずかにはみ出す**。
`RankingApp` の `p-4` が左右に16pxあるので、その範囲なら横スクロールにはならない。

**`nowrap` を外さないこと。** 外した瞬間、詰めた幅がそのまま「円が2行目に落ちる」に戻る。
**幅を詰めるほど失敗の出方が「2行になる」から「行からはみ出す」に変わる**ので、ここを
動かすときは開発環境の実測（「2,178万円」に72px）ではなく実機で見ること。

器の幅を中身に合わせる（`w-fit`）逃げ方は採れない。**バーが全行で同じ幅であることは、
長さを見比べる前提そのもの**だからである。

**バーの幅は全行で同じでなければならない**（長さを見比べる前提そのもの）ので、器を
`w-fit` にして中身に合わせる逃げ方は採れない。固定幅のまま余裕を持たせるのが唯一の解になる。

**金額は右寄せではなく左寄せ。** 右寄せだと桁数の少ない会社ほど数値の左端が右へずれ、
真下のバーの起点と合わない（`1,880万円` と `988万円` で左端が1文字ぶんずれる）。左寄せなら
どの行でも金額とバーの左端が同じ x に来る。E2E は9行ぶんの左端が1つの値に収束することで
これを固定している。

**行の `gap` は `2.5`（10px）から `1.5`（6px）へ。** 器を広げた時期に社名の列を確保する
ために詰めた（`w-24`＋`gap-2` では 360px で社名が 120px ちょうどになり、`logo.spec.ts` の
「社名が読める幅を保つ」が求める下限に届かなかった）。器を 80px に戻した現在、360px での
社名の幅は 142px ある。

**器を大きくできるようになったのは、行の高さの決まり方が変わったから。** L1 で
モバイルの器を 38×48 に留めていたのは「56px以上にすると meta 行の従業員数が丸ごと
消える」ためだった（`docs/logo/` の実測）。縦積みをやめてバーを金額側へ移したことで、
**行の高さはロゴの48pxと `py-2.5` が決める**ようになり、器を広げても隣の列を削らない。
9社ぶんの行の高さが社名の長さによらず揃うのはこのため。

読み上げ順は 順位 → 社名 → 平均年齢 → （推定）偏差値 → 金額 になる。**4カラムに
した結果、金額が偏差値の後ろに移った**——列の並びと DOM の並びを一致させたので、
金額だけを前に出す `order` は入れていない。`aria-label` は変えていない。

HTML は raw 371,849 B → **355,341 B**（−4.4%）。減ったのは30行ぶんの従業員数・バッジ・
バーの器のマークアップ。`/company/[id]` は変わらない（raw 87,866 B のまま）。
gzip は 61,952 B → 61,791 B だが、**この値は起動ごとに揺れるので raw で比べている**
（3巡目と同じ理由）。

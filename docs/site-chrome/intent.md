# intent.md — サイト共通の外装

## 狙い

`ranking` と `company` は**中身**の施策で、どちらも「そのページに何を出すか」を決めてきた。結果として **3ページとも独自のヘッダを持ち、共通の外装が無い**。`/`（`max-w-5xl`）・`/about`（`3xl`）・`/company/[id]`（`3xl`）で幅も先頭要素も揃っていない。

サイト全体に一度だけ置くもの——ブランド名、全ページ共通の導線、表示設定——の置き場所を作る。

## North Star KPI

`ranking`・`company` と同じく**自然検索からの月間セッション数**。この施策はそれを直接は増やさないが、次の2つで支える。

- **回遊。** どのページからでもランキング／計算方法に戻れる導線を1箇所に持つ
- **ブランドの想起。** 「OpenReport」という名前が全ページに出る

## 仮説

**H1.** 3ページで導線の位置がバラバラなことは、読者が「同じサイトの別ページ」だと認識する妨げになっている。

*検証*: 企業詳細ページからの回遊率（2ページ目を見る割合）を Clarity で見る。

**H2.** 表示設定（ライト/ダーク）は、読者が自分で選べることよりも **OS の設定に黙って従うこと** のほうが効く。切替UIは「従っていること」を確認・上書きする手段として要る。

*検証*: トグルの操作率を Clarity で見る。操作率が極端に低ければ、OS 追従が正しく効いている裏返しと読む。

## 前提の確認

- **運営者は1名で、2026年10月以降は運用工数がほぼ取れない**（product.md の制約）。外装は作り切りで、運用の要らないものに限る
- **SSR の出力はエッジで24時間キャッシュされる**（`next.config.ts` の `s-maxage=86400`）。読者ごとに変わるものをサーバー側のHTMLに焼けない。表示設定はクライアント側だけで完結させる

## この施策で扱わないもの

ナビゲーションの階層化（メニュー・ドロワー）、フッタの共通化、ログイン。ページ数が3つの段階では要らない。

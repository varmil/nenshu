# S3 データの時点（決算期）の明示 — design.md

参照: Issue #134（親: #104）, `docs/site-chrome/spec.md` 1.4・5.（AC-17〜AC-20）, ADR-0006
依存: #53（U8・`web/lib/seo/`）, #68（S1）

## 出来上がりの形

決算期という1つの事実が、**データ → 1つの文字列 → 3方向の出力**という一直線で流れる。

```
pipeline/data/ranking_unified_2026.csv （period_end 列）
        │  dominantFiscalPeriod()      … 最頻の決算期を1つ採る
        ▼
web/public/data/companies.json  meta.fiscalPeriod = "2026-03"
        │  web/lib/data/period.ts      … 唯一の文字列化
        ▼
   fiscalPeriodLabel(meta) → "2026年3月期"
        ├─ lib/seo/ranking.ts            … `/` の title（末尾）・全ページの description
        ├─ app/company/[id]/page.tsx     … description・CompanyDetail への prop
        ├─ app/about/page.tsx            … description・「対象範囲」
        └─ features/ranking/components/RankingApp.tsx … リード文の1文目
```

**`2026年3月期` という文字列はアプリのコードに1つも無い**（AC-20）。あるのはテストと docs だけで、そこは値が動いたら落ちるべき場所である。

## データ

### `companies.meta`

```ts
interface CompaniesMeta {
  version: string;        // データの版（提出期。"2026-06"）
  count: number;          // 掲載社数
  fiscalPeriod: string;   // 決算期（最頻。"2026-03"）  ← S3 で追加
  generatedAt: string;
}
```

`version` は残す。提出期（いつ取ってきたか）と決算期（いつの事業年度か）は別物で、`version` は前者、`fiscalPeriod` は後者を指す。**画面と検索結果に出すのは後者**——読者が知りたいのは「この数字がいつの会社の姿か」であって、我々がいつ取得したかではない。

### 決算期を1つに代表させる（`dominantFiscalPeriod`）

`period_end` は会社ごとに違う。実測は次のとおり。

| 決算期 | 社数 |
| --- | ---: |
| 2026-03 | 1,865 |
| 2026-04 | 2（株式会社ヤガミ・株式会社ダイサン。どちらも 2026-04-20） |

最頻の1つを採る。**過半に届かなければ例外で落とす。** そのときは「1つの決算期で代表できる」という前提そのものが崩れており、黙って多数派を出すと読者に嘘の時点を見せることになる。`build-data.ts` が行数やカーブのキーで落ちるのと同じ方針で、公開前のビルドで止める。

**代表であることは `/about` の「対象範囲」でだけ断る**（「決算期は3月期が中心で、4月期の会社も含みます」）。ランキングの1行と企業詳細の見出しに毎回この但し書きを付けると、伝えたい1つの事実より但し書きのほうが長くなる。

## 文字列（`web/lib/data/period.ts`）

| 関数 | 返す形 | 使う場所 |
| --- | --- | --- |
| `fiscalPeriodLabel(meta)` | `2026年3月期` | title・description・3ページの本文 |
| `filingWindowLabel(meta)` | `2026年6月1日〜7月10日` | `/about` の「対象範囲」だけ |

**置き場所は `lib/`。`features/<施策>/` ではない。** ranking と company の両方が使う横断の関心で、`lib/seo/`・`lib/analytics/` と同じ位置づけになる。

`filingWindowLabel` の日付（6/1〜7/10）は定数のまま year だけデータから引く。**窓は有報の提出期に貼り付いていて年で動かない**——動かしているのは `pipeline/salary/` の取得側で、ここはその表示にすぎない。

形の違う値は例外で落とす。`NaN年NaN月期` が全ページに出るくらいなら、ビルドで止まるほうがよい（`aboutFacts.ts` が実例を見つけられないときに落とすのと同じ）。

## 出力

### title（AC-17）

```
/          OpenReport | 有価証券報告書ベースの平均年収ランキング 1,867社【2026年3月期】
/?page=3   OpenReport | 有価証券報告書ベースの平均年収ランキング【2026年3月期】（3ページ目）
/?age=N    {N}歳年収ランキング | OpenReport                      … 決算期を入れない
/?ind=X    {X}の平均年収ランキング | OpenReport                  … 決算期を入れない
```

**決算期は末尾、社数の隣に置く。** 社数と決算期は「規模と鮮度」という同じ種類の情報で、隣り合っているほうが読める。**前に置かないのは、差別化要因である「有価証券報告書」がSERPで見える位置から押し出されるため**（`spec.md` 1.4 の競合実測）。日本語のSERPは全角30字前後で切れるので、この位置の決算期は切れることがある——それでも入れるのは、`<title>` がクエリとの一致判定に使われ、description（後述）が同じ事実を先頭側に持っているため。

**ファセット（`?age=N` 8件・`?ind=X` 33件）の title には入れない。** 限られた文字数は「◯歳」「業種名」に使うという 1.4 の決めをそのまま引き継ぐ。ページ番号より決算期を前に置くのは、2ページ目以降が検索結果に出ることがほぼ無いため。

### description（AC-18）

5種類すべてに入れる。入れ方は「有価証券報告書」と同じ文の中で、括弧で添える。

```
/            金融庁 EDINET の有価証券報告書（2026年3月期）に載っている平均年間給与そのままの実測値で、…
/?ind=X      金融庁 EDINET の有価証券報告書（2026年3月期）に載っている平均年間給与そのままの実測値を、…
/?age=N      有価証券報告書（2026年3月期）の平均年間給与を{N}歳時点に補正した推定年収のランキング。…
/about       金融庁 EDINET の有価証券報告書（2026年3月期）から平均年収をどう取り、…
/company/[id] …金融庁 EDINET の有価証券報告書（2026年3月期）に載っている提出会社単体の実測値です。
```

企業詳細の title には入れない。会社名と金額で既に埋まっていて、押し出す価値のあるものが無い。

### 画面（AC-19）

| ページ | 場所 | 文 |
| --- | --- | --- |
| `/`（実測値） | `h1` 直下のリード文の**1文目** | `2026年3月期の有価証券報告書の平均年間給与（単体）で1,867社。` |
| `/`（年齢そろえ） | 同上 | `2026年3月期の平均年間給与を業種の賃金カーブで35歳時点に補正した1,867社。` |
| `/company/[id]` | 「有価証券報告書の実測値」の `h2` | `有価証券報告書の実測値（2026年3月期）` |
| `/about` | 「対象範囲」の1行目 | `2026年3月期の有価証券報告書（EDINET に 2026年6月1日〜7月10日に提出されたもの）。決算期は3月期が中心で、4月期の会社も含みます` |

**リード文は1文目に置く。2文目に回さない。** 2文目は `hidden md:inline` で狭い画面では消えるので、そこに置くとモバイルの読者にだけ「いつの数字か」が届かない。E2E は 390px でこれを見ている。

**企業詳細では見出しに付ける。** この節の中身がその決算期の数字そのもので、見出しに付くのがいちばん短く、読者が数字を見る直前に目に入る。

**1画面に1回**（`spec.md` 5.1）。Issue #128 で「推定」について決めたのと同じ扱いで、見出しと脚注に重ねない。そのために `CompanyDetail` のフッタから `2026年6〜7月提出` を落とした（決算期は上の `h2` にある）。E2E が本文中の出現回数を1で固定している。

## 併せて直したもの

- **`RankingApp` のリード文の `1,867社` が直書きだった。** `spec.md` 1.4 が「社数は直書きしない」と決めているのに、画面側だけ守られていなかった。決算期と同じ行を書き換えるので、この機会に `companies.meta.count` から引くようにした
- **`CompanyDetail` のフッタの `推移は2017〜2026年の各年` が直書きだった。** `history.years` の両端から引く
- **`CompanyDetail` のフッタの `2026年6〜7月提出` を落とした。** 決算期を `h2` に出したので重複であり、かつ直書きの年でもあった

```
768px          ＋「年齢は会社ごとに違うため、若い会社は低めに出ます。」            … 2行
1280px         同上                                                              … 1行
```

## 触っていないもの

- **`app/layout.tsx` の `metadata`。** ここは各ページが自分で返さなかったときの受け皿（`/_not-found`）で、`spec.md` 5.1 の一覧にも入っていない。`companies.json` を layout の依存に足すだけの価値が無い
- **`/company/[id]` の「平均年収推移（過去10年間）」**（`spec.md` 5.4）。各点に年が書いてあり、決算期1つでは表せない
- **`companies.meta.version`。** 提出期を指す別の値で、決算期に置き換わるものではない
- **OGP・JSON-LD**（S2・#116）。`og:title` / `og:description` は title・description と同じ文字列にすると決めてあるので、S3 が先に入った時点でそのまま乗る

## 「2026年度」と書かない理由

親 Issue #104 のタイトルは「2026年度みたいなニュアンス」だが、**そのままの語は使わない**。

2026年3月期は、日本の会計年度でいえば **2025年度**（2025年4月〜2026年3月）にあたる。「2026年度」と書くと、決算期のつもりで読む人と会計年度のつもりで読む人で**指すものが1年ずれる**。有価証券報告書ベースであることを差別化にしているサイトが、その有報の時点を曖昧に書くのは筋が通らない。

決算期（`2026年3月期`）は有価証券報告書そのものの言い方で、ずれようがない。検索の側でも「2026」という数字は同じように含まれる。

## テスト

| 対象 | 場所 |
| --- | --- |
| 決算期の導出（最頻・過半に届かない・形違い） | `pipeline/scripts/build-data.test.ts` |
| 実データの決算期が `2026-03`（3月期1,865社・4月期2社） | 同上 |
| 文字列化（0落とし・提出の窓・壊れた値） | `web/lib/data/period.test.ts` |
| title・description に入ること／ファセットに入れないこと／`meta` を差し替えれば一斉に変わること | `web/lib/seo/ranking.test.ts` |
| 返るHTMLの title・description・本文（AC-17〜AC-20）、1文目に置くこと、1画面に1回 | `web/e2e/data-period.spec.ts` |

E2E を新しいファイルにしたのは、この Unit が `/`・`/about`・`/company/[id]` の3ページとメタデータにまたがっていて、**既存のどのファイルにも「全部が入る場所」が無い**ため。`/` の title の完全一致だけは `e2e/seo.spec.ts` に既にあるので、そちらは書き換えた。

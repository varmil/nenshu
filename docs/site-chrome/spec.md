対象面: user-web（ユーザー画面）

全ページに共通して出るもの。用語は `docs/product/glossary.md` に従う。

## 1. サイト名

### 1.1 何を（WHAT）

サイト名を **OpenReport** とする。

`docs/ranking/spec.md` 5. 未決事項の「サイト名」はこれで決定とする。

### 1.2 なぜ（WHY）

全ページに出るブランドが無く、`/` の `h1`「年齢補正年収ランキング」が事実上サイト名を兼ねていた。企業詳細ページが増えた今、「ランキング」はサイト名として実態に合わない。

### 1.3 制約

`docs/product/glossary.md` の「使わない語」（年収診断・想定年収・実力年収 等）に抵触しないこと。**OpenReport は抵触しない**（確認済み）。

### 1.4 ページタイトル

| ページ | title |
| --- | --- |
| `/` | `OpenReport \| 有価証券報告書ベースの平均年収ランキング {社数}社【{決算期}】` |
| `/about` | `計算方法 \| OpenReport` |
| `/?age=N` | `{N}歳年収ランキング \| OpenReport` |
| `/?ind=X` | `{X}の平均年収ランキング \| OpenReport` |
| `/company/[id]` | 現行のまま（会社名と金額が主役。ブランドは入れない） |

`h1` はサイト名ではなく**そのページの内容**を表す。`/` の `h1` は「年齢補正年収ランキング」のまま残す。

**`/` のタイトルは U8（Issue #53）で中身を足した。** ブランドを先頭に置く形は変えていない。競合6社を実測すると、タイトルで競っているのは鮮度（「2026年8月最新」）と規模（TOP100・21626社）で、**有価証券報告書をタイトルに置いている競合は1つも無かった**（Zaimiru・OpenMoney・OpenWork・Yahoo!しごとカタログ・Ullet・J-LiC。うち Ullet・J-LiC・OpenMoney はデータ元が同じ有報である）。「有報ベース」はデータ源として独自なのではなく、**それを明示していること**が差別化になる——口コミベースの数字と並んだときに読者が見分けられる。

**タイトルに有価証券報告書を入れるのは `/` だけにする。** `?age=N` 8件・`?ind=X` 33件のファセットページでは「◯歳」「業種名」のほうが情報量が高く、限られた文字数をそちらに使う。`/company/[id]` の実測値タイトルには既に入っている（`有価証券報告書は{金額}`）。

**description は全ページに有価証券報告書を入れる**（`/about` を含む）。description は順位を動かさないが SERP のスニペットに出るため、`docs/ranking/intent.md` の差別化要因がそこで読者に届く。

社数はタイトルにも description にも直書きしない。`companies.meta.count` から引く——直書きすると年1回のデータ更新でそこだけ古い数字が残る。

**決算期（`2026年3月期`）はタイトルの末尾に置く**（5.）。前に置くと、差別化要因である「有価証券報告書」がSERPで見える位置から押し出される。社数と同じく `companies.meta` から引く。

## 2. 共通ヘッダ

### 2.1 何を（WHAT）

全ページの最上部に1本のバーを置く。左にサイト名、右に共通の導線と表示設定。

| 位置 | 中身 |
| --- | --- |
| 左 | `OpenReport`（`/` へのリンク） |
| 右 | 「計算方法」（`/about` へのリンク）、表示モードの切替 |

### 2.2 見た目

地の色（`--background`）＋下罫線（`--border`）。塗りつぶさない。

ライト/ダークのどちらでも破綻せず、コントラストの危険が無いことを優先する。

### 2.3 幅

中身は `max-w-5xl` で中央寄せ（一番広い `/` に合わせる）。バー自体は全幅。

### 2.4 各ページ側への影響

- `/` の「計算方法」リンクはバーへ移す（重複させない）
- `/company/[id]` のパンくず先頭は「ランキング」に短縮する（ブランドはバーが持つため）

## 3. 表示モード（ライト/ダーク）

### 3.1 何を（WHAT）

ライトとダークの2状態。**未操作の間は OS の設定（`prefers-color-scheme`）に従う。**

一度切り替えたら、その選択をブラウザに保存して次回以降も維持する。

### 3.2 なぜ（WHY）

`tokens.css` に `.dark` の配色は揃っているが、適用する仕組みが無く一度も画面に出ていない。まず見られる状態にする。

### 3.3 制約（重要）

- **表示モードをサーバー側のHTMLに焼かない。** SSR の出力はエッジで24時間キャッシュされる（`next.config.ts`）ため、焼くとある読者の選択がキャッシュ経由で他の読者に配られる
- **初回描画でちらつかせない。** OS がダークの読者に、一瞬ライトの画面を見せない
- **切替でネットワークリクエストを発生させない**（CLAUDE.md「クエリ文字列を読みたいとき」の方針と同じ理由）

### 3.4 3状態にしない

Light / Dark / System の3状態は採らない。2状態＋OS追従で同じことができ、ドロップダウンのプリミティブを増やさずに済む。

## 4. SNS共有と構造化データ（OGP・JSON-LD）

### 4.1 何を（WHAT）

**共有されたときとリッチリザルトで、このサイトが何を出しているかが分かる形にする。**

| 出すもの | 対象 | 値 |
| --- | --- | --- |
| `og:title` / `og:description` | 全ページ | そのページの title・description（1.4 の表と同じもの） |
| `og:url` | 全ページ | **canonical と同じURL**（U8 の `rankingCanonical()` を通す） |
| `og:site_name` | 全ページ | `OpenReport` |
| `og:type` | 全ページ | `website` |
| `og:locale` | 全ページ | `ja_JP` |
| `og:image` | 全ページ | 4.3 |
| `twitter:card` | 全ページ | `summary_large_image` |
| JSON-LD | 4.4 の範囲 | 4.4 |

### 4.2 なぜ（WHY）

North Star KPI は自然検索からの月間セッション数（`docs/ranking/intent.md`）だが、**共有と検索結果の見え方はそこに直接効く**。いまは `og:` が1つも無く、SNS に貼られてもURLだけの帯になる。

U8 で「どのURLをインデックスさせるか」は片付いた（ADR-0006）。残っているのは**そのURLがどう見えるか**で、これは 1.4 のページタイトルの決めごとの続きにあたる。

### 4.3 OG画像

**v1は静的な1枚**にする。ブランドと「有価証券報告書ベースの平均年収ランキング」が読める図で、全ページで同じものを使う。

**会社ごとに数字を焼き込んだ画像は作らない**（v1）。1,867社ぶんを動的生成すると Workers の CPU 予算（10ms/リクエスト・`docs/company/company-page/design.md`）とエッジキャッシュの設計に踏み込むことになり、OGP を出すこと自体より重い。効果を見てから次段階で判断する。

### 4.4 構造化データ（JSON-LD）

**出すのは、画面に既にある情報を機械可読にしたものだけ。** 画面に無い主張を構造化データにしない（Google の構造化データのポリシーに反するうえ、「根拠を隠した推定値を表示しない」という開発上の約束とも合わない）。

| ページ | 型 | 中身 |
| --- | --- | --- |
| `/company/[id]` | `BreadcrumbList` | 画面のパンくずと同じ（ランキング / 業種 / 会社名） |
| `/`・`/about` | `WebSite` | サイト名と `/` のURL |

**`Organization` は出さない。** 企業ページが表すのは当該企業だが、その主体を名乗るのは我々ではない。

### 4.5 受け入れ基準

- **AC-10**: 全ページに `og:title`・`og:description`・`og:url`・`og:site_name`・`og:type`・`og:locale`・`og:image`・`twitter:card` が出る
- **AC-11**: `og:url` が `<link rel="canonical">` と**同じ文字列**である（`/?age=35&ind=銀行業` のような非正規URLでも、両方が寄せ先を指す）
- **AC-12**: `og:title`・`og:description` が、そのページの `<title>`・`<meta name="description">` と一致する
- **AC-13**: OG画像が絶対URLで、200 で返り、SNS が要求する寸法（1200×630）である
- **AC-14**: `/company/[id]` に `BreadcrumbList` の JSON-LD があり、画面のパンくずと同じ階層・同じURLを指す
- **AC-15**: JSON-LD に、画面に出ていない値が入っていない
- **AC-16**: `/` のHTMLサイズ（gzip）が 75,000 バイトを超えない（`docs/logo/spec.md` AC-13 と同じ予算）

## 5. データの時点（決算期）

### 5.1 何を（WHAT）

**全ページに「いつのデータか」を出す。** 表記は決算期 `{年}年{月}期`（現行データなら `2026年3月期`）。

| 場所 | 出し方 |
| --- | --- |
| `/` の title | 末尾に `【2026年3月期】` |
| 全ページの description | 「有価証券報告書」と同じ文の中に置く（`/`・`/?age=N`・`/?ind=X`・`/about`・`/company/[id]`） |
| `/` の画面 | 見出し直下のリード文の先頭 |
| `/company/[id]` の画面 | 「有価証券報告書の実測値」の見出し（節の中身がその決算期の数字そのもの） |
| `/about` の画面 | 「対象範囲」の1行目 |

**1画面に1回でよい。** 見出しと脚注のように同じ語を重ねない（Issue #128 と同じ扱い）。

### 5.2 なぜ（WHY）

有価証券報告書ベースであることは title・description・本文のどこにも書いてあるが、**それが「いつ」の有報なのかがサイトのどこにも無い**（Issue #104）。読者は目の前の数字が今年のものか去年のものかを確かめられず、更新の止まったサイトと見分けが付かない。

検索でも同じことが効く。競合6社のタイトルを実測したときに競っていたのは**鮮度と規模**だった（1.4）。規模（社数）は既にタイトルに入れてあり、鮮度だけが抜けている。

### 5.3 表記

**「2026年度」とは書かない。** 2026年3月期は年度でいえば2025年度で、どちらの意味で読むかが読者によって1年ずれる。決算期（`2026年3月期`）は有価証券報告書そのものの言い方で、ずれようがない。

**決算期は全社が同じではない。** 掲載1,867社のうち1,865社が3月期、2社が4月期になる。だから最頻の決算期を代表として出し、`/about` の「対象範囲」では**3月期が中心である**ことを断る。

**直書きしない。** 決算期は `companies.meta` から引く。社数と同じ理由で、直書きすると年1回のデータ更新でそこだけ古い数字が残る（1.4）。

### 5.4 10年推移は別

`/company/[id]` の「平均年収推移（過去10年間）」は各年の有報の数字なので、この節の決算期1つでは表せない。推移の節は**いまも各点に年を書いている**ので、そのままにする。

### 5.5 受け入れ基準

- **AC-17**: `/` の `<title>` に決算期（`2026年3月期`）が入る
- **AC-18**: `/`・`/?age=N`・`/?ind=X`・`/about`・`/company/[id]` の description に決算期が入る
- **AC-19**: `/`・`/company/[id]`・`/about` の**画面上**に決算期が読める形で出る（HTML に含まれ、クライアントの描画待ちにしない）
- **AC-20**: 決算期は `companies.meta` から導出され、アプリのコードのどこにも `2026年3月期` を直書きしていない

## 6. 受け入れ基準

- **AC-1**: 全ページの最上部にバーが出る。左に `OpenReport`、右に「計算方法」と表示モードの切替がある
- **AC-2**: `OpenReport` を押すと `/` に遷移する
- **AC-3**: OS の設定がダークなら、**初回表示の時点で**ダークで描画される（ライトが一瞬見えない）
- **AC-4**: 切替を押すとライト⇄ダークが切り替わる
- **AC-5**: 切り替えた選択はリロード後も維持される
- **AC-6**: 切替の操作でネットワークリクエストが発生しない
- **AC-7**: ダークでも、リンク・選択中のタブ・年齢別チャートが WCAG AA（4.5:1）を満たす
- **AC-8**: `/` の `h1` は「年齢補正年収ランキング」のまま。ページタイトルは 1.4 の表のとおり
- **AC-9**: モバイル幅（390px）でバーが折り返しても横スクロールが発生しない

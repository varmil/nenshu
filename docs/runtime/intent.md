# intent.md — Worker の実行予算

## 狙い

**公開中のサイトが、読者ではなくクローラに壊されている。** Cloudflare Workers の無料枠は1リクエストあたり CPU 10ms で、`/company/[id]` が散発的にこれを超えて `exceededCpu` で落ちている（Issue #118）。落ちたリクエストはHTMLを返さない。

報告されたログの発生元は `ClaudeBot`（`verifiedBotCategory: "AI Crawler"`）だった。これは偶然ではない。**クローラは1,867社ぶんの異なるURLを次々に叩く**ので、エッジキャッシュはほぼ全部ミスし、しかも世界中のコロに散るため isolate は毎回冷えている。読者が踏みにくく、クローラが必ず踏む形になっている。

インデックスされたいページで落ちているので、実害は「たまにエラーが出る」では済まない。

**この施策は、1リクエストが使う CPU を予算の内側に収める。** 画面に出るものは1つも変えない。

## North Star KPI

**`exceededCpu` の発生数がゼロであること。** Cloudflare のログで見る。

## 仮説

**H1. いちばん重いのは描画そのものである。** 読むデータを削るより、描かないほうが効く。

*検証*: 事前生成したページと動的に描くページの CPU を、同じ手法で並べて測る。

**H2. `next build` が `○ (Static)` と出していても、実際には毎回描き直している。** OpenNext の `incrementalCache` は既定が `"dummy"` で、事前生成した結果を1枚も返さない。

*検証*: `/about`（静的なはずのページ）と `/company/[id]`（動的なページ）の CPU を比べる。前者が重ければ仮説どおり。

**H3. 企業詳細ページの表示基準（年齢そろえ）は、URL に出す必要が無い。** 年齢そろえで変わるのは推定年収まわりだけで、実測値の節も10年推移も変わらない。

*検証*: `?age=` を外して、画面の機能が失われないことを E2E で確かめる。

## 前提の確認（調査済み）

**実測（`wrangler dev --local`・40リクエストの平均 CPU・同一セッション）。**

| | 事前生成の前 | 後 |
| --- | ---: | ---: |
| `/company/8282` | 29.6〜29.7ms | **14.0〜14.1ms** |
| `/company/7203` | 26.5〜29.0ms | **13.6〜13.7ms** |
| `/about`（`incrementalCache` を挿す前） | 47.7〜59.6ms | **12.4〜13.5ms** |
| `/`（動的のまま） | 41.7〜46.5ms | 46.3〜48.5ms |
| `/favicon.ico`（静的アセットの床） | 5.3〜6.1ms | 5.1〜5.6ms |

**H2 は当たっていた。** 静的なはずの `/about` が企業詳細より重かった。`incrementalCache` を挿すまで、事前生成した結果は1枚も使われていない。

**この環境は本番より数倍遅いので絶対値は使えない。** 見るのは同じ手法で並べた前後の比だけ（測り方は `cpu-budget/design.md`）。

## 既知の限界

**`/` は事前生成できない。** `searchParams`（`?age=`・`?ind=` の41ファセット・`?q=`・`?page=`）を読んでSSRするため。ここは動的なまま残る。

**cold は無くせない。** クローラが世界中のコロから叩く以上 isolate は冷えたまま来る。**cold を安くすることはできても、cold を起こさないことはできない。**

**デプロイのアセットが 15MB → 344MB になる。** 1,874ページぶんの事前生成した結果（1枚あたり約180KB）を静的アセットとして配るため。無料枠の上限は「ファイル数 20,000・1ファイル 25MiB」で、ファイル数は 1,655 → 3,528 に収まる。

## 作らないもの

**表示の変更。** 出す数字も、切り替えたときの振る舞いも変えない。**ただし企業詳細ページの表示基準は URL から外す**（ADR-0012）——これは事前生成の前提条件で、画面の機能は変わらない。

**データの間引き。** 掲載社数も、10年推移の年数も減らさない。

**有料プランへの移行。** `docs/product/product.md` の「ランニングコストをゼロに保つ」に反する。

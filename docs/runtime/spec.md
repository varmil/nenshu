# spec.md — Worker の実行予算

対象面: user-web（ユーザー画面）

用語は `docs/product/glossary.md` に従う。**画面に出る数値と文言は変えない。** 受け入れ基準はそれと「予算に収まること」で書く。

---

## 1. 1リクエストの CPU

### 1.1 何を（WHAT）

`/company/[id]`・`/about`・`/robots.txt`・`/sitemap.xml` は、リクエスト時に**描画しない**。ビルド時に確定した結果を返すだけにする。

### 1.2 なぜ（WHY）

超えたリクエストは HTML を返さず `exceededCpu` で落ちる（Issue #118）。落ちているのはインデックスさせたい企業詳細ページで、踏んでいるのはクローラである。

### 1.3 受け入れ基準

- **AC-1**: `/company/[id]` は 1,867社すべてがビルド時に生成される（`next build` の出力で `●` になる）。
- **AC-2**: 事前生成した結果が実際に返る。`incrementalCache` を挿し、リクエスト時の描画が起きないこと。
- **AC-3**: `companies.json` に無いIDは 404 を返す。
- **AC-4**: `/company/[id]` の CPU が、事前生成の前より減っている（測り方は 4.）。

## 2. 企業詳細ページの表示基準

### 2.1 何を（WHAT）

**企業詳細ページの表示基準（実測値／年齢そろえ）を URL に出さない。** `/company/[id]?age=N` を出さず、クライアントの状態としてだけ持つ。

### 2.2 なぜ（WHY）

2つある。

**事前生成の前提条件である。** `force-static` のページは `searchParams` を読めない。読めるようにすると1,867枚が毎リクエストの描画に戻る。

**年齢そろえで変わるのはページの一部だけである。** 変わるのは推定年収まわり（金額・順位・偏差値・分布・近傍5社・要点）で、実測値の節も10年推移も変わらない。ページ全体にかかるパラメータとして持つと、この先この画面に項目が増えるほど「URLが指しているのは何なのか」が曖昧になる。いずれ推定年収の要素に付いたスイッチへ寄せる。

**ランキング（`/`）は変えない。** あちらは `?age=N` が1,867行の並び順そのものを変え、8件をインデックスさせている（ADR-0006）。同じ語だが役割が違う。

### 2.3 受け入れ基準

- **AC-5**: 企業詳細ページで表示基準を切り替えても URL が変わらず、履歴も増えない。
- **AC-6**: 配ってしまった `/company/[id]?age=N` は実測値で開き、URL から `age` が落ちる（`replaceState`）。
- **AC-7**: 企業詳細ページのメタデータ（title・description・canonical）は表示基準で変わらない。
- **AC-8**: 年齢そろえ・年齢の切り替えでネットワークが発生しない（company AC-8 のまま）。

---

## 3. 変わらないこと

### 3.1 受け入れ基準

- **AC-9**: `/`・`/company/[id]`・`/about` の画面に出る文字・数値・ロゴが前後で変わらない。
- **AC-10**: `Cache-Control`・`Cloudflare-CDN-Cache-Control` が前後で変わらない（ADR-0004 の規則は `web/lib/cache/headers.ts` の1か所のまま）。
- **AC-11**: canonical・sitemap・robots が変わらない（ADR-0006・U8）。
- **AC-12**: `/` のHTMLサイズが増えない（Issue #22 の予算 75,000B）。

---

## 4. 測り方

**同じ手法で前後を並べる。** `wrangler dev --local` に対して N リクエストを投げ、`/proc/<workerd>/schedstat` の第1フィールド（ナノ秒）の差分を N で割る。

**絶対値は使えない。** この環境は本番より数倍遅く、cold は 508〜1,776ms（4.7MB の `handler.mjs` を毎回一から評価するため）と揺れる。**静的アセット（`/favicon.ico`）を床として一緒に測り、床を引いた「アプリぶん」で比べる。**

---

## 5. 対象外

**`/` の事前生成。** `searchParams` を読むため。動的なまま残す。

**フレームワークの CPU。** Next.js・React・OpenNext の処理そのものには触らない。

**有料プランへの移行**・**掲載データの削減**。

**ページが読むデータファイルの分割。** 一度やって戻した（#165・#179）。企業詳細を事前生成すれば `JSON.parse` はビルド時にしか走らないので、残るのは `/` だけになる。必要になったら測り直してから入れる。

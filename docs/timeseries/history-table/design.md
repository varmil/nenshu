## データモデル

`buildHistoryTable(history)` が `{ rows, baseYear }` を返す。

| フィールド | 意味 |
| --- | --- |
| `rows[].year` | 報告書の提出年。`history.years` の並びのまま（古い年から新しい年） |
| `rows[].value` | その年の平均年間給与（円）。有報が無ければ `null` |
| `rows[].yoy` | 前年比（`0.25` が ＋25.0%）。**直前の年に値があるときだけ** |
| `rows[].cumulative` | 基準年からの累積。**基準年の行と欠損の行は `null`** |
| `baseYear` | 累積の基準年＝**その会社で最初に値のある年**。全年欠損なら `null` |

### 欠損の扱いが、この表のほぼ全部

**基準年は会社ごとに違う。** 2017年の値を持たない会社が230社ある（実データを数えた）。固定の2017年基準にすると、その230社では累積の列が丸ごと空になる。**列の見出しに基準年を書く**（`2017年比` / `2018年比`）ので、読者は何と比べた値かを見出しだけで読める。

**飛び年をまたぐ比は「前年比」ではないので出さない。** 内部に欠損のある会社が33社ある（例: 2117 は2023・2024が欠損）。2022年と2025年の比を前年比の列に置くと、読者は1年ぶんの動きとして読む。**累積のほうは基準年からの比なので、間が飛んでいても意味が変わらない**——2117 の2025年は前年比が空で累積だけが入る。

**丸めてから符号を決める**（`formatRate`）。−0.04% を「−0.0%」と出すと、動いていない年に向きが付いて見える。丸めて0なら `±0.0%`。

## 表の構造

4列（年度 / 平均年収 / 前年比 / `<基準年>年比`）×10行。**器は年齢別の表（`AgeSalaryTable`）と同じ**——罫線で仕切り、値は中央、`TABLE_NO_VERTICAL_SCROLL` で縦スクロールの小窓を殺す。同じページに数表が2つ並ぶので、見た目が違うと別の種類の情報に見える。

- **最新年の行だけ濃くする。** 棒グラフで最新年だけ濃いのと同じ理由で、10行のうちどれが「いまの数字」かを、ページの他の場所に出ている金額と突き合わせずに見つけられるようにする
- **値の無い年は行ごと落とさず「データなし」**（AC-7 と同じ扱い）
- 年度の列は狭い器で `w-14`、`@md:` から `w-24`。**`sm:` ではなく `@md:`** で切るのは年齢別の表と同じ理由——同じ768pxでもサイドバーの有無で器の幅が割れる

## 節の並び

**チャート → 説明文 → 表。** 初版は年齢別の推定年収に合わせて表を先に置いたが、運営者の指示で入れ替えた——**推移で先に見たいのは10年ぶんの形**で、値そのものは形を掴んだあとに確かめるものになる（年齢別は8点の金額を先に確かめる読み方なので、施策として順が割れているのは意図どおり）。

増減の1文（`buildHistorySummary`）はグラフの `figcaption` の中にいたが、グラフと表の間の `<p>` に出した。`figcaption` には軸の断り（「横軸は報告書の提出年です。」）だけが残る。

**読み上げの経路は1つにした。** グラフが持っていた `sr-only` の10件は表と同じ中身なので落とし、AC-10 は表が担う。`SalaryHistoryChart` の `summary` prop も無くなった。

## 呼び名

**「昇給率」とは呼ばない。** 親 Issue #137 の例は「昇給率」「累積昇給率」だったが、有報の平均年間給与の前年差は**個人の昇給ではなく、採用・退職による構成の変化を含む**。出す数字は Issue のとおりのまま、列の見出しを「前年比」「`<基準年>年比`」にし、節の説明にも1行置いた（「前年比は会社の平均が動いた幅で、個人の昇給率ではありません。」）。数値の意味より強い名前を付けない、という点で「根拠を隠した推定値を表示しない」（CLAUDE.md）と同じ線にある。

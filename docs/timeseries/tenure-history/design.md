## データモデル

### `pipeline/data/salary_history.csv`

`avg_tenure`（平均勤続年数・年）を `avg_age` の直後に足した。**抜き出す処理（`edinet.to_record`）は T0 の時点からあり、書き出していなかっただけ**なので、抽出の規則は1つも増えていない。有報の桁のまま持つ（平均年齢と同じ）。

**平均年齢と違い、空欄がありうる。** 26,865行のうち1行（パシフィックネット2021）。給与と年齢のタグはあるのに勤続のタグが無く、本文には「8年2ヶ月」と書かれている書類で、**本文へ降りるのは給与か年齢のタグが無いときだけ**（`to_record`）なので拾えていない。1行のために抽出の規則を足していない——画面ではその年が「データなし」になる。

| 見たこと | 結果 |
| --- | --- |
| 作り直した CSV と前の版（在籍年数の列を除く） | **26,865行すべて、全列で一致**（平均年齢も） |
| 採用書類の行の在籍年数と `ranking_unified_2026.csv` | **全2,961社で一致**（`build-data.test.ts` の AC-17） |
| 値の範囲 | 0.5〜29.9年（中央値14.4年）。`0 <= 勤続 <= 年齢 - 15` を外れる行は0 |
| 隣の年との差（本文→本文 / 本文→タグ / タグ→タグ） | 中央値 0.1 / 0.0 / 0.1年・1%点 −1.9 / −2.0 / −1.9年・99%点 2.0 / 1.7 / 1.9年。**本文由来の側だけ裾が重い形になっていない** |
| 小数第2位の値 | 1,990行（タグ 1,161・本文 829）。本文の「13年6ケ月」は `_num_unit` が小数第2位で丸めて年に直している |

**隣の年と5年以上動く組が49組ある。** 見た限り会社側の構造の変化で、読み違いではない——アサヒグループHD は 17.0 → 11.9 → 2.7 → 1.0 → 13.6年（単体の従業員数が 336 → 164 → 192 → 265 → 328人）、ＬＩＸＩＬ は 8.5 → 21.3年（単体 35 → 14,408人。持株会社が事業会社を吸収した年）。平均年収・平均年齢と同じく「浮いて見えるだけでは直さない」（`docs/timeseries/salary-history/design.md`）。テストが見るのは帯だけにした。

**書類一覧は取得の窓の終わり（2026-08-25）までに絞って回した。** その後の提出（6月決算の会社の2026年9月の有報など）を混ぜると、ランキングより新しい年の値が推移にだけ入る。

### `web/public/data/history.json`

```
{
  "years": [2017, …, 2026],
  "byId": { … }, "ageById": { … },
  "tenureById": { "<企業ID>": [年 or null, …] },
  "tenureIndustryMedian": [[年 or null, …], …]   // companies.industries と同じ並び
}
```

- `tenureById` のキーは `byId` と同じ。**同じ CSV の同じ行から同じループで組む**（`buildHistory`）ので、平均年収の無い年に在籍年数だけがある状態は作れない
- `tenureIndustryMedian` は**業種ごと・年ごとの中央値**。業種は**いまの業種**（`companies.json` の `tse33`）で、**その年に値を持つ会社だけ**で数える。この会社自身も入る。小数第2位で丸める（偶数個の平均が浮動小数の端数を持つため。画面は第1位）
- **33業種×10年を1回数えるだけ**で、リクエスト時には何も数えない。`performance.json` の `industryMedian` と同じく `companies.industries` の並びで持ち、企業詳細は `companies.rows` の業種の添字で1本を引く

| | 前 | 後 |
| --- | ---: | ---: |
| `history.json`（gzip） | 143.1KB | **187.0KB** |

**上限は 180KB から 224KB に上げた**（実測の 1.2 倍。T3 と同じ扱い）。F1（ADR-0014）以降このファイルは `/company/[id]` をビルド時に生成するときに読まれるだけ。**`dist/server` を在籍年数の業種の中央値で grep して0件**——Worker バンドルにも入っていない。

**同業が3社未満の年は中央値を出さない**（`null`）。1社なら中央値はその会社の値そのもので、2社なら2社の平均になる。当たるのは空運業の2017・2018年だけ（値を持つのはアジア航測1社で、日本航空のページでは自社に値の無い年にだけ点線が出ていた）。次に少ないのは鉱業の3社。

### `TenureHistory`（`web/features/company/types.ts`）

`{ years, values, industryMedian }`。**`SalaryHistory` に混ぜない**——同じ書類の値だが、描く節が別で、業種の中央値という会社の外の値を一緒に持つ。`byBasis` の外に置くのは推移の2つと同じ（表示基準と独立）。**1年も値が無い会社は `null`** で、節ごと出ない。

## 読み方が割れた書類の在籍年数

2017・2018年は本文の表から拾っていて、区切りの無いセルは読みが割れる（`textblock._best`）。

```
コメリ2017   4,179(4,046)34.09.924,320,256
  → 勤続 9.9  / 給与 2,432万（並び順で先に来る読み）
  → 勤続 9.92 / 給与   432万（正しい読み）
```

`history.resolve_candidates` は同じ会社の他の年を基準に**給与だけ**を選び直していた。**給与が変われば同じセルの勤続（と年齢）の読みも変わる**のに、勤続は選ばなかったほうの読みのまま残る。

**候補ごとの年齢・勤続を持たせ、給与と一緒に差し替える**ようにした。

- `textblock._best` が `readings`（給与 → `{avg_age, avg_tenure}`）を残す。同じ給与になる読みが複数あれば `DP_PAIRS` の並びで先のもの（`best` を選ぶのと同じ規則）
- `edinet.to_record` がそれを `salary_readings` として渡す
- `edinet.adopt_salary(rec, salary)` が給与と、同じ読みの年齢・勤続を差し替える。**`history.resolve_candidates` と `unified.resolve_ambiguous_salary` の両方がこれを使う**——片方だけ直すと、推移とランキングで同じ書類の勤続が違う値になりうる

**実測で、読みが割れた書類は131件、年をまたいで給与を選び直したのは22件。22件とも勤続の読みが変わり、差は 0.01〜0.02年**（`9.9` → `9.92`、`11.0` → `11.02`）。**平均年齢が変わった行は無かった**——割れ方はどれも「勤続の小数第2位と給与の先頭の桁」の境目で、年齢の桁は同じだった。表示（小数第1位）にはほぼ出ない幅だが、同じ書類の同じセルの読みを混ぜないためにそろえた。

**並びはチャート → 表 → 説明文**（推移の2節と同じ）。

### 折れ線（`TenureHistoryChart`・`buildTenureChart`）

- **viewBox 720×300。** 文字の大きさは年齢別の折れ線と同じ（`chartText.ts`。器の幅で刻む）。同じ本文カラムに縦に並ぶ2枚の図で字の大きさが違うと、別の種類の図に見える
- **縦軸は0起点にしない。** 範囲は会社と中央値の両方を含め、上下に範囲の15%（少なくとも0.5年）の余白を取って整数に丸める。目盛は `niceTicks`（年齢別と同じ）
- **欠損の年で線を切る**（`M` から始め直す）。点は値のある年だけ打つ。中央値の点線も同じ
- **各点に値を書く**（小数第1位）。最新年の点だけ塗り、値を太字にする
- **値のラベルは全部中央揃え。** 値は4文字（`12.4`）までで、最も大きい字（22）でも幅は約43と点の間隔（69）に収まる。年齢別の折れ線のように両端を内側へ寄せると、寄せたぶん隣に近づく（390px で先頭の2つが接していた）。**先頭だけ12右へずらす**——点が縦軸の上にあり、目盛の数字に掛かる
- **目盛は整数の年**（1・2・5年刻み。`niceTicks` に刻みの候補を渡す）。2.5 を許すと `7.5 / 12.5` が並び、目盛のほうが値に見える
- **点線が点のすぐ上（30 user unit 以内）を通る年は、値を点の下に置く。** 既定は上。ラベルが点線に乗って読めなくなるのを避ける
- **中央値のラベル（「業種の中央値 16.7」）は最新年の位置に、会社の線と反対側に置く。** 会社の線が上なら点線の下、下なら上。会社の点のラベルは点線の反対側に出るので2つが重ならない
- **読み上げは表が担う。** 表に無いのは中央値だけなので、`svg` の `aria-label` は中央値の10年ぶんを言う

**共通化していない。** 平均年収・稼ぐ力の棒（`YearlyBarChart`）とは0起点かどうかが違い、年齢別の折れ線（`SalaryCurveChart`）とは横軸（年齢8点と10年）と帯の有無が違う。共有しているのは文字の大きさだけ。

### 表（`TenureHistoryTable`・`buildTenureTable`）

3列（年度 / 在籍年数 / `<基準年>年との差`）×10行。器・罫線・最新年の行の塗りは平均年収の表と同じ。

- **差は比ではなく年**（`＋4.2年`）。在籍年数の % は意味が取りにくい（モック 1a の注記）。比の列と同じく計算した値なので文字を薄くする
- **基準年はその会社で最初に値のある年**（平均年収の表と同じ）
- **差は画面に出ている小数第1位の値どうしで引く。** 有報の桁のまま引くと、表が「19.4年」「15.2年」と出している2行の差が「＋4.3年」になりうる
- **業種の中央値の列は置かない**（モックの表は 1a と同じ3列）

### 説明文（`buildTenureSummary`）

```
2026年の株式会社キーエンスの平均勤続年数は、単体（提出会社）で11.3年です。
電気機器の中央値（16.4年）より5.1年短く、2017年の12.4年から9年で1.1年短くなっています。
```

- **1文目は年・社名・値で閉じる**（モックの注記。検索結果の抜粋に引かれやすい形）
- **時点は年で書く。決算期は書かない**——モックは「（2026年3月時点）」としていたが、企業詳細で決算期を出すのは「年収に関するQ&A」の説明（C16）と要約の説明の2か所だけ（`docs/site-chrome/spec.md` 5.1）
- 2文目は中央値との差と最初の年からの動き。どちらかが言えなければその句だけ落とす（値が1年だけなら動きは言えない）。**差も動きも表示している小数第1位の値どうしで取る**
- **向きは語で言う。** 「伸びています」「短くなっています」「変わっていません」。符号（`＋4.2年伸びて`）は付けない

### 節の説明

「各年の有価証券報告書に載った平均勤続年数の実測値（提出会社単体）。点線は{業種}の中央値です。」（モック 1b のまま）。**見出しと表は読者の語（在籍年数）、出典の文は有報の語（平均勤続年数）**——glossary の決まりと、「年収に関するQ&A」（C16）の質問と回答が「平均勤続年数」と書いているのと同じ。

**「誰も辞めず誰も入らなければ毎年1年ずつ伸びる」ことは書いていない。** モックの論点で、1c・1e はこの読み違いを防ぐための案だった。運営者が選んだのは 1b で、業種の中央値が同じ時期の同業の水準を示す。

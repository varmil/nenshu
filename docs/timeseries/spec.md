# spec.md — 平均年収の10年推移

対象面: user-web（ユーザー画面）… `docs/product/product.md` の面一覧に対応

`docs/timeseries/intent.md` の狙いを、何を作るか（WHAT）と満たすべき条件に落とす。用語は `docs/product/glossary.md` に従う。

## 1. データ（パイプライン）

### 1.1 何を取るか

金融庁 EDINET の有価証券報告書（`docTypeCode=120`）から、**提出会社単体の平均年間給与**を10年ぶん取る。

- 対象期間: 2017年〜2026年の**各暦年に提出されたもの**
- 対象会社: **現行の `ranking_unified_2026.csv` に載る1,867社**（`edinet_code` で絞る）
- 取得形式: CSV形式（`type=5`）。XBRL完全パッケージは使わない（1件73KBに収まるため）

**窓は暦年ぜんぶを見る。** 母集団は2026年の掲載1,867社に固定してあるので、窓を広げても母集団は変わらない——変わるのは「その会社がその年に出した有報を見つけられるか」だけである。6/1〜7/10 に限ると、COVID期の提出期限延長で2020年の96社を取り逃がす（T0 実測）。

### 1.2 名寄せ

**`edinet_code` を主キーにする**（ADR-0006）。証券コードは上場・廃止で変わるが EDINETコードは変わらない。

同じ `(edinet_code, 年)` に複数の書類がある場合（訂正報告など）は、**`docID` が大きいもの＝後に提出されたもの**を採る。

### 1.3 出力

`web/public/data/history.json`。

```
{
  "years": [2017, ..., 2026],
  "byId": { "<企業ID>": [値 or null, ...] },     // years と同じ並び・同じ長さ
  "ageById": { "<企業ID>": [歳 or null, ...] },  // byId と同じ会社・同じ並び（T3）
  "tenureById": { "<企業ID>": [年 or null, ...] }, // byId と同じ会社・同じ並び（T4）
  "tenureIndustryMedian": [[年 or null, ...], ...] // companies.json の industries と同じ並び（T4）
}
```

- キーは**企業ID**（証券コード／EDINETコード。ADR-0006）。`companies.json` の `id` と一致させる
- 値は円・整数。**その年の値が無ければ `null`**
- 全年が `null` の会社はキーごと落とす（ペイロードを無駄にしない）
- `ageById` は**平均年間給与と同じ書類の平均年齢**（歳）。有報に載った桁のまま持ち（`42.49` のような小数第2位もある）、丸めは画面で行う——`companies.json` の平均年齢と同じ扱い
- `tenureById` は**同じ書類の平均勤続年数**（年。画面では「在籍年数」）。桁の扱いは平均年齢と同じ。**平均年齢と違い、平均年収のある年に `null` がありうる**——給与と年齢はタグ付けされていて勤続だけが無い書類がある
- `tenureIndustryMedian` は**業種ごと・年ごとの在籍年数の中央値**。業種は**いまの業種**（`companies.json` の `tse33`）で、**その年に値を持つ会社だけ**で数える（古い年ほど母集団が小さい）。**値を持つ会社が3社未満の年は `null`**——1社ならその会社の値そのもの、2社なら2社の平均で、業種の水準とは呼べない（当たるのは空運業の2017・2018年だけ）

#### AC-17 在籍年数

#### AC-18 在籍年数の業種の中央値

```gherkin
Given history.json が生成されている
Then tenureIndustryMedian は companies.json の industries と同じ数の配列を持ち、各配列は years と同じ長さである
```

## 2. 表示（企業詳細ページ）

### 2.1 何を出すか

企業詳細ページ `/company/[id]` に「平均年収推移（過去10年間）」の節を置く。

- 各年の平均年間給与を**棒グラフ**で並べる（デザイン: `改善案.dc.html` 4b / 2b）
- 横軸は**報告書の提出年**
- 単位は万円。各年の値を数値でも併記する
- 10年の増減（例「10年で ＋317万円（2017年 1,861万円 → 2026年 2,178万円）」）を文で添える
- **最高値の年**を同じ文に足す（company 施策の C4・Issue #146）。**最新年が最高値の会社では出さない**——増減の文が同じ数字を既に書いており、2度並べることになる（1,852社中1,287社がこれに当たる）

### 2.2 実測値であることの扱い

**推移は補正を通さない実測値のみ**である。表示基準（実測値 / 年齢そろえ、ADR-0007）**の切替と独立**に、常に実測値を出す。年齢そろえを選んでいても推移は実測値のままにし、その旨を節の説明に書く。

### 2.3 欠損の見せ方

値が無い年は**棒を描かず、軸ラベルは残す**。「データなし」と分かる形にする。内挿しない。

## 2.5 表

グラフと同じ10年ぶんを**表でも出す**（T2）。グラフは形を、表は値そのものを読ませる。並びは**チャート → 表 → 説明文**——推移で先に見たいのは10年ぶんの形で、増減の1文は図と表の両方を受けた締めとして末尾に置く。年齢別の推定年収（`docs/company/spec.md` 1.14）が表を先に置いているのとは逆になるが、そちらは8点の金額を確かめる読み方が先に来る。

列は4つ。

| 年度 | 平均年収 | 平均年齢 | 基準年比（累積） |
| --- | --- | --- | --- |
| 2017 | 1,234万円 | 36.1歳 | |
| 2018 | 1,543万円 | 36.4歳 | ＋25.0% |
| 2019 | 1,324万円 | 35.8歳 | ＋7.3% |

- 並びは**古い年から新しい年**（グラフと同じ読み向き）
- **平均年齢は平均年収と同じ有報の実測値**（提出会社単体）。書式はページ上部のカードと同じ小数第1位
- **基準年はその会社で最初に値のある年。** 2017年を持たない会社が230社ある（T0 実測）ので、基準年は会社ごとに決まる。列の見出しにその年を書く
- 基準年の行は累積が空
- 値の無い年は「データなし」と出し、**行は落とさない**（AC-7 と同じ扱い）。平均年齢も累積も空にする

**T2 では3列目が前年比だった。T3（親 #826）で平均年齢に置き換えた。** 有報の平均年間給与は会社の平均で、採用・退職で年齢構成が変わるだけでも動く。前年比は動いた幅しか言えないが、平均年齢が隣にあれば、年収の伸びが年齢の上昇と一緒に起きたか（ベースアップとは限らない）を読者が読める。

**累積の比は「その会社の平均年間給与が基準年から何%動いたか」であって、個人の昇給率ではない。** 採用・退職で平均が動くぶんを含む。節の説明にその旨を書く。

## 2.7 在籍年数の推移

「平均年収推移（過去10年間）」と「稼ぐ力の推移（過去10年間）」の間に「**在籍年数推移（過去10年間）**」の節を置く（T4・親 #829。Claude Design `在籍年数推移.dc.html` の 1b）。社員が長く働ける環境に近づいているかを、読者が10年ぶんの値と同業の水準から判断できるようにする。

- 各年の平均勤続年数を**折れ線**で描く。**縦軸は0起点にしない**——在籍年数は10年で数年しか動かず、0から描くと差が潰れる。各点に値を書き、0起点でないことを図の下に断る
- その会社の**業種の中央値を点線**で重ねる（1.3 の `tenureIndustryMedian`）。節の説明で業種名を名乗る
- 最新年の点だけ塗る（平均年収の棒で最新年だけ濃いのと同じ理由）
- 下に**表**（年度 / 在籍年数 / 基準年との差）。差は比ではなく**年**で出す（在籍年数の % は意味が取りにくい）。基準年はその会社で最初に値のある年
- 末尾に**説明文**。1文目は年・社名・値で閉じ、2文目で業種の中央値との差と最初の年からの動きを言う。**決算期は書かない**（企業詳細で決算期を出すのは2か所だけ。`docs/site-chrome/spec.md` 5.1）
- 並びは**チャート → 表 → 説明文**（2.5 と同じ）
- **表示基準の切替と独立**（2.2 と同じ）。1年も値が無い会社では節ごと出さない
- 値の無い年は**線をつながない**。表の行は落とさず「データなし」

**業種の中央値は表の列にしない**（モックの表は 1a と同じ3列）。中央値は図の点線と説明文が持つ。

## 3. 非機能要件

**リクエスト時の計算を増やさない。** `history.json` はサーバー側で当該1社ぶんを引くだけにする。Workers Free の CPU 10ms/リクエスト制約（`docs/company/company-page/design.md`）。

**`/` のペイロードを増やさない。** `app/page.tsx` から `history.json` を import しない。

**再取得は年1回。** 有報の提出が集中する6〜7月に、その年ぶんだけ足す。過去年のキャッシュは再利用する。

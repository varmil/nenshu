# spec.md — 平均年収の10年推移

対象面: user-web（ユーザー画面）… `docs/product/product.md` の面一覧に対応

`docs/timeseries/intent.md` の狙いを、何を作るか（WHAT）と満たすべき条件に落とす。用語は `docs/product/glossary.md` に従う。

## 1. データ（パイプライン）

### 1.1 何を取るか

金融庁 EDINET の有価証券報告書（`docTypeCode=120`）から、**提出会社単体の平均年間給与**を10年ぶん取る。

- 対象期間: 2017年〜2026年の**各暦年に提出されたもの**
- 対象会社: **現行の `ranking_unified_2026.csv` に載る1,867社**（`edinet_code` で絞る）
- 取得形式: CSV形式（`type=5`）。XBRL完全パッケージは使わない（1件73KBに収まるため）

**窓は暦年ぜんぶを見る。** 母集団は2026年の掲載1,867社に固定してあるので、窓を広げても母集団は変わらない——変わるのは「その会社がその年に出した有報を見つけられるか」だけである。6/1〜7/10 に限ると、COVID期の提出期限延長で2020年の96社を取り逃がす（T0 実測）。

### 1.2 名寄せ

**`edinet_code` を主キーにする**（ADR-0006）。証券コードは上場・廃止で変わるが EDINETコードは変わらない。

同じ `(edinet_code, 年)` に複数の書類がある場合（訂正報告など）は、**`docID` が大きいもの＝後に提出されたもの**を採る。

### 1.3 出力

`web/public/data/history.json`。

```
{
  "years": [2017, ..., 2026],
  "byId": { "<企業ID>": [値 or null, ...] }   // years と同じ並び・同じ長さ
}
```

- キーは**企業ID**（証券コード／EDINETコード。ADR-0006）。`companies.json` の `id` と一致させる
- 値は円・整数。**その年の値が無ければ `null`**
- 全年が `null` の会社はキーごと落とす（ペイロードを無駄にしない）

### 1.4 受け入れ基準（データ）

#### AC-1 取得と件数

```gherkin
Given 10年ぶんの書類一覧がキャッシュされている
When 母集団1,867社に絞って有報を取得する
Then 対象は17,000件以上18,000件以下になる
And 取得に失敗した件数が全体の1%未満である
And キャッシュに置いたファイルがすべて実体のあるZIPである
```

#### AC-2 カバー率

```gherkin
Given history.json が生成されている
Then 2026年の値を持つ会社が1,850社以上ある
And 2017年の値を持つ会社が1,600社以上ある
And どの会社も years と同じ長さの配列を持つ
And 隣接する年で1.8倍以上または0.55倍以下に動く組が全体の0.1%未満である
```

#### AC-3 既存データとの一致

```gherkin
Given history.json の2026年の値
Then companies.json の avg_salary と全社で一致する
```

同じ有報から取った同じ数字なので、**ここがずれていたら抽出が壊れている。**

#### AC-4 欠損の表現

```gherkin
Given 2017年に有報を出していない会社
Then その年の値が null になる
And 前後の年から内挿した値が入っていない
```

#### AC-5 ペイロード

```gherkin
Given history.json
Then gzip後のサイズが150KB以下である
And トップページ（/）のHTMLサイズが変わらない
```

`/` は `history.json` を読まない（Issue #22）。

## 2. 表示（企業詳細ページ）

### 2.1 何を出すか

企業詳細ページ `/company/[id]` に「平均年収推移（過去10年間）」の節を置く。

- 各年の平均年間給与を**棒グラフ**で並べる（デザイン: `改善案.dc.html` 4b / 2b）
- 横軸は**報告書の提出年**
- 単位は万円。各年の値を数値でも併記する
- 10年の増減（例「10年で ＋317万円（2017年 1,861万円 → 2026年 2,178万円）」）を文で添える
- **最高値の年**を同じ文に足す（company 施策の C4・Issue #146）。**最新年が最高値の会社では出さない**——増減の文が同じ数字を既に書いており、2度並べることになる（1,852社中1,287社がこれに当たる）

### 2.2 実測値であることの扱い

**推移は補正を通さない実測値のみ**である。表示基準（実測値 / 年齢そろえ、ADR-0007）**の切替と独立**に、常に実測値を出す。年齢そろえを選んでいても推移は実測値のままにし、その旨を節の説明に書く。

### 2.3 欠損の見せ方

値が無い年は**棒を描かず、軸ラベルは残す**。「データなし」と分かる形にする。内挿しない。

### 2.4 受け入れ基準（表示）

#### AC-6 初期表示

```gherkin
Given /company/6861 を開く
Then 「平均年収推移（過去10年間）」の節がある
And 10年ぶんの棒と年のラベルが表示される
And 各年の金額が数値でも読める
And 10年間の増減が文で書かれている
```

#### AC-7 欠損のある会社

```gherkin
Given 2017年の値を持たない会社のページを開く
Then その年の棒が描かれない
And 2017 の軸ラベルは残っている
And 前後の年からつないだ線・棒が無い
```

#### AC-8 表示基準と独立

```gherkin
Given /company/6861 を開いている
When 「年齢そろえ」に切り替える
Then 推移の各年の値が変わらない
And 推移が実測値であることが節の説明に書かれている
```

#### AC-9 出典

```gherkin
Given 推移の節
Then 各年の有価証券報告書に載った実測値であることが明示されている
And 提出会社単体の数字であることが分かる
```

#### AC-10 アクセシビリティ

```gherkin
Given 推移の節
Then 10年ぶんの値が画像ではなく数値として読み上げられる（表、または role と代替テキスト）
```

`SalaryCurveChart` と同じ方針（`docs/company/spec.md` 2.）。**2.5 の表を置いてからは表がこれを担う**——同じ10件を読み上げる経路を2つ置かない。

#### AC-11 モバイル

```gherkin
Given 390px 幅で企業詳細ページを開く
Then 推移のグラフが横スクロールを起こさない
```

## 2.5 表

グラフと同じ10年ぶんを**表でも出す**（T2）。グラフは形を、表は値そのものを読ませる。並びは**チャート → 表 → 説明文**——推移で先に見たいのは10年ぶんの形で、増減の1文は図と表の両方を受けた締めとして末尾に置く。年齢別の推定年収（`docs/company/spec.md` 1.14）が表を先に置いているのとは逆になるが、そちらは8点の金額を確かめる読み方が先に来る。

列は4つ。

| 年度 | 平均年収 | 前年比 | 基準年比（累積） |
| --- | --- | --- | --- |
| 2017 | 1,234万円 | | |
| 2018 | 1,543万円 | ＋25.0% | ＋25.0% |
| 2019 | 1,324万円 | −14.2% | ＋7.3% |

- 並びは**古い年から新しい年**（グラフと同じ読み向き）
- **前年比は直前の年に値があるときだけ出す。** 値の無い年をまたいだ比は「前年比」ではないので出さない（内挿しないのと同じ理由）
- **基準年はその会社で最初に値のある年。** 2017年を持たない会社が230社ある（T0 実測）ので、基準年は会社ごとに決まる。列の見出しにその年を書く
- 基準年の行は前年比も累積も空
- 値の無い年は「データなし」と出し、**行は落とさない**（AC-7 と同じ扱い）

**この比は「その会社の平均年間給与が前年から何%動いたか」であって、個人の昇給率ではない。** 採用・退職で平均が動くぶんを含む。節の説明にその旨を書く。

### 2.6 受け入れ基準（表）

#### AC-12 表の内容

```gherkin
Given /company/6861 を開く
Then 推移の節に10行の表がある
And 各行に年度と平均年収がある
And 2018年の行の前年比が ＋ または − と % で書かれている
And 最初に値のある年の行には前年比も累積も書かれていない
```

#### AC-13 欠損のある会社

```gherkin
Given ある年の値を持たない会社のページを開く
Then その年の行が「データなし」になる
And その次の年の行に前年比が書かれていない
And 累積の基準はその会社で最初に値のある年になる
```

#### AC-14 モバイル

```gherkin
Given 390px 幅で企業詳細ページを開く
Then 推移の表が横スクロールを起こさない
```

## 3. 非機能要件

**リクエスト時の計算を増やさない。** `history.json` はサーバー側で当該1社ぶんを引くだけにする。Workers Free の CPU 10ms/リクエスト制約（`docs/company/company-page/design.md`）。

**`/` のペイロードを増やさない。** `app/page.tsx` から `history.json` を import しない。

**再取得は年1回。** 有報の提出が集中する6〜7月に、その年ぶんだけ足す。過去年のキャッシュは再利用する。

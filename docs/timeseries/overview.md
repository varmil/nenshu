## T0 10年ぶんの平均年収の取得

spec.md の 1.（データ）すべて。EDINET から10年ぶんを取り、`history.json` を出すところまで。

**表示に影響しない Unit である。** 既存のUnitテスト・E2Eが緑のままであることが完了条件の一部になる。

### 事前に確認済みの数値

着手前に実測した（`docs/timeseries/intent.md`「前提の確認」）。

- 書類一覧のキャッシュ: 286日ぶん・9秒
- ダウンロード対象: **17,717件**（全提出者だと29,931件。母集団で絞って40%減）
- 1件あたり約73KB・合計約1.3GB・6並列で約28分

**「約18,000書類のダウンロードが要る」という Issue #54 の見立ては件数としては正しかったが、重さの見積もりは過大だった。** CSV形式（`type=5`）で落とせば30分弱で済む。

### この Unit で決めること

- 2020年のカバー率が低い（1,655社）理由の切り分けと、窓を広げるかの判断
- 10年のあいだの開示タグの揺れの有無
- `history.json` の実サイズ（spec の予算は gzip 150KB）

## T1 企業詳細ページの推移グラフ

spec.md の 2.（表示）すべて。**C2 に同梱したため、この Unit は単独の Issue を持たない**——AC-6〜AC-11 は Issue #83 の完了条件に入れてある。

## T2 推移の表

spec.md の 2.5 と AC-12〜AC-14。**グラフの下に数表を足すだけの Unit で、データは1バイトも増えない**——`history.json` は T0 が出したものをそのまま使い、前年比と累積は描画時に引き算で出す。

年齢別の推定年収が既に「表 → 説明文 → チャート」の順で並んでいる（C3）ので、推移も同じ順に揃える。**AC-10（読み上げ）の担い手が表に移る**ので、グラフが持っていた `sr-only` の一覧は落とす——同じ10件が2つの経路で読み上げられる状態にしない。

## 共有コンポーネント

**棒グラフ。** `features/company/components/` に置く。`SalaryCurveChart`（年齢別の折れ線）と同じく**依存を足さずインライン SVG**で描く（recharts は使わない。`docs/company/company-page/design.md`）。

折れ線と棒で共通化できる部分があるかは C2 の設計時に見た。**共通化していない**——軸の取り方（推移は0起点でよい、年齢別は0起点にしない）が違い、共通化すると軸の設定を引数に出すことになるため。

## 昇格の判断

`features/company/components/` に留める。企業詳細ページにしか無いUIなので `design-system/` には昇格させない。

## 対象外

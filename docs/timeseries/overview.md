## T0 10年ぶんの平均年収の取得

spec.md の 1.（データ）すべて。EDINET から10年ぶんを取り、`history.json` を出すところまで。

**表示に影響しない Unit である。** 既存のUnitテスト・E2Eが緑のままであることが完了条件の一部になる。

### 事前に確認済みの数値

着手前に実測した（`docs/timeseries/intent.md`「前提の確認」）。

- 書類一覧のキャッシュ: 286日ぶん・9秒
- ダウンロード対象: **17,717件**（全提出者だと29,931件。母集団で絞って40%減）
- 1件あたり約73KB・合計約1.3GB・6並列で約28分

**「約18,000書類のダウンロードが要る」という Issue #54 の見立ては件数としては正しかったが、重さの見積もりは過大だった。** CSV形式（`type=5`）で落とせば30分弱で済む。

### この Unit で決めること

- 2020年のカバー率が低い（1,655社）理由の切り分けと、窓を広げるかの判断
- 10年のあいだの開示タグの揺れの有無
- `history.json` の実サイズ（spec の予算は gzip 150KB）

## T2 推移の表

spec.md の 2.5 と AC-12〜AC-14。**グラフの下に数表を足すだけの Unit で、データは1バイトも増えない**——`history.json` は T0 が出したものをそのまま使い、前年比と累積は描画時に引き算で出す。

並びは**チャート → 表 → 説明文**（推移で先に見たいのは10年ぶんの形。年齢別の推定年収も #846 で同じ順にそろえた）。**AC-10（読み上げ）の担い手が表に移る**ので、グラフが持っていた `sr-only` の一覧は落とす——同じ10件が2つの経路で読み上げられる状態にしない。

## T3 推移の表の平均年齢

spec.md の 1.3（`ageById`）・AC-5・AC-12・AC-13・AC-15・AC-16。**表の「前年比」の列を「平均年齢」に置き換える。**

**取り直しは要らない。** T0 の `salary_history.csv` は `avg_age` 列を最初から持っていて（「v1 では表示しない」としていたもの）、平均年収のある 26,865行すべてに値がある。変わるのは `history.json` に出すかどうかと、表の1列だけ。

**前年比を捨てて平均年齢を入れる理由**（親 Issue #826）。有報の平均年間給与は会社の平均で、採用・退職で年齢構成が変わるだけでも動く。前年比は「動いた幅」しか言えないが、平均年齢が隣にあれば、年収の伸びが年齢の上昇と一緒に起きたのか（ベースアップとは限らない）を読者が読める。検索結果の抜粋でも「約1,507万円（平均年齢37.0歳）」の形で年次の値が引かれている。**基準年比（累積）の列は残す。**

## T4 在籍年数の推移

spec.md の 1.3（`tenureById`・`tenureIndustryMedian`）・2.7・AC-5・AC-17〜AC-22。**「平均年収推移」と「稼ぐ力の推移」の間に節を1つ足す**（Claude Design `在籍年数推移.dc.html` の 1b）。

**データは EDINET から取り直す。** T3 の平均年齢と違い、`salary_history.csv` は在籍年数の列を持っていない。ただし抜き出す処理（`edinet.to_record` の `avg_tenure`）は T0 の時点からあり、書き出していなかっただけなので、**抽出を書き足す作業ではない。** 書類のキャッシュ（gitignore）が空のコンテナでは ZIP を落とし直すところから始まる。

**業種の中央値はビルド時に1回出す**（33業種×10年）。リクエスト時には何も数えない。業種は**いまの業種**（`companies.json` の `tse33`）で、その年に値を持つ会社だけで数える。

**描き方は折れ線。棒にしない。** 在籍年数は10年で数年しか動かず、0起点の棒では差が潰れる（1a の検討で、最小の棒でも最大の78%）。縦軸は `SalaryCurveChart` と同じく0起点にせず、各点に値を併記する。

## 共有コンポーネント

**棒グラフ。** `features/company/components/` に置く。`SalaryCurveChart`（年齢別の折れ線）と同じく**依存を足さずインライン SVG**で描く（recharts は使わない。`docs/company/company-page/design.md`）。

折れ線と棒で共通化できる部分があるかは C2 の設計時に見た。**共通化していない**——軸の取り方（推移は0起点でよい、年齢別は0起点にしない）が違い、共通化すると軸の設定を引数に出すことになるため。

## 昇格の判断

`features/company/components/` に留める。企業詳細ページにしか無いUIなので `design-system/` には昇格させない。

**在籍年数の折れ線（T4）は棒グラフと共通化しない。** 0起点にしない・業種の中央値を重ねる、の2点で棒と描き方が違う。年齢別の折れ線（`SalaryCurveChart`）とも共通化していない——あちらは横軸が年齢8点で ±20% の帯を持ち、こちらは横軸が10年で欠損年に線をつながない。

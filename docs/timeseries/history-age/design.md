## データモデル

### `web/public/data/history.json`

```
{
  "years":   [2017, …, 2026],
  "byId":    { "<企業ID>": [円 or null, …] },
  "ageById": { "<企業ID>": [歳 or null, …] }
}
```

- `ageById` のキーと null の位置は `byId` と同じ。**同じ CSV の同じ行から同じループで組む**（`buildHistory`）ので、片方だけの会社や年はできない。ファイルも分けていない——分けると片方だけ古いまま配れてしまう
- **平均年収があって平均年齢が無い行が来たらビルドが落ちる。** 平均年収を捨てると AC-3 の突き合わせが黙って崩れ、空欄で出すと「◯◯万円・空欄」の行が表に出る。いまの CSV には1行も無い
- **値は有報の桁のまま**（`42.49`・`35.17` のような小数第2位が 1,614行）。丸めは描画の `formatDecimal1` で行う。`companies.json` の平均年齢も丸めずに持っているので、**パイプラインで丸めると同じ値を2回丸めることになり、カードと表の片方だけがずれる余地ができる**

### `SalaryHistory`（`web/features/company/types.ts`）

`{ years, values, ages }`。`byBasis` の外に置くのは変わらない——平均年齢も表示基準（実測値／年齢そろえ）と独立で、年齢そろえにしても過去の有報の平均年齢は変わらない。

### `HistoryRow`（`buildHistoryTable` の行）

| フィールド | 意味 |
| --- | --- |
| `year` | 報告書の提出年 |
| `value` | その年の平均年間給与（円）。有報が無ければ `null` |
| `age` | 同じ書類の平均年齢（歳）。**`value` が `null` の年は `null`** |
| `cumulative` | 基準年からの累積。基準年の行と欠損の行は `null` |

**`yoy`（前年比）は落とした。** 画面に出さない値を行に残すと、読む人が「どこで使っているか」を探すことになる。飛び年をまたいだ比を出さない規則（T2）も一緒に消えた。

**基準年は `historyBaseYear` の1か所で求める。** 表の列見出し（`2017年比`）と節の説明（「2017年比は会社の平均が動いた幅で…」）の両方がこれを読む。別々に求めると見出しと説明で違う年を名乗りうる。

## 表の構造

4列（年度 / 平均年収 / 平均年齢 / `<基準年>年比`）×10行。器・罫線・最新年の行の塗りは T2 のまま。

- **平均年齢の文字は薄くしない。** 累積の列は割り算で出した比なので `text-muted-foreground` だが、平均年齢は平均年収と同じ有報の実測値
- **太字にもしない。** 最新年の行で太字になるのは年度と平均年収だけ。平均年収カードと同じく、太字は金額に使う（C14）
- **書式はカードと同じ `formatDecimal1` ＋「歳」。** 最新年の行（3月期でない会社は2025年）とカードは同じ書類の同じ数字なので、同じ文字列になる（AC-16）
- 値の無い年は平均年収の列に「データなし」、平均年齢と累積は空

## 節の説明

```
各年の有価証券報告書に載った平均年間給与と平均年齢の実測値（提出会社単体）。
2017年比は会社の平均が動いた幅で、個人の昇給率ではありません。
```

**前年比の断りは累積の列に付け替えた。** 累積も会社の平均の比で、採用・退職による構成の変化を含むことは前年比と変わらない。平均年齢の読み方（年収の伸びが年齢の上昇と一緒に起きたか）は書いていない——数字が隣に並んでいれば読者が読めるので、仕組みの説明を足さない（C3 の「補正の仕組みの説明はこの会社の数値から導ける事実ではない」と同じ線）。

## 平均年齢の値の点検

2017・2018年は本文の表から拾った値で、平均年収では小数桁の取り方で読みが割れていた。平均年齢を出す前に次を見た。

| 見たこと | 結果 |
| --- | --- |
| 採用書類の行の平均年齢と `companies.json` | **全2,961社で一致** |
| 隣の年との差（本文→本文 / 本文→タグ / タグ→タグ） | 中央値 0.3歳・95%点 1.4 / 1.3 / 1.4歳・99%点 3.0 / 2.5 / 2.9歳。**本文由来の側だけ裾が重い形になっていない** |
| 値の範囲 | 25.4〜60.6歳 |

**小数第2位の値は読み違いではない。** 本文由来の年の小数第2位は700行あり、2つに分かれる。

- **395行は端数が12分の1刻み**（`.08` `.17` `.25` … `.92`。`35.17`・`44.92`）。有報が「35歳2ヶ月」と書いたものを年に直した値で、この書き方の会社は2019年以降のタグが整数（`36.0`）になっていることが多い（タグを持つ194社中154社）。**タグが月を落としているのは会社の書き方**で、ランキングとカードも同じタグの値を出している
- **305行はもともと小数第2位で書く会社**（146社）。うち104社は2019年以降のタグでも小数第2位で書いている

**隣の年と3歳以上動く組が 222組ある。** 見た限り大半は持株会社化で単体の従業員数が桁で変わった年（オープンアップグループ 5,092人→12人・35.7→50.5歳）。平均年収で決めた「浮いて見えるだけでは直さない」（`docs/timeseries/salary-history/design.md`）をそのまま当て、均していない。テストが見るのは帯（20〜70歳）だけにした。

## ペイロード

| | 前 | 後 |
| --- | ---: | ---: |
| `history.json`（gzip） | 99.6KB | **143.1KB** |

**上限は 150KB から 180KB に上げた**（実測の 1.2 倍）。150KB は Worker バンドルに同梱されていた頃の予算で、F1（ADR-0014）以降このファイルは `/company/[id]` をビルド時に生成するときに読まれるだけになっている。**`dist/server` を2017年のキーエンスの平均年収で grep して0件**——Worker バンドルにも入っていない。

`astro build` の成果物を前後で比べた（同じ手順で2回ビルド）。

| ページ | raw 前 → 後 | gzip 前 → 後 |
| --- | ---: | ---: |
| `/company/6861` | 145,877 → 145,800 B（−77） | 21,163 → 21,206 B（+43） |
| `/company/2117` | 144,974 → 144,906 B（−68） | 21,100 → 21,151 B（+51） |
| `/company/9983` | 150,552 → 150,465 B（−87） | 22,961 → 23,003 B（+42） |
| `/company/8058` | 152,097 → 152,024 B（−73） | 22,910 → 22,937 B（+27） |

島の props に平均年齢の10件（約50 B）が増え、表のセルからは前年比の列の `text-muted-foreground` が10個消えた。**`/` は `history.json` を読まないので変わらない。**

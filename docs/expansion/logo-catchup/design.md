# design.md — E3 ロゴの追随（新規社ぶんの調達）

Issue: [#175](https://github.com/varmil/nenshu/issues/175)
spec: `docs/expansion/spec.md` 1.6・AC-8 ／ 手順書: `docs/logo/logo-pipeline/design.md`
ADR: [ADR-0008](../../adr/0008-company-logos.md)

**ロゴを持つ会社が 1,625社 → 2,509社になった**（母集団2,961社の **84.7%**）。**コードで変えたのは定数3つと `meta` の作り方だけ**で、調達の仕組みは触っていない。

---

## 取りに行った先

**2巡した。** 1巡目は「`logos.json` に無い全1,336社」——新規1,094社に加え、**旧母集団で取れなかった242社も混ぜてある**。取得の失敗はキャッシュしないので、走らせ直すたびに回収される（CLAUDE.md）。

| | 対象 | ロゴあり | 増分 |
| --- | ---: | ---: | ---: |
| 開始時 | — | 1,625 | — |
| 1巡目 | 1,336社 | 2,500 | **+875** |
| 2巡目 | 461社 | 2,509 | +9 |

**2巡目で9社しか増えなかったので止めた。** 残り452社の内訳は「公式サイトURLが無い」271社が過半で、**そこは走らせ直しても増えない**（Wikidata にも gBizINFO にもURLが無い会社）。

**`--limit` は使えない。** `pruneOrphans` が対象外の画像を全部消すので、既存1,625枚が消える。既存を残したまま足すのは `--only`。

## 到達率が旧母集団より低い

| | 旧（1,867社） | 新（2,961社） |
| --- | ---: | ---: |
| ロゴあり | 1,625（**87.0%**） | 2,509（**84.7%**） |

**新しく入った会社のほうが取りにくい。** 決算期が3月でない会社には非上場・新規上場が多く、**Wikidata に項目が無い**（2巡目の461社では 271社が「公式サイトURLが無い」）。

出典の内訳は旧母集団と同じ順序のまま。

```
header 1,268 ／ commons 630 ／ icon 409 ／ jsonld 202
```

**「先に取れたものを採る」であって「一番大きいものを採る」ではない**（ADR-0008）。出典の確からしさを解像度より優先する順序（`commons` → `jsonld` → `header` → `icon`）は変えていない。

## `meta.count` が母集団を指していなかった

**`--only` で回すと `count` に前回の値が残る**実装だった。E2（#173）で母集団そのものが 1,867 → 2,961社に変わったので、**到達率が `2500/1867 = 133.9%` と出た。**

```ts
count: previous ? previous.meta.count : targets.length,   // 旧
count: companies.length,                                   // 新（CSV の行数＝母集団）
```

**`missReasons` と `rejectReasons` も前回の値を残していた。** 「母集団ぜんぶを回して初めて意味を持つ数だから」という理由だったが、**E3 のように1,336社を回すと、旧母集団の231件がそのまま残り、実際の欠け（461社）と食い違う。** 今回のぶんを入れ、**`partialOf`（何社を回した内訳か）**を添える形にした。サマリーにも分母が出る。

```
落ちた理由（461社を回したぶん）: { noUrl: 271, fetchFailed: 0, noCandidate: 138, allRejected: 43 }
```

## 引き上げた線

| | 前 | 後 | 根拠 |
| --- | ---: | ---: | --- |
| `EXPECTED_ROW_COUNT` | 1,867 | **2,961** | CSV の行数。直さないと走らない |
| `MAX_TOTAL_BYTES` | 10MB | **18MB** | 実測 **13.09MB**（2,509枚・1枚平均5.3KB） |
| `MIN_WITH_LOGO` | 1,400 | **2,300** | 実測2,509社に対し余裕209社 |

**`MIN_WITH_LOGO` は社数のまま置く。率にしない**——母集団が動いたときに「何社ぶん取れなくなったか」が読めなくなる。

**`MAX_FILE_BYTES`（1枚20KB）は変えていない。** 最大は 18.4KB（`1888.webp`）で、母集団が増えても1枚あたりの大きさは変わらない。

## ペイロード

**`/` にロゴの情報を渡す形は変えていない。** `logos.json`（gzip 60KB超）は渡さず、**`companies.rows` と同じ並びの有無マスク**（`buildLogoMask`）だけを渡す。

| | 前（E2 の後） | 後 | 増分 |
| --- | ---: | ---: | ---: |
| `/`（gzip） | 92,797 B | **93,327 B** | +530 B |
| `/about`（gzip） | 21,070 B | **23,368 B** | +2,298 B |
| `/company/6861`（gzip） | 18,797 B | **19,541 B** | +744 B |

**`/` の +530 B は、マスクの `0` が `1` に変わった875文字ぶん**（文字数は母集団と同じ2,961のまま）。予算100KBに対して **91.1%**。

**`/about` の増分がいちばん大きい。** 帰属表示（`attr: true`）が **44社 → 62社**に増えたため。**パブリックドメインの568社は並べない**（本当に帰属が要るものが埋もれる・ADR-0008）。

## 白いロゴ

**明るい器で空白のマス目になるロゴは落とす**（`blankOnLight`・#156）。2巡で **9件**が候補の段で落ちた（`rejectReasons` の `blankOnLight`）。

**配ってしまったものは判定では消えない**ので、`build-logos.test.ts` が `web/public/logos/` の全画像を毎コミット走査する。2,509枚に増えても通る。

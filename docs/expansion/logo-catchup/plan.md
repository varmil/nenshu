# plan.md — E3 ロゴの追随（新規社ぶんの調達）

Issue: [#175](https://github.com/varmil/nenshu/issues/175)
spec: `docs/expansion/spec.md` 1.6・AC-8 ／ 手順書: `docs/logo/logo-pipeline/design.md`
ADR: [ADR-0008](../../adr/0008-company-logos.md)（ロゴの出典と扱い）

E2（#173）で母集団が 1,867社 → 2,961社になった。**新しく入った1,094社にロゴが1枚も無い**ので、既存の手順（`npm run build:logos`）で調達する。**設計上の判断は無い。**

---

## 段取り

### 1. 取りに行く先を「まだ持っていない会社」に限る

**`--limit` を使わない。** `pruneOrphans` が対象外の画像を全部消すので、既存1,625枚が消える。既存を残したまま足すのは `--only`。

対象は**「`logos.json` に無い全社」**で、新規1,094社だけではない。**取得の失敗はキャッシュしないので、走らせ直すたびに数十社ぶん回収される**（CLAUDE.md・Issue）——旧母集団で取れなかった242社もここに含める。

### 2. 母集団に合わせた線を引き直す

`build-logos.ts` が持つガードは3つあり、**どれも母集団に比例する**。

| | 何を見ている | 母集団が1.59倍になると |
| --- | --- | --- |
| `EXPECTED_ROW_COUNT` | CSV の行数 | 必ず落ちる。先に直す |
| `MAX_TOTAL_BYTES` | `public/logos/` の合計 | 実測8.8MBが14MB程度になる見込み |
| `MIN_WITH_LOGO` | ロゴを持つ社数 | **率ではなく社数で置く**——率にすると母集団が動いたとき「何社ぶん取れなくなったか」が読めない |

**上限は「気づくための線」であって守るべき値ではない。** 実測に合わせて引き上げ、根拠を書く。

### 3. 走らせて、到達率を見る

**1回で終わらせようとしない**（Issue）。429 と一時的な失敗は毎回数十社ぶん残るので、率が伸びなくなるまで繰り返す。

### 4. 取れたものを検める

**明るい器で空白のマス目になる白いロゴが混ざっていないこと**（`blankOnLight`・#156）。**配ってしまったものは判定では消えない**ので、`build-logos.test.ts` が `web/public/logos/` の全画像を毎コミット走査する——ここが新しい画像で落ちないことを見る。

**`/about` の帰属表示**（`attr: true` の会社）が新しい母集団で正しいこと。パブリックドメインの会社は並べない。

### 5. `/` のペイロードが増えていないことを確かめる

**`logos.json` を丸ごと渡していない**（gzip 41.5KB）。渡すのは**ロゴの有無だけ**——`companies.rows` と同じ並びの文字列マスク（`buildLogoMask`）で、2,961文字ぶんが gzip 約250B に畳まれる。**ここが崩れると `/` の予算（余白7.6KB）を一撃で使い切る。**

### 6. 検証

1. **Unit テスト** — `build-logos.test.ts`（全画像の走査）・マスクのテスト
2. **`npm run build:data`** — サマリーのロゴの充足率が上がっていること（AC-8）
3. **型・lint・ビルド**
4. **ペイロードの実測** — `/` の gzip が増えていないこと
5. **E2E** — ロゴを持つ会社／持たない会社の出し分け。**`logo.spec.ts` の `WITHOUT_LOGO` は検索で絞ってある**ので、その会社にロゴが付いたら別の会社に差し替える
6. **ブラウザで触る** — 新しく入った会社のロゴが表・カード・企業詳細で出ること

### 7. docs を書く

`design.md` に到達率・出典の内訳・落ちた理由の内訳を残す。CLAUDE.md の「現在地」を実態に合わせる。

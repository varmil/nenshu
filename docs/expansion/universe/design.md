# design.md — E2 母集団の拡大（取得の窓を直近12か月に）

Issue: [#173](https://github.com/varmil/nenshu/issues/173)
spec: `docs/expansion/spec.md` 1.1〜1.3・1.5b・1.6a・1.6b
ADR: [ADR-0011](../../adr/0011-company-universe-twelve-month-window.md)・[ADR-0006](../../adr/0006-public-url-strategy.md)・[ADR-0012](../../adr/0012-prerender-company-pages.md)

掲載が **1,867社 → 2,961社**（+1,094社）になった。**それまで載っていた1,867社は、1社も落ちず、金額も採用書類も1つも変わっていない。**

---

## 母集団の組み立て

```
EDINET 書類一覧（窓の中の平日261日）
  └ docTypeCode=120 かつ withdrawalStatus≠1        10,657件
      └ EDINETコードで1社1件に寄せる（期末の新しいほう）  4,529社   edinet.annual_reports
          └ 提出者種別が「内国法人・組合」            4,133社   run.build
              └ 有報CSVから平均年間給与・平均年齢を取る
                  └ 読み方が割れた金額を解決／落とす           unified.resolve_ambiguous_salary
                      └ 平均年齢20〜65歳・平均年間給与100万円超  4,008社
                          └ 単体従業員100人以上         2,961社   ← 掲載
```

**この形にする前は、経路が証券コードの有無で2つに割れていた。** 上場側（`edinet.annual_reports`）は証券コードをキーに、非上場側（`run.unlisted_docs`）は EDINETコードをキーに寄せており、**どちらも「後に見つかったものが勝つ」**だった。非上場側は窓すら持たず、キャッシュ済みの `list_*.json` を全部走査していた（10年推移のために10年ぶん温めてあるので、**母集団がキャッシュの広さで変わる**状態だった）。**`unlisted_docs()` は消した。**

### 寄せ方は「期末が新しいほう、同じなら docID が大きいほう」

`edinet.doc_rank` の1か所。**走査順に依存する寄せ方は、窓を広げると会社を落とす。**

| | 窓の中の有報 | 「後勝ち」で残るもの |
| --- | ---: | --- |
| りそな銀行 | 4件 | 従業員の状況を持たない書類 → **母集団から消える** |
| 三井住友信託銀行 | 4件 | 同上 |

**この2社は、期末で選び直す前は実際に消えていた**（着手前の調査で実測）。いまはどちらも残っている。

**キーは EDINETコード**（ADR-0006 と同じ理由）。証券コードは非上場の会社に無く、上場廃止で外れる。掲載2,961社のうち **142社が証券コードを持たない**。

### 窓は回す日から遡って12か月

`run.twelve_month_window()`。**日付を直書きしない。** 今回作ったデータの窓は **2025-08-25 〜 2026-08-25**（両端を含む）で、値は `pipeline/data/universe.json` に残る。

両端を含むので厳密には366日あり、**窓の両端に同じ会社の2年ぶんが入りうる**。それは期末優先が受け止める。

## 読み方が割れた平均年間給与

「従業員の状況」本文の区切りの無いセルは、`231(13)57.309.822,360,598` が「勤続9.8／2,236万円」とも「勤続9.82／236万円」とも読める。**1書類の中では決められない**（同型の並びで正解が逆になる例が実在する。`textblock._best`）。**窓を広げると、この読み違いが実測値の3位に出た**（株式会社山田クラブ２１・E04731・非上場・従業員231人・平均年齢57.3歳）。

`unified.resolve_ambiguous_salary` が**2段で絞る**。

1. **帯** — 候補は10倍違うので、片方だけが「平均年間給与としてあり得る帯」に入ることが多い。判定は `run.plausible_salary_range`＝**桁ズレ補正（`fix_salary_typos`）が使うのと同じ線**
2. **年をまたぐ基準** — 帯で決まらなければ、`history.resolve_candidates` と同じ規則で「その会社の他の年に近いほう」を採る。基準は10年推移（`salary_history.csv`）の中央値
3. **どちらでも決まらなければ落とす**

**実測: 候補が割れた11社のうち7社が帯で決まり、4社が落ちた。** 山田クラブ２１は2,236万も236万も帯の中で、10年推移にも1行も無いので落ちる。

**この順序は入れ替えられない。** `fix_salary_typos` は帯の外の値を10の冪で帯に戻すので、先に当てると**候補のどれとも一致しない値**になる。

**textblock 由来を経路ごと切ってはいけない**（spec 1.5b）。同じ経路で入る会社が上位にいる。

```
サントリーホールディングス  1,176万円   候補 [1,176万, 176万] → 帯で決まる
株式会社竹中工務店         1,153万円   候補 [1,153万, 153万] → 帯で決まる
株式会社日本経済新聞社     1,224万円   候補は1つ
```

## 母集団の内訳をどこに置くか

**CSV の行からは出せないものが2つある**——取得の窓（行に残らない）と、掲載条件で落とした社数（そもそも行にならない）。`pipeline/data/universe.json` に置き、`build-data.ts` が `companies.meta` に写す。

```json
{
  "filingWindow": { "from": "2025-08-25", "to": "2026-08-25" },
  "fetched": 4133, "resolvedSalary": 7, "ambiguousSalary": 4,
  "eligible": 4008, "minEmployees": 100,
  "excludedByEmployees": 1047, "published": 2961
}
```

`meta.filingWindow` と `meta.excluded` になる。**社数（`meta.count`）・決算期（`meta.fiscalPeriodRange`）と同じ扱いで、画面には直書きしない。**

**`/about` の「対象範囲」が変わる。**

```
単体従業員100人以上（数人しかいない持株会社が上位を埋めるのを避けるため）。この線で1,047社を省いています
```

**条件そのものは以前から書いてあったが、それが何社を落としているかは書いていなかった**（運営者の指示・2026-08-24）。1,047社は掲載2,961社の3分の1超で、**数が無いと「有報を出している会社は全部載っている」と読めてしまう。**

`filingWindowLabel` も定数から `meta.filingWindow` に変えた。**窓が動くようになった以上、`2026年6月1日〜7月10日` は次にデータを作り直した瞬間に嘘になる。**

## 派生データの充足率をビルドのサマリーに出す

```
companies.json:      2961行, gzip 71.6KB, 決算期 2025-03〜2026-05（14種類）
history.json:        1867/2961社（63.1%） × 10年, gzip 65.6KB
worklife.json:       1548/2961社（52.3%）,      gzip 128.1KB
performance.json:    1865/2961社（63.0%）,      gzip 8.2KB
radar.json:      4軸 × 2961/2961社（100.0%）,   gzip 14.3KB
profit-history.json: 1867/2961社（63.1%） × 10年, gzip 187.0KB
logos.json（build:logos）: 1625/2961社（54.9%）
```

**新しく入った会社だけ中身が空になる状態を、気づけないまま公開しない**（spec 1.6・AC-8）。画面は壊れない（どれも「掲載なし」の表示を持つ）ので、**数を出さないと気づけない**。追随は E3〜E6。

**ロゴは `build:data` の生成物ではない**（`build:logos` が作る）が、AC-8 が名指しする4つのうちの1つなので同じサマリーに並べる。無い環境では黙って飛ばす。

**`radar.json` が 100% なのは欠測の持ち方が違うから。** あちらは全社ぶんの行を持ち、**軸ごとに欠測を表す**（`docs/performance/company-radar/design.md`）。新しく入った会社は有給・残業・稼ぐ力の3軸が欠測になり、平均年収と定着の2点だけで多角形を閉じる。

## 生成物とペイロード

**gzip の上限に当たったものは無い**（AC-9）。母集団が1.59倍になっても超えなかったのは、**追随していない4つのファイルは行数が増えていない**ため。E4・E5・E6 で追随したときに当たる（spec 1.6a の見込み）。

| | 前 | 後 | 上限 |
| --- | ---: | ---: | ---: |
| `companies.json` | 44.6KB | **71.6KB** | 102.4KB |
| `stats.json`（`/` には渡さない） | — | — | — |

**`/` の HTML は gzip 63,856 B → 92,797 B**（`next start` に対する実測。予算100KBの **90.6%**）。spec 1.5 の見込み（90,724 B）より +2KB で、差は E1 の会社ごとの決算期ぶん。

| | raw | gzip |
| --- | ---: | ---: |
| `/` | 465,600 B | **92,797 B** |
| `/about` | 86,305 B | 21,070 B |
| `/company/6861` | 135,686 B | 18,797 B |
| `/company/8058` | 140,747 B | 20,171 B |

**余白は 7.6KB しか残らない。** 1行あたりの情報を増やす変更がそのまま予算にぶつかる（E0・ADR-0013）。

## 事前生成

`generateStaticParams` は `companies.json` から引く（ADR-0012）ので**追随は自動**。`next build` で **2,967ページを26.4秒**（前は 1,874ページ・19.9秒）。`dynamicParams = false` なので一覧に無いIDは 404 になるが、新しく入った会社は一覧に入っているので開く（キヤノン `/company/7751`・JT `/company/2914`・楽天 `/company/4755`・サントリーHD `/company/E22559` を実測）。

デプロイの成果物は ADR-0012 の実測値を更新した。

## テストで固定したもの

**AC-2〜AC-4 は目視で一度確かめて終わりにしない。**

- **AC-2** — EDINETコードが一意・りそな銀行と三井住友信託銀行が残る・その行が従業員の状況を持つ
- **AC-3** — 全行が内国法人・組合
- **AC-4** — 旧1,867社が全部残る／全行が掲載条件を満たす

**10年推移の突き合わせ（`build-data.test.ts` の AC-3）は「全社ぶん揃っている」から「推移を持つ会社ぶん（1,867社）」に変えた。** 数で固定するのは、**E4 で追随したことをテストの側でも見えるようにするため**（`toBeGreaterThan` にすると追随しても何も動かない）。

**近傍の会社のテストは社数を書き写さない。** 「10社に満たない業種」は母集団に依存する（前は空運業5社、いまは6社）ので、`rows.length` から引いて比べる。

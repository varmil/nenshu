# design.md — E5 働きやすさ指標の再突合

Issue: [#177](https://github.com/varmil/nenshu/issues/177)
spec: `docs/expansion/spec.md` 1.6・1.6a・AC-8 ／ 手順書: `docs/worklife/data-ingest/design.md`
ADR: [ADR-0009](../../adr/0009-worklife-corporate-number.md)

**働きやすさ指標を持つ会社が 1,548社 → 2,369社になった**（母集団2,961社の **80.0%**）。**コードで変えたのは定数2つだけ**で、突合の仕組みは触っていない。

---

## 突合の結果

| | 前（1,867社） | 後（2,961社） |
| --- | ---: | ---: |
| 法人番号で突合 | 1,690（**90.5%**） | 2,641（**89.2%**） |
| うち3指標のいずれかを持つ | 1,548 | **2,369** |
| 女性活躍DB側の行数 | 64,879 | 64,963 |

**突合率は 90.5% → 89.2% とほぼ変わらない。** 法人番号は EDINETコードリストから全社ぶん引けており（引けない会社は0件）、**新しく入った会社でも同じように当たる。**

指標ごとの記入率は下がった。

| | 突合比 | 全社比 |
| --- | ---: | ---: |
| 平均残業時間 | 1,534社（58.1%） | 51.8% |
| 年次有給休暇の取得率 | 1,487社（56.3%） | 50.2% |
| 男女の賃金の差異 | 2,235社（84.6%） | 75.5% |
| 賃金の差異の注釈 | 1,057社（40.0%） | 35.7% |

**掲載は任意なので、新しく入った会社ほど記入していない。** 女性活躍DBへの登録も記入も企業の自己申告で、非上場・新規上場の会社は登録自体が無いことが多い。

**落とした異常値は前回と同じ1社2箇所**（ビジネスエンジニアリングの残業 `-16.8`）。負の残業時間は全体値と区分別の両方に入っている。

## ZIP の入手

**ダウンロードURLに UUID が入っていて固定できない**ので取得は自動化していない（`extract.ts` の注記）。今回は厚労省のオープンデータページから落とした。

```
https://positive-ryouritsu.mhlw.go.jp/positivedb/opendata/download_b.html?w=99
```

**`w=99` が全件版**（ファイル名の `99_` と対応する）。**curl の既定 User-Agent では 403 が返る**（AWS ELB が弾く）ので、通常のブラウザの UA を名乗る必要がある。

**取れたのは 20260825 版で、W0 で使った 20260820 版とは別物。** オープンデータは日々更新されるので、**どの版で作ったデータかは `manifest.json` の sha256 が示す。**

```json
{
  "file": "99_20260825_utf8_bom.zip",
  "sha256": "5a18c442cfef80d15d26dc8b07c30ed7df3657e035963e6fae187ddbdedc9cbf",
  "sourceRows": 64963, "matched": 2641, "written": 2369
}
```

**236列の検証（`assertHeader`）が通った**ので、厚労省は列を足していない。**ここが止まったら添字がずれている**——別の指標を残業時間として公開することになるので、通ったこと自体が結果になる。

## 上限を引き上げた（切り出さなかった）

`worklife.json` が gzip **186.2KB** になり、上限160KBを超えた。

**`docs/worklife/overview.md` は「超えたら注釈を切り出す」と書いているが、その発動条件はこのファイル単体の大きさではない。** W0 の実測はこう書いている——「増分152.5 KiB の6割が注釈・説明（gzip 93KB）で、**バンドルが苦しくなったら**ここが最初の切り出し候補になる」。

**だから Worker バンドルを実測した。**

| | E2 の後 | E5 の後 | 無料枠の上限 |
| --- | ---: | ---: | ---: |
| Worker（gzip） | 1.85MB（61.7%） | **2.089MB（66.4%）** | 3MiB |

**余裕が1MB以上あるので同梱のままでよい。** 上限は気づくための線として **220KB** に置き直した（実測186.2KBに対して余裕34KB）。

**切り出しは手札として残る。** E4（10年推移）と E6（稼ぐ力）が追随すると `history.json` と `profit-history.json` も1.59倍になり、バンドルは 2.2MB 台に届く見込み。**そこでもまだ上限には遠いが、次に何かを足すときはこの数字を見てから決める。**

**`worklife.json` は `/company/[id]` だけが読む。** `/` のペイロードには効かない（`app/page.tsx` から import しない）。企業詳細は事前生成なので（ADR-0012）、リクエスト時のコストにもならない。

## 動いた数

**レーダーの母集団が変わった**（`radar.json`）。有給と残業は「全体値か、区分がちょうど1つの会社」だけが軸に乗る（代表を選ばないため・P1）。

| | 前 | 後 | 母集団比 |
| --- | ---: | ---: | ---: |
| 有給 | 895 | **1,266** | 42.8% |
| 残業 | 974 | **1,420** | 48.0% |

**「6割前後しか公表がない」と書いていたテストを実測に直した。** 母集団を広げると公表率は下がる——4〜5割になる。

`radar.json` は gzip 14.3KB → **15.7KB**（上限48KB）。

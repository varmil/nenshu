# intent.md — 掲載企業数の拡大

親 Issue: [#22](https://github.com/varmil/nenshu/issues/22)

## 狙い

**有価証券報告書を出している会社なら、OpenReport で引ける状態にする。**

いま載っているのは 1,867社で、これは「2026年6月1日〜7月10日に EDINET へ提出された有報」から作った集合になる（`docs/product/product.md`「データの前提」・`/about`「対象範囲」）。窓が有報提出のピークに貼り付いているため、**3月期決算の会社しか入っていない**（1,865社が3月期・2社が4月期）。

直近12か月（2025-08-25〜2026-08-24）に有報を出した内国法人は **4,132社**ある。窓の外にいるために載っていない会社に、次のような名前が並ぶ。

**すべてが載るわけではない。** 日本マクドナルドホールディングスは12月期で窓の外だが、**単体従業員が2人**（有報の実測値）なので、窓を広げても `MIN_EMPLOYEES = 100` で落ちる。それは意図した挙動になる。

**これは「まだ足せていない会社がある」ではなく、「決算期という読者に関係のない属性で会社が消えている」状態になる。** 転職検討者がキヤノンを探して0件を見たとき、そこにあるのは「キヤノンは有報を出していない」でも「まだ集めていない」でもなく、**サイトの取得の窓が3月期に貼り付いている**という、読者からは見えない理由になる。

## North Star KPI

ranking 施策と同じ **自然検索からの月間セッション数**（`docs/ranking/intent.md`）。

母集団を広げることは、この KPI に対して**インデックス可能なページ数を増やす**という形で効く。いま `/company/[id]` は1,867件で、sitemap に載る URL 全体（1,910件）のほとんどを占めている（ADR-0006・U8）。**実測で掲載は2,962社になる**（下の「先に測ったこと」）ので企業ページは **1.59倍**になり、「会社名 年収」で検索したときに当たる面がそのぶん増える。

社名の指名検索は、年齢別・業種別のクエリより意図が強い。**いま欠けているのが JT・キヤノン・楽天・花王のような指名検索の的そのもの**である以上、ここは伸びしろの中でも取りやすい側にある。

## 仮説

**H1.** 欠けているのは「知られていない会社」ではなく「決算期が3月でない会社」である。母集団を広げると、指名検索の当たる面が社数の比（1.59倍）以上に増える。

*検証*: 追加後3か月の Search Console で、追加分の企業ページへの自然検索流入が、既存の企業ページ1件あたりの流入と比べて同等以上であること。

**H2.** 全件をHTMLに埋める方式（`docs/ranking/ranking-pagination/design.md`）は、母集団を広げる際の制約になる。

*検証*: 拡大後の母集団で `/` の初回ロードを実測し、`docs/ranking/spec.md` 3.「gzip 後 100KB 以内」に収まるかを見る。**この検証はこの intent の中で先に済ませた。結果は「収まる」で、H2 は支持されなかった**（下の「先に測ったこと」）。

## 先に測ったこと

**窓の広さ**（EDINET API の書類一覧・直近12か月・平日261日ぶん）。

| | 件数 |
| --- | ---: |
| 有報（`docTypeCode=120`・取下げ除く）の提出件数 | 10,657件 |
| EDINETコードでユニークにした社数 | 4,528社 |
| うち内国法人・組合 | **4,132社** |
| うち現行CSVに載っている | 1,867社 |
| 窓を広げて新たに現れる会社（フィルタ前） | 2,265社 |

**内国法人にかぎった理由。** 窓の中には外国法人・組合が200社、外国政府等が28社いる。転職先ではないので現行の `unlisted_docs()` と同じ線で落とす（`pipeline/salary/run.py`）。

**掲載条件を通したあとの社数。** 4,132社ぶんの有報CSVを実際に落として、いまと同じフィルタに通した。

| 段階 | 社数 |
| --- | ---: |
| 窓の中の内国法人 | 4,132 |
| 平均年間給与が取れた | 4,014 |
| 平均年齢20〜65歳・平均年間給与100万円超 | 4,011 |
| **単体従業員100人以上（`MIN_EMPLOYEES`）** | **2,962** |

**親 Issue の見立て（4,000社以上）は、有報の提出社数としては当たっていて、掲載社数としては外れる。** 1,049社が単体従業員100人未満で落ちる（数人しかいない持株会社・REIT・小型株）。**この線は緩めない**（下の「作らないもの」）。

掲載は **1,867社 → 2,962社（+1,095社・1.59倍）** になる。**いま載っている1,867社は1社も落ちない**（実測）。上場2,800・非上場162で、「本社のみ」バッジは173社から244社になる。

決算期（`YYYY-MM`）の内訳は次のとおり。

```
2026-03 1,881   2025-12 388   2026-02 162   2025-09 120   2025-06 107   2025-08  63
2025-11    44   2025-10  42   2026-01  40   2025-05  37   2026-04  33   2025-07  28
2026-05    16   2025-03   1                                          （合計 2,962）
```

**最頻の 2026-03 は 1,881/2,962 = 63.5%** で、`build-data.ts` の `dominantFiscalPeriod()`（過半に届かなければ落とす）は**通ってしまう**——1,081社の決算期が違うのに「2026年3月期」と名乗ることになる。

**`2025-03` の1社は、提出が1年遅れているニデック**（6594）。直近12か月の窓に入っているのが前の期の有報だけ、という会社が実在する。

**初回ロードのペイロード（実測）。** 拡大後のCSVで `npm run build:data` と `npm run build` を回し、`next start` に対して測った。**基準は `a859567`。**

| | 1,867社 | 2,962社 |
| --- | ---: | ---: |
| `/` の HTML（gzip） | 63,654 B | **90,724 B** |
| `/` の HTML（raw） | 373,821 B | 456,338 B |
| `companies.json`（gzip -9） | 44,631 B | 70,610 B |
| `stats.json`（gzip -9） | 39,922 B | 68,515 B |
| `/company/[id]`（gzip・キーエンス） | 14,610 B | 14,663 B |

**`docs/ranking/spec.md` 3. の予算（gzip 後 100KB）には収まる。** 親 Issue のコメントが見込んでいた137KB超過は、**社数を4,000で見積もったことと、比例で伸ばしたことの2つで外れていた**（gzip は行数に比例しない）。ただし**予算の90.7%まで使う**ので、1行あたりの情報をこれ以上増やす余地はほとんど残らない。

**新しく入った会社のページは実際に出る**（キヤノン `/company/7751` が gzip 13,687 B で描画された）。

**ランキングの1位が入れ替わる。** 拡大後の上位は次のようになる。

```
1 ヒューリック株式会社                    2,295万円  12月期  本社のみ（単体234人 / 連結3,495人）
2 Ｍ＆Ａキャピタルパートナーズ株式会社     2,266万円   9月期
3 株式会社山田クラブ２１                  2,236万円  12月期  非上場・textblock 由来（下記）
4 株式会社キーエンス                      2,178万円   3月期
```

`docs/ranking/spec.md` の AC-1 は**「1位に株式会社キーエンスが2,178万円で表示される」を受け入れ基準として書いており、E2E もそれを固定している**。母集団を変えるとここが落ちる。**落ちるのが正しい**——1位が変わるほどの入れ替えを、テストが通ったまま入れられるほうがまずい。

**textblock 由来の読み違いが1件、3位に来る。** 株式会社山田クラブ２１（E04731・ゴルフ場運営・非上場）の「従業員の状況」は `231(13)57.309.822,360,598` と続いており、**「勤続9.8／2,236万円」とも「勤続9.82／236万円」とも読める**。パーサは候補を2つ返したうえで大きいほうを採っている（CLAUDE.md の既知の問題そのもの）。

いまの1,867社では textblock 由来103社の最高が1,206万円で、この割れが上位に出ていなかった。**拡大後は139社になり、そのうち1社が3位に来る。** 年をまたいで選び直す仕組み（`history.resolve_candidates`）はタグ由来の値を基準にするが、この会社はどの年もタグを持たないので効かない。

**同じ拡大で、非上場の大手が正しく入る。** サントリーホールディングス・日本経済新聞社・竹中工務店はいずれも textblock 由来で、値は妥当な範囲にある。**textblock を切り捨てる話ではない。**

## 外資系日本法人について（親 Issue の2つ目の問い）

**Google・Meta・Microsoft の日本法人の平均年収を、公式情報から出す手段は無い。**

EDINETコードリスト（11,385社）を実際に引くと、これらの名前で登録があるのは**外国の親会社**だけで、いずれも有報の提出義務者ではない。

```
グーグル・インターナショナル・エルエルシー   外国法人・組合（有価証券報告書等の提出義務者以外）
マイクロソフトコーポレーション               外国法人・組合（非上場）
アマゾン・ドット・コム・インク               外国法人・組合（非上場）
セールスフォース・インク                     外国法人・組合（有価証券報告書等の提出義務者以外）
ゴールドマン・サックス証券株式会社           内国法人・組合（有価証券報告書等の提出義務者以外）
アクセンチュア株式会社                       内国法人・組合（有価証券報告書等の提出義務者以外）
```

「提出義務者以外」は、大量保有報告書や公開買付届出書のために EDINET に登録されているだけで、**有報を出さない**＝平均年間給与が存在しない。フェイスブック／メタの日本法人にいたっては登録自体が無い。

有報以外に当たれる公式情報も無い。

- **決算公告（会社法440条）** — 株式会社に課される義務で、合同会社（グーグル合同会社など）は対象外。出るのも貸借対照表（大会社は損益計算書まで）で、**給与総額も平均年収も含まれない**
- **法人番号公表サイト（国税庁）** — 商号・所在地・法人番号だけ
- **女性の活躍推進企業データベース（worklife 施策で取り込み済み）** — 男女の賃金の**差異（％）**であって水準ではない。金額は入っていない
- **賃金構造基本統計調査** — 産業・規模別の集計で、会社単位ではない（`pipeline/salary/fetch_estat.py` で既に使っている）
- **口コミサイト（OpenWork・OpenMoney）** — 自己申告であり、そもそも取得はアクセス制御の回避になるので作らないと決めてある（ADR-0008 決定1）

**したがって、この施策の対象は「有報を出している会社」に閉じる。** 外資系日本法人のうち日本で上場して有報を出している会社（日本オラクル・コカ・コーラボトラーズジャパン等）は、窓を広げれば自動的に入る——**上の表のとおり、そのほとんどが「窓の外にいるから載っていない」だけである。**

## 作らないもの

**有報以外を出典にした平均年収。** 上のとおり公式情報が無い。推定値を出典なしで並べることは、この施策の前提（`docs/product/product.md`「数値の出典と計算方法は必ずユーザーから見える場所に置く」）と両立しない。

**単体従業員100人未満の会社の掲載。** いまの `MIN_EMPLOYEES = 100` は「数人しかいない持株会社が上位を埋めるとランキングとして読めなくなる」ための線で、母集団を広げる話とは独立している。**この線は動かさない。**

**掲載社数を目標値にすること。** 「4,000社」は窓を広げた結果として出る数であって、目標ではない。フィルタを緩めて社数を作りにいくと、載っている数字の意味が薄まる。

## 既知の限界

**決算期が1つに代表できなくなる。** いまサイトは「2026年3月期」を1つの時点として全ページに出している（S3・Issue #134）。母集団を広げると3月期は 63.5% になり、`dominantFiscalPeriod()` の「過半に届かなければ落とす」は**通ってしまう**——1,081社の決算期が違うまま「2026年3月期」と名乗る。**代表を過半で名乗ることと、決算期の違う会社を同じ表に並べることは別の問題で、後者は既にいまも起きている**（3月期と4月期）。ただし12月期を含めると15か月ずれる会社が同じ表に並ぶ。

**派生データが母集団に追随する。** ロゴ（`logo` 施策）・10年推移（`timeseries` 施策）・働きやすさ指標（`worklife` 施策）はすべて母集団を単位に作ってある。母集団を広げた直後は、**新しく入った会社だけロゴも推移も無い状態**になる。

**取得のコストが上がる。** 有報CSVの取得は 4,132件で36分（並列3・実測。書類一覧261日ぶんは別に2分）。10年推移は母集団×10年なので、1,095社ぶんを足すと約1万件の追加取得になる。年1回の更新でこれが走る。

**初回ロードの余白がほとんど無くなる。** `/` の HTML は gzip 90,724 B で、予算（100KB）の 90.7% を使う。**1行あたりの情報を増やす変更が、そのまま予算にぶつかる。**

**デプロイの成果物が母集団に比例して増える。** `/company/[id]` は全社ぶんが事前生成されており（ADR-0012・R1）、現状で 1,874ページ・**344MB**・ファイル数 3,528。無料枠の上限はファイル数 20,000・1ファイル 25MiB。**2,969ページなら 545MB・約4,600ファイルの見込み**（比例。上限には当たらない）で、事前生成は 19.9秒 → 32秒ぶんになる。

**動的なまま残る `/` では、モジュールの初期化が同じ比で増える。** `import` したデータファイルは画面が1バイトしか使わなくても丸ごと `JSON.parse` され、isolate の初回リクエストに課金される（`companies.json` gzip 44,631 B → 70,610 B、`stats.json` 39,922 B → 68,515 B・実測）。**`/` は `searchParams` を読むので事前生成できない**（ADR-0012 決定4）。

**textblock 由来の読み違いが上位に出る。** 上の実測のとおり1件（山田クラブ２１）。**母集団を広げると、読み方の割れが「どこかにある」から「上位3位に見える」に変わる。**

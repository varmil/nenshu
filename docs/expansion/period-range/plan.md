# plan.md — E1 決算期を幅で出す

Issue: [#172](https://github.com/varmil/nenshu/issues/172)
spec: `docs/expansion/spec.md` 1.4・AC-7 ／ 改訂する spec: `docs/site-chrome/spec.md` 5.
ADR: [ADR-0011](../../adr/0011-company-universe-twelve-month-window.md)（母集団を直近12か月にする）

データの時点の出し方を「最頻の決算期を1つ代表として名乗る」から「幅で出す」に変える。**母集団の拡大（E2・#173）より先に入れる。**

---

## 段取り

### 1. 先に測る

**会社ごとの決算期を持たせるとトップページのペイロードがいくら増えるかを、実装を決める前に測る。** 増分しだいで持たせ方が変わる（`companies` に足すか、企業詳細だけが読むものに足すか）。決算期は現状2種類・拡大後14種類しかないので、値そのものではなく添字で持てば小さいはずだが、**はず**で進めない。

現状の `/` の HTML は gzip 63,654 B（予算100KB）。測り方は `next start` に対して `curl -H 'Accept-Encoding: gzip'`。

### 2. 幅の端をデータから出す

`companies.meta` が持つ時点を、1つの代表から**最古と最新の組**に変える。

**代表が過半に届かなければ落とす、というガードが無くなる。** 代わりのガードを置く——「1年ぶんの有報から作った」という前提が壊れたことに気づける形にする。壊れたまま公開されるより、ビルドで止まるほうがよい。

**会社ごとの決算期も同時に出せるようにする。** 企業詳細は1社ぶんなので幅ではなく実際の決算期を出す。

### 3. 文字列を作る場所は1か所のまま

`web/lib/data/period.ts` が唯一の場所であることを変えない（S3 の決定）。幅の文字列と、会社ごとの決算期の文字列の両方をここから出す。

**「年度」と書かない・直書きしない**（S3 の決定）もそのまま持ち越す。

### 4. 画面とメタデータを差し替える

決算期が出ている場所は5つある。**母集団の話は幅に、1社の話はその会社の決算期に**分ける。

| どこ | 何に変える |
| --- | --- |
| `/` の title 末尾 | 幅（運営者の判断・2026-08-25） |
| 全ページの description | 幅 |
| `/` の画面（リード文） | 幅 |
| `/company/[id]` の見出し | **その会社の決算期** |
| `/about`「対象範囲」 | 幅＋分布の断り |

**1画面に1回**（S3 の決定）を守る。増やさない。

### 5. `/about` の分布の断りを書き直す

いまは「決算期は3月期が中心で、4月期の会社も含みます」。**幅を出すようになると、端（現状は4月期の2社）が全体を代表しているように読めてしまう**ので、どのくらい偏っているかをここで断る。数字はデータから引く。

### 6. site-chrome の spec を改訂する

`docs/site-chrome/spec.md` 5.3 と AC-17〜AC-20 が「最頻の決算期を代表として出す」を前提に書かれている。**この Unit で覆すので、あちらを直す。** 覆さない決定（「年度」と書かない・直書きしない・1画面に1回）はそのまま残す。

### 7. 検証

順に確かめる。**前を確かめずに次へ進まない。**

1. **Unit テスト** — 幅の文字列・会社ごとの決算期・新しいガード・メタデータの文言。**現状の1,867社（3月期1,865・4月期2）でも、拡大後の分布（3月期63.5%・14種類）でも同じ規則で読める文字列が出ることを、両方の入力で固定する**
2. **`npm run build:data`** — 落ちないこと。サマリーに幅が出ること
3. **型・lint・ビルド** — `cd web && npm run typecheck && npm run lint && npm run build`
4. **ペイロードの再測** — 1. で測った値と突き合わせる。増分が見込みどおりか
5. **E2E** — `e2e/data-period.spec.ts` を幅に合わせて直す。**決算期の直書きが1つも無いことを見る既存のテスト（AC-20）は、幅になっても効く形で残す**
6. **ブラウザで触る** — `/`・`/company/[id]`・`/about` の3画面で、時点が1回ずつ読めること

### 8. docs を書く

`design.md` に**出来上がりの構造**を書く。幅の表し方、会社ごとの決算期の持たせ方、新しいガードの線、ペイロードの実測値。

CLAUDE.md の「現在地」を実態に合わせる。

## 先に決めてあること

**title にも幅をそのまま出す**（運営者の判断・2026-08-25）。`【2026年3月期〜2026年4月期】`、拡大後は `【2025年3月期〜2026年5月期】`。

- 正確さを優先する。「2026年5月期まで」は短いが「それ以前を全部含む」と読めてしまい、実際は直近1年ぶんなので誤解を生む
- title が9文字伸びるが、**日本語の title は SERP で約30文字で切られるため末尾の決算期は現状でもほぼ見えておらず、実害は小さい**という読み

## この Unit でやらないこと

**母集団の拡大そのもの**（E2・#173）。窓は変えない。`/about` の「EDINET に 2026年6月1日〜7月10日 に提出されたもの」もそのまま。

**10年推移の各点の年**（`docs/site-chrome/spec.md` 5.4 のとおり変えない）。

**新しいデータファイルを増やすこと。** #179 が「仕掛けの重さに対して効果が見合っていない」として生成物を2つ戻したばかり。1. の実測で増分が問題にならないなら、既にあるものに足す。

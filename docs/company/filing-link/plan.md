# C13 有報への直リンク — plan.md

参照: Issue [#814](https://github.com/varmil/nenshu/issues/814), `docs/company/spec.md` 1.20・AC-31・1.15, `docs/site-chrome/spec.md` 5.1
依存: C12（#805。このページの出典）

## Context

企業詳細ページに、その会社の有報——実測値の4項目を取った書類そのもの——を EDINET で開くリンクを置く。
置き場所は実測値の4項目の表の下辺に付けた帯（Claude Design の案 D・2026-09-24 に運営者が選んだ）。

**着手前に確かめたこと。** EDINET の書類閲覧ページは書類 ID だけで開き、キーエンスの ID で
キーエンスの有報（第57期）の本文が出る。存在しない ID はリダイレクトされる。書類 ID は掲載
2,961社すべてにあり（`ranking_unified_2026.csv` の `doc_id`）、キーエンスは2017年の書類まで開いた。

**10年ぶんのリンクは入れない**（推移の表から張るのはつながりが弱い・運営者の判断）。

## 進め方

1. **spec を先に書く。** 1.20 と AC-31 を足し、1.15 の「一次情報にリンクする」を合わせる
2. **E2E を先に書く。** 帯のリンク先・別タブ・決算期を書かないこと・生の HTML にあること・
   モバイルで1行かつ押せる高さ・出典の節の実測値の行・`/` に書類 ID が無いこと。**この時点で
   走らせて落ちることを確かめる**
3. **パイプラインで書類 ID を渡す。** CSV の読み込みに書類 ID を足し、企業詳細だけが読むデータに
   ID の辞書として書く。全社にあること・形が合うことをビルドで確かめる。Unit テストを足してから
   `build:data` を回し、差分が新しいファイルと `generatedAt` だけであることを見る
4. **web で描く。** 閲覧ページの URL を組み立てる関数を1か所に置き、企業詳細のページデータに
   書類 ID を足す。帯を描き、出典の節の実測値の行をその書類へのリンクにする。Unit テストを足す
5. **検証。** lint・typecheck・vitest、E2E を dev サーバーに向けて全件回す。PC とモバイル、ライトと
   ダークで帯を撮って Claude Design の案と見比べる。`/company/6861` と `/` の HTML を前後で測る
6. **docs を直す。** design.md、CLAUDE.md の現在地

## Context

C18 で、決算期末が2026年3月31日以後の1,925社のうち1,862社について、有報の「人材戦略に関する
基本方針等」（参照先の節を含む）から給与の決定方針を原文のまま切り出した
（`pipeline/data/pay_policy_2026.json`）。C19 はこれを企業詳細ページに出す。

意匠は Claude Design `C19 給与の決定方針.dc.html`（1a 置き場所・1b モバイル・1c 会社ごとの状態・
1d 出典の行）。デザインと spec 1.23 が食い違っていた3点は、着手時に運営者が決めた。

1. **見出しは spec のまま** `{社名}の給与の決定方針`（デザインは「給与・賞与の決定方針」）
2. **出典の行は spec に合わせる。** 区分「原文」の出典に、どこまでが給与の決定方針かを生成AIが
   判定したことを書く（デザインは「有価証券報告書をそのまま」だけ）
3. **会社が給与の決定方針に付けた小見出しは、デザインどおり引用の先頭に残す**（spec は落とすとしていた）

置き場所はデザインの 1a を採る——「有価証券報告書の要約」の直後、「年収に関するQ&A」の直前
（spec 4. の未決事項）。

C18 で分かっている、表示に効く事実:

- 字数は中央値313字・75%点509字・90%点752字・最長3,140字（西武HD）。1,000字超が80社、2,000字超が7社
- 本文に表を含むのが58社、画像を含むのが17社
- 本文の `heading` は「句点で終わらない短い行」で、箇条書きの1項目や言いさしも入る（1,728個のうち112個がひらがなや読点で終わる）
- 出どころは 人材戦略に関する基本方針等 1,760社・サステナビリティ 101社・従業員の状況 1社

## 進め方

1. **変更前を測る。** main のまま `astro build` し、`/company/7203`・`3032`・`9024`・`9433`・`4452`・
   `9501`・`6861` と `/` の HTML（raw / gzip）を記録する
2. **spec を先に直す。** 1.23 に運営者の3つの決定と置き場所を書き、未決事項（spec 4.）から
   置き場所と表の出し方を外す。1.15・AC-16 に区分「原文」、AC-36 の文言を決定に合わせる
3. **E2E を先に書く。** AC-36 の各項目を、既存の企業詳細の spec に足す（横スクロール・JS 実行前の
   HTML・表示基準から独立な節は既存のループと配列に会社を足す）。**この時点で走らせて落ちることを
   確かめる**
4. **データを書き出す。** `build-data.ts` で `pay_policy_2026.json` を企業 ID の辞書
   （本文のある会社だけ）にして `web/public/data/pay-policies.json` に出す。突合が全件当たることと
   gzip の上限を確かめる。`/` からは読まない
5. **切る位置を実データで決める。** 1,000字を超える会社で、先頭をどこまで開いておくかを字数の
   分布と 390px での高さで決める
6. **見せ方を組む純粋関数を書く。** 見出し・出どころの1行・本文の塊（先頭に会社の小見出し）・
   開いておく部分と畳む部分の分け目を1つの関数から出し、Unit テストで固定する
7. **節を描く。** C10・C12・C16 と同じく島の外（名前付きスロット）で描き、要約と Q&A の間に置く。
   出典の一覧に区分「原文」を足し、`/about` に抜き出し方を書く
8. **検証。** lint・typecheck・vitest、E2E を dev サーバーに向けて企業詳細の spec 一式と全件で回す。
   1. と同じ条件で測り直して並べる。`/` が変わっていないことを確かめる
9. **docs を直す。** design.md、CLAUDE.md の現在地、overview.md

## 着手前に見えている判断

**本文の近くに「生成AI」の語を置かない。** 範囲の判定に生成AIを使ったことは、出典の一覧と `/about`
に書く。節の説明に置くと、文そのものを AI が書いたように読める（Issue #852 の論点）。

**`heading` を強い見出しとして描かない。** 言いさしや箇条書きの1項目が見出しの顔をする。

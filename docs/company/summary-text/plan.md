# C4 企業詳細ページの説明文の強化 — plan.md

参照: Issue #146（親: #145）, `docs/company/spec.md` 1.14・1.17（AC-14・AC-17）, `docs/timeseries/spec.md` 2.1
依存: #89（C3）

## Context

企業詳細ページに並んでいる数値は正確だが、**地の文がほとんど無い。** いま文章になっているのは
年齢別の説明文2つ（最高水準・伸びの最大区間）、推移の1文、サイドバーの要点だけで、
主役の金額も実測値の4項目も `dl` の `dd` と表のセルに入っている。

親 Issue #145 が挙げているのは年齢別の「到達年齢」の文で、OpenWork の
「30歳で500万円を超え、その後40歳で700万円、55歳で1000万円を超えている」がその形になる。
**同じ欠けは実測値の節と推移の節にもある**ので、同じ Unit で3か所を揃える。

**書けるのは数値から機械的に導ける事実だけ**（spec 1.11 と同じ線）。会社ごとの解説文は
1.10・1.16 のまま作らない——手元にあるのは有報の5項目・賃金カーブ・10年推移だけである。

## 進め方

1. **到達年齢の算出を、描画から切り離した純関数として先に書く。** 入力は8点の推定年収、
   出力は `{ 年齢, 到達金額 }` の並び。ここが Unit のほぼ全部なので、単体テストで先に固める。
2. **判定は画面に出ている万円の値で行う。** 表は `formatManYen`（円 → 万円へ四捨五入）で
   描いているので、円のまま比べると**表が「600万円」と出している行を文が「600万円に達する」に
   数えない**ことが起こりうる。丸めてから比べる。
3. **実データで段の粗さを確かめる。** 全1,867社に当てて、到達段が0個になる会社が何社出るかを
   数える。0個の会社には文を出さない（該当しない項目は出さない）ので、それが多すぎるなら段が粗い。
4. **実測値の節と推移の節に文を足す。** どちらも既存の値を言い直すだけで、新しい数値は出さない。
   推移の最高値の文は**最新年と違うときだけ**出す（同じなら1文目の言い直しになる）。
5. **既存のテストを直す。** 年齢別の1文目が到達年齢の文に変わるので、最高水準の文言を
   当たり判定にしている単体テストと E2E を新しい並びに合わせる。
6. **測って出す。** `/company/[id]` の初期HTMLサイズを raw と gzip で測り直し、13,824 B
   （Issue #95 時点）からの増減を design.md に記録する。

## 着手前に見えている判断

**「超える」ではなく「達する」。** 万円に丸めた値で比べるので、`600万円` ちょうどの会社が出る。
そこに「超える」と書くと嘘になる。段への到達は `≥` で判定し、文は「達します」にする。

**1文に載せる到達年齢は最大3つ。** 段を細かくすると6つ以上並ぶ会社が出て、文が読めなくなる。
4つ以上あるときは最初・真ん中・最後を採る（両端を落とさない）。

**同じ年齢で2段を同時に超える会社は、大きいほうだけを書く。** 「30歳で500万円、30歳で600万円」と
並べても年齢の情報が増えない。

**h1 直下の紹介文は作らない。** モック（アートボード 4b/2b）にはあるが、C3 でデータが無いと
判断したものをここで作り直さない。**SEO のための文だからといって、根拠の無い文を置かない**
（開発上の約束「根拠を隠した推定値を表示しない」の裏返し）。

## 検証

```bash
cd web && npm run typecheck && npm run lint && npm test && npm run test:e2e
cd web && npm run build
```

- 到達段が0個の会社（`日ノ丸自動車` 系の低位）と、5段を超える会社（`キーエンス`）の両方を実際に開く
- 表示基準を切り替えても年齢別の説明文が変わらないことを E2E で固定する（8点は表示基準に依らない）
- 表の金額と文の金額が同じであることを、実データを使った単体テストで固定する
- 390px で文が横スクロールを起こさないこと（長い社名＋3段の文）

## 非対象

会社ごとの解説文、構造化データ・OGP（site-chrome の S2・#116）、業種平均との比較文
（業種ごとの平均を `stats.json` に持っていない）、ランキングページ側の文言。

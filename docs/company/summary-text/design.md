# C4 企業詳細ページの説明文の強化 — design.md

参照: Issue #146（親: #145）, `docs/company/spec.md` 1.14・1.17（AC-14・AC-17）, `docs/timeseries/spec.md` 2.1
依存: #89（C3）

## 何がどこに増えたか

文を作るのは `web/features/company/lib/highlights.ts` の純関数だけで、描画側（`CompanyDetail`）は
受け取って `<p>` に置く。既存の3つ（要点・年齢別・推移）と同じ場所に並ぶ。

| 節 | 関数 | 出るもの |
| --- | --- | --- |
| 年齢別の推定年収 | `findSalaryMilestones` → `buildCurveSummary` | 到達年齢の文（1文目）。最高水準は2文目に下がる |
| 有価証券報告書の実測値 | `buildActualsSummary` | 4項目を1文にした地の文 |
| 平均年収推移 | `buildHistoryPeak` | 最高値の年（増減の文と同じ `<p>` に続ける） |

**数値は1つも増えていない。** どれも画面の他の場所に既に出ている値の言い直しで、
`companies.json` / `stats.json` / `history.json` はそのまま。ページのデータ量は変わらない。

## 到達年齢

```
段 = [300, 400, 500, 600, 700, 800, 900, 1000, 1200, 1500, 2000, 2500, 3000]（万円）
```

8点（25〜60歳）を若い順に走査し、**その年齢で初めて超えた段のうち最大のもの**を1つ拾う。

- **判定は `toManYen`（画面に出ている万円の整数）で行う。** `formatManYen` と同じ丸めを
  数値のまま取り出した関数を `features/ranking/lib/format.ts` に足し、表と文の両方がそれを使う。
  円のまま比べると、表が「600万円」と描いている行（599万9,600円）を文が数えず、
  **同じ節の中で表と文が食い違う**
- **25歳で既に上回っている段は数えない。** 8点の左端より前を持っていないので、そこで
  「達する」と書くと 25歳より前のどこかで届いたはずのものを25歳のこととして書くことになる
- **同じ年齢で複数の段に届いたら大きいほうだけ。** 「30歳で500万円、30歳で600万円」では
  年齢の情報が増えない
- **いったん届いた段は数え直さない。** 走査中の最大値を基準にするので、末尾の60歳で下がっても
  同じ段が2度出ない
- **文に載るのは最大3つ。** 4つ以上あるときは最初・真ん中・最後を採る（両端が最も情報を持つ）

段の粗さは実データで決めた。800万円までを100万円刻み、その上を 1,000 / 1,200 / 1,500 / 2,000 /
2,500 / 3,000 にしてある。8点の最大値は中位772万円・上位10%が1,049万円・最大2,699万円に散るので、
上まで100万円刻みを続けると高い会社だけ段が10個以上並び、200万円刻みにすると
600〜900万円台に集まる大半の会社で何も言えなくなる。

**この段で1つも届かない会社は8社**（福井鉄道・ビケンテクノ・島原鉄道・光ハイツヴェラス・
ヤマノホールディングス・ショクブン・オーケー・ＪＳＨ）。8点が362〜369万円のように
1つの段の中に収まる会社で、**到達年齢の文を出さない**（該当しない項目は出さない）。
そのとき切り出しの「◯◯の推定年収を年齢別に見ると」は最高水準の文が引き継ぐ——
節の地の文が社名から始まらなくなるのを避ける。

実データでの分布は 0段:8社 / 1段:66社 / 2段:246社 / 3段:707社 / 4段:708社 / 5段以上:132社。

### 「超える」ではなく「達する」

万円に丸めた値で判定するので、ちょうど段と一致する会社が出る。そこに「超える」と書くと嘘になる。
親 Issue の例（OpenWork）は「超え」だが、**判定を円で行って表と食い違わせるより、語を変えるほうを採った。**

### 3文は1つの段落に続ける

公開後の指摘（運営者）。1文ずつ `<p>` に分けていたので、**どれも同じ8点についての話なのに
3つの話題が並んでいるように見えていた**。到達年齢・最高水準・伸びの最大区間を1つの `<p>` に
連結し、改行は器の幅に任せる。和文なので句点のあとに空白は入れない（推移の説明と同じ扱い）。

文を組み立てる側（`buildCurveSummary`）は文の配列を返したままにしてある——「該当しない項目は
出さない」を配列の増減で表せるほうが素直で、つなぎ方は描画側の関心になる。

## 実測値の1文

`有価証券報告書によると、株式会社キーエンスの平均年収は2,178万円、平均年齢は35.0歳、平均勤続年数は11.3年、従業員数は3,306人です。`

すぐ下の4セルと同じ値で、**決算期は書かない**——節の見出し（`有価証券報告書の実測値（2026年3月期）`）が
持っている（S3・Issue #134）。1画面に1回。表示基準を切り替えても変わらない（実測値そのもの）。

## 推移の最高値

`buildHistoryPeak` は**最高値の年が最新年と同じなら `null`**。増減の1文が最新年の金額を既に
書いているので、同じ数字が2度並ぶ。**実データでは1,852社中1,287社が最新年＝最高値**で、
残る565社でだけ1文が増える。

## 調査: ほかに文を置ける場所（Issue #145 の「調査から」）

| 候補 | 判断 |
| --- | --- |
| 年齢別の到達年齢 | **採った**（親 Issue の依頼そのもの） |
| 実測値の4項目 | **採った**。`dl` の `dt`/`dd` にしか無く、抜粋にも読み上げにも「ラベルと値」以上に読めない |
| 推移の最高値 | **採った**。増減1文に1文足すだけで、表の10行を読まなくても形が分かる |
| h1 直下の会社紹介文 | **作らない**。モック（4b/2b）にはあるがデータが無い（spec 1.10・1.16、C3 で判断済み）。**SEO のための文だからといって根拠の無い文は置かない** |
| 上部カードの金額を文にする | **作らない**。要点の箇条書き（サイドバー）が同じ内容を既に持っており、同じ画面に3つ目の言い直しを増やすことになる |
| 業種平均との比較文 | **作らない**。`stats.json` は全体の平均・標準偏差・分布は持つが、**業種ごとの平均を持っていない**。持たせるならビルド時の統計を増やす話で、この Unit の外 |
| よくある質問（FAQ）の節 | **作らない**。読者が実際に訊いた質問ではなく、こちらで作った問いに自分で答える形になる。数値の裏付けが無い文が混ざる入口になる |
| 構造化データ（JSON-LD） | **この Unit では触らない。** site-chrome の S2（#116）が持つ。画面にある情報だけ（`BreadcrumbList`）という線もそちらで決まっている |

## テスト

  3つまで）と、**全1,867社で「文が挙げた年齢の行は表でもその金額以上」**を突き合わせる

  表示基準を切り替えても年齢別の文が変わらないこと、初期HTMLに入っていること、390px で横スクロールが
  出ないこと

# C2 企業詳細ページのレイアウト刷新 — plan.md

参照: Issue #83（親: #21）, `docs/company/spec.md` 1.11〜1.16・AC-11〜AC-16, `docs/timeseries/spec.md` 2.・AC-6〜AC-11
依存: #52（C1）, #80（U12）, #74（T0）

## Context

C1 で必要な数字は揃えた。C2 は**同じ数字を読める形に組み直す**Unit である。加えて T0 で取った10年ぶんの実測値を表示に繋ぐ（timeseries 施策の T1 を同梱する）。Bolt 2 の最後で、これで Issue #21 のアートボードが全て実装済みになる。

**この Unit で壊れやすいのは3つ。**

1. **表示基準ごとに別物になるもの**が増える（中位・ヒストグラム・近傍5社）。U12 で年収バーの基準を取り違える危険を扱ったのと同じ性質で、切替時に片方だけ古い値が残る壊れ方をする
2. **10年推移だけは表示基準と独立**に常に実測値である。上の1と逆の性質を同じページに並べるので、取り違えると「年齢そろえにしたら過去の有報の数字が変わる」ことになる
3. **リクエスト時の計算量**（Workers Free の CPU 10ms）。「水準が近い会社」を安易にビルド時へ寄せると `stats.json` が膨らみ、リクエスト時へ寄せすぎると制約に当たる

作業の順序はこの3つを最後まで確かめられるように組む。

## 進め方

1. **パイプラインから始める。** `buildStats` に表示基準ごとの中位とヒストグラムを足し、`stats.json` の増分を測る。**ここで増分が読めないまま先に進まない**——`/` はこのファイルを読まないが、企業詳細ページのペイロードには効く。既存の順位・偏差値が1件も変わっていないことを固定してから次へ行く。
2. **表示基準に依存する値と、しない値を先に分ける。** 中位・ヒストグラム・近傍5社は基準ごと、10年推移は基準と独立。この境界を型と純粋関数の側で決め、切替時にどちらがどう動くかを単体テストで固めてから画面を作る。
3. **「水準が近い会社」の計算をリクエスト時に置く。** 1業種の最大社数で計算量を実測し、C1 が測った1社ぶんの計算に足して見合うかを確かめる。見合わなければビルド時に寄せる判断をここでする。
4. **10年推移を繋ぐ。** `history.json` を企業詳細ページからだけ読む。欠損年を内挿しないこと・表示基準を切り替えても値が動かないことを、この時点で単体テストに落とす。
5. **器を組み替える。** PC の2カラム（右サイドバー）から作り、モバイルの1カラムを後に回す。**390px で横スクロールが出ないことを毎回確かめる**——U3・U12 で2度踏んでいる。
6. **推定範囲 ±20% を出す。** 表とチャートの帯を同時に入れ、**「統計的な信頼区間ではない」断りを近くと `/about` の両方**に置く。片方だけにしない。
7. **固める。** ロジックは単体テストで、描画とモバイル幅は E2E で固定する。既存の `e2e/company-page.spec.ts` に載るものはそこに足し、推移・分布・近傍は新規に分ける。
8. **測る。** `npm run measure:prefetch` を回す（近傍5社ぶんの `<Link>` が増えるため）。`/company/[id]` の HTML gzip を測り、C1 時点の 8,250 B からの増減を記録する。
9. **出す。** ビルド・単体・E2E・実操作の結果を PR にまとめ、問題が無ければマージする。

## 着手前に見えている判断

**中位とヒストグラムはビルド時、近傍5社はリクエスト時。** 前者は母集団全体の形なので1社ごとに変わらず、`stats.json` に9基準ぶん持てば済む。後者は1社ごとに違う5社なので、ビルド時に持つと 1,867×9×5 の表になる。1業種は最大150社で、C1 が確かめた「リクエスト時は当該1社ぶんの16回だけ」に足しても収まる見込み——手順3で実測する。

**推移のグラフと年齢別の折れ線を共通化しない。** 軸の取り方が違う（推移は0起点でよい、年齢別は0起点にしない）。共通化するなら軸の設定を引数に出すことになり、2つしか無い時点では割に合わない（`docs/timeseries/overview.md`）。

**`features/ranking` ↔ `features/company` の相互依存**（U12 で作った）をこの Unit で解消するかは design.md で判断する。**解消するなら独立した Unit に切る**——2施策のファイル移動はレイアウト刷新と混ぜて1つの PR にすべきものではない。

## 検証

```bash
cd pipeline && npm test
cd web && npm run typecheck && npm run lint && npm test && npm run test:e2e
cd web && npm run build            # / が ƒ (Dynamic)、/about が ○ (Static) のまま
cd web && npm run measure:prefetch # 近傍5社ぶんの <Link> が増えるので必ず回す
```

- dev server を起動し、ブラウザで実際に触る（表示基準の切替で中位・ヒストグラム・近傍5社が動き、推移が動かないこと・390px で横スクロールが出ないこと）。ブラウザ操作ツールが使えなければ E2E の結果で代替する
- `stats.json` と `/company/[id]` の実サイズを design.md に記録する

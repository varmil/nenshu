# C15 平均年収カードを本文の先頭へ — design.md

参照: Issue [#821](https://github.com/varmil/nenshu/issues/821)（親: [#820](https://github.com/varmil/nenshu/issues/820)）, `docs/company/spec.md` 1.21・AC-33・AC-29, `docs/performance/spec.md` 2.1
依存: なし（C14・#818 のカードと P1・#167 のレーダーの位置だけを変える）

## 出来上がり

`/company/[id]` の本文（左の列）の並び。**動いたのは先頭の2つだけ**で、中身は1つも変わっていない。

```
変更前（P1〜C14）                       変更後（C15）
h1 社名 / 順位 / 説明文 / 見せ方・年齢の帯（変わらない）
① 公開資料による全体像（レーダー）      ① 平均年収カード
② 平均年収カード                        ② 公開資料による全体像（レーダー）
③ {社名}の現状と今後（AI 分析）          ③ {社名}の現状と今後（AI 分析）
④ 残業・有給・男女の賃金の差異          ④ 〃
⑤ 年齢別の推定年収                      ⑤ 〃
⑥ 有価証券報告書の実測値                ⑥ 〃
⑦ 平均年収推移（過去10年間）            ⑦ 〃
⑧ 稼ぐ力の推移（過去10年間）            ⑧ 〃
⑨ {社名}の有価証券報告書の要約          ⑨ 〃
⑩ このページの出典                      ⑩ 〃
```

右のサイドバー（水準が近い会社）は変わらない。PC では**カードの上端がサイドバーの上端とそろう**
（どちらも本文の列の先頭の行から始まる）。

## 構成

| 場所 | 中身 |
| --- | --- |
| `web/features/company/components/CompanyDetail.tsx` | 本文の列の中で `<Card>`（平均年収カード）と `<OverviewSection>`（レーダー）の順を入れ替えた。位置の理由を書いたコメントを3つとも直した（カード・レーダー・分析） |
| `web/features/company/components/OverviewSection.tsx` | 冒頭の説明の「ページの先頭に置く」を「平均年収カードの直後に置く」に直した |

**props も描画のたびの計算も変わらない。** `radarAxes`・`cardFacts` は並びと無関係に組み立てて
いたので、JSX の2ブロックを入れ替えるだけで済んだ。

## 決めたこと

- **入れ替えるのは2つだけ。分析（C10）の位置は動かさない。** 分析はカードの直後からレーダーの直後に
  なる。C10 が分析をカードの直後に置いた理由は「読者の答え（カード）を押し下げない」「数字を見た
  直後に『この会社はいまどうなのか』を続ける」の2つで、カード → レーダー → 分析 の順でもどちらも
  満たせる。分析をカードの直後に据え置いてレーダーを分析の後ろへ回す案もあったが、レーダーが
  分析の下まで下がり、親 #820 が頼んだ「入れ替え」より大きく動く
- **レーダーの位置づけは「最初に来る要約」から「カードの後ろの全体図」に変わる。** 図が含む5軸の
  うち平均年収はすぐ上のカードと同じ値で、残りの4軸（残業・有給・定着・稼ぐ力）は下の節の要約に
  なる。**節の中身（説明・断り・軸の並び）は変えていない**——断りの「区分ごとの値は下の節に
  あります」は、働きやすさの節が下にあることに変わりがないのでそのまま成り立つ
- **カードに見出しを足さない。** 並びの E2E のために h2 を足すと、見出しの無いカードとして組んだ
  C3 のデザインが変わる。並びは見出しではなく DOM と画面の上下で見る（下の「固定しているもの」）

## 実測値

`/company/[id]` を dev サーバーで開き、各要素の上端（ページの先頭から）と高さを測った。

| | 1280×800 変更前 | 1280×800 変更後 | 390×844 変更前 | 390×844 変更後 |
| --- | --- | --- | --- | --- |
| 6861 カードの金額の上端 | 954px | **525px** | 1,139px | **660px** |
| 6861 レーダーの上端 | 469px | 807px | 604px | 1,184px |
| 6861 分析の上端 | 1,237px | 1,237px | 1,664px | 1,664px |
| 7203 カードの金額の上端 | 977px | 547px | 1,162px | 683px |
| 8058 カードの金額の上端 | 977px | 547px | 1,158px | 679px |

**金額が最初の画面の外から中に入った**（PC は画面の高さ 800px、390px 幅は 844px）。上がった幅は
レーダーの高さ（PC 382px・モバイル 431px）と節の間隔（48px）の和になる。**分析から下の節の
位置は変わらない**——入れ替えた2つの高さの和が同じなので。

| | 変更前 | 変更後 |
| --- | --- | --- |
| `/company/6861` の HTML（raw / gzip） | 146,544 B / 20,893 B | 146,543 B / 20,953 B |
| `/company/7203` の HTML（raw / gzip） | 149,654 B / 22,163 B | 149,654 B / 22,255 B |
| `/company/8058` の HTML（raw / gzip） | 152,766 B / 22,622 B | 152,765 B / 22,700 B |

（`astro build` の成果物。gzip は `gzip -9`。）**raw は変わらない。** 6861 と 8058 の −1 B は島の
`uid`（Astro がハッシュから振る識別子で、5〜6文字と長さが揺れる）の違いで、JS の指紋を除いた中身の
文字は前後で同じ。**gzip は +60〜92 B 動く**——同じ文字列でも並びが変わると圧縮の効き方が変わる
（前後を比べるときは raw で見る、は CLAUDE.md のとおり）。**`/` は変わらない**——企業詳細の
コンポーネントを import していない。

## 固定しているもの

- **E2E**（`e2e/company-refresh.spec.ts` の「節の並び」）——
  - 1280×800: 見出しの並び全体（レーダーの見出しの**直後**が分析の見出し）、カードが本文の列の最初の
    子で、レーダーの節がそのすぐ次の兄弟であること、カードの金額がスクロールせずに見えること
  - 390×844: カードがレーダーより上にあり、金額がスクロールせずに見えること。横スクロールは同じ
    ファイルの AC-15 のループ（375px）が見る
- **E2E**（`e2e/company-page.spec.ts` の AC-10）——JS 実行前の HTML で、カードの金額のラベルが
  レーダーの見出しより前に出ること
- **E2E**（`e2e/company-radar.spec.ts` の「節の中身」）——レーダーの見出しが h2 の中で先頭のままであること
- **Unit テストは足していない。** 変えたのは JSX の順だけで、純粋関数の入出力が1つも変わらない
  （C11・#799 と同じ扱い）。既存の vitest が全件通ることを確かめた

**分析の位置は兄弟の関係では見られない。** 分析と要約は Astro の名前付きスロットで届き、DOM では
`astro-slot` の要素に包まれている（C10）。だから分析の位置は見出しの並びで見る。

**カードには見出しが無い**ので、見出しの並び（AC-29）だけ見ていてもカードとレーダーの入れ替えは
検出できない。実際、AC-29 のテストは入れ替える前も後も通る。AC-33 を足したのはそのため。

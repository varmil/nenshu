# C15 平均年収カードを本文の先頭へ — plan.md

参照: Issue [#821](https://github.com/varmil/nenshu/issues/821)（親: [#820](https://github.com/varmil/nenshu/issues/820)）, `docs/company/spec.md` 1.21・AC-33・AC-29, `docs/performance/spec.md` 2.1
依存: なし（C14・#818 のカードと P1・#167 のレーダーの位置だけを変える）

## Context

企業詳細ページの本文は、P1（#167）からレーダー「公開資料による全体像」が先頭で、平均年収カードは
その下にある。検索からの流入の語は「年収」「年収ランキング」が100%を占めており（親 #820）、読者が
探している金額はレーダーの下まで降りないと出てこない。

**2つの節を入れ替えるだけにする。** 中身には触らない。分析（C10）から出典（C12）までの並びも
変えない。

## 進め方

1. **変更前を測る。** dev サーバーで `/company/6861`・`7203`・`8058` を 1280×800 と 390×844 で開き、
   カード・金額・レーダー・分析の上端と高さを記録する。`astro build` で同じ3社の HTML（raw / gzip）を
   記録する
2. **spec を先に直す。** company の 1.21 に本文の並びと理由を書き、AC-33 を足す。performance の 2.1
   の「企業詳細ページの先頭に置く」を改める。C10 の「分析はカードの直後」の記録に C15 の注を足す
3. **E2E を先に書き換える。** レーダーの節の「ページの先頭にある」をカードの直後に書き換え、AC-33 の
   3つ（DOM の並び・390px の上下・JS 実行前の HTML の並び）を足す。AC-29 の並びにレーダーと分析が
   隣り合うことを足す。**この時点で走らせて落ちることを確かめる**
4. **並びを入れ替える。** `CompanyDetail.tsx` のカードとレーダーの2ブロックを入れ替え、それぞれの
   位置の理由を書いたコメントを直す
5. **検証。** lint・typecheck・vitest、E2E を dev サーバーに向けて企業詳細の spec 一式と全件で回す。
   1. と同じ条件で測り直して並べる。HTML の大きさが変わっていないこと（並びを変えただけなので
   バイト数は同じになるはず）を確かめる
6. **docs を直す。** design.md、C10 の design.md の「置き場所」、P1 の design.md・plan.md、CLAUDE.md の
   レーダーと分析の位置の記述

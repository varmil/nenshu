# spec.md — 企業詳細ページ

対象面: user-web（ユーザー画面）

1社につき1枚、計2,961枚のページを `/company/[id]` に置く。用語は `docs/product/glossary.md` に従う。URL の構成は ADR-0006 に従う。

---

## 1. 企業詳細ページ（`/company/[id]`）

### 1.1 何を出すか（WHAT）

1社の年齢補正年収と、その会社が全体・業界内でどの位置にあるかを出す。載せる数値はすべて `companies.json` / `curves.json` から導けるものに限る。

初期状態は目標年齢35歳。

### 1.2 なぜ（WHY）

読者の多くは特定の1社を頭に置いて訪れる。「◯◯（社名） 年収」という検索の受け皿が無く、その問いは2,961行の表の中でしか解けない。順位だけでは水準が伝わらないため、偏差値と母集団の中での位置を同時に出す。

### 1.3 ID

- 証券コードがある会社はそれ（1,760社。`6861`・新形式の `285A` を含む）
- 無ければ EDINETコード（107社。`E01798` 形式）

上場か否かではなく証券コードの有無で分ける。

ADR-0006 で決定。書類ID由来のIDは使わない（毎年変わるため）。

### 1.4 載せるもの

| 区分 | 項目 | 備考 |
| --- | --- | --- |
| 見出し | 会社名 | 「本社のみ」バッジを添える |
| | 業種（tse33） | ランキングの業種フィルタへのリンクにする |
| **主役** | **目標年齢時点の推定年収** | 推定であることを常時示す |
| | 有報の平均年収を言い直す1文 | `{社名}の最新の有価証券報告書に基づく平均年収は 約◯万円（平均年齢◯歳）です。` 表示基準では変わらない |
| 位置 | 業界内順位 | `n位 / m社`。業種名を添える |
| | 全体順位 | `n位 /2,961社` |
| | 年収偏差値 | 数字だけを出す。**注記も添えない**（2026-08-20 改訂）。100を超えうる理由はランキングの脚注と `/about` にあり、このページでは同じ視界の順位・位置バーに水準を読ませる。**位置バーの見出しの隣に1回だけ出す**（#831） |
| 実測値 | 平均年収（実額） | 補正前。**4項目とも「年収に関するQ&A」の質問と回答で出す**（1.22） |
| | 平均年齢 / 在籍年数 / 従業員数（単体） | Q&A では在籍年数を「平均勤続年数」と書く（1.22） |
| 推移 | 年齢別の推定年収チャート | 25〜60歳の8点 |
| 前提 | 出典と `/about` への導線 | ページに出ているデータすべての出典（1.15） |

金額の書式はランキングと揃える（万円単位・カンマ区切りの整数）。年齢と在籍年数は小数第1位まで。偏差値は小数第1位まで。

**平均年収カードに並べるのは、金額とそれを言い直す1文の下に2段**（C14・#818・親 #817）。1段目が 平均年齢・従業員数（単体）、2段目が 業界内順位・全体順位。**業界内順位を左に置く**（2026-09-26・運営者の指示）——読者が先に知りたいのは同業の中の位置で、h1 直下の1行も業界が先。**太字は金額だけ**で、順位は通常の太さにする。**在籍年数はカードに出さない**——値は「年収に関するQ&A」（1.22。C16 までは「有価証券報告書の実測値」の節）とレーダーの「定着（在籍）」の軸にある。

**偏差値は順位の段に置かない**（2026-09-25、#831）。同じカードの右の位置バーの見出し（`全体2,961社の中の位置`）の隣に `偏差値 124.8` として出ており、C14 のまま左の段にも置くと1枚のカードに同じ値が2回並ぶ。位置バーの側に残すのは、帯の右端＝偏差値の大きさという対応をその場で見せられるから。順位（左の段）と位置バーは PC では横に、モバイルでは上下に続けて並ぶので、**偏差値と順位が同じ視界にある**ことは変わらない（glossary）。2段とも2項目になったので、器は2列にそろえる。

**なぜ** — C3 のカードは 金額 → 太字の順位3つ → 平均年齢・在籍年数・従業員数 の順で、数字が6つ並び、金額の次に目に入るのが順位だった。金額の直後に要るのは「どういう会社の金額か」（年齢と規模）で、OpenWork・OpenMoney も平均年収・年収範囲・平均年齢・回答者数の4つに絞っている。順位はカードの右の位置バーと同じ話なので、その隣の段に下げる。順位は h1 の直下の1行にもある。

**金額の直下は、有報の平均年収と平均年齢を言い直す1文にする**（2026-09-25、運営者の指示）。それまで置いていた全体平均との差（`全体平均 693万円 に対して ＋1,486万円`）は外した——母集団の中の位置は同じカードの順位・偏差値・位置バー・分布が持っている。**年齢そろえのときもこの文は有報の値のまま**で、「推定」の語は置かない（見出しが持つ。Issue #128）。

**「上位◯%」は画面に出さない**（2026-08-20、運営者の判断。Claude Design のモックに無いものを足さないため）。値そのものは `CompanyAgeStats.topPercent` として残っている（`docs/product/glossary.md`）。

**推定値と実測値を同じ書式で並べない**（CLAUDE.md）。推定年収と平均年収（実額）は視覚的に区別する。

### 1.5 年齢スイッチ

ランキングと同じ 25 / 30 / 35 / 40 / 45 / 50 / 55 / 60 歳の8段。単一選択。

操作すると推定年収・全体順位・業界内順位・偏差値が更新される。**ページ遷移も再取得も発生させない。**

**URL には出さない**（R1・ADR-0012）。表示基準はクライアントの状態としてだけ持つ。このページを全社ぶん事前生成しており、`force-static` のページは `searchParams` を読めない。年齢そろえで変わるのは推定年収まわりだけで、実測値（1.22 の Q&A）も10年推移も変わらないので、ページ全体にかかるパラメータとして持つ理由がない——いずれ推定年収の要素に付いたスイッチへ寄せる。

**ランキング（`/`）の `?age=N` は変えない**（ADR-0007）。あちらは2,961行の並び順そのものを変え、8件をインデックスさせている。同じ語だが役割が違う。

配ってしまった `/company/[id]?age=N` は**読まずに URL から落とす**（`replaceState`）。落とさないと「URLは30歳・画面は実測値」がそのまま残る。

### 1.6 年齢別の推定年収チャート

25〜60歳の8点を結ぶ折れ線。縦軸は推定年収。選択中の目標年齢を強調する。

**このチャートは1社の中の推移であって、同じ人が歳を取っていく軌跡ではない**（賃金カーブの性質）。**この注記はチャートの近くには置かず、`/about` の1か所に持たせる**（2026-08-20 改訂）。図に添える断りは ±20% の帯の意味だけにする——**帯だけを見ると信頼区間に見える**ので図の側から外せないのはそちらで、軌跡の話は仕組みの説明にあたり `/about` の担当になる。

### 1.7 順位・偏差値の定義

母集団は**その目標年齢時点の推定年収**で並べた全2,961社。

- **全体順位** — 同額の会社は同順位にする（自分より高い会社の数 ＋ 1）
- **上位◯%** — `全体順位 ÷ 2,961 × 100`
- **業界内順位** — 同じ tse33 の会社に限った同じ計算
- **年収偏差値** — `50 + 10 ×（自社の推定年収 − 母集団の平均）÷ 母集団の標準偏差`。母集団は全2,961社

年齢ごとに母集団の平均・標準偏差が変わるため、これらはすべて目標年齢に依存する。

### 1.8 存在しないID

`/company/存在しないid` は 404 を返す。

### 1.9 ランキングからの導線

ランキング表・カードの会社名から企業詳細ページに遷移できる。

### 1.10 対象外（v1）

平均年収の10年推移、株価推移、信用格付け、業績、口コミ、会社ごとの解説文、同業他社の比較表。

10年推移は `docs/product/product.md` の `timeseries` 施策、株価・格付けは `market-data` 施策として別に扱う。

**10年推移は Bolt 2 の C2 で入れる**（timeseries 施策の T1 を C2 に同梱する。`docs/timeseries/overview.md`）。株価・格付け・業績・口コミは対象外のまま。

**会社の説明文は 1.18 で対象に入れた**（2026-08-23・ADR-0010・#158）。v1 で外していたのは「2,961社ぶんを人手で書けず、生成して埋めれば根拠の無い断定が混ざる」ためだったが、**出所を有価証券報告書の「事業の内容」に固定し、原文から導けない文を落とす**ことでこの理由が外れた。**一般に知られた話や評価を含む解説文は引き続き作らない**（1.16）。

## 1B. 企業詳細ページ（Bolt 2 の追加）

Issue #21（UI改善）で足す。アートボード 4b（PC）/ 2b（モバイル）に対応する。数字を増やすのではなく、**すでに出している数字を読める形にする**のが主眼になる。

### 1.11 ~~この会社の要点~~（C11・#799 で削除）

~~手持ちのデータから箇条書きを組み立てて出す。~~ **2026-09-24 に外した**（運営者の判断）。当初は有報の要約を入れる場所として考えていたが、C10（#242）の配置を検討して**要約の置き場所にもしない**と決めた。中身はカードの数値を文にした繰り返しで、右サイドバーを画面より高くしていた（1280×800 で最大1,029px）。経緯は `docs/company/highlights-removal/design.md`。**番号は詰めない**（AC-11 を参照している文書がある）。

### 1.12 水準が近い会社

**同じ業種**で、現在の表示基準の金額が近い会社を10社出す（2026-08-25 に5社から増やした。Issue #195）。会社名と金額を並べ、それぞれの企業詳細ページへのリンクにする。**「本社のみ」バッジはここでは出さない**（2026-08-20、運営者の判断）——316px の列にバッジを足すと社名がそのぶん切れる。

**リクエスト時に算出する。** 1業種は最大223社なので、当該1社ぶんの計算に加えても Workers の CPU 制約（2. 非機能要件）に収まる。ビルド時に2,961社×9基準ぶんの近傍表を作らない。

自分自身は含めない。表示基準を切り替えたら選ばれる10社も変わる。

**各行に業界内順位と平均年齢を添える**（C3）。社名と金額だけでは、並んでいる会社が自分より上なのか下なのかが読み取れない。**業界内順位は自分を含めた並びで数える**——自分を除いてから振ると、自分より上の会社が1つずつ繰り上がって本来の順位とずれる。

末尾に「◯◯150社をすべて見る」の導線を置く。行き先は `?ind=` のURLで、ランキングの業種チップと同じ経路になる（ADR-0006）。

**なぜ** — 「2,178万円」が高いのか低いのかは、順位や偏差値よりも「同じ業種のどのあたりに並ぶか」で伝わる。**10社にしたのは回遊のため**（Issue #195）——同じ業種の別の会社へ渡る経路はこの節と末尾の「◯◯150社をすべて見る」しかなく、5社では業種の中の一帯が見えないまま終わっていた。

### 1.13 分布の中での位置

金額の絶対値ではなく分布の形を見せる。

- **位置バー** — 母集団の中でどこにいるかを1本の帯で示す。中位（median）の位置に印を置く
- **分布ヒストグラム** — 母集団の金額分布を**9ビン**で描き、その会社が入るビンを強調する

母集団は現在の表示基準の全2,961社。**中位とヒストグラムはビルド時に確定させる**（2. 非機能要件と同じ理由）。

**両端の階級が外側を含むことは文で断らない**（C14・#818）。横軸の目盛が `〜500` / `1,200+`（実測値の場合）の形で既に示しており、読み上げ用の一覧も「500万円未満」「1,200万円以上」と読む。

**なぜ** — 年収の分布は右に強く裾を引く（偏差値が100を超える理由そのもの）。平均との差だけでは、その会社が「平均よりやや上」なのか「裾のほう」なのかが区別できない。

### 1.14 年齢別の推定年収（表と幅）

1.6 の折れ線に加えて**表**を出す。列は 年齢 / 推定年収 / 推定範囲。

**推定範囲は ±20%** とし、折れ線にも同じ幅の帯を重ねる。

**±20% は目安の幅であって、統計的な信頼区間ではない。** 賃金カーブは会社間の差から作った1本の平均的な形で、1社ごとのばらつきを推定する仕組みを持っていない。この断りをチャートの近くと `/about` の両方に置く。**表の側には重ねて置かない**（Issue #95）——表・説明文・チャートは1つの節に縦に続くので、表にも同じ文を置くと一度の視界に断りが2つ並ぶ。帯を持つのはチャートなので、残すのは図の側にする。

縦軸に目盛を付け、各点の金額を数値で併記する（0起点にしない方針は `docs/company/company-page/design.md` のまま）。**目盛は丸い数字にする**（C3）——描画範囲を等分すると `422 / 1,430 / 2,439` のような端数が並び、物差しとして働かない。

**表とチャートの間に説明文を置く**（C3）。書けるのは8点から機械的に導ける事実だけ。**該当しない項目は出さない**（1.11 と同じ線）。

出す順に、**到達年齢**（C4）・最高水準の年齢・伸びが最大の5歳区間の3つ。

- **到達年齢** — 「30歳で600万円、35歳で700万円、40歳で800万円に達します」。丸い金額の段（300〜3,000万円）に8点がどこで届くかを機械的に拾う。**1文に載せるのは最大3つ**で、4つ以上あるときは最初・真ん中・最後を採る。**25歳で既に上回っている段は数えない**（8点の左端より前を持っていないため）。段に1つも届かない会社では出さない
- **判定は画面に出ている万円の値で行う。** 円のまま比べると、表が「600万円」と描いている行を文が数えないことが起こりうる。**表の金額と文の金額が食い違ってはならない**
- 「超える」ではなく「達する」と書く。万円に丸めた値で判定するので、ちょうど一致する会社で「超える」が嘘になる

**末尾で下がる理由は書かない**（Issue #95）。「60歳で下がるのは補正に使う統計側の賃金カーブが定年前後で下向きになるため」は、この会社の数値から導ける事実ではなく補正の仕組みの説明で、上の線から外れる。仕組みの話は `/about` にある。

### 1.15 このページの出典

ページ本文の末尾に、**このページに出ているデータの出典を1か所にまとめた節**を置く（C12・Issue #805）。以前の「この数字の作り方」（実測値 → 賃金カーブ → 推定年収の3ステップ）を置き換える。

データを**加工の度合い**で6つに分け、区分ごとに「該当するもの」と「どこから来たか」を並べる。

| 区分 | 該当するもの | 出典 |
| --- | --- | --- |
| 実測値 | 平均年収・平均年齢・在籍年数とその推移・従業員数 | 金融庁 EDINET の有価証券報告書（単体） |
| 計算値 | 順位・偏差値・分布・レーダー・稼ぐ力・業種の中央値 | 実測値・自己申告値と、有価証券報告書（連結）から計算 |
| 推定値 | 年齢別の推定年収と、年齢そろえの金額・順位 | 実測値と、厚生労働省「賃金構造基本統計調査」の賃金カーブ |
| 自己申告値 | 残業・有給・男女の賃金の差異 | 厚生労働省「女性の活躍推進企業データベース」への登録値 |
| AIの要約 | 社名の下の説明文・「有価証券報告書の要約」 | 有価証券報告書の本文に書いてあることだけ |
| AIの評価 | 「現状と今後」 | 有価証券報告書・公開資料（分析の節の断りと同じ2つ。材料の全部は `/about`） |

**場所を取らないこと。** 補足の節なので、作り替える前の3ステップより高くしない。

- **一次情報にリンクする。** EDINET・賃金構造基本統計調査・女性の活躍推進企業データベース。**実測値の行の「有価証券報告書」は、その会社の書類そのものへのリンク**（1.20・C13。C12 の時点では EDINET のトップだった）
- **ページに出ていないものは挙げない。** 説明文の無い会社では「AIの要約」に説明文を挙げず、推移の無い会社では推移を挙げない（在籍年数の推移が無ければ、在籍年数を「その推移」にかけず、計算値から業種の中央値を落とす。`docs/timeseries/spec.md` 2.7）。該当するものが1つも無い区分は行ごと出さない
- **時点は書かない。** 決算期は「年収に関するQ&A」の説明（1.22）と要約の節の説明が、女性活躍DBの集計時点は働きやすさの節が、分析を書いた年月と参照日は分析の節が持っている（`docs/site-chrome/spec.md` 5.1 が企業詳細で認めている決算期は2か所だけ）
- **要約と分析は別の区分にする。** どちらも生成AIの文章だが、書いてよいことの線が違う（ADR-0015 決定5）。1つに束ねると、2つを見分けられることという 1.19 の前提がこの節で崩れる

**年齢補正の手順は「年齢別の推定年収」の節の説明1行に置く。** 業種の賃金カーブで実測値を各年齢の水準に置き換えたことと、計算方法（`/about`）への導線。

**フッタには出典を重ねない。** フッタに残すのは表示基準ごとの断り（AC-9）と「本社のみ」の断り（AC-6）。

**なぜ** — 「この数字の作り方」は、ページの数字が推定年収しか無かった頃に年齢そろえの補足として置いた（C2）。C10 までに出どころの違うデータが5種類に増えた後も推定年収の説明しかしておらず、見出しの「この数字」がどれを指すのか読めなくなっていた。既定の表示は実測値（ADR-0007）なので、ページを開いたままの読者にはほとんど関係の無い説明が、カード3枚ぶんの場所を取っていた。出典を並べていた場所（フッタ・`/about` の「出典」）にも EDINET と賃金構造基本統計調査しか無く、女性活躍DBはどこにも載っていなかった。

根拠の公開そのものが差別化だという立て方（`docs/ranking/spec.md` 2.）に対しては、節ごとの出典の1行だけでなく、ページ全体を見渡せる場所が要る。**区分を加工の度合いにするのは、読者が知りたいのが「この数字をどこまで信じてよいか」だから**で、「推定値と実測値を同じ書式で並べない」（CLAUDE.md）をページ単位で見える形にする。検索エンジンに対しても、一次情報の機関名とリンクが本文に並ぶ。

### 1.16 対象外（Bolt 2 でも作らない）

株価推移、信用格付け、業績、口コミ、同業他社の比較表（1.12 の近傍10社は比較表ではない）、平均年齢・従業員数の推移。

**会社ごとの「解説文」は引き続き作らない。** 1.18 で足すのは、有報の「事業の内容」の原文から導ける事実だけを述べた**説明文**である。同じ位置に置く文でも、次は書かない——一般に知られた事業の特徴（原文に無いもの）、評価語（「業界最大手」「日本初」「高い収益性」）、他社との比較、将来の見通し。**モデルの一般知識から補った文は、混ざったことを検出する手段が無い**（ADR-0010 決定2）。

**1.19 の AI分析セクションだけが例外になる**（ADR-0015 決定1〜3。2026-08-28 に評価語、2026-09-16 に推測と一般知識）。分析では評価語に加えて、一般に知られた事業の特徴・他社との比較・将来の見通しも書いてよい。**分析でも書かないのは、モデルの記憶から書いた具体的な数値だけ**である。説明文（1.18）と要約セクションでは、この段落の線がそのまま効く。

### 1.17 数値を文章でも読めるようにする

C4（Issue #146、親 #145）。**新しい数値は1つも増やさない。** 画面に出ている数値のうち、`dl` と表のセルにしか無いものを、地の文としても置く。

- ~~**「有価証券報告書の実測値」の節** — 平均年収・平均年齢・在籍年数・従業員数を1文にする~~ → **C16（#838）で、4項目を1問ずつの質問と回答にした**（1.22）。回答はどれも「◯◯の平均年収は◯万円です」の形の文なので、この節の目的（`dl` にしか無い数値を文でも読めるようにする）はそのまま満たされる
- **平均年収推移の節** — 増減の1文（timeseries 2.1）に、**最高値の年**を足す。**最新年が最高値の会社では出さない**（増減の文が同じ数字を既に書いている）

**なぜ** — 数値が `dt`/`dd` の対と表のセルにしか無いと、読み上げでも検索結果の抜粋でも「ラベルと値」以上には読めない。同じ内容が文としても置いてあれば、どちらの経路でも意味のある形で届く。

**この節（C4）で書けるのは、画面の数値を言い直したものだけである。** 有報の「事業の内容」を材料にする説明文は 1.18 として別に立てた（ADR-0010）ので、そちらと混ぜない。

**SEO のための文だからといって、根拠の無い文は置かない**——この線は 1.18 でも変わらない。1.18 が通すのは「原文から導ける事実だけに絞る」という別の道で、根拠を緩めたのではない。

### 1.18 会社の説明文（事業の内容）

C5〜C7（#159 / #160 / #161、親 #158）。**ADR-0010 が先**。規格の文数と字数は C17（#840）で改めた。

h1 と順位行の直後——モックのアートボード 4b（PC）/ 2b（モバイル）が3行の紹介文を描いている位置——に、その会社が何をやっている会社かを述べる1〜3文を置く。

**出所は有価証券報告書の「事業の内容」だけ**（XBRL 要素 `jpcrp_cor:DescriptionOfBusinessTextBlock`）。原文をパイプラインで持ち、そこからの要約に限って載せる。他の出所（外部サイト・Wikipedia・gBizINFO の `business_summary`・モデルの一般知識）を本文の材料にしない。

**書いてよいのは原文から導ける事実だけ。** 出力の規格は次のとおり。

- 全角15〜130字 / 1〜3文
  - **1文にするのは、原文の事業の中身が1文ぶんしか無いときだけ**（「茶エキス・天然調味料・植物エキス及び粉末酒の製造販売を行っております」のような会社）。原文に中身があるなら2〜3文で書く。**2文目を有報の記載作法の文（「単一セグメントであるため記載を省略している」「子会社により構成される」）で埋めない**
  - **下限15字は、業種名の言い換えにしかならない文を落とす線**（「化学品事業を営む。」は9字）。業種はページの別の場所に出ている
  - C6 の時点では「全角60〜130字 / 2〜3文」だった。**2文に届かない会社は空にしていた**ので、事業の中身が1文だけ書かれている会社（東京海上ホールディングス・ニコン・くら寿司など）に説明文が出ていなかった（C17・#840）
- **社名を含まない**（h1 にある）
- **数値を含まない**（順位・年収・従業員数・子会社数。同じページの他の節が持っている）
- **評価語を含まない**（「業界最大手」「日本初」「高い収益性」）
- **原文に現れない固有名詞を含まない**

**書けない会社では節ごと出さない。** 原文があっても中身が当期の異動の説明だけ、という型がある（ENEOSホールディングス。事業の内訳は画像の事業系統図にあり、テキストブロックには残らない）。**文字数では検出できない**ので、落とすのは生成側の検証パスの仕事になる。**空の器・プレースホルダ・「準備中」を出さない**——ロゴが掲載社の一部にしか出ていないのと同じ扱いにする。

**要約であることと出典を、説明文の近くに出す。** 「有価証券報告書『事業の内容』をもとに要約」。**決算期はこの1行に入れない**——C7 の時点では同じ画面の「有価証券報告書の実測値（2026年3月期）」の見出しと重なり、**決算期が1画面に2回出た**（S3・`docs/site-chrome/spec.md` 5.1。Issue #128 で「推定」について決めたのと同じ扱い）。いまの企業詳細の決算期は Q&A の説明（1.22）と要約の説明の2か所と決まっていて、ここに入れると3回目になる。この1行の役目は**何を原文にしたか**で、いつかは同じページの Q&A の説明が持っている。方法は `/about` に書き、説明文から導線を張る。**同じ断りを1画面に2回置かない**（Issue #128 で「推定」について決めたのと同じ扱い）。

**表示基準（実測値 / 年齢そろえ）と年齢スイッチに依らない。** 説明文は事業の記述であって金額の話ではないので、timeseries の推移・worklife の節と同じく切り替えても変わらない。

**なぜ** — 読者の多くは「◯◯（社名） 年収」で1社を頭に置いて訪れる（`docs/company/intent.md` H1）。金額・順位・偏差値は出しているが、**その会社が何をやっているかがページのどこにも無い**。掲載社ぶんのページの一等地が空いたままになっている。

**対象外** — meta description と JSON-LD への流用（site-chrome の S2・#116 と衝突する）、ランキング表への表示（#22）、説明文の検索対象化、会社ごとの手動での上書き。

### 1.19 有報の要約と AI 分析

C8（[#240](https://github.com/varmil/nenshu/issues/240)）・C9（[#241](https://github.com/varmil/nenshu/issues/241)）・C10（[#242](https://github.com/varmil/nenshu/issues/242)）、親 [#214](https://github.com/varmil/nenshu/issues/214)。**ADR-0015 が先**。

企業詳細ページに**2つのセクション**を置く。**規格が違うので、読者が見分けられることが要件になる。**

| | 要約セクション | AI分析セクション |
| --- | --- | --- |
| 出所 | 有報の4節（下表） | 同じ4節＋**同じページが表示している数値**＋**取得した外部の文書**＋**モデルの一般知識**（具体的な数値を除く） |
| 書いてよいこと | 原文に**書いてある**事実 | 材料から**推測できる**解釈・因果・評価・見通し |
| 評価語 | **書かない**（1.18 と同じ線） | **書く**（これが本体） |
| モデルの記憶から補う | 不可 | **文脈・相場観・一般的な理解は可。具体的な数値（金額・率・順位・シェア・従業員数）は不可** |
| 出典の表示 | 有報とその節 | **参照した URL を画面に出す** |

**要約セクションの出所は有価証券報告書の4節だけ**（`docs/company/business-analysis-text/design.md` に要素名の表がある）。

| 節 | どの観点に効くか |
| --- | --- |
| 経営者による財政状態・経営成績及びキャッシュ・フローの状況の分析（MD&A） | うまくいっていること / いないこと |
| 事業等のリスク | うまくいっていないこと |
| 経営方針・経営環境及び対処すべき課題等 | 今後の挑戦 |
| サステナビリティに関する考え方及び取組（**人的資本を含む**） | 求職者向けの要約 |

**「事業の内容」は出所に入れない。** 1.18 の説明文が同じ原文を使っており、両方に置くと1画面に同じ内容が2回出る（ADR-0015 決定6）。

**分析の主役は事業の定性的な状況で、数値は脇役。** 数値を並べるのは目的ではない——有報が無機質なのは数値しか無いからで、それを短くしても読者の負担は減らない。**分析に含めてよい算用数字の個数には上限を置く**（見出しと合わせて5個。C9 で決めた。`pipeline/analysis/gate.py`）。「半減」「増収増益」「2割」のように語で言えるものは語で言う。

**分析の冒頭に「その会社がいまどうなのか」を一言で置く。** 続けて「うまくいっていること」「うまくいっていないこと」「今後の挑戦」を地の文で書く。**観点は固定し、語彙は固定しない**——段階評価（好調 / 安定 / 不振）に潰すと、「本業は苦しいが最終利益は増えている」「業績は堅いが平均年収は10年で下がっている」のような**この機能の値打ちそのものである食い違い**が出せない（ADR-0015 却下案）。

**分析の材料は次の3つで、いずれも取ってきた実体がある**（ADR-0015 決定3）。そのうえでモデルの一般知識も使ってよい（下記）。

1. **有報の4節**（上の表。C8 が全社ぶん調達済み）
2. **同じページが既に表示している数値** — 平均年収の10年推移・稼ぐ力とその推移・定着（平均在籍年数）・残業と有給
3. **その会社について Web から取得した文書** — 公式サイト・ニュースリリース（自社ページでも PR TIMES 等の配信サービスでも）・採用求人（自社ページでも HRMOS・Indeed 等でも）・その他、検索で辿れる一次情報

**3 は積極的に使う。** 有報は年1回・法定の書式で、書いてあるのは提出時点の会社の言い分に限られる——**いま何を募集し、直近に何を発表したかは1文字も無い**。有報の無機質な情報を多面的に読み、求職者に分かりやすい形へ消化することがこのセクションの狙いなので、有報だけに閉じると狙いに届かない。**配信サービスや求人サイトを理由に落とさない**——出所の格ではなく、取れて出典を示せるかどうかで見る。

**モデルの一般知識は使ってよい。ただし具体的な数値は材料にあるものに限る**（2026-09-16・ADR-0015 決定3）。業界の文脈・語の説明・相場観・競合との位置関係・将来性の評価は、取ってきた文書の裏付け無しに書いてよい。**記憶から金額・率・順位・シェア・従業員数を書かない**——記憶から書いた文脈が外れても「そう読める話」の範囲に収まるが、**記憶から書いた数字は事実の顔をして出る**。読者は有報の数値と区別できず、同じページの表と食い違えば、根拠を全部画面に出すという立て方が崩れる。

**参照した URL を分析の近くに並べる。** 読者が開いて確かめられることが、材料を有報の外へ広げてよい前提になる。**出所の信頼性は読者が評価してよい**——我々が配信サービスを選別すると、その基準自体が画面に出ない主観になる。

**取り方は ADR-0008 の線を引き継ぐ。** ブラウザの UA への偽装をしない、ヘッドレスブラウザで取りに行かない、アクセス制御（画像認証・WAF のチャレンジ）を回避しない。403・503 はその会社ではその材料を使わない、と読む。**転載しない**——導いた解釈を自分の言葉で書くのであって、原文を長く写さない。

**AI による評価であることを分析セクションに書く**（ADR-0015 決定5）。推測を言い切ってよくなったぶん、これが有報に書いてある事実ではないと読者に分かることの重みが増す。要約セクションには書かない（あちらは事実なので、同じ断りを付けると2つの区別が消える）。**同じ断りを1画面に2回置かない**（Issue #128 で「推定」について決めたのと同じ扱い）。

**2つのセクションはそれぞれの時点を示す**（2026-09-24・運営者の判断）。分析は**書いた年月**（公開資料と一般知識を使って「今後」まで書くので、いつの評価かが読めないと古くなったことに気づけない）、要約は**原文の決算期**（有報の言い直しなので、書いた日ではなくどの年度の有報かが効く）。要約の決算期は Q&A の説明（1.22。C16 までは「有価証券報告書の実測値」の見出し）と合わせて企業詳細に2回出るが、`docs/site-chrome/spec.md` 5.1 の例外として認めた。

**書けない会社ではそのセクションを出さない。** 空の器・プレースホルダ・「準備中」を出さない（1.18 と同じ扱い）。

**要約と分析は対で出す。片方だけのページを作らない**（2026-08-28・運営者の判断。~~要約は書けるが分析は書けない会社が出てよい~~ を改めた）。満たし方は2つあり、**書けなかったほうを書き直して両方通す**のが本筋になる——C9 のパイロットで落ちた2社は、どちらも**1文を直せば通った**（材料は足りていて、言い過ぎていただけだった）。**それでも通らなければ、残ったほうも落とす。**

**この「両方落とす」を残すことが要件である。** 「必ず対にする」を絶対条件にすると、**通らない分析を通す圧力がそのまま検証パスに掛かる**——落とせるようにしておくことで、書き直しの回数に上限を置ける。**対にするのは両方向**（要約が落ちたときも分析を落とす）。原文に書いてあることすら書けなかった会社の解釈は据わりが悪く、表示側の分岐も「両方あるか、両方無いか」の2状態で済む。

**材料の薄い会社でも、一般知識の範囲までは書いてよい。** 外部の文書が取れる量は上場の大手に偏るが、一般知識の範囲は材料の多寡によらない。**埋めてはならないのは具体的な数値だけ**で、外部の文書が取れなかったぶんを記憶の数字で補わない（ADR-0015 決定8）。

**表示基準（実測値 / 年齢そろえ）と年齢スイッチに依らない。** 事業の状況の話であって金額の話ではないので、切り替えても変わらない（1.18・推移・worklife の節と同じ扱い）。

**なぜ** — 有報には定量的・無機質な情報しか無く、定性的な意味付けが欠けている。求職者が知りたいのは「この会社はいまどうなのか」で、それは数万字の本文を読める人にしか分からない。金額・順位・偏差値・推移は出しているのに、**その意味を言った文がページのどこにも無い。**

**対象外** — リクエスト時の生成（ADR-0012・ADR-0004）、**モデルの記憶から書いた具体的な数値**（金額・率・順位・シェア・従業員数）、外部の材料を全社ぶん事前に集める工程（生成時に集めて URL を残す。ADR-0015 決定7）、会社ごとの手動での上書き、meta description と JSON-LD への流用（S2・#116 と衝突する）、ランキング表への表示、ページタイトルの変更（#214 の未決事項のまま）。

### 1.20 有報への直リンク

C13（Issue #814）。**その会社の有価証券報告書——実測値の4項目（1.22 の Q&A。C16 までは「有価証券報告書の実測値」の節）を取った書類そのもの——を EDINET で開くリンク**を置く。

- **置き場所は、実測値の4項目の下辺に付けた帯。** 左に「この会社の有価証券報告書」、右に「EDINETで開く」。帯は4項目の枠とつながって見え、どの数字の出典かが形で分かる（Claude Design の案 D・2026-09-24 に運営者が選んだ）。**帯全体を1つのリンクにする**——押せる高さを確保するため。**C16 で4項目を Q&A に作り替えたので、いまは Q&A の枠の下辺に付く**（1.22）
- **モバイルでも1行に収める。** 見出しの隣に置く案は、見出しだけで本文の幅を使い切っているモバイルで行が折れるので採らない
- **帯に決算期を書かない。** 企業詳細の決算期は Q&A の説明と要約の説明の2か所と決まっている（`docs/site-chrome/spec.md` 5.1）。どの年の書類かは同じ節の Q&A の説明が持っている
- **「このページの出典」の実測値の行の「有価証券報告書」も、同じ書類へのリンクにする**（1.15）
- **別タブで開く。** 読者はページの数字と書類を見比べる

**なぜ** — 有報ベースであることがこのサービスの差別化で、**読者が数字を自分で確かめられること**がその中身になる。これまでリンクは EDINET のトップにしかなく、2,961社の中から目当ての書類を探すのは読者の手間だった。

**対象外** — 10年ぶんの有報へのリンク（平均年収推移の表から張るのはつながりが弱い。見せ方を決めてから別に扱う）、書類の中の該当ページへの直接の移動（EDINET の画面が持つ機能で、こちらからは指定できない）。

本文の並びは次のとおり。**C15 で動かしたのは先頭の2つだけ**で、3つ目から後ろは変えていない。

1. 平均年収カード
2. 公開資料による全体像（レーダー）
3. {社名}の現状と今後（AI 分析・1.19）
4. 残業・有給・男女の賃金の差異
5. 年齢別の推定年収
6. 平均年収推移（過去10年間）
7. 在籍年数推移（過去10年間）（T4・#835。`docs/timeseries/spec.md` 2.7）

9. {社名}の有価証券報告書の要約（1.19）

11. このページの出典（1.15）

**C16（#838）で「有価証券報告書の実測値」（5. と 6. の間にあった）を Q&A に作り替え、要約の直後へ移した**（1.22）。他の節の並びは変えていない。

**なぜ** — 検索からの流入の語は「年収」「年収ランキング」が100%を占めている（親 #820・運営者の観察）。読者が探しているのは金額で、レーダーはその金額を5軸の1本として含む全体の図になる。レーダーを先に置くと、答えの手前に読者が求めていない図が1枚挟まる。実測で、カードの金額は PC（1280×800）で上から 954px、390×844 で 1,139px にあり、**どちらも最初の画面の外だった**。

**分析はカードの直後ではなくなる。** C10 が「平均年収カードの直後」に置いた理由は、答え（カード）を押し下げないことと、数字を見た直後に「この会社はいまどうなのか」を続けることの2つで、どちらもカードとレーダーの後ろのままで満たせる。

### 1.22 実測値の4項目を Q&A で出す

C16（Issue #838・親 #836）。平均年収・平均年齢・平均勤続年数・従業員数（いずれも有報の単体の値）を、**1項目1問の質問と回答**で出す。C1 からの「有価証券報告書の実測値」の節（C4 の地の文と4セルの表）を置き換える（Claude Design `Company Actuals QA.dc.html` の 1b。2026-09-26 に運営者が選んだ）。

| 部分 | 文言（キーエンスの例） |
| --- | --- |
| 見出し | `株式会社キーエンスの年収に関するQ&A` |
| 説明 | `2026年3月期の有価証券報告書の値です。提出会社（単体）のもので、連結子会社の従業員は入りません。` |
| 質問 / 回答 | `株式会社キーエンスの平均年収はいくらですか？` / `株式会社キーエンスの平均年収は2,178万円です。` |
| | `株式会社キーエンスの平均年齢は何歳ですか？` / `株式会社キーエンスの平均年齢は35.0歳です。` |
| | `株式会社キーエンスの平均勤続年数は何年ですか？` / `株式会社キーエンスの平均勤続年数は11.3年です。` |
| | `株式会社キーエンスの従業員数は何人ですか？` / `株式会社キーエンスの従業員数は3,306人です（提出会社単体。連結子会社の従業員は含みません）。` |

- **4問とも開いたまま並べる。** 折りたたむ案（1c）は採らない——閉じた回答は抜粋に使われにくく、4問なら開いたままでも高さを抑えられる
- **質問も回答も社名から始める。** 回答の1文だけが切り出されても、どの会社の話かが残る
- **従業員数の回答にだけ単体の断りを重ねる。** 説明の1行と同じ内容だが、「◯◯の従業員数」を探す読者は連結の人数を思い浮かべていることが多く、回答だけが引用されたときに断りが落ちると別の数字として読まれる
- **太字は回答の値だけ。値は数字と単位の間で折り返さない**（390px では回答が2〜3行になる）
- **在籍年数は「平均勤続年数」と書く**（`docs/product/glossary.md` の例外）。質問は読者が検索に打つ語に合わせる。C4 の地の文も「平均勤続年数」だった
- **決算期は説明の1行に1回**（`docs/site-chrome/spec.md` 5.1）。見出しにも質問と回答にも入れない
- **置き場所は要約（1.19）の直後、このページの出典（1.15）の直前**（同 1d）。本文の並びは 1.21
- **EDINET の帯（1.20）は Q&A の枠の下辺に付ける**
- **表示基準と年齢スイッチに依らない。** どれも有報の値そのもの
- **「推定」の語を置かない**（AC-9。実測値だけの節）

**なぜ** — 問いの形で書いた本文は、検索結果の抜粋や AI による回答に1問ずつ引用されやすい（親 #836）。「◯◯ 平均年収」「◯◯ 平均年齢」は読者がそのまま打つ問いで、同じ問いと答えがページにあれば、どの1問を切り出しても意味が通る。C1 の表と C4 の地の文は同じ4つの数字を2回言っており、Q&A にすると1回で済む。

**末尾に移すのは**、同じ金額が本文の先頭のカード（1.21）にあり、年齢別の推定年収と推移の間に挟まった実測値の節は「今年の1点」を繰り返していたから。推移の2節は、節の説明（各年の有報の実測値）で自立している。

**構造化データ（`FAQPage`）は出さない**（2026-09-26・運営者の判断）。Google は 2026-05-07 に FAQ のリッチリザルトを終了しており、書いても検索結果の見え方は変わらない。`potentialAction` を出さないのと同じ扱い（`docs/site-chrome/spec.md` 4.4）。画面の Q&A は1つの関数から組んでいるので、必要になれば同じ配列から出せる。

**対象外** — FAQPage の JSON-LD、質問の追加（順位・推移・残業など）、折りたたみ、過去の年の値の Q&A。

## 2. 非機能要件

**配信** — ランキングと同じフルSSR（ADR-0004）。エッジキャッシュを効かせる。

**データ量** — クライアントに送るのは当該1社ぶんの数値だけにする。全社ぶんのデータを企業詳細ページに載せない。

**計算量** — 順位・偏差値の母集団統計はビルド時に確定させる。リクエストごとに1,867社×8年齢を計算しない（Workers Free の CPU 10ms/リクエスト制約。`docs/ranking/ssr-migration/design.md` 参照）。

**応答** — 年齢スイッチの操作から表示更新まで100ms以内。ネットワークアクセスを伴わない。

**対応環境** — モバイルを主とする。横スクロールを発生させない。

**SEO** — 数値はすべて初期HTMLに含める。クライアント側の描画待ちにしない。canonical・sitemap は ADR-0006 に従う。

**アクセシビリティ** — 年齢スイッチはキーボードで操作できる。チャートは画像ではなくSVGで、数値を読み上げられる代替を持たせる。

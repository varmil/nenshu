# spec.md — 企業詳細ページ

対象面: user-web（ユーザー画面）

1社につき1枚、計2,961枚のページを `/company/[id]` に置く。用語は `docs/product/glossary.md` に従う。URL の構成は ADR-0006 に従う。

---

## 1. 企業詳細ページ（`/company/[id]`）

### 1.1 何を出すか（WHAT）

1社の年齢補正年収と、その会社が全体・業界内でどの位置にあるかを出す。載せる数値はすべて `companies.json` / `curves.json` から導けるものに限る。

初期状態は目標年齢35歳。

### 1.2 なぜ（WHY）

読者の多くは特定の1社を頭に置いて訪れる。「◯◯（社名） 年収」という検索の受け皿が無く、その問いは2,961行の表の中でしか解けない。順位だけでは水準が伝わらないため、偏差値・全体平均との差・母集団の中での位置を同時に出す。

### 1.3 ID

- 証券コードがある会社はそれ（1,760社。`6861`・新形式の `285A` を含む）
- 無ければ EDINETコード（107社。`E01798` 形式）

上場か否かではなく証券コードの有無で分ける。

ADR-0006 で決定。書類ID由来のIDは使わない（毎年変わるため）。

### 1.4 載せるもの

| 区分 | 項目 | 備考 |
| --- | --- | --- |
| 見出し | 会社名 | 「本社のみ」バッジを添える |
| | 業種（tse33） | ランキングの業種フィルタへのリンクにする |
| **主役** | **目標年齢時点の推定年収** | 推定であることを常時示す |
| 位置 | 全体順位 | `n位 /2,961社` |
| | 業界内順位 | `n位 / m社`。業種名を添える |
| | 年収偏差値 | 数字だけを出す。**注記も添えない**（2026-08-20 改訂）。100を超えうる理由はランキングの脚注と `/about` にあり、このページでは同じ視界の順位・位置バーに水準を読ませる |
| | 全体平均との差 | `＋◯万円` / `−◯万円`。母集団の平均額も出す |
| 実測値 | 平均年収（実額） | 補正前 |
| | 平均年齢 / 在籍年数 / 従業員数（単体） | |
| 推移 | 年齢別の推定年収チャート | 25〜60歳の8点 |
| 前提 | 出典と `/about` への導線 | EDINET・賃金構造基本統計調査 |

金額の書式はランキングと揃える（万円単位・カンマ区切りの整数）。年齢と在籍年数は小数第1位まで。偏差値は小数第1位まで。

**「上位◯%」は画面に出さない**（2026-08-20、運営者の判断。Claude Design のモックに無いものを足さないため）。値そのものは `CompanyAgeStats.topPercent` として残っている（`docs/product/glossary.md`）。

**推定値と実測値を同じ書式で並べない**（CLAUDE.md）。推定年収と平均年収（実額）は視覚的に区別する。

### 1.5 年齢スイッチ

ランキングと同じ 25 / 30 / 35 / 40 / 45 / 50 / 55 / 60 歳の8段。単一選択。

操作すると推定年収・全体順位・業界内順位・偏差値・全体平均との差が更新される。**ページ遷移も再取得も発生させない。**

**URL には出さない**（R1・ADR-0012）。表示基準はクライアントの状態としてだけ持つ。このページを全社ぶん事前生成しており、`force-static` のページは `searchParams` を読めない。年齢そろえで変わるのは推定年収まわりだけで、実測値の節も10年推移も変わらないので、ページ全体にかかるパラメータとして持つ理由がない——いずれ推定年収の要素に付いたスイッチへ寄せる。

**ランキング（`/`）の `?age=N` は変えない**（ADR-0007）。あちらは2,961行の並び順そのものを変え、8件をインデックスさせている。同じ語だが役割が違う。

配ってしまった `/company/[id]?age=N` は**読まずに URL から落とす**（`replaceState`）。落とさないと「URLは30歳・画面は実測値」がそのまま残る。

### 1.6 年齢別の推定年収チャート

25〜60歳の8点を結ぶ折れ線。縦軸は推定年収。選択中の目標年齢を強調する。

**このチャートは1社の中の推移であって、同じ人が歳を取っていく軌跡ではない**（賃金カーブの性質）。**この注記はチャートの近くには置かず、`/about` の1か所に持たせる**（2026-08-20 改訂）。図に添える断りは ±20% の帯の意味だけにする——**帯だけを見ると信頼区間に見える**ので図の側から外せないのはそちらで、軌跡の話は仕組みの説明にあたり `/about` の担当になる。

### 1.7 順位・偏差値の定義

母集団は**その目標年齢時点の推定年収**で並べた全2,961社。

- **全体順位** — 同額の会社は同順位にする（自分より高い会社の数 ＋ 1）
- **上位◯%** — `全体順位 ÷ 2,961 × 100`
- **業界内順位** — 同じ tse33 の会社に限った同じ計算
- **年収偏差値** — `50 + 10 ×（自社の推定年収 − 母集団の平均）÷ 母集団の標準偏差`。母集団は全2,961社
- **全体平均との差** — `自社の推定年収 − 母集団の平均`

年齢ごとに母集団の平均・標準偏差が変わるため、これらはすべて目標年齢に依存する。

### 1.8 存在しないID

`/company/存在しないid` は 404 を返す。

### 1.9 ランキングからの導線

ランキング表・カードの会社名から企業詳細ページに遷移できる。

### 1.10 対象外（v1）

平均年収の10年推移、株価推移、信用格付け、業績、口コミ、会社ごとの解説文、同業他社の比較表。

10年推移は `docs/product/product.md` の `timeseries` 施策、株価・格付けは `market-data` 施策として別に扱う。

**10年推移は Bolt 2 の C2 で入れる**（timeseries 施策の T1 を C2 に同梱する。`docs/timeseries/overview.md`）。株価・格付け・業績・口コミは対象外のまま。

**会社の説明文は 1.18 で対象に入れた**（2026-08-23・ADR-0010・#158）。v1 で外していたのは「2,961社ぶんを人手で書けず、生成して埋めれば根拠の無い断定が混ざる」ためだったが、**出所を有価証券報告書の「事業の内容」に固定し、原文から導けない文を落とす**ことでこの理由が外れた。**一般に知られた話や評価を含む解説文は引き続き作らない**（1.16）。

## 1B. 企業詳細ページ（Bolt 2 の追加）

Issue #21（UI改善）で足す。アートボード 4b（PC）/ 2b（モバイル）に対応する。数字を増やすのではなく、**すでに出している数字を読める形にする**のが主眼になる。

### 1.11 この会社の要点

手持ちのデータから箇条書きを組み立てて出す。**会社ごとの解説文は書かない**（1.16 のまま対象外。事業の内容の要約は 1.18 が別に持つ）——ここで書けるのは数値から機械的に導ける事実だけである。

出す候補は、位置（全体順位と偏差値・業界内順位）、平均年齢と在籍年数から読める人員構成、従業員規模、「本社のみ」バッジの含意。**該当しない項目は出さない**（無理に項目数を揃えない）。

**なぜ** — カードに並ぶ数値は正確だが、どれが目立つ数字なのかは読者が自分で見つけるしかない。箇条書きはその要約であって、新しい情報ではない。

### 1.12 水準が近い会社

**同じ業種**で、現在の表示基準の金額が近い会社を10社出す（2026-08-25 に5社から増やした。Issue #195）。会社名と金額を並べ、それぞれの企業詳細ページへのリンクにする。**「本社のみ」バッジはここでは出さない**（2026-08-20、運営者の判断）——316px の列にバッジを足すと社名がそのぶん切れる。

**リクエスト時に算出する。** 1業種は最大223社なので、当該1社ぶんの計算に加えても Workers の CPU 制約（2. 非機能要件）に収まる。ビルド時に2,961社×9基準ぶんの近傍表を作らない。

自分自身は含めない。表示基準を切り替えたら選ばれる10社も変わる。

**各行に業界内順位と平均年齢を添える**（C3）。社名と金額だけでは、並んでいる会社が自分より上なのか下なのかが読み取れない。**業界内順位は自分を含めた並びで数える**——自分を除いてから振ると、自分より上の会社が1つずつ繰り上がって本来の順位とずれる。

末尾に「◯◯150社をすべて見る」の導線を置く。行き先は `?ind=` のURLで、ランキングの業種チップと同じ経路になる（ADR-0006）。

**なぜ** — 「2,178万円」が高いのか低いのかは、順位や偏差値よりも「同じ業種のどのあたりに並ぶか」で伝わる。**10社にしたのは回遊のため**（Issue #195）——同じ業種の別の会社へ渡る経路はこの節と末尾の「◯◯150社をすべて見る」しかなく、5社では業種の中の一帯が見えないまま終わっていた。

### 1.13 分布の中での位置

金額の絶対値ではなく分布の形を見せる。

- **位置バー** — 母集団の中でどこにいるかを1本の帯で示す。中位（median）の位置に印を置く
- **分布ヒストグラム** — 母集団の金額分布を**9ビン**で描き、その会社が入るビンを強調する

母集団は現在の表示基準の全2,961社。**中位とヒストグラムはビルド時に確定させる**（2. 非機能要件と同じ理由）。

**なぜ** — 年収の分布は右に強く裾を引く（偏差値が100を超える理由そのもの）。平均との差だけでは、その会社が「平均よりやや上」なのか「裾のほう」なのかが区別できない。

### 1.14 年齢別の推定年収（表と幅）

1.6 の折れ線に加えて**表**を出す。列は 年齢 / 推定年収 / 推定範囲。

**推定範囲は ±20%** とし、折れ線にも同じ幅の帯を重ねる。

**±20% は目安の幅であって、統計的な信頼区間ではない。** 賃金カーブは会社間の差から作った1本の平均的な形で、1社ごとのばらつきを推定する仕組みを持っていない。この断りをチャートの近くと `/about` の両方に置く。**表の側には重ねて置かない**（Issue #95）——表・説明文・チャートは1つの節に縦に続くので、表にも同じ文を置くと一度の視界に断りが2つ並ぶ。帯を持つのはチャートなので、残すのは図の側にする。

縦軸に目盛を付け、各点の金額を数値で併記する（0起点にしない方針は `docs/company/company-page/design.md` のまま）。**目盛は丸い数字にする**（C3）——描画範囲を等分すると `422 / 1,430 / 2,439` のような端数が並び、物差しとして働かない。

**表とチャートの間に説明文を置く**（C3）。書けるのは8点から機械的に導ける事実だけ。**該当しない項目は出さない**（1.11 と同じ線）。

出す順に、**到達年齢**（C4）・最高水準の年齢・伸びが最大の5歳区間の3つ。

- **到達年齢** — 「30歳で600万円、35歳で700万円、40歳で800万円に達します」。丸い金額の段（300〜3,000万円）に8点がどこで届くかを機械的に拾う。**1文に載せるのは最大3つ**で、4つ以上あるときは最初・真ん中・最後を採る。**25歳で既に上回っている段は数えない**（8点の左端より前を持っていないため）。段に1つも届かない会社では出さない
- **判定は画面に出ている万円の値で行う。** 円のまま比べると、表が「600万円」と描いている行を文が数えないことが起こりうる。**表の金額と文の金額が食い違ってはならない**
- 「超える」ではなく「達する」と書く。万円に丸めた値で判定するので、ちょうど一致する会社で「超える」が嘘になる

**末尾で下がる理由は書かない**（Issue #95）。「60歳で下がるのは補正に使う統計側の賃金カーブが定年前後で下向きになるため」は、この会社の数値から導ける事実ではなく補正の仕組みの説明で、上の線から外れる。仕組みの話は `/about` にある。

### 1.15 この数字の作り方

ページ最下部に、実測値 → 賃金カーブ → 推定年収の**3ステップ**を並べる。詳細は `/about` に置いたまま、ここでは流れだけを見せて導線にする。

**なぜ** — 出典と `/about` へのリンク（1.4）は footer にあり、読み飛ばされる。根拠の公開そのものが差別化だという立て方（`docs/ranking/spec.md` 2.）に対して、導線が弱い。

### 1.16 対象外（Bolt 2 でも作らない）

株価推移、信用格付け、業績、口コミ、同業他社の比較表（1.12 の近傍10社は比較表ではない）、平均年齢・従業員数の推移。

**会社ごとの「解説文」は引き続き作らない。** 1.18 で足すのは、有報の「事業の内容」の原文から導ける事実だけを述べた**説明文**である。同じ位置に置く文でも、次は書かない——一般に知られた事業の特徴（原文に無いもの）、評価語（「業界最大手」「日本初」「高い収益性」）、他社との比較、将来の見通し。**モデルの一般知識から補った文は、混ざったことを検出する手段が無い**（ADR-0010 決定2）。

### 1.17 数値を文章でも読めるようにする

C4（Issue #146、親 #145）。**新しい数値は1つも増やさない。** 画面に出ている数値のうち、`dl` と表のセルにしか無いものを、地の文としても置く。

- **「有価証券報告書の実測値」の節** — 平均年収・平均年齢・在籍年数・従業員数を1文にする（「有価証券報告書によると、◯◯の平均年収は◯万円、平均年齢は◯歳、平均勤続年数は◯年、従業員数は◯人です」）。**決算期は書かない**——節の見出しが持っている（`docs/site-chrome/spec.md` 5.1。1画面に1回）
- **平均年収推移の節** — 増減の1文（timeseries 2.1）に、**最高値の年**を足す。**最新年が最高値の会社では出さない**（増減の文が同じ数字を既に書いている）

**なぜ** — 数値が `dt`/`dd` の対と表のセルにしか無いと、読み上げでも検索結果の抜粋でも「ラベルと値」以上には読めない。同じ内容が文としても置いてあれば、どちらの経路でも意味のある形で届く。

**この節（C4）で書けるのは、画面の数値を言い直したものだけである。** 有報の「事業の内容」を材料にする説明文は 1.18 として別に立てた（ADR-0010）ので、そちらと混ぜない。

**SEO のための文だからといって、根拠の無い文は置かない**——この線は 1.18 でも変わらない。1.18 が通すのは「原文から導ける事実だけに絞る」という別の道で、根拠を緩めたのではない。

### 1.18 会社の説明文（事業の内容）

C5〜C7（#159 / #160 / #161、親 #158）。**ADR-0010 が先**。

h1 と順位行の直後——モックのアートボード 4b（PC）/ 2b（モバイル）が3行の紹介文を描いている位置——に、その会社が何をやっている会社かを述べる2〜3文を置く。

**出所は有価証券報告書の「事業の内容」だけ**（XBRL 要素 `jpcrp_cor:DescriptionOfBusinessTextBlock`）。原文をパイプラインで持ち、そこからの要約に限って載せる。他の出所（外部サイト・Wikipedia・gBizINFO の `business_summary`・モデルの一般知識）を本文の材料にしない。

**書いてよいのは原文から導ける事実だけ。** 出力の規格は次のとおり。

- 全角60〜130字 / 2〜3文
- **社名を含まない**（h1 にある）
- **数値を含まない**（順位・年収・従業員数・子会社数。同じページの他の節が持っている）
- **評価語を含まない**（「業界最大手」「日本初」「高い収益性」）
- **原文に現れない固有名詞を含まない**

**書けない会社では節ごと出さない。** 原文があっても中身が当期の異動の説明だけ、という型がある（ENEOSホールディングス。事業の内訳は画像の事業系統図にあり、テキストブロックには残らない）。**文字数では検出できない**ので、落とすのは生成側の検証パスの仕事になる。**空の器・プレースホルダ・「準備中」を出さない**——ロゴが掲載社の一部にしか出ていないのと同じ扱いにする。

**要約であることと出典を、説明文の近くに出す。** 「有価証券報告書『事業の内容』（2026年3月期）をもとに要約」。決算期は直書きせず `web/lib/data/period.ts` から引く（`docs/site-chrome/spec.md` AC-20）。方法は `/about` に書き、説明文から導線を張る。**同じ断りを1画面に2回置かない**（Issue #128 で「推定」について決めたのと同じ扱い）。

**表示基準（実測値 / 年齢そろえ）と年齢スイッチに依らない。** 説明文は事業の記述であって金額の話ではないので、timeseries の推移・worklife の節と同じく切り替えても変わらない。

**なぜ** — 読者の多くは「◯◯（社名） 年収」で1社を頭に置いて訪れる（`docs/company/intent.md` H1）。金額・順位・偏差値は出しているが、**その会社が何をやっているかがページのどこにも無い**。掲載社ぶんのページの一等地が空いたままになっている。

**対象外** — meta description と JSON-LD への流用（site-chrome の S2・#116 と衝突する）、ランキング表への表示（#22）、説明文の検索対象化、会社ごとの手動での上書き。

## 2. 非機能要件

**配信** — ランキングと同じフルSSR（ADR-0004）。エッジキャッシュを効かせる。

**データ量** — クライアントに送るのは当該1社ぶんの数値だけにする。全社ぶんのデータを企業詳細ページに載せない。

**計算量** — 順位・偏差値の母集団統計はビルド時に確定させる。リクエストごとに1,867社×8年齢を計算しない（Workers Free の CPU 10ms/リクエスト制約。`docs/ranking/ssr-migration/design.md` 参照）。

**応答** — 年齢スイッチの操作から表示更新まで100ms以内。ネットワークアクセスを伴わない。

**対応環境** — モバイルを主とする。横スクロールを発生させない。

**SEO** — 数値はすべて初期HTMLに含める。クライアント側の描画待ちにしない。canonical・sitemap は ADR-0006 に従う。

**アクセシビリティ** — 年齢スイッチはキーボードで操作できる。チャートは画像ではなくSVGで、数値を読み上げられる代替を持たせる。

## 3. 受け入れ基準

数値は `2026-06` 版データの実測値。

### AC-1 初期表示

ランキングと同じく既定の表示基準は**実測値**（ADR-0007）。順位・偏差値も実測値の分布に対して出す。

```gherkin
Given /company/6861 をクエリ無しで開く
When 何も操作しない
Then 「株式会社キーエンス」と業種「電気機器」が表示される
And 「平均年収（有価証券報告書・単体）」として2,178万円が表示される
And 全体順位が「1位 / 1,867社」と表示される
```

# C8 分析用テキストの調達 — plan.md

参照: Issue [#240](https://github.com/varmil/nenshu/issues/240)（親: [#214](https://github.com/varmil/nenshu/issues/214)）, `docs/company/spec.md` 1.19（AC-24）, [ADR-0015](../../adr/0015-company-analysis-subjectivity.md)
依存: なし（ADR-0015 の後）

## Context

ADR-0015 で「要約セクションと AI分析セクションを作る」と決めた。その原文を持ってくるのが
この Unit で、**要約も分析も作らないし、画面も1ピクセルも変わらない。** C5 と同じ
「表示に影響しない Unit」の型になる。

材料は既に取得経路の中を通っている。`pipeline/salary/edinet.py` が EDINET API v2 の
CSV 形式（`type=5`）を叩き、いまテキストブロックを2つ——「従業員の状況」と
「事業の内容」——拾っている。**同じ ZIP の中に4節も入っている**ので、拾う対象を増やす
だけで済む。

**C5 と違うところが1つある。** 「事業の内容」は `jpcrp_cor:` の1要素で全社ぶん取れたが、
**人的資本の節は会社独自の名前空間で来ることがある**（キーエンスの
`jpcrp030000-asr_E26831-000:StrategyHumanCapitalTextBlock`）。`TEXT_BLOCKS` はいま
完全一致の辞書なので、**引き方を1段変える必要がある。** P2（#168）で経常利益の要素名が
名前空間で決め打ちできなかったのと同じ形。

## 進め方

1. **実物の要素名を数えてから引き方を決める。** 名前空間・局所名がどう散らばっているかを
   母集団ぶんの ZIP に対して数える。**「接尾辞で拾う」と決め打ちで書き始めない**——
   接尾辞にすると `…StrategyHumanCapitalTextBlock` のような別の要素まで巻き込みうるので、
   実物がどの形で来ているかを見てから幅を決める。
2. **引き方を変える。** 完全一致の辞書を、名前空間に依らない引き方に替える。
   **既存の2要素の振る舞いを変えない**ことが条件になる——広げた結果、従業員の状況や
   事業の内容が別の値を採るようになっていないかを、出力の差分で確かめる（手順6）。
3. **4節を `TEXT_BLOCKS` に足す。** 要素ごとに保存の条件と複数現れたときの採り方を
   持たせる形（C5 が作った `TextBlockSpec`）はそのまま使う。平文にする規則
   （`businesstext.to_plain_text`）も共有する——**節ごとに整え方を分けない。**
4. **母集団ぶんの書類を落とす。** `ranking_unified_2026.csv` の `doc_id` ——平均年間給与を
   拾ったのと同じ書類。キャッシュが生きている環境では0件になる。
5. **抽出を回して CSV を書き、節ごとの取得率・文字数と落ちた理由の内訳を見る。**
   1つも取れない会社が何社かはここで初めて分かる（無作為60社の実測では4節とも 60/60）。
6. **既存の出力が1バイトも変わっていないことを確かめる。** `build:data` を回して
   `web/public/data/` に差分が出ないことと、`business_text_2026.csv` が変わらないことを見る
   （AC-24 の最後）。**手順2で引き方を広げているので、ここが実質の回帰テストになる。**
7. **CSV の持ち方を実測で決める。** 1社あたり約14,400字・全社で約4,270万字になる見込み。
   `business_text_2026.csv` が15.2MB あるので、1ファイルにするか節ごとに分けるかは
   **実際の大きさを見てから**決める。

## 着手前に見えている判断

**取得の窓を引き直さない。** `run.py` を回し直すと `twelve_month_window()` が「回した日から
12か月」を取り直し、**母集団そのものが入れ替わる**（C5 と同じ理由）。母集団は
`ranking_unified_2026.csv` に確定しているものを使う。

**「事業の内容」を4節に足さない。** 説明文（C7）が同じ原文を使っており、両方に置くと
1画面に同じ内容が2回出る（ADR-0015 決定4）。C5 の出力はそのまま残し、この Unit は
別の CSV を作る。

**書けない会社をここで落とさない。** 節が短い・中身が定型句だけ、という型は
**文字数では検出できない**（C5 の ENEOS と同じ）。落とすのは C9 の検証パスの仕事で、
C8 は取れた原文をそのまま置く。

**30,000字の打ち切りを復元しない。** EDINET 側で切れているもの（実測5,897件中3件）で、
原本の XBRL を取り直せば伸びるが、**この Unit の範囲は「同じ書類から拾う」ことに閉じている。**
切れていることは実行ログと design.md に残す。

**SHA-1 は節ごとに取る。** 翌年に原文が変わった会社だけ C9 を回し直すための鍵で、
**4節をまとめて1つにすると、1節だけ変わった会社と全部変わった会社を区別できない。**

# C5 事業の内容テキストの調達 — plan.md

参照: Issue [#159](https://github.com/varmil/nenshu/issues/159)（親: [#158](https://github.com/varmil/nenshu/issues/158)）, `docs/company/spec.md` 1.18（AC-18）, [ADR-0010](../../adr/0010-company-summary-sourcing.md)
依存: なし（ADR-0010 の後）

## Context

ADR-0010 で「会社の説明文を作る」と決めた。その原文を持ってくるのがこの Unit で、
**要約は作らないし、画面も1ピクセルも変わらない。** C0（企業IDの安定化）と同じ
「表示に影響しない Unit」の型になる。

材料は既に取得経路の中を通っている。`pipeline/salary/edinet.py` は EDINET API v2 の
CSV 形式（`type=5`）を叩き、テキストブロックを1つ——「従業員の状況」——だけ拾っている。
**同じ ZIP の中に「事業の内容」も入っている**ので、拾う対象を増やすだけで済む。

**母集団は 2,961社**（E2・ADR-0011 で 1,867社から広げた）。Issue #159 の本文と
`spec.md` AC-18 が「1,867社」と書いているのは E2 より前の数字で、条件は
「そのとき掲載している全社の 99% 以上」と読む。

## 進め方

1. **平文にする規則を、取得から切り離した純関数として先に書く。** タグ・実体参照・
   連続空白の落とし方（AC-18）はここに閉じる。単体テストで固定してから取得に繋ぐ。
2. **実物を1件読んで、規則が実物に当たっているかを確かめる。** 想定（HTMLタグが
   入っている）と実物（CSV 形式では既に落ちている）がずれていないかは、書く前に
   1社ぶん取って見る。ずれていたら規則ではなく想定のほうを直す。
3. **`TEXT_BLOCK` を単数から複数にする。** 要素ごとに**保存の条件**（従業員の状況は
   給与の行がある値だけ、事業の内容は空でなければ）と**複数現れたときの採り方**が
   違うので、要素名と一緒に持たせる。既存の従業員の状況の振る舞いは変えない。
4. **母集団ぶんの書類を落とす。** 落とすのは `ranking_unified_2026.csv` の `doc_id`
   ——平均年間給与を拾ったのと同じ書類。キャッシュが生きている環境では0件になる。
5. **抽出を回して CSV を書き、取得率と落ちた理由の内訳を見る。** 99% に届かなければ、
   届かない理由を数えてから次を決める（要素が無いのか、値が空なのか、取得に失敗したのか）。
6. **既存の出力が1バイトも変わっていないことを確かめる。** `build:data` を回して
   `web/public/data/` に差分が出ないことを見る（AC-18 の3つ目）。
7. **Python にもコミット前のゲートを付ける。** この Unit で足すロジックは Python 側に
   あり、いまの `lint-staged` は `pipeline/scripts/**/*.ts` しか見ていない。**足した
   テストが一度も走らないまま入るのを防ぐ。**

## 着手前に見えている判断

**取得の窓を引き直さない。** `run.py` を回し直すと `twelve_month_window()` が
「回した日から12か月」を取り直し、**母集団そのものが入れ替わる**（`universe.json` の
窓は 2025-08-25〜2026-08-25）。この Unit は原文を足すだけなので、母集団は
`ranking_unified_2026.csv` に確定しているものをそのまま使う。

**書けない会社をここで落とさない。** 原文が417字あって中身が当期の異動の説明だけ、
という型（ENEOSホールディングス）は**文字数では検出できない**。落とすのは C6 の
検証パスの仕事で、C5 は取れた原文をそのまま置く。

**SHA-1 は平文にした後の文字列で取る。** 翌年に原文が変わった会社だけ C6 を回し直す
ための鍵なので、比べたいのは「要約の入力が変わったか」。整え方を変えたときに全社ぶんが
変わるのは正しい振る舞いになる。

```bash
cd pipeline/summary && python3 fetch.py && python3 extract.py
cd pipeline && npm test
cd pipeline && npm run build:data -- --out ../web/public/data && git diff --stat web/public/data
cd web && npm run typecheck && npm run lint && npm test && npm run build
```

- 取得率が 99% 以上で、落ちた会社が理由ごとに数えられていること（AC-18）

- `web/public/data/` に差分が出ないこと（AC-18 の3つ目）
- 既存の Unit テストと E2E が緑のまま

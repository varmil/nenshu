# C3 企業詳細のモック合わせ — plan.md

参照: Issue #89（親: #84）, `docs/company/spec.md` AC-11〜AC-16, `docs/timeseries/spec.md` AC-6〜AC-11, ADR-0007
依存: #83（C2 企業詳細ページのレイアウト刷新）, #88（U13 ランキングのモック合わせ）

## Context

C2 も U12 と同じ条件——Claude Design の `改善案.dc.html` を直接読めないセッションで、計画に書き起こした仕様から組んだ——で作った。数字と受け入れ基準は満たしているが、器の形がモックと食い違っている（Issue #84）。この Unit はアートボード **4b / 2b / 5b** に合わせ直す。

**数字は1つも変えない。** 変えるのは並べ方と器で、`view.ts` / `stats.ts` / `buildStats` には触らない。触るとしたら「近くの5社に添える情報」を増やすところだけで、それも算出は既存の関数の中に閉じる。

**U13 で決めた器をそのまま使う。** 表示基準の帯（`ControlBand`）・ロゴマーク・共通ヘッダはランキングと同じものを import する。ここで別の形を作ると、2ページで同じ操作が違う見た目になる。

## 進め方

1. **境界を先に確認する。** このページで最も取り違えやすいのは「表示基準ごとに変わるもの」と「独立なもの」の区別で、**10年推移だけは常に実測値**である（C2 の design.md）。器を組み替える前に、推移が `byBasis` の外に居ることを確かめる——組み替えの途中で中に入れてしまうと「年齢そろえにしたら過去の有報の数字が変わる」を作れてしまう。
2. **見出しから直す。** ロゴマークを大きくし、h1・業種・順位の行をその右に積む。ここが決まらないと下の2カラムの上端が決まらない。
3. **上部カードを2カラムにする。** 左に金額と数値、右に位置バーとヒストグラム。**モバイルでは縦に積む**ので、積んだときの読み順（金額 → 順位 → 位置 → 分布）が保たれることを確かめる。
4. **年齢別の節を組み替える。** 表 → 説明文 → チャートの順にし、チャートの縦軸を丸い目盛にする。**説明文は数値から機械的に導ける事実だけ**にする（要点の箇条書きと同じ線。`highlights.ts` の隣に置く）。
5. **実測値と推移を整える。** 実測値は罫線付きのグリッド、推移は棒の上に数値・4桁の西暦・最新年だけ濃く。**推移の要約文は図の下**へ。
6. **サイドバーを2枚のカードにする。** 要点は muted の帯、近い会社は枠付き。近い会社の行に業界順位と平均年齢を足す——ここだけ算出が要るので、`findNeighbors` の中で完結させる。
7. **固める。** `e2e/company-refresh.spec.ts` は当たり判定が動くので同じ PR で直す。**同じ文字列がページに2か所出る**（h1 直下の順位とカードの中）ことは C2 で踏んでいるので、当たり判定は `dl` か `.first()` に寄せる。
8. **測って出す。** `/company/[id]` の初期HTMLの gzip サイズを測り直し、C2 の 13,283 B（U13 でヘッダが増えたあとの値）からの増減を記録する。`npm run measure:prefetch` も回す——近い会社に「すべて見る」リンクを足すので、`<Link>` が増える。

## 着手前に見えている判断

**紹介文は作らない。** 4b・2b の h1 直下にある3行（事業内容の説明）は、**手元にデータが無い**。有報の「事業の内容」を取ってくるのは timeseries とは別の調達で、spec 1.10・1.16 が会社ごとの解説文を対象外にしている。要点カードの「将来は…要約を入れる想定です」という注記も同じ理由で入れない——実装していない予定を読者に見せない。

**モバイルでヒストグラムを独立した節にしない。** 2b は「1,867社の分布のどこにいるか」という節に切り出しているが、PC の2カラムが縦に積まれた時点で読み順は同じになる。同じ中身を2つ描き分けると、片方だけ直す事故が起きる。

**±20% が信頼区間ではない断りは3か所に残す**（表の caption・チャートの figcaption・`/about`）。帯だけを見ると信頼区間に見えるため、図の側の断りは省けない（spec 1.14）。

## 検証

```bash
cd web && npm run build
cd web && npm run measure:prefetch
```

- dev server を起動し、1280px と 390px の両方をブラウザで触る（表示基準の切替・年齢の切替・戻る/進む）
- **ライトとダークの両方を見る。** 罫線と帯を増やすので、ダークで沈まないことを確かめる
- 推移が表示基準を切り替えても変わらないことを画面で確かめる
- `/company/[id]` の gzip サイズを design.md に記録する

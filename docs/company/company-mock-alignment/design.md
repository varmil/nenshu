### 上部カードが2カラムである理由

左が「いくらか」、右が「その額が母集団のどこか」。C2 は全部を縦に積んでいたため、金額と位置バーの間に順位4件が挟まり、**同じことを言う数字が離れていた**。モバイルでは縦に積まれ、読み順は 金額 → 順位 → 実測3つ → 位置 → 分布 になる。

**平均年齢・在籍年数・従業員数はカードの中にも出す**（下の「有価証券報告書の実測値」の節と重複する）。金額の隣に無いと「35.0歳の会社の2,178万円」という読み方ができない。下の節は「ここから下は補正していない数字」という区切りの役目を持つので消さない。

### 位置バーとヒストグラム

- 両端のラベルは **`1,867位` / `中位 ◯万円` / `1位`**。「下位／上位」だけでは何位の話か分からない
- 帯は `--muted` から `--chart-1` へのグラデーション。位置は**順位から**出す（`positionPercent`）——金額の絶対値に線形で当てると上位1社の外れ値で帯の9割が空く（C2 のまま）
- **各ビンの社数を棒の上に出す。** 棒の高さは相対値でしかないので、9本の形だけでは「170社」か「17社」かが分からない
- 色は非選択が `--chart-1`（ダークでは `--chart-3`）、その会社のビンが `--primary`。**ダークでは `--primary` が明るいティールで `--chart-1` とほぼ同じ明度になり、選択中が見分けられなかった**ので、ダークだけ非選択を1段暗い `--chart-3` に落としている

### 年齢別の節

**表 → 説明文 → チャート**の順。8点の金額を確かめたい読者は表を、形を掴みたい読者はチャートを見る。先に数値を出しておくと、図は「その形」を確かめるためのものになる。

- 表は罫線付き・値は中央寄せ・選択中の年齢の行だけ地を敷いて太字（年齢スイッチとの対応を見せる）
- チャートの縦軸は `niceTicks` が返す丸い数字。**0起点にしない方針は変えていない**（`niceTicks` は描画範囲の内側に入る刻みだけを返す）
- 軸の単位は `（万円）`（左上）と `（歳）`（右下）。**下の余白は2行ぶん取る**——1行に詰めると右端の「60」と「（歳）」が重なる
- 説明文は `buildCurveSummary`。最高水準の年齢／伸びが最大の5歳区間の最大2文で、**伸びが1度も無ければ2文目は出さない**。**末尾で下がる理由は書かない**（Issue #95。補正の仕組みの説明であって、この会社の数値から導ける事実ではない）

### 近い会社（`findNeighbors`）

各行に業界内順位と平均年齢を添えた。**業界内順位は自分を含めた並びで数える**——自分を除いてから振ると、自分より上の会社が1つ繰り上がって本来の順位とずれる。1業種は最大173社なので、並べ直しの追加コストは当該1社ぶんの計算に埋もれる。

## モックに合わせなかったもの

| モック（`改善案.dc.html`） | この実装 | 理由 |
| --- | --- | --- |
| h1 直下に会社の紹介文3行（4b・2b） | 出さない | **データを持っていない。** spec.md 1.10・1.16 で会社ごとの解説文は対象外 |
| 要点カードの「将来は有報の要約を入れる想定です」 | 出さない | 実装していない予定を読者に見せない |
| モバイルはヒストグラムを独立した節にする（2b） | 上部カードが縦に積まれるだけ | 積んだ時点で読み順は同じ。同じ中身を2つ描き分けると片方だけ直す事故が起きる |
| 偏差値の数字だけ（5b の位置バー脇） | **モックに合わせた**（当初は上位◯%を併記していたが、公開後に外した。下記） | — |
| 推定範囲の表に注記なし | モックどおり注記なし（Issue #95 で外した） | C3 では表の caption にも置いたが、表・説明文・チャートが1つの節に縦に続くので断りが2つ並んでいた。**帯だけを見ると信頼区間に見える**ので図（`figcaption`）と `/about` の2か所からは外さない |

## 公開後に直したもの（2026-08-20）

本番を見た運営者からの指摘。**数字は変えていない。**

| 指摘 | 直したもの |

| 年齢別の表にスクロールバーが出る | ランキングと同じ器の問題（`docs/ranking/ranking-mock-alignment/design.md`）。`TABLE_NO_VERTICAL_SCROLL` で縦だけ止める |
| 偏差値の「上位◯%」が要らない | カードの3つ目・h1 直下・要点から外した。h1 直下はモックの言い回し（`電気機器 ・業界150社中1位 ・全体1,867社中1位`）に揃え、要点の括弧は偏差値にした（アートボード 4b と同じ） |

| 位置バーの見出しが無い | 「全体1,867社の中の位置」と「偏差値 ◯」の行を足した（アートボード 5b）。**カードの左にある偏差値と同じ値をここにも置く**のは、帯の右端＝偏差値の大きさという対応をその場で見せるため |
| 分布の横軸が縦にズレ、棒の太さが揃わない | 完全な範囲（「500〜600万円」）を9つ並べると折り返して2行になり、階級ごとに軸の高さが変わっていた。`formatBinTick` で下限だけの1行ラベルにし、列を `min-w-0 basis-0` にして9等分を固定した。読み上げ用の完全な範囲は `sr-only` の一覧に残っている |
| 近い会社の「本社のみ」バッジが要らない | 316px の列でバッジのぶん社名が切れていた。バッジの意味はその会社のページで説明している |

### 2巡目（チャート）

| 指摘 | 直したもの |
| --- | --- |
| 年齢別の折れ線の文字がPCで大きい（モバイルは適正） | **文字の大きさを器の幅で決める**（`@container` ＋ `@md`〜`@2xl`）。viewBox が固定なのでSVGごと拡大縮小し、22 ユニットの文字はPCで実効20px、本文14pxより大きくなっていた。倍率の逆数で刻み、どの幅でも実効10〜13pxに収める。PCで 14/15.5/12.5 ユニット＝実効 12.7/14.0/11.3px となり、アートボード 4b の 13/15/12px とほぼ一致する |
| 平均年収推移が「有価証券報告書の実測値」より前にある | アートボード 4b の順（実測値 → 推移）に入れ替えた。どちらも補正していない数字で、上が今年の1点、下がその10年ぶんになる |
| 推移の説明文が長い | 節の説明は出典1行（`各年の有価証券報告書に載った平均年間給与の実測値（提出会社単体）。単位は万円。`）だけにし、「年齢そろえを選んでも変わらない」の断りと軸の説明を落とした。表示基準と独立であることは値そのもの（と AC-8 のE2E）が担保する。図の下は増減の要約＋`横軸は報告書の提出年です。`の1文（アートボード 4b と同じ） |
| どちらのチャートも縦が薄い | 折れ線は 720×270 → **720×340**（PCで244px→308px）。推移の棒は `--bar-max` を器の幅で 6rem / 7.5rem に切り替える（PCで80px→120px。アートボード 4b の `hPc` が120px）。年のラベルは棒とは別の行にして間に罫線を1本通した——棒が高くなるほど揃っている先が要る |

**`md:` のような画面幅の変種は使えない。** 同じ 768px でも、サイドバーが出る直前（器 735px）と出た直後（器 396px）で幅が倍近く違う。見ているものが器の幅である以上、条件も器の幅で書く。

`/company/[id]` の HTML は gzip 14,223 B → **13,993 B**（説明文を落としたぶん）。`/` は変わっていない。

### 4巡目（年齢別の表の列幅）

| 指摘 | 直したもの |
| --- | --- |
| 狭い画面で年齢の列にゆとりがあり、推定年収・推定範囲がぎりぎり | 年齢の列の `w-36`（144px）を `w-14`（56px）にし、器が `@md`（448px）以上のときだけ 144px に戻す。中身は「25歳」の3文字しか入らないのに、右の2列——とくに「1,190万円〜1,785万円」が入る推定範囲——を押し出していた |

**ここでも条件は器の幅で書く**（2巡目のチャートと同じ理由）。`sm:` で切ると、**サイドバーが出た直後の768pxでは器が396pxしかないのに144pxを敷く**ことになり、狭い画面と同じことが起きる。表を包む `<div>`（`TABLE_NO_VERTICAL_SCROLL` の器）に `@container` を足して `@md:w-36` で切っている。

| 343px（ビューポート375px） | 105 → **56** | 80 → **97** | 157 → **189** |

狭い側で `w-36` が144pxそのままにならないのは、`table-fixed` ではないので**中身が入りきらないぶんは表の割り付けが縮めるため**。それでも年齢の列は必要な56pxの1.6〜1.9倍を取り、そのぶん右の2列が痩せていた。

### 注記を減らした（`d041d01 UI微調整`、2026-08-20）

運営者が直接コミットしたぶん。**このページから注記を2つ外している。**

| 外したもの | 残る場所 |
| --- | --- |
| 「年収の分布は右に裾を引くため、偏差値は100を超えることがあります」 | ランキングの表・カードの脚注と `/about`。企業詳細では、**偏差値の隣にある全体順位・業界内順位・位置バーが水準を持つ**（`glossary.md` の「偏差値だけが単独で置かれた画面を作らない」線はこれで保たれている） |
| 「縦軸は0起点ではありません」「1社の中の年齢ごとの水準であって、同じ人が歳を取っていく軌跡ではありません」 | `/about`。0起点でないことは**各点の金額を数値で併記している**ことが実際の担保になっている（C1 から変わらない） |

**`figcaption` に残したのは ±20% の帯の意味だけ。** 帯だけを見ると信頼区間に見えるので、図の側のこの1文は外せない（3巡目で表の `caption` を外したときと同じ線）。

受け入れ基準に関わるので `docs/company/spec.md` の 1.4・1.6・AC-2・AC-4 と `docs/product/glossary.md`・CLAUDE.md を改訂した。E2E（`e2e/company-page.spec.ts` の AC-2・AC-4）は、消えた文を確かめる形から**残したもの（順位・位置バー・`figcaption`・8点の金額）を確かめ、消した文が戻っていないことを併せて見る**形に置き換えた。

### 5巡目（表示基準の語と帯のヒント、Issue #128）

ランキングと同じ指摘（`docs/ranking/ranking-mock-alignment/design.md` の5巡目）をこのページにも当てた。**語を減らしただけで、推定であることの明示は落としていない**（AC-9）。

| 指摘 | 直したもの |
| --- | --- |
| カードの「推定」バッジが冗長 | 金額の上のラベルが `35歳時点の推定年収` なので、隣にバッジを置くと**同じ語が1行の中で2回**出ていた。バッジを外し、ラベルだけにした。AC-9 はこのラベルと、下の「推定年収は年齢補正後の推定値です」で満たす |
| 見せ方の帯のヒントの「（平均年齢 37.2歳の会社全体の平均）」が冗長 | `有価証券報告書の数値そのまま` だけにした。**平均年齢はカードの中の実測3つに出ている**ので、帯で繰り返す必要がない。帯が言うべきなのは「いま何を見ているか」だけである |

実測値のときに「推定」の語が1つも出ないこと（AC-9 の逆向き）は変わらない。`e2e/company-page.spec.ts` が両モードで数えており、年齢そろえ側は**バッジの有無ではなくラベルの文字列**を見る形に置き換えた。

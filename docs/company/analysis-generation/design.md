# C9 要約と分析の生成 — design.md

参照: Issue [#241](https://github.com/varmil/nenshu/issues/241)（親: [#214](https://github.com/varmil/nenshu/issues/214)）, `docs/company/spec.md` 1.19（AC-25〜AC-28）, [ADR-0015](../../adr/0015-company-analysis-subjectivity.md), [ADR-0010](../../adr/0010-company-summary-sourcing.md), [ADR-0008](../../adr/0008-company-logo-sourcing.md)

## 出来上がり

```
pipeline/analysis/
  extract_analysis.py   4節の原文を抜く（C8。同じデータセットなので summary/ から移した）
  generate.py           plan → gate → merge → clear → status。**LLM を呼ばない**
  gate.py               要約と分析の機械ゲート。**純関数だけ**
  test_gate.py          33件
  test_generate.py      9件（原文をどちらから読むか・対で出すか）
  prompts/generate.md   生成エージェントが読む
  prompts/verify.md     検証エージェントが読む
  work/                 中間ファイル（gitignore）
pipeline/data/
  analysis_text_2026.csv                原文。167MB・**gitignore**
  analysis_text_cut2200-1500-3000-1500_2026.csv.gz  節ごとに切った版。gzip 17.0MB・**git に置く**
  analysis_text_manifest_2026.csv       節ごとの字数と SHA-1。740KB・**git に置く**
  company_analysis_2026.csv             成果物。**git に置く**
```

**web には出さない**（表示は C10）。`web/public/data/` は1バイトも変わらない。

## 工程は C6 のものをそのまま使う

`plan → 生成エージェント → 機械ゲート → 検証エージェント → merge`。再開の仕組み
（原文の SHA-1 が同じ社を飛ばす）、**バッチと生成物の社数を突き合わせる検査**、失敗の型を
prompts に積み上げるやり方——どれも `summary/generate.py` と同じ形にしてある。

**違うのは3つ。**

1. **規格が2つあり、1回の呼び出しで両方書かせる。** 機械ゲートも検証パスも規格ごとに分かれる
2. **材料に `figures` が加わる。** 同じページが既に表示している数値を `plan` が組んで渡す
3. **外部の文書は生成エージェントが取りに行く**（ADR-0015 決定6）。`generate.py` は
   Web を1回も叩かない

**`ANALYSIS_SECTIONS` の SHA-1 は節ごとに残したまま、再開の判定には4つをまとめた鍵を使う**
（`combined_sha1`）。節ごとの SHA-1 は C8 のマニフェストにあり、どの節が変わったかは
そちらで分かる。

## 2つのゲート（`gate.py`）

| | 要約 | 分析 |
| --- | --- | --- |
| 評価語 | **落とす**（C6 の表を共有） | **通す**（これが本体） |
| 社名 | 落とす | 通す |
| 算用数字 | 通すが、**原文に無い数は落とす** | **個数に上限（3個）** |
| 原文に無い固有名詞 | 落とす | **見ない** |
| 落とし方 | **文ごと**（C6 と同じ） | **分析ごと** |

**分析で固有名詞を見ないのは、外部の文書も材料だからである。** 有報の原文だけと突き合わせ
ると、公式サイトやリリースから採った正しい語がすべて「原文に無い」になる。**埋め合わせは
検証パスの側にあり、生成が挙げた URL を実際に取りに行って突き合わせる**（AC-27）。

**分析は文ごとに落とさない。** 要約と違い、一言と地の文が1つの筋で繋がっているので、
途中の1文を抜くと残りが宙に浮く。

**要約に「原文に無い数値」の検査を足した**（C6 には無い）。C6 の説明文は数値を1つも
書かせなかったが、要約は4節から事実をまとめるので数値が要る。**要約は原文に書いてある
事実だけなので、原文に無い数はそこで作られたもの**になる——桁区切りを落として突き合わせる。

**`summary/gate.py` を書き写さない。** 評価語の表・字形のそろえ方・字数の数え方は
`importlib` でファイルを名指しして読んでいる。**`sys.path` を足して `import gate` とは
書けない**——このファイル自身が `gate` なので、初期化の途中の自分が返る（実際になった）。

## 数値の裏付けの照合——できる範囲を先に切った

AC-26 は「10年で13%下がっている」と書いたなら `history.json` が支持するかを確かめよ、と
求めている。**機械でやれるのはその型ひとつだけである。**

- 見るのは `N年で M% 上がった／下がった` の1パターン（`gate.trend_claims`）
- **主張一般は突き合わせられない。** 「規模を追う段階は終えた」に対応する数字は無い
- **できないことをゲートに書かない。** 通ったことが保証にならなくなる

**基準年は1つに決まらない。** 2017〜2026 の10年ぶんを持つ会社で「10年で」と書けば、ふつう
端から端（差は9年）を指す。差を10年と取れば基準は2016年になる。**日本語の側があいまいなので、
どちらでも支持されれば通す**——片方に決め打ちすると、正しい主張を年の数え方だけで落とす。

**照合できないときは黙って通す。** 系列にその年が無い会社で「照合できない」を「誤り」と
数えると、10年ぶんを持たない会社の分析が理由なく落ちる。

### 決めたこと1: 原文は節ごとに切る。長さは節で変える

**4節すべてを使う。減らさない。** MD&A だけでは「うまくいっていないこと」と「今後の挑戦」が
書けず、実際に課題の節から拾った文が6社ぶんある。

**1巡目は1,800字一律で始めた。** 「その節が何を言っているか」は冒頭で決まる（MD&A は経営成績の
概要が先でセグメント別の内訳が続き、リスクは総論が先）ためで、**一言の材料はそれで足りていた。**

**足りなかったのは固有名詞のほうだった**（下の「具体性を上げる」）。**節ごとに長さを変えて
帳尻を合わせた。**

| | 長さ | 中央の字数 | カギ括弧の語をどこまで拾えるか（1,800 / 2,500 / 3,000字） |
| --- | --- | --- | --- |
| 経営者による分析 | 2,200 | 6,153字 | 40.4% → 50.8% → 56.7% |
| 事業等のリスク | 1,500 | 4,010字 | 36.6% → 46.1% → 53.4% |
| 対処すべき課題 | **3,000** | 2,749字 | **64.8% → 76.3% → 82.2%** |
| サステナビリティ | 1,500 | 4,104字 | 34.2% → 43.0% → 48.2% |

**対処すべき課題が最も密である。** 節そのものが短い（中央2,749字）のに、カギ括弧で囲まれた語
——有報が製品名・ブランド名・計画名を書く形——が2万9千個あり、3,000字まで取ると82.2%が入る。
**リスクとサステナビリティを薄くして帳尻を合わせた**——あちらは総論と方針名が主で、語の数は
多いが製品名ではない。

**1社あたり6,968 → 7,553字。全社で2,236万字**（切らなければ6,220万字）。C6 が12セッションで
535万字を回したので、**単純計算で約50セッション**になる。**2,500字一律にすると62回かかり、
しかも課題の節は76.3%にしかならない。**

### 決めたこと2: 分析の算用数字は3個まで

**#214 の良い例5つは0〜2個**だったが、あれは**一言と短い裏づけだけの63〜90字**で、ここで書く
本文は3観点まで含めて**約250字**になる。**3倍の長さに同じ上限を当てると、数を漢数字で書いて
逃げるという別の歪みが出た**（実際にディスコの草稿で「十年」と書いた）。8社の実測は1〜3個で、
3で頭打ちになる。

**見出しの下限は12字。** 15字にしていたら、#214 が人手で書いたディスコの
「数字の上ではほぼ隙がない。」（13字）が落ちていた。

### 決めたこと3: 1社あたり検索は2回まで、取りに行くページは3つまで

**8社中5社は有報と `figures` だけで書けている。** 外部の文書が本文に効いたのは三陽商会と
出前館の2社で、どちらも**会社自身のニュースリリース**だった。

**探せば必ず何か出てくる**ので、上限を決めないと会社ごとに青天井になる。上限を超えたら
**薄いまま書く**——埋めにいけば記憶から補うことになる。

### 決めたこと4: 材料の線は「会社自身が出しているか」

**ADR-0015 決定2 の「取ってきた文書か、記憶か」だけでは足りなかった。**

「ファナック 採用 初任給」で検索すると、**上位8件のうち5件が年収まとめ記事・転職メディアの
解説**で、**平均年収を 1,238万・1,163万・1,164万と互いに違う値で書いている。** どれも
「取ってきた文書」の条件は満たすが、**このサイトが有報から出している数字と食い違うものを
材料にすると、有報ベースだという立て方そのものが崩れる。**

**線は「会社自身が出しているか」に引いた。** 運営者が PR TIMES・HRMOS・Indeed を許した理由が
**「出しているのは会社自身で、第三者の編集物より一次に近い」**だったので、その理由をそのまま
基準にしている。**報道記事も本文の根拠にしない**——会社の発表があるならそちらを当たる
（三陽商会の新業態を日経が報じていたが、リリースのあるほうを引いた）。

**会社の自称は帰属を付ける。** 「業界シェアNo.1」は会社が出した文書にあるので材料の条件は
満たすが、こちらが地の文で書くと我々の評価になる。

### 決めたこと5: 分析の規格

`headline` 全角12〜75字の1文、`analysis` 全角120〜500字・3〜10文。要約は全角200〜700字・
3〜10文。**実測はどれも中ほどに収まっており、上限にも下限にも触れていない。**

## 落ちた2社が新しい型になった

**どちらも機械ゲートを通り、検証パスで落ちた。** 材料の言葉はすべて材料にあり、間違って
いるのは**繋げ方**のほうである——C6 の型②・型⑥と同じ性質で、**規則を言い直しても減らない側**
に属する。

- **型A1 内訳が書かれていない影響を、切り分けたように書いた**（出前館）。原文は
  「付与型クーポンの導入に伴い販売促進にかかる金額を売上高から減額する処理を採用」と
  書いているが**金額は書いていない**。そこから「会計処理の変更を差し引いても縮小は続いて
  いる」とは言えない
- **型A2 材料が述べていない因果を作った**（第一建設工業）。MD&A は減益を数字で示すだけで
  理由を書いていない。課題の節にある「労務費・建設資材価格の高騰」は**今後の見通し**として
  挙がっているもので、当期の減益の原因としては書かれていない。**同じ文書の別の節に A と B が
  載っていることは、A が B の原因だという意味ではない**

**要約は1つも落ちていない**（8/8）。C6 の型①〜⑪がそのまま効く場所で、こちらの規格は
「原文に書いてあるか」なので判定がぶれにくい。

### どちらも1文を直せば通った

**「材料が足りない」ではなく「言い過ぎ」だった**ことが、この2社の要点である。直し方は
2つ——材料が述べている範囲まで**主張を弱める**か、**帰属を付ける**。

| 落ちた文 | 直した形 |
| --- | --- |
| 会計処理の変更を差し引いても縮小は続いている | この落ち込みには販売促進費を売上から差し引く会計処理の変更も含まれる |
| 労務費と資材価格の高騰が利益を削っている | 会社自身も労務費と建設資材価格の高騰を今後の課題に挙げている |

**書き直して両方とも通った**（機械ゲート 8/8・検証パス 8/8）。この対照表は
`prompts/generate.md` の型A1・型A2 と `prompts/verify.md` に置いてある。

## 具体性を上げる——固有名詞を積極的に出す

**1巡目の分析は抽象に逃げていた**（2026-08-28・運営者の指摘）。「ファッションビル向けの
新ブランド」「本体のEC支援」「ロボットは中国のEV関連向けが伸び」——**どれも名前を書けば
一段具体的になる。**

**3つ挙がった例は、原因がそれぞれ違った。**

| 例 | 具体名 | どこにあったか | 原因 |
| --- | --- | --- | --- |
| ファッションビル向けの新ブランド | **AUREME** | 課題の節の**2,465字目**。**公式リリースからも取得済み**（`sources` に入れていた） | **プロンプトが「名前を出せ」と言っていなかった** |
| 本体のEC支援 | **リコメン堂** | 課題の節の**1,947字目** | **1,800字で切ると落ちる** |
| ロボットが伸びた | R-2000 / CRX-3iA | **4節のどこにも無い** | **有報に無い。公式サイトを取りに行くしかない** |

**1つめが最も痛い。** 材料に持っていて `sources` にも入れていたのに、本文では
「ファッションビル向けの新ブランド」と書いた。**分析の機械ゲートは固有名詞を見ない**
（外部の文書も材料なので、有報の原文だけと突き合わせると誤判定する）ので、**抽象に逃げても
機械は通す。** 具体的に書くかどうかはプロンプトだけで決まっていた。

**全社で測ると、1,800字で切ることで固有名詞候補のほぼ半分が落ちていた**（1,800字以内に
中央73語、切ると落ちるだけの候補が中央67語。落ちる候補が1つ以上ある会社が2,953社＝99.7%）。

### 手当ては3つ

1. **プロンプトに「材料にある固有名詞は積極的に出す」を書いた**（対照表つき）。同時に
   **「知っている製品名を書かない」**も念を押した——それは記憶から補うことそのものである
2. **切る長さを節ごとにした**（上の表）。課題の節を3,000字にして「リコメン堂」も「AUREME」も
   拾えるようにした
3. **探し方に「主力製品やブランドの名前」を足した。** 有報に無い名前は公式サイトの製品ページに
   ある（ファナックの型番はこの経路でしか取れない）

### カギ括弧の中の数字は数えない

**具体的に書くほど数値の上限に食い込む**、という逆向きの圧力が出た。中期経営計画
`「変革2030」`、家電の `「S!mplus」`、ロボットの `「R-2000シリーズ」` ——**固有名詞に数字が
入っている型は珍しくない。** 実際、第一建設工業の書き直しで `「変革2030」` を入れたら上限3個を
超えた。

**カギ括弧の中を数えないようにした**（`gate.digit_runs`）。**上限が止めたいのは量を並べる
ことであって、名前を出すことではない。** 有報もこのプロンプトも製品名をカギ括弧で書くので、
判定は「括弧の中か外か」で足りる。

### 書き直した結果

**8社とも通ったまま、6社に固有名詞が入った**（機械ゲート 8/8・検証パス 8/8。上の表の
「固有名詞」列）。数値の個数は1〜3個のままで、**具体性と「数値は脇役」は両立する。**

## 要約と分析は対で出す

**片方だけのページを作らない**（2026-08-28・運営者の判断。spec 1.19・AC-28。ADR-0015
決定7 の「要約は書けるが分析は書けない会社が出てよい」を覆した）。**読者から見て
「事実はあるのに解釈が無い」ページに意味が無い**ためである。

満たし方は2つしかない。

1. **書き直して両方通す** ← 本筋。上の2社はこれで通った
2. **残ったほうも落とす** ← `generate.pair_or_drop`

**2 を残すことが 1 の暴走を止めている。** 「必ず対にする」を絶対条件にすると、**通らない
分析を通す圧力がそのまま検証パスに掛かる。** 落とせるようにしておくことで、書き直しの
回数に上限（2回）を置ける——`prompts/verify.md` にその運用がある。

**対にするのは両方向。** 要約が落ちたときも分析を落とす。原文に書いてあることすら書け
なかった会社の解釈は据わりが悪く、**表示側（C10）の分岐も「両方あるか、両方無いか」の
2状態で済む。**

**落ちた元の理由は残す。** 「対で落とした」だけだと、なぜ片方が付かなかったのかが実行
ログから消える（`summary_reason` に元の理由を括弧で添える）。**`merge` は要約と分析の
社数を並べて出す**ので、ずれていれば対にする処理が効いていないと分かる。

## 検証パスが URL を取りに行く

**これが C6 に無かった工程で、材料を有報の外へ広げたぶんの埋め合わせになっている。**
パイロットでは三陽商会の新ブランドのリリースと、出前館の店舗数のリリースを実際に取得して、
**書いた内容がそこに書いてあることを確かめた**（新ブランドの展開開始時期・全国展開と
店舗数）。

## 切った版を git に置く——セッションを持ち運べるようにするため

**ZIP キャッシュ（`pipeline/salary/cache/`・326MB）はコンテナが変わると消える。** C8 の
design.md は「原文はキャッシュから27秒で作り直せる」と書いたが、**キャッシュ自体が
毎回無い**環境がある（Claude Code on the web。実際にこのセッションは空のキャッシュから
始まり、`fetch.py` に26分かかった）。

**C9 は約48セッションかかるので、毎回26分の取り直しが乗ると21時間になる。**

**そこで、C9 が実際に読む「節ごとに切った版」を git に置いた**（2026-08-28・運営者の判断）。

| | 字数 | CSV | gzip |
| --- | --- | --- | --- |
| **節ごと（2200 / 1500 / 3000 / 1500）** | 2,236万字 | 61.5MB | **17.0MB** |
| 1,800字/節（1巡目） | 2,063万字 | 56.7MB | 15.8MB |
| 2,500字/節 | 2,740万字 | 74.9MB | 20.7MB |
| 切らない | 6,220万字 | 167.4MB | 46.6MB |

**gzip 17.0MB は `business_text_2026.csv`（15.2MB）と同じ桁**で、リポジトリの形を変えない。
置いたことで **C9 のセッションはキャッシュも EDINET キーも要らなくなった。**

**C8 が「切ってから置く案は採らない」としていたのは、切る長さが決まっていなかったから**
である（「切る長さを決めるのは C9 のパイロット」）。**その条件はパイロットで満たされた。**

- **切らない版があればそちらを使う**（`source_path`）。`--max-chars 0` で切らずに読ませる
  余地を残すため。無ければ切った版に落ちる
- **切った版しか無いときに `--max-chars` がその節の長さを超えていたら止める。** 出せないものを
  黙って短く出さない
- **行数をマニフェストと突き合わせる。** 切った版は git 経由で運ばれてくるので、古い版が
  混ざっても字面では気づけない（C6・C8 の「ファイルを数える」と同じ線）
- **ファイル名に長さの並びを入れてある**（`cut2200-1500-3000-1500`）。切り方を変えれば別名に
  なり、古い版が残っていても混ざらない
- **両方から作ったバッチが完全に一致することを確かめてある**（同じ8社で `diff` が空）

**ZIP キャッシュそのものは残す手立てを持たない。** 年1回のデータ更新（`run.py`・
`history.py`・稼ぐ力・C8）では26分を受け入れる——**そこは元から年1回の手間**である。

## 全社ぶんの1回目（2026-08-28・8社）

**1セッションで8社。** パイロットと同じ規模で、内訳は生成（材料を読んで書く）が手数の
大半を占める。**1社ずつ読む**——2社まとめて読むと戻りが大きく、その場で読み切れずに
ファイルへ落ちる（C6 の `generate.py` が「手数が増えることがそのまま高くつく」と
書いていたとおり）。

**機械ゲートは 8/8・8/8 で通り、検証パスが5件落とした**（要約2・分析3）。**機械が全部
通した後に検証が5件落とした**という比率そのものが、二段構えの2段目が働いていることを
示している。3巡目で 8/8・8/8。

| 巡 | 要約 | 分析 | 落ちた型 |
| --- | --- | --- | --- |
| 1 | 6/8 | 5/8 | S1×2・A2×1・A3×1・A4×1 |
| 2 | 8/8 | 7/8 | A4×1 |
| 3 | 8/8 | 8/8 | — |

**新しい型が3つ出た**（`prompts/generate.md` に書き戻した。**番号はあちらが正**）。

- **型S1（要約）増減や影響の向きを取り違えた。** 三菱商事のセグメント表で金属資源は
  2,278 → 2,045 億円と減っているのに「前年度を上回った」と書いた——**拾ったのは `[+]`
  要因（銅事業の戻入・市況上昇）だけ**で、それを上回る `[-]`（豪州原料炭の売却益の反動）
  を見ていない。伊藤忠では生活消費分野を「国内景気の影響を受けやすい」→「受けにくい」と
  逆に書いた。**要約で初めて観測した型で、どちらも原文を素直に読めば起きない**
- **型A3 材料が述べていない日付・出来事を、近い記述から移した。** グロービングの4節には
  公募増資の日付しか無いのに「上場も2024年11月と新しく」と書いた
- **型A4 条件の良さから、材料の外にある事実を導いた。** 三菱商事の「待遇がそろっている
  分だけ入り口の競争は厳しい」——採用の競争率はどの材料にも無い

**型S1 だけは直し方が違う。** 型A1〜A4 はどれも「言い過ぎ」で、主張を弱めるか帰属を
付ければ通る。**型S1 は誤読なので、原文どおりに直すしかない**（弱めても間違いは残る）。

**この回の `sources` は8社とも空だった。** 商社・M&A仲介・不動産・コンサルで、有報の4節が
厚く `figures` との突き合わせだけで一言が立つ会社が並んだため。**上限まで探さないことを
失敗と数えない**（材料が薄い会社は薄いまま書く、の裏返し）。

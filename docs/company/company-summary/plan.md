# C6 説明文の生成 — plan.md

参照: Issue [#160](https://github.com/varmil/nenshu/issues/160)（親: [#158](https://github.com/varmil/nenshu/issues/158)）, `docs/company/spec.md` 1.18（AC-19・AC-20）, [ADR-0010](../../adr/0010-company-summary-sourcing.md)
依存: [#159](https://github.com/varmil/nenshu/issues/159)（C5）

## Context

C5 が原文を落とした（`pipeline/data/business_text_2026.csv`・2,960社）。ここからその会社が
何をやっている会社かを述べる2〜3文を作る。**オフラインの工程で、web には出さない**（C7）。

**ADR-0010 の追記（2026-08-26）で生成の器が変わった。** Anthropic API は使わず、
**Claude Code のセッション（Max サブスクの枠）で回す**。決定1〜3（出所・原文から導ける
事実だけ・生成であることの明示）は変わらず、変わったのは誰が呼ぶかだけだが、**段取りに
2つ効く。**

- **1回では全社ぶんが回らない。** 原文は535万字あり、生成で1回・検証でもう1回読ませると
  1,000万トークンを超える。**回すたびに未生成のぶんを進める形**にする
- **「スクリプトを1本回して終わり」にならない。** 機械の仕事（バッチの切り出し・機械
  ゲート・CSV への取り込み）とエージェントの仕事（生成・検証）が交互に来る

## 進め方

1. **機械ゲートを、生成より先に純関数として書く。** 規格（字数・文数・社名・数値・評価語・
   原文に無い固有名詞）はここに閉じる。**この Unit で固定入力のテストが書けるのはここだけ**
   なので、先に書いて先に固める。ADR-0010 が名指しした「自社工場を持たないファブレス体制」
   が落ちることを回帰ケースにする
2. **プロンプトをファイルに置く。** 生成と検証で別の1枚（`prompts/generate.md`・
   `prompts/verify.md`）。**来年また回すときに読むのはこの2枚**なので、会話の中に置かない
3. **パイロットを60社で回す。** 回帰ケース5社（キーエンス・ＥＮＥＯＳ・ベリテ・東北新社・
   新日本科学）＋無作為55社。ここで見るのは文の出来だけでなく、**生成率・機械ゲートの
   誤爆・実際に消費した量**の3つ
4. **パイロットの結果でプロンプトとゲートを直す。** 直したら**同じ60社を回し直して**前後を
   比べる（`--force`）
5. **未決事項をここで決める。** ①原文を打ち切るか（ADR-0010 の却下理由は費用だったので
   消えている）②2文に足りない会社（ベリテ型）を通すか落とすか ③検証パスを生成と同じ
   セッションでやってよいか
6. **全社ぶんを、回るぶんずつ進める。** `status` で残りを見ながら、セッションを跨いで進める
7. **目視レビュー**（AC-7）。無作為50社と年収上位50社を読んで design.md に残す

## 着手前に見えている判断

**機械ゲートは文ごとに落とす。** AC-3 がそう決めている。1文だけが原文から離れている型を、
説明文ごと捨てずに済む。落とした結果2文に満たなくなれば、そこで初めて不合格になる。

**「書けない」を字数で判定しない。** ＥＮＥＯＳホールディングスの原文は417字あるが中身は
当期の異動の説明だけで、**文字数では検出できない**（ADR-0010 決定2）。落とすのは検証パスの
仕事になる。

**検証パスは「読んで自然か」を見ない。** 見るのは原文に書いてあるかどうかだけ。**迷ったら
`false`**——説明文が1つ減ることの損は、根拠の無い文が1つ出ることの損より小さい。

**生成したエージェントに自分の出力を検証させない。** 別のバッチ・別のプロンプトで読ませる。
同じ文脈で続けると、自分が書いた理由がそのまま「支持されている」の根拠になる。

**費用のログ（AC-9）は意味が変わった。** 出すのは金額ではなく、進み具合と、その回で
読ませた原文の量になる。

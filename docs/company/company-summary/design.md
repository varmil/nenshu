# C6 説明文の生成 — design.md

参照: Issue [#160](https://github.com/varmil/nenshu/issues/160)（親: [#158](https://github.com/varmil/nenshu/issues/158)）, `docs/company/spec.md` 1.18（AC-19・AC-20）, [ADR-0010](../../adr/0010-company-summary-sourcing.md)

## 出来上がり

```
pipeline/summary/
  prompts/
    generate.md        # 生成の規格と守る線。**来年また回すときに読むのはこれ**
    verify.md          # 検証パス。生成とは別の仕事として読ませる
  gate.py              # 機械ゲート（純関数）
  generate.py          # plan / gate / merge / clear / status
  test_gate.py
  work/                # 中間ファイル（gitignore）
pipeline/data/
  company_summary_2026.csv   # 成果物
```

**`web/` は触らない。** 表示は C7。

## 生成の器

**Anthropic API は使わない。生成と検証は Claude Code のセッションで回す**（ADR-0010 の追記・
2026-08-26）。**スクリプトは LLM を呼ばない**——`generate.py` が持つのは機械の仕事だけで、
生成と検証はセッションのエージェントが担う。

```
company_summary_2026.csv に無い会社（＋原文のSHA-1が変わった会社）
        │
   plan │ → work/batch_NNNN.json（1本20社）
        ↓
   〔エージェント：prompts/generate.md〕 → work/gen_NNNN.jsonl
        │
   gate │ → work/gated_NNNN.json（機械ゲートを通ったものだけ）
        ↓
   〔エージェント：prompts/verify.md〕 → work/verify_NNNN.jsonl
        │
  merge │ → company_summary_2026.csv（verdict が ok 以外は summary を空にする）
  clear │ → work/ を空にする
```

**`clear` を忘れると次の回に前の回の生成物が混ざる。** `plan` は `batch_0001.json` から
振り直すので、`gen_*.jsonl` が残っていると `merge` がそれを拾う。

## データモデル

`pipeline/data/company_summary_2026.csv`。1社1行。

| 列 | 中身 |
| --- | --- |
| `edinet_code` | 突合の鍵 |
| `sec_code` | 証券コード。非上場は空 |
| `summary` | 説明文。`verdict` が `rejected` なら空 |
| `source_doc_id` / `source_period_end` | 原文の書類IDと期末。**1文ごとに原本まで遡れる** |
| `source_sha1` | 原文の SHA-1。**翌年これが同じ会社は回し直さない**（AC-8） |
| `model` | 生成に使ったモデル |
| `generated_at` | 生成した時刻 |
| `verdict` | `ok` / `rejected` |
| `reject_reason` | 落ちた理由（AC-1 に無い列。**AC-6 が理由ごとの件数を求めており、数えられないと直せない**） |

## 機械ゲート（`gate.py`）

**文ごとに落として、残りで全体を見る。**

1. 説明文を句点で文に分ける
2. **文ごと**に、社名・数値・評価語・原文に無い固有名詞を見て、違反する文を落とす
3. 残った文で文数（2〜3）と字数（全角60〜130）を見る。外れたら不合格

**文ごとに落とすのは AC-3 がそう決めているため。** 1文だけが原文から離れている型
（ADR-0010 が名指しした「自社工場を持たないファブレス体制」）を、説明文ごと捨てずに済む。

| 規則 | 見るもの |
| --- | --- |
| 社名 | 社名そのものと、`株式会社`・`㈱`・`ホールディングス` を落とした形 |
| 数値 | アラビア数字は一律。**漢数字は助数詞が続くときだけ**（`三社` は落ち、`十分` は落ちない） |
| 評価語 | `最大手`・`日本初`・`高い収益性`・`優れた`・`急成長` ほか32語 |
| 原文に無い固有名詞 | カタカナ4文字以上・ラテン文字2文字以上・`◯◯株式会社` の形 |

**一般名詞まで見ない。** 「製薬会社」のような言い換えは原文に無くても正しい。**カタカナは
4文字から**——「センサ」まで見ると原文の言い換えが通らなくなる。

## 検証パス（`prompts/verify.md`）

**見るのは「原文に書いてあるか」だけ。** 読んで自然かは見ない。説明文の各文について原文が
述べているかを確かめ、1文でも支持されなければ `false`。**迷ったら `false`**——説明文が1つ
減ることの損は、根拠の無い文が1つ出ることの損より小さい。

**生成したエージェントに自分の出力を検証させない。** 別のバッチ・別のプロンプトで読ませる。

## パイロットの実測（60社・2026-08-26）

回帰ケース5社（キーエンス・ＥＮＥＯＳ・ベリテ・東北新社・新日本科学）＋無作為55社。

| | 値 |
| --- | --- |
| 説明文が付いた | **56社 / 60社（93.3%）** |
| 生成の段階で空 | 3社（ＥＮＥＯＳ 5020・ベリテ 9904・東京製鐵 5423） |
| 機械ゲート落ち | **0件** |
| 検証パス落ち | 1社（堺化学工業 4078） |
| 字数（全角） | 中央値119・最小83・最大130 |
| 消費 | 生成 421,957 / 検証 405,150 トークン（**1社あたり約13,800**） |

**ＥＮＥＯＳは狙いどおり落ちた**（AC-5・AC-20）。ただし**落ちたのは検証パスではなく生成の
段階**で、エージェントが「原文が当期の異動の説明しか持たない」と判断して空を返した。
ADR-0010 は「落とすのは検証パスの仕事になる」と見込んでいたが、**プロンプトに型を書けば
生成の側で止まる**。検証パスはその後ろの網として残す。

**機械ゲートは0件しか落としていない。** 生成のプロンプトが規格を持っているので、当たる前に
守られている。**それでも外さない**——ゲートが守っているのは「プロンプトが効かなかったとき」
であって、効いている間は0件が正しい姿になる。

**検証パスが捕まえた1件は、機械ゲートでは絶対に捕まらない型だった。** 堺化学工業の説明文は
有機化学品・衛生材料まで含めて「無機材料」と括っていたが、原文では無機材料は独立した
セグメントで有機系は別。**語はすべて原文にあり、間違っているのは分類のしかた**なので、
文字列の照合では届かない。**検証パスを外せない根拠がこの1件になる。**

## 原文は2,000字で切る（決めた・2026-08-26）

ADR-0010 は打ち切りを却下していたが、**その根拠は費用**（「2,000字で切っても浮くのは1割」）で、
API を使わなくなった時点で消えている。代わりに効くのは**1セッションに入る量**のほうになった。

**20社を2,000字で切って回し、切られた8社をすべて読んだ。** 説明文の質は落ちていない
（三井物産・伊藤忠商事・丸紅・三菱地所のような、原文が4,000字を超える会社を含む）。
**「事業の内容」は冒頭に要旨を書く様式**なので、後半にあるのは関係会社の一覧と事業系統図の
残骸で、説明文の材料にはならない。**機械ゲートは打ち切り前の原文に対して当てて19/19 で通過**した。

**検証パスに渡すのは原文の全部。** 切った先に書いてあることを説明文が述べていたら、それは
原文が支えていない——**検証は配っている原文そのものに対して行う。**

## 消費量の実測（2026-08-26）

| 条件 | 1バッチ（20社） | 1社あたり | 検証パスの却下 |
| --- | --- | --- | --- |
| 打ち切りなし・手数13〜17手 | 140,652 | 7,033 | 1 / 57社 |
| 2,000字・手数4手 | 126,321 | 6,316 | **3 / 19社** |

**原文を23%減らし手数を1/4にして、1割しか下がらない。** 1ターンの費用は
`固定費（システムプロンプトとツール定義。逆算で約14,000）＋そこまでに積んだ文脈` で、
**原文は読んだ後の2ターンぶんしか乗らない。** 20社ぶん（約30,000トークン）を4ターンで
読み書きすると、内訳は 14 + 17 + 47 + 51 ＝ 約129,000 になり実測と合う。

**手数を削る節約は割に合わない。** 1割しか安くならないのに**却下率が 1.8% → 15.8% に上がった**。
落ちた3社のうち2社は打ち切られていない（レーザーテック486字・ドリームインキュベータ553字）
ので、**原因は打ち切りではなく「検算もしない」と指示したこと**である。

**効くのはバッチを大きくすること。** ターン数はバッチが大きくなっても増えないので、固定費
（14,000 × ターン数）が薄まる。**60社バッチで実測すると 1社あたり 7,034（生成3,544＋検証3,490）
になり、20社バッチの 13,785 のほぼ半分**だった。

| バッチ | 生成 | 検証 | 合計（1社あたり） | 検証パスの却下 |
| --- | --- | --- | --- | --- |
| 20社（パイロット） | 7,033 | 6,753 | 13,785 | 1 / 57社 |
| 20社（手数を削った回） | 6,316 | 7,712 | 14,028 | 3 / 19社 |
| **60社（採用）** | **3,544** | **3,490** | **7,034** | **4 / 118社** |

**却下率は 16% → 3.4% に戻った。** 落ちた4つの型を `prompts/generate.md` に書き戻し、
指示を「手数は3手だが読みは丁寧に」に変えたぶん。**60社バッチのほうが手数も少ない**ので、
安さと質が同じ方向を向いている。

**落ちた4つの型は生成プロンプトに書き戻した**（`prompts/generate.md` の「実際に落ちた型」）。
どれも語はすべて原文にあり、間違っているのは**まとめ方・括り方・帰属**のほうで、機械ゲートでは
捕まらない。**書き戻した後に落ちた4社も同じ4型の中に収まっている**ので、型の見立ては合っている。

| 型 | 例 |
| --- | --- |
| 原文が対等に並べているものに重みを付けた | 三菱地所「2事業を柱とする」（原文は6事業を対等に列挙） |
| 原文が書き分けている地域や主体をまとめた | レーザーテック「海外は子会社が担う」（原文は「国内及びアジアは当社」）／ソフトバンクグループ「個人および法人顧客向けのモバイル・ブロードバンド」（法人向けブロードバンドは原文に無い）／大和工業「3か国でＩ形鋼・鋼矢板」（インドネシアは作っていない） |
| 別のセグメントの事業内容を隣に付けた | ドリームインキュベータの投資事業組合の運用／テクノ菱和の太陽光発電（原文は当社の事業） |
| 区分の名前や動詞を原文の範囲を超えて使った | 堺化学工業「無機材料」に有機化学品まで含めた／野村不動産ホールディングス「賃貸住宅・ホテルの分譲」（原文は「開発・賃貸・売却」） |

## 機械ゲートの誤爆を1つ直した

60社バッチで8社が「原文に無い固有名詞」で落ちたが、**中身はどれも全角と半角の食い違い**だった。
有報は略語を全角で書くことが多く（`ＩＴ`・`ＤＸ`・`ＰＦＩ`）、説明文は半角で書く。突き合わせの
前に NFKC で字形をそろえ、大文字と小文字も区別しないようにして **8社 → 1社**になった。

残る1社（ファナック）は本物——説明文が原文の「ＦＡ」を「ファクトリーオートメーション」に
展開しており、その語は原文に無い。**標準的な展開でも原文に無いものは通さない。**

**誤爆は落ちる社数だけの問題ではない。** 先に回したバッチのエージェントは、この誤爆を避ける
ために略語をわざと言い換えていた（報告に残っている）。**ゲートの誤爆は書き方まで歪める。**

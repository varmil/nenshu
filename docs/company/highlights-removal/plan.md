# C11 「この会社の要点」の削除 — plan.md

参照: Issue [#799](https://github.com/varmil/nenshu/issues/799)（親: [#214](https://github.com/varmil/nenshu/issues/214)）, `docs/company/spec.md` 1.11・AC-11（削除する）・AC-15
依存: なし（C3 で作ったサイドバーを変える）

## Context

右サイドバーの「この会社の要点」は、当初は有報の要約を入れる場所として考えていた。要約が
できるまでの間は、カードの数値を文にした箇条書きで埋めていた。C10（#242）の配置を検討し、
**要約の置き場所にもしない**と決めた（2026-09-24・運営者の判断）ので、ブロックごと外す。

**この Unit で足すものは無い。** 外したあとのサイドバーが画面に収まることを確かめて固定する
ところまでが範囲になる。

## 進め方

1. **外す前にサイドバーの高さを測る。** PC（1280×800）で 3003・6861・9107 を開き、`aside`・
   要点・水準が近い会社の高さを記録する。外したあとの値と並べるため
2. **spec を先に直す。** 1.11 と AC-11 を消し、消した経緯を残す（番号は詰めない——
   設計文書や Issue から AC-11 を参照している箇所がある）。AC-15 に「サイドバーが画面の
   高さに収まる」を足す
3. **E2E を先に書き換える。** AC-11 の3件を「要点が出ない」1件に置き換え、AC-15 に
   サイドバーの高さのテストを足す。**この時点で走らせて落ちることを確かめる**（外す前は
   要点が出ていて、サイドバーも画面より高い）
4. **コンポーネントと `buildHighlights` を消す。** `highlights.ts` の他の関数（説明文の
   組み立て）は残す。三分位の判定（`features/ranking/lib/filter.ts`）はランキングが
   使っているので触らない
5. **Unit テストを消す。** `buildHighlights` の4件だけ。同じファイルの他の `describe` は残す
6. **検証。** lint・typecheck・vitest、E2E（企業詳細の spec 一式）を dev サーバーに向けて回す。
   3003・6861・9107 の高さを測り直し、1. の値と並べる。`/company/6861` の HTML を前後で測る
7. **docs を直す。** design.md、CLAUDE.md・C2 / C3 の design.md に残る「要点」の記述

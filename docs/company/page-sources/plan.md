# C12 出典の節 — plan.md

参照: Issue [#805](https://github.com/varmil/nenshu/issues/805), `docs/company/spec.md` 1.15・AC-16（改訂）・AC-9・AC-29, `docs/site-chrome/spec.md` 5.1
依存: C10（#242。要約と分析の節が出ていること）

## Context

企業詳細ページの末尾の「この数字の作り方」は、ページの数字が推定年収しか無かった頃に年齢そろえの
補足として置いた節で、C10 までに出どころの違うデータが5種類に増えた後も推定年収の説明しか
していない。これを**ページ全体の出典を1か所で見渡す節「このページの出典」**に作り替え、
3ステップは「年齢別の推定年収」の節の1行に縮める（運営者の判断・2026-09-24）。

運営者の指摘は「補足説明に過ぎないのにスペースを取りすぎ」。**作り替えた節が前より場所を
取らないことも完了の条件に含める。**

## 進め方

1. **変更前を測る。** HEAD を別の作業ツリーでビルドし、`/company/6861`・`8802`・`7203`・`8058` の
   HTML（raw・gzip）と島の JS の大きさを記録する。dev サーバーで PC（1280×800）とモバイル
   （390×844）の節の高さ・フッタの高さを測る
2. **spec を先に直す。** 1.15 と AC-16 を改訂し、1.4 の「前提」の行を合わせる。「計算値」は新しい
   語なので glossary に足す
3. **E2E を先に書き換える。** AC-16 を新しい節の形にし、AC-29 の並び（要約の次が末尾の節）の
   見出しを差し替える。**この時点で走らせて落ちることを確かめる**
4. **区分を決める純粋関数を書き、Unit テストを付ける。** 会社ごとに変わるのは「その節がある
   かどうか」だけなので、有無の組み合わせで行と文言が変わることを固定する
5. **節を島の外で描く。** C10 と同じ名前付きスロットで `[id].astro` から差し込む。3ステップの
   コンポーネントを消し、年齢別の節に1行を足し、フッタの出典の行を外す
6. **一次情報の URL を1か所に寄せる。** `/about` の「出典」と新しい節が同じ表を見るようにし、
   `/about` に女性の活躍推進企業データベースを足す
7. **検証。** lint・typecheck・vitest、企業詳細と `/about` の E2E を dev サーバーに向けて回す。
   AC-9（「推定」の単独語）・AC-29（AI の断りの回数）・決算期の回数（S3）の既存テストが通ることを
   見る。1. と同じ手順で高さと HTML を測り直して並べる
8. **docs を直す。** design.md、CLAUDE.md の現在地、「この数字の作り方」を名指ししている他の
   design.md

# C12 出典の節 — design.md

参照: Issue [#805](https://github.com/varmil/nenshu/issues/805), `docs/company/spec.md` 1.15・AC-16（改訂）・AC-9・AC-29, `docs/site-chrome/spec.md` 5.1, [ADR-0015](../../adr/0015-company-analysis-subjectivity.md)

## 出来上がり

`/company/[id]` の本文の末尾（要約の節の後ろ）にあった「この数字の作り方」（3枚のカード）が、
「このページの出典」の一覧に替わる。年齢補正の手順は「年齢別の推定年収」の節の見出しの直下に
1行で入る。フッタから出典の行が消える。

```
PC（本文 652px）
このページの出典                                                            h2
───────────────────────────────────────────────────────────────
実測値      平均年収とその推移・平均年齢・在籍年数・従業員数  金融庁 EDINET の有価証券報告書（単体）
───────────────────────────────────────────────────────────────
計算値      順位・偏差値・分布・レーダー・稼ぐ力  実測値・自己申告値と、有価証券報告書（連結）から計算
───────────────────────────────────────────────────────────────
推定値      年齢別の推定年収と、年齢そろえの金額・順位  実測値と、厚生労働省「賃金構造基本統計調査」の賃金
            カーブ
───────────────────────────────────────────────────────────────
自己申告値  残業・有給・男女の賃金の差異  厚生労働省「女性の活躍推進企業データベース」への登録値
───────────────────────────────────────────────────────────────
AIの要約    社名の下の説明文・「有価証券報告書の要約」  有価証券報告書の本文に書いてあることだけ
───────────────────────────────────────────────────────────────
AIの評価    「現状と今後」  有価証券報告書・公開資料
───────────────────────────────────────────────────────────────
            ↑ 該当するもの（地の色）       ↑ 出典（muted。一次情報の名前はリンク）
```

モバイル（本文 358px）では出典を次の行に下ろす。ラベルの列は同じ 4.5rem。

```
年齢別の推定年収                                                             h2
実測値を業種の賃金カーブ（賃金構造基本統計調査）で各年齢の水準に置き換えた値です（計算方法）
┌ 年齢 │ 推定年収 │ 推定範囲（±20%） ┐
```

## 区分

| 区分 | 該当するもの | 出典 |
| --- | --- | --- |
| 実測値 | 平均年収とその推移・平均年齢・在籍年数・従業員数 | 金融庁 EDINET の**有価証券報告書**（単体）。C13（#814）でその会社の書類へのリンクにした（それまでは EDINET のトップ） |
| 計算値 | 順位・偏差値・分布・レーダー・稼ぐ力 | 実測値・自己申告値と、有価証券報告書（連結）から計算 |
| 推定値 | 年齢別の推定年収と、年齢そろえの金額・順位 | 実測値と、厚生労働省「**賃金構造基本統計調査**」の賃金カーブ |
| 自己申告値 | 残業・有給・男女の賃金の差異 | 厚生労働省「**女性の活躍推進企業データベース**」への登録値 |
| AIの要約 | 社名の下の説明文・「有価証券報告書の要約」 | 有価証券報告書の本文に書いてあることだけ |
| AIの評価 | 「現状と今後」 | 有価証券報告書・公開資料 |

太字は一次情報へのリンク。

**会社によって変わるのは、その節があるかどうかだけ。**

| 節が無い会社 | 変わるところ |
| --- | --- |
| 平均年収推移（`history` が `null`） | 実測値から「とその推移」が落ちる |
| 説明文（178社） | AIの要約から「社名の下の説明文」が落ちる |
| 要約と分析（いまは0社。対なので1つで持つ） | AIの評価の行が消え、AIの要約から「有価証券報告書の要約」が落ちる |
| 説明文も要約と分析も | AIの2行とも消える |

## 構成要素

| 場所 | 役割 |
| --- | --- |
| `web/lib/data/sources.ts` | 一次情報3つの名前と URL（`PRIMARY_SOURCES`）。`/about` の「出典」と、この節が同じ表を見る |
| `web/features/company/lib/sources.ts` | `buildSourceRows(presence)`。節の有無から行と文言を決める純関数。出典は文字列と `{ source }`（リンク）の切れ端の配列 |
| `web/features/company/components/SourcesSection.tsx` | 行を `dl` に描く。状態を持たない |
| `web/src/pages/company/[id].astro` | 節の有無を渡して行を作り、`slot="sources"` で島に差し込む |
| `web/features/company/components/CompanyDetailIsland.tsx`・`CompanyDetail.tsx` | スロットを受け取り、本文の末尾（要約の後ろ）に置く。年齢別の節に1行を足し、フッタの出典の行を外した |
| `web/features/about/components/AboutPage.tsx` | 「出典」を `PRIMARY_SOURCES` から引く。女性の活躍推進企業データベースを足し、EDINET の項目に稼ぐ力の材料（連結の経常利益・従業員数）を足した |

**消したもの:** `HowItWorks.tsx`（3ステップ）、フッタの `出典: 金融庁 EDINET の有価証券報告書（推移は…年の各年）、厚生労働省「賃金構造基本統計調査」。`

```
[id].astro
  ├ companyPageData(id)        → data（島の props）
  ├ companyAnalysisFor(id)     → analysis
  ├ buildSourceRows({ history, summary, analysis }) → rows
  └ <CompanyDetailIsland data client:load>
       ├ slot="analysis" … AnalysisSection
       ├ slot="digest"   … DigestSection
       └ slot="sources"  … SourcesSection rows   ← 静的な HTML。島の JS にも props にも入らない
```

## 決めたこと

- **区分の軸は加工の度合い。** 節の並び順で並べると、同じ出典（有報）が5つの節に散って読者が
  「どこまで信じてよいか」を拾えない。「推定値と実測値を同じ書式で並べない」（CLAUDE.md）を
  ページ単位で見える形にする
- **要約と分析を別の行にする。** どちらも生成AIの文章だが書いてよいことの線が違い（ADR-0015
  決定5）、束ねると AC-29 の前提がこの節で崩れる。**要約の節そのものには AI の語を置かない**
  （AC-29）ままで、この一覧だけが「AIの要約」と名指しする——生成したことは `/about` と説明文の
  出典の1行（C7・ADR-0010）がすでに言っており、ページの中で1か所に集めて見えるようにした
- **分析の材料は分析の節の断りと同じ2つ**（有価証券報告書・公開資料。2026-09-24・運営者の
  指示）。当初は `/about`「要約と分析の作り方」の4つ（このページの数値・AIの一般知識を含む）を
  すべて挙げていたが、同じ画面の2か所で材料の数が違うと片方が言い落としに見える。全部は `/about` にある
- **時点を書かない。** 決算期は「有価証券報告書の実測値」の見出しと要約の節の説明、女性活躍DBの
  集計時点は働きやすさの節、分析を書いた年月と参照日は分析の節が持っている。
  `docs/site-chrome/spec.md` 5.1 が企業詳細で認めている決算期は2か所だけで、ここに書くと3回目になる
- **島の外で描く。** 中身が表示基準で変わらないので、C10 と同じ名前付きスロットにした。3ステップの
  文言が島の JS から抜けた
- **一次情報へのリンクに `nofollow` を付けない。** 分析の「参照した資料」は会社ごとに違う外部
  サイトなので付けているが、こちらは全ページ共通の公的な一次情報。`/about` と同じく別タブ・
  `noreferrer`
- **女性活躍DBのリンク先はデータベースの入口**（`/positivedb/`）。データを落としたのは
  オープンデータのページ（`/positivedb/opendata/`）だが、読者が会社名で引けるのは入口のほう
- **PC では該当するものと出典を1つの段落に流し、モバイルでは出典を次の行に下ろす。** PC で
  2行に分けるとどの行も2行になり、3ステップより高くなる。モバイルで流すと「…従業員数 金融庁
  EDINET…」が行の途中でつながって境目が読めない
- **年齢別の1行は見出しと包まない。** 既存の E2E が見出しの親をこの節として引いている。見出しの
  直下の余白は `-mt-1.5` で詰めた
- **年齢別の1行に「推定」を置かない。** 見出しが「年齢別の推定年収」なので同じ語を重ねない
  （Issue #128）

## 実測

変更前は HEAD を別の作業ツリーでビルドした値、高さは dev サーバーで測った値。

| | 変更前 | 変更後 |
| --- | --- | --- |
| 末尾の節の高さ（PC 1280×800） | 260px（3ステップ） | 241px |
| 末尾の節の高さ（モバイル 390×844） | 580px | 421px |
| フッタ（PC / モバイル） | 36px / 68px | 16px / 32px |
| 年齢別の節（PC / モバイル） | 841px / 758px | 863px / 796px |
| ページ全体（6861・PC / モバイル） | 5,304px / 7,143px | 5,287px / 6,986px |
| `/company/6861` の HTML（raw / gzip） | 146,411 B / 20,454 B | 145,705 B / 20,541 B |
| `/company/8058` の HTML（raw / gzip） | 152,574 B / 22,173 B | 151,867 B / 22,275 B |
| `CompanyDetailIsland` の JS（raw / gzip） | 37,147 B / 10,571 B | 35,590 B / 10,210 B |
| `/about` の HTML（raw） | 52,015 B | 52,435 B |

**HTML は raw で約700 B 減り、gzip では約80 B 増える。** 3枚のカードは同じ `class` の繰り返しで
よく縮み、一覧は文字の種類が多い。`/` は `CompanyDetail` を読まないので変わらない。

## 固定しているもの

- **6区分が決めた順に並び、3つの一次情報へのリンクがある**（`e2e/company-refresh.spec.ts` の
  AC-16。`features/company/lib/sources.test.ts`）
- **JS 実行前の HTML にあり、「この数字の作り方」が無い**
- **説明文の無い会社（8802）では AIの要約に説明文を挙げない。** 推移が無い・要約と分析が無い
  ときの行と文言は Unit テストが見る
- **本文の末尾（要約の節の次）にある**（`e2e/company-refresh.spec.ts` の「節の並び」が見出しの並び全体で見る）
- **年齢別の節に年齢補正の1行と計算方法へのリンクがあり、フッタに出典の行が無い**
- **PC でもモバイルでも、作り替える前の3ステップ（260px・580px）より低い**
- **既存の規則との突き合わせ**——「推定」を単独の語にしない（AC-9）、「AIが書いた評価」を
  繰り返さない（AC-29）、決算期を書かない（S3。企業詳細で2回と `e2e/data-period.spec.ts` が
  数えている）。Unit テストで文言を、既存の E2E で画面を見る

**既存の E2E を3件直した。** 年齢別の説明文を「節の最初の `p`」で引いていたので、見出しの直下に
1行が入って別の段落を掴むようになった。うち1件（表示基準を切り替えても説明文は変わらない）は
**落ちずに検査が空振りする形**だった（新しい1行は切り替えても変わらない）。説明文の段落を
「年齢別に見ると」で引くように直した。

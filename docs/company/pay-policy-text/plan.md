# C18 給与の決定方針の抜き出し — plan.md

参照: Issue [#851](https://github.com/varmil/nenshu/issues/851)（親: [#850](https://github.com/varmil/nenshu/issues/850)）, `docs/company/spec.md` 1.23（AC-35）, `docs/company/overview.md` C18, [ADR-0010](../../adr/0010-company-summary-sourcing.md)（生成AIを使うビルド工程の前例）
依存: なし

## Context

2026年3月31日以後に終了する事業年度の有報から、「人材戦略に関する基本方針等」の節に
**給与の決定方針**の記載が義務になった。企業詳細ページにこれを原文のまま出す（C19）ために、
全社ぶんの原文を切り出してパイプラインのデータにする。**表示は変わらない。**

起票前（2026-09-27）に分かっていること:

- **対象は1,925社。** 掲載2,961社のうち、決算期末が2026年3月31日以後の書類を採っている会社。
  書類は `ranking_unified_2026.csv` の `doc_id`（平均年間給与を取ったのと同じ書類）
- **節は各社の独自要素で付いている。** 5社で `jpcrp030000-asr_{EDINETコード}-000:BasicPolicyOnHumanResourcesStrategyEmployeesEtcTextBlock`。
  2026年版タクソノミが府令の改正より前の公表なので、標準の要素が無い
- **CSV 形式（`type=5`）は段落の区切りを落とす。** XBRL 本体（`type=1`）の HTML なら p 要素で残る
- **無作為40社を1社ずつ読んだ判定結果がある**（`sample40.json`。PDF から起こしたもの）。
  節の中にある37社・参照先にある2社・無い1社、見出しのある24社と無い15社

C5・C8 と違うのは2点。**取得経路が `type=1` になること**と、**生成AIに文を書かせず範囲だけを
答えさせること**。

## 進め方

1. **節の要素名が全件で1つに決まるかを先に数える。** 1,925件のうち最初の100件を `type=1` で
   取り、接尾辞に当たる要素が0件・2件以上の書類を数える。0件の書類は PDF で節の有無を確かめ、
   名前の揺れなのか節が無いのかを分ける。**ここで揺れが大きければ、拾い方を決め直してから先へ進む**
2. **`type=1` の取得を足す。** EDINET は流量制限を HTTP 200 で返すので、先頭が `PK` であることを
   確かめてから書く（`fetch_csv` と同じ）。並列は3まで。**1件約1.9MB なので ZIP は残さず、
   節と、参照先になりうる節（サステナビリティ・人的資本）の HTML だけを残す**
   （1,925件ぶんの ZIP は約3.6GB で、コンテナのディスクの割り当てを超えうる）
3. **節を「文の列」にする規則を決め、テストで固める。** 段落は p 要素、文は句点で区切る
   （括弧の中の句点では切らない）。見出し（h4）と中身の無い段落（`&#160;` だけのもの）の扱い、
   表のセルの扱いを決める。**文の列をつなぎ直すと原文に戻ること**を全件で確かめるテストを置く——
   これが「1字も変えない」の担保になる
4. **範囲の判定の指示を書き、40社で答え合わせをする。** 生成AIには、番号を振った文の列を渡し、
   給与の決定方針が始まる文と終わる文の番号（無ければ空、参照だけなら参照先の節で同じこと）
   だけを答えさせる。`sample40.json` と突き合わせ、食い違いを1件ずつ見て指示を直す。
   **答え合わせの材料は PDF 由来なので、比べるのは空白を落とした文字列にする**
5. **全件を回す。** Claude Code のセッションでバッチに分けて回す（API キーは使わない。C6・C9 と同じ）。
   **エージェントの報告ではなく、書き出されたファイルで数える**（C6 で報告とファイルの食い違いが4回起きた）
6. **機械で確かめる。** 番号が存在すること・始まりが終わりより前であること・範囲が空でないこと、
   切り出した本文が原文の連続した一部であること、段落の区切りが原文と一致すること
7. **目視で確かめる。** 無作為50社と、最長・最短の各5社。見るのは人材戦略の文が混ざって
   いないか・給与の文が落ちていないか。見つけたら指示を直して、その型の会社を回し直す
8. **書き出して数える。** 付いた社数・空になった社数とその理由・範囲に表を含む社数・長さの分布を
   実行ログと design.md に出す。**原文の SHA-1 を持つ**（翌年、原文が変わった会社だけ回し直すため。C5 と同じ理由）

## 着手前に見えている判断

**生成AIには文を書かせない。** 原文を切り出すのは機械なので、文が変わることが構造上起きない。
C6・C9 の検証パス（書いた文が原文にあるか）はここでは要らない。代わりに確かめるのは範囲の
取り違えで、それは機械では判定できないので 4 の答え合わせと 7 の目視で見る。

**範囲は1つの連続した区間にする。** 40社のうち、給与の文が原文の中で飛び飛びだったのは
2社だけだった。愛媛銀行は会社自身の小見出し（「基本方針」のラベル）を外したために切れていた
だけで、spec 1.23（小見出しは本文の一部として残す）に従えば連続する。残る西菱電機は、給与の
決定方針と明示した記述が無く、人材戦略の文の中に処遇の話が2文あるだけの会社で、判定に迷った。
**この型は空にする方向で指示を書く**——区間を広げて人材戦略の文を混ぜるよりよい。

**参照先から取るのは、参照先がサステナビリティの節（人的資本）のときだけにする。** 40社で
参照先にあった2社（KDDI・兼松）はどちらもそこだった。他の節を指す会社が出たら数えてから決める。

**最大人員会社の年収表は取らない**（spec 1.23 の対象外）。同じ `type=1` の HTML にあるが、
表の組み方が会社ごとに違う。取得の段で HTML を捨てずに残しておけば、後で別の Unit が使える。

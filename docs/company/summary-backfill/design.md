# C17 説明文の無い会社を減らす — design.md

参照: Issue [#840](https://github.com/varmil/nenshu/issues/840)（親: [#158](https://github.com/varmil/nenshu/issues/158)）, `docs/company/spec.md` 1.18（AC-19〜AC-22）, [ADR-0010](../../adr/0010-company-summary-sourcing.md), `docs/company/company-summary/design.md`（C6）

## 出来上がり

```
pipeline/summary/
  prompts/
    generate.md        # 1文の規則と「書き直し（C17）」の節を足した
    verify.md          # 1文を落とす理由にしない、書き直しでも判定は同じ、を足した
  gate.py              # 文数 1〜3・字数 全角15〜130
  generate.py          # plan --rejected / retry を足し、merge を回をまたいで読む形にした
  test_gate.py
  test_generate.py     # 新規。選び方・書き直しの回し方・取り込み方
  work/                # 中間ファイル（gitignore）
    round_1/ round_2/  # retry が前の回を退避する場所
pipeline/data/
  company_summary_2026.csv   # 177社の行だけが変わる
web/public/data/
  summaries.json             # build:data で作り直す
```

**出所・二段構えの検証・表示は C6・C7 のまま。** 変わったのは規格の文数と字数の下限、落ちた会社の選び方、書き直しの工程の3つ。

## 規格

| | C6 | C17 |
| --- | --- | --- |
| 文数 | 2〜3 | **1〜3** |
| 字数（全角） | 60〜130 | **15〜130** |
| 社名・数値・評価語・原文に無い固有名詞 | 含まない | 変えない |

**1文にするのは、原文の事業の中身が1文ぶんしか無いときだけ。** 「当社は、茶エキス・天然調味料・植物エキス及び粉末酒の製造販売を行っております」のように、事業を述べた文が1つで残りが記載作法（系統図の案内・インサイダー取引規制の説明・子会社の数）だけの原文がこれに当たる。**この条件は機械ゲートでは判定できない**——原文に中身があるのに1文で済ませた出力はゲートも検証パスも通すので、プロンプトと目視で止める。

**下限15字は、業種名の言い換えにしかならない文を落とす線。** 「化学品事業を営む。」（9字・大伸化学）は業種と同じことしか言っておらず、業種はページの別の場所に出ている。ベリテの「宝飾品等の小売販売及び卸売販売を行う。」（19字）は通る。

C6 が2〜3文にしていたのは、**2文目を記載作法の文で埋める型⑪を防ぐため**に「2文に足りなければ空」としていたからで（C6 の design.md「目視レビュー」）、1文を認めればその動機ごと消える。

## 工程

```
company_summary_2026.csv の rejected（177社）
        │
   plan --rejected │ → work/batch_NNNN.json（前回の理由を previous_reason に添える）
        ↓
   〔生成エージェント：prompts/generate.md〕 → work/gen_NNNN.jsonl
        │
   gate │ → work/gated_NNNN.json（機械ゲートを通ったものだけ）
        ↓
   〔検証エージェント：prompts/verify.md〕 → work/verify_NNNN.jsonl
        │
  retry │ → 前の回を work/round_N/ へ移し、落ちた会社だけ work/batch_NNNN.json へ
        │   （previous と previous_reason を添える。2回まで）
        ↓   ……gate → 検証 → retry を繰り返す
  merge │ → round_1 → round_2 → work/ の順に読み、後の回で上書きして CSV へ
  clear │ → work/ と round_N/ を空にする
```

### 選び方（`plan --rejected`）

`rejected()` が選ぶのは **CSV で `rejected` かつ原文の SHA-1 が変わっていない会社**だけ。

- **`ok` の会社を選ばない。** 選べてしまうと、通っていた文が回し直しで変わりうる（`test_generate.py` が固定）
- **原文が変わった会社も選ばない。** そちらは `pending()` の仕事で、前回の理由は古い原文に対するものになっている
- **`previous_reason` は検証パスと機械ゲートの理由だけ。** 「説明文が空」（生成側が自分で書かないと判断した）は添えない——添えると「前回は書かなかった」ことが書く圧力になる

### 書き直し（`retry`）

| 渡すもの | 生成側 | 検証側 |
| --- | --- | --- |
| 原文 | 2,000字で切ったもの | 全文 |
| `previous`（前回の文） | 渡す | **渡さない** |
| `previous_reason`（落ちた理由） | 渡す | **渡さない** |

- **検証パスは書き直した文を初めて読む文として判定する。** 検証エージェントには `batch_*.json`・`gen_*.jsonl`・`round_N/` を開かせない（前回の理由が入っている）
- **書き直しに回すのは、生成側が書いた文が機械ゲートか検証パスで落ちた会社だけ。** 生成側が自分で空を返した会社（ENEOS のように原文に事業の中身が無い）は回さない
- **上限は `MAX_RETRIES = 2`。** 3回目を呼ぶと止める。C9（#241）と同じ——通るまで直せるなら検証パスは落とすことができなくなる
- **検証が済んでいない回からは `retry` も `merge` もできない**（`_check_verified`）。C6 の `merge` は検証の無い会社を「検証パス未実施」として rejected にしていたが、`retry` がそれを「落ちた」と読むと、検証していない文を書き直しに回してしまう

### 回の退避（`work/round_N/`）

`retry` は `work/` 直下のファイルを丸ごと `work/round_N/` へ移し、直下には次の回の `batch_*.json` だけを残す。**`gate` と検証エージェントは初回と同じ手順・同じファイル名で回せる。** `merge` は番号順に読んで後の回で上書きする——ある回で通った会社は次の回に回らないので、上書きされるのは落ちた会社だけになる。

## 結果（2026-09-26）

**177社中 168社に説明文が付いた。** 掲載社全体では 2,783社（94.0%）→ **2,951社 / 2,961社（99.7%）**。`summaries.json` は gzip 261.8KB → **273.7KB**（上限 320KB）。

| --- | --- | --- | --- |
| 検証パス | 93 | 93 | 0 |
| 機械ゲート | 18 | 18 | 0 |
| 生成側が空を返した | 66 | 57 | 9 |

| 回 | 対象 | 機械ゲート | 検証パス |
| --- | --- | --- | --- |
| 1回目 | 177社（うち空9社） | 168/168 | 166/168 |

- **1文で書いたのは61社。** 残り107社は2〜3文
- **機械ゲートで落ちた文は0件。** 生成エージェントが自分でゲートを当てて直してから書いている（C6 の後半と同じ手順）。自己チェックで直したのは29件で、すべて130字の超過
- **検証パスが落としたのは2社**（岡本工作機械製作所・アリアケジャパン）。前者は型⑥（販売の主体を品目をまたいでまとめた）、後者は型③（コンビニを営む連結子会社1社を「国内子会社」とまとめた）で、どちらも C6 と同じ型だった。岡本工作機械製作所は書き直し1回目、アリアケジャパンは2回目で通った
- **C6 で検証パスに落ちた93社は、前回の理由を添えて回すと93社とも通った。** 落ちた型の大半が言い過ぎで、1か所直せば通るという C9 の観察と同じだった

### 目視で落とした1社

**アリアケジャパン（2815）の書き直し1回目は、検証パスが true にしたものを落とした。** 2文目「海外子会社も**各地域で**天然調味料を製造・販売し」は、原文が海外子会社の**販売先の地域**を書いているだけで**製造した場所は書いていない**のに、「各地域で」を製造にまで掛けている（型⑥の修飾語の共有）。検証エージェント自身が「迷った点」として挙げたうえで true にしていた。**基準は「迷ったら false」**なので、目視の判断として落とし、最後の書き直しに回した。

**検証パスの「迷ったうえで true」は他にも2社あった**（テクノ菱和・山一電機）。どちらも子会社ごとに書き分けられている仕事を「子会社は A や B を担う」とまとめた形で、**まとめた主語が全体として A と B の両方をしている**ので事実として外れていない。これは型⑥ではない——型⑥は「A と B の両方を、A だけをしている主体に帰す」ときに起きる。

## 目視レビュー（Issue #840 の完了条件）

**新しく付いた168社を全件読んだ。** 見たのは型⑪（記載作法だけの文）と、原文に中身があるのに1文で済ませた文の2つ。

**1文の61社は、原文の事業の中身がどれも1文ぶんだった。** 原文が長い会社も中身は短い——クリエイト・レストランツ・ホールディングス（1,294字）は子会社26社の社名の列挙と系統図の文字、ゼロ（657字）はセグメント名と会社の対応表が大半を占める。

**残したが薄いもの。** 原文そのものがそれ以上を述べていない。

- 博展（2173）の「リアル・デジタルの両方を通じて人の“体験”を統合的にデザインする。」——原文はパーパスの文だけ
- 三井住友信託銀行・りそな銀行——原文が述べているのはグループの構成と、グループ会社が提供する業務の一覧

**下限15字に合わせて足したもの**が2社ある。ブルドックソースの「連結子会社とともに」、クリエイト・レストランツの「事業子会社が飲食の提供等を担う」。どちらも原文にある事実で、記載作法の文ではないので残した。**下限を設けた代わりに、中身が13〜14字の会社では原文にある別の事実を1つ添えることになる。**

## データモデルの差分

`company_summary_2026.csv` の列は変えていない。177社の行だけが変わる。

- `verdict` / `reject_reason` — 付いた会社は `ok` と空、残った会社は `rejected` と `説明文が空`
- `generated_at` — C17 で回した日時
- `model` — **C17 で回した行は空**

# spec.md — 配信フレームワークの移行

対象面: user-web（ユーザー画面）

用語は `docs/product/glossary.md` に従う。**画面に出る数値・文言・レイアウトは1つも変えない。** 受け入れ基準はそれと「Worker を起こす URL を減らすこと」で書く。

決定は ADR-0014。**なぜ Astro なのか、なぜ他を却下したのかはそちらにある。**

---

## 1. Worker を起こす URL

### 1.1 何を（WHAT）

**`/` とそのファセット以外は、すべてビルド時に生成して静的アセットとして返す。** 対象は `/about`・`/company/[id]`（全社）・`/sitemap.xml`・`/robots.txt`。

### 1.2 なぜ（WHY）

事前生成済みのページを返すだけで、本番の warm CPU が `/company/6501` 24ms・`/about` 22ms かかっている。**無料枠の 10ms を2倍以上超えており、落ちていないのは Cloudflare 側の許容の内側にいるだけになる。** 踏んでいるのはクローラで、母数は掲載社数に比例して増える（1,867 → 2,961社）。

**静的アセットへのリクエストは Worker を呼ばず、無料・無制限になる。**

### 1.3 受け入れ基準

- **AC-1**: `/about`・`/company/[id]`・`/sitemap.xml`・`/robots.txt` が Worker を起動せずに返る。**判定は CPU が床（静的アセットのそれ）と同じであること**——ヘッダでは判らない（`docs/framework/intent.md`「測り方」）。
- **AC-2**: `/`・`/?age=N`・`/?ind=X`・`/?q=…`・`/?page=N` は従来どおりサーバーで描く。
- **AC-3**: `companies.json` に無いIDは 404 を返す（ADR-0012 決定1のまま）。存在しないパスで Worker を起動しない（現行の `not_found_handling` の振る舞いを保つ）。
- **AC-4**: Worker のバンドルが現行より小さい（`wrangler deploy --dry-run` の `Total Upload`）。

## 2. 画面

### 2.1 何を（WHAT）

**移行の前後で、画面に出るものが1つも変わらない。**

### 2.2 なぜ（WHY）

この施策が買うのは実行コストだけで、表示は対価に含まれない。U11〜U16・C1〜C4・W1・P1〜P2・S2〜S4 が積み上げた表示上の判断は、どれも design.md に理由が書いてある。**移行のついでに変えると、変えた理由が誰にも辿れなくなる。**

### 2.3 受け入れ基準

- **AC-5**: `/`・`/company/[id]`・`/about` の画面に出る文字・数値・ロゴ・レイアウトが前後で変わらない。
- **AC-6**: E2E 343件が通る。**Next.js 固有に触る4ファイル**（`cache-headers.spec.ts`・`theme.spec.ts`・`prefetch-loop.spec.ts`・`network.ts`）は、**何を守っていたかを引き継いだ形に書き換える**。消してよいのは、守る対象そのものが無くなったものだけ。
- **AC-7**: 操作（年齢そろえ・絞り込み・検索・並び替え・ページ送り・表示モード）でネットワークが発生しない（ranking AC-7・company AC-8 のまま）。
- **AC-8**: 戻る/進むでランキングの絞り込み・ページ番号・表示基準が復元される（U14・#108 のまま）。
- **AC-9**: FOUC が起きない。表示モードの切り替えが `<html>` のクラスで、ハイドレーション前に効いている（`e2e/theme.spec.ts` が見ている性質）。

## 3. 検索エンジン向けの出力

### 3.1 何を（WHAT）

**ADR-0006 を1文字も変えない。** canonical・sitemap・robots・OGP・JSON-LD・URL の形をそのまま出す。

### 3.2 受け入れ基準

- **AC-10**: canonical・sitemap・robots・`og:`・JSON-LD が前後で一致する（U8・S2）。
- **AC-11**: URL の形が変わらない（末尾スラッシュを付けない）。**一度公開したURLは変えない**（product.md の制約）。
- **AC-12**: クライアントの操作でメタデータが URL に追随する（U16・#135。`usePageMeta` が担っていた性質）。

---

## 4. キャッシュ

### 4.1 何を（WHAT）

**規則の置き場所を1か所に保つ**（ADR-0004「キャッシュの設計」）。

### 4.2 受け入れ基準

- **AC-13**: `/` の `Cache-Control`・`Cloudflare-CDN-Cache-Control` が現行と一致する。
- **AC-14**: 静的アセット（`_astro/*` 等の指紋つきファイル）が `immutable` で配られる。
- **AC-15**: 規則が1か所にある。ページやフレームワークの設定ファイルに散らさない。

---

## 5. 測り方

**`docs/framework/intent.md` の「測り方（次に測る人へ）」に従う。** 要点は3つ。

- CPU は `wrangler dev --local` の `/proc/<workerd>/schedstat` 第1フィールドを N リクエストで割る。**`wrangler dev` は workerd を2本立てるので合計で見る**
- **cold は起動し直して1本目だけ叩く。** 現行は 358〜1,119ms と揺れるので、桁が違う相手と並べるときだけ読む
- **「Worker が起きたか」は CPU が床のままかで判る。** ヘッダでは判らない

**絶対値は使えない。** このコンテナは本番より数倍遅い。前後を同じ手法で並べた比だけを見る。

---

## 6. 対象外

**`/` の CPU を下げること。** 40ms のうち 16ms は全社ぶんの props 直列化で、これは ADR-0013（E0・#174）の領分になる。**フレームワークを替えても直らないし、替えなくても直る。**

**ファセットのパス化。** `?age=N` 8件・`?ind=X` 33件をパスにすれば `/` もアセットにできるが、ADR-0006 を丸ごとひっくり返すことになる。**この施策では扱わない。**

**画面の追加・変更。** 2. のとおり。

**データパイプライン（`pipeline/`）。** フレームワークに依存していない。

**有料プランへの移行。**

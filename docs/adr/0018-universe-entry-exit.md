# ADR-0018 母集団に入る条件と出る条件を分ける——入るのは直近12か月、出るのは最後の有報から24か月

状態: Accepted

日付: 2026-09-29

関連: [ADR-0011](0011-company-universe-twelve-month-window.md)（母集団の窓。**「窓は12か月」を入る側の条件に限る**）, [ADR-0017](0017-stable-company-id.md)（企業 ID）, 親 Issue [#868](https://github.com/varmil/nenshu/issues/868)。施策は `docs/refresh/`

## 文脈

ADR-0011 は母集団を「直近12か月に有報を提出した内国法人・組合」にした。**窓は取得を回す日から遡って12か月**（`run.twelve_month_window`）で、年1回の一括更新では、回す日を1つ選べばよかった。

refresh 施策で、更新を毎日の差分にする。**毎日窓を切り直すと、提出が数日遅れた会社が一時的に母集団から消える。** 前年6月30日に有報を出した会社が、今年は7月2日に出したとする。7月1日に回すと、窓（前年7月1日〜今年7月1日）の中にこの会社の有報が無い。

提出の間隔が12か月を超えるのは、遅れだけが理由ではない。

- **決算期の変更。** 決算期を変えた最初の事業年度は1年を超えてよい（会社計算規則では最長1年6か月）。その年は有報の間隔が12か月を大きく超える
- **提出の遅れ。** ADR-0011 の時点でも、窓の中に前の期の有報しか無い会社があった（ニデック 6594・2025-03-31期）

**母集団から消えると企業ページが消える**（事前生成の一覧から外れて 404 になる。ADR-0012）。インデックスされたページが一時的に消えると、戻ってきても評価を取り戻すまでに時間がかかる。

## 決定

1. **入る条件は ADR-0011 のまま。** 直近12か月に有報を出し、掲載の条件（単体従業員100人以上・平均年齢20〜65歳・平均年間給与100万円超）を満たす会社
2. **出る条件を別に置く。** 一度載った会社は、**最後の有報の提出から24か月たつまで**母集団に残す。その間は最後の有報の数字で並ぶ
3. **24か月を過ぎた会社は、ランキングと母集団（順位・偏差値・母集団の統計）から外す。企業ページは残し**、最後の有報の決算期と、提出が途切れていることを出す（`docs/refresh/spec.md` 1.16）
4. **窓そのものは24か月に広げない**

## 理由

- **ページが誤って消えるほうが、SEO の痛手が大きい**（運営者の判断・2026-09-29）。猶予を長めに取り、決算期の変更も含めて覆う
- **24か月は、決算期の変更（最長1年6か月）に提出の遅れを足しても収まる長さ**として選んだ。12か月を少し超える程度（13か月など）では、決算期の変更を覆えない
- **ADR-0011 が「窓を置かない」案を退けた理由は、形を変えて残る。** 退けたのは「上場廃止・合併で提出をやめた会社が何年も残る」ことだった。この ADR でも、提出をやめた会社は24か月で母集団から外れる。変わるのは外れる時期が遅くなることだけ
- **窓そのものを広げないのは、1〜2年前に提出をやめた会社が新しく載ってしまうため。** 入る条件と出る条件を分ければ、この問題は起きない

## 結果

- **上場廃止・合併した会社が、最後の有報から最大24か月ランキングに残る。** 読者が転職先として選べない会社が並ぶことがある。ページが消えるほうを重く見た
- **母集団の決算期の幅が広がる。** `pipeline/scripts/build-data.ts` の決算期の幅のガード（24か月を超えたら落とす）は、猶予中の会社がいると超えうるので、線を引き直す（refresh の D2）
- 母集団への出入りを判断するには「一度載ったか」と「最後の有報の提出日」を覚えておく必要がある。更新台帳（`docs/refresh/spec.md` 1.1）に持つ
- `/about`「対象範囲」と `docs/product/product.md`「データの前提」の「直近12か月に有報を提出した」の書き方を改める（refresh の D2）

## 却下案

**窓は12か月のまま、毎日切り直す。** 仕組みは変えずに済む。採らなかったのは、提出が数日遅れた会社が毎年どこかで一時的に消え、ページが 404 になるため。

**猶予を短くする（13か月など）。** 提出の数日〜数週間の遅れは覆えるが、決算期を変えた年（最長1年6か月の事業年度）を覆えない。

**窓そのものを24か月に広げる。** 1本の規則で済む。採らなかったのは、1〜2年前に提出をやめた会社（上場廃止・合併）が新しく載ってしまうため。

**窓を置かず、各社の最新の有報を採る。** ADR-0011 が退けたとおり、提出をやめた会社が何年も残る。

## 追記（2026-09-30）: 単体従業員の線を割った会社も、ランキングから外してページを残す

**載っている会社の次の有報が、掲載の条件のうち単体従業員の線（100人）を割ったら、その有報の数字で反映し、ランキングと母集団から外す。企業ページは残す**（refresh の D11・#903。運営者の判断）。次の有報で線に戻れば、ランキングに戻る。

**きっかけ。** サイバーステップＨＤ（3810）が 2026年5月期に持株会社へ移り、単体の従業員が177人から40人（全員が管理部門）になった。この ADR の決定のままでは、線を割った会社は「前の期の数字のまま」（差分更新の待ち行列）でランキングに残り続け、台帳の提出日が進まないので、24か月後に決定3の「提出が途切れた会社」になる。**提出はしているのに、ページが「提出が途切れています」と断ることになる。**

**決定**

1. 外す理由は2つになる——**最後の有報から24か月たった**（決定3）と、**単体従業員の線を割った**。どちらもランキングと母集団（順位・偏差値・母集団の統計）から外し、企業ページは残す
2. 線を割った会社の数字は**その最新の有報のもの**。台帳の提出日も進むので、24か月の出る条件とは独立に扱える
3. **外すのは単体従業員の線だけ。** 平均年齢（20〜65歳）と平均年間給与（100万円超）の条件は読み違いの検査として働いているので、割ったら前の期の数字のまま運営者に知らせる（#892・#895 はどちらも読み違いだった）
4. **入る条件は変えない。** 一度も載ったことのない会社は、線を割っていれば載らない（ページも作らない）

**理由**

- **線を引いた理由がそのまま当てはまる。** 100人の線は「従業員の少ない持株会社が上位を埋めるとランキングとして読めなくなる」ために引いた（`docs/expansion/intent.md`）。持株会社に移った会社の単体の平均は管理部門の数十人の平均で、事業会社と同じ表に並べると線の目的と逆になる
- **ページは残す。** 検索からの入口を消さない（決定3と同じ判断）。運営者はゆくゆく企業と求職者のマッチングを考えており、採用を続けている会社のページを消すのは惜しい
- **前の期の数字のまま残すのは、古い数字をいまの数字として見せること**になる

**却下案**

- **いまのまま（前の期の数字でランキングに残す）。** 上のとおり、古い数字を出し続けたうえで、24か月後に事実と違う断りが出る
- **例外として新しい数字でランキングに残す。** 持株会社の管理部門の平均が事業会社と同じ表に並ぶ
- **線を割った会社の状態を台帳に持つ。** 行の従業員数から決まることを別に持つと、線に戻ったときに書き換え忘れが起きうる。ビルドが行から決めれば、戻るときに何もしなくてよい

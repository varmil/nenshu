# ADR-0009 女性活躍DBとの突合は法人番号だけで行う

状態: Accepted
日付: 2026-08-22

## 文脈

厚生労働省「女性の活躍推進企業データベース」から平均残業時間・年次有給休暇の取得率・男女の賃金の差異を取り込み、企業詳細ページに出す（`docs/worklife/`）。有報の1,867社と、女性活躍DBの64,879行を突合する必要がある。

突合の候補は3つあり、実物の全件CSV（`4e6b3d07-99_20260820_utf8_bom.zip`・2026-08-20 生成）で全部を測った。

**この決定は不可逆である。** 一度「その会社のもの」として残業時間を公開すれば、間違っていても読者はそれを見た後になる。持株会社の行に子会社の数字を出す構成で公開すると、後から引っ込めても「あのサイトは別会社の数字を出していた」が残る。

## 決定

**法人番号（13桁）だけで内部結合する。**

- 有報側は `ranking_unified_2026.csv` に `corporate_number` 列を足す。値は EDINETコードリスト（`Edinetcode.zip`・APIキー不要）の `提出者法人番号`
- 女性活躍DB側は2列目の `法人番号`
- **証券コードでも社名でも突合しない**
- **一致しない会社は「データ無し」として扱う。** 子会社・親会社・同名の別会社で代用しない

## 理由

**証券コードの列は自己申告で、実際に誤っている。** 実測で2件見つけた。

```
有報: 阪急阪神ホールディングス株式会社（9042） → 証券コード9042 で引くと「阪神電気鉄道株式会社」
有報: 株式会社ジェイエスピー（7942）         → 証券コード7942 で引くと「株式会社JSP」
```

そもそも証券コードが入っているのは64,879行のうち2,296行（3.5%）しかない。キーとして貧弱なうえ、間違っている。

**社名は同名の別会社が多い。** 正規化（NFKC・空白除去）しても決まらない。

```
大和工業株式会社 → 大阪府・兵庫県・北海道の3社（上場しているのは兵庫）
マツダ株式会社   → 広島県（上場）と兵庫県
株式会社マキタ   → 愛知県（上場）と香川県
松尾建設株式会社 → 佐賀県・神奈川県・茨城県
```

証券コードで確定した1,265社に対して社名突合を検算すると、相手が食い違うのは2件（0.16%）だった。低いが0ではない。**別会社の残業時間を出すのは、URLが別の会社を指すのと同じ種類の誤りである**（ADR-0006 で書類IDを退けたのと同じ線）。

**法人番号は国税庁が振る一意キーで、両側が持っている。** 女性活躍DBは62,534行（96.4%）が持ち、EDINETコードリストには `提出者法人番号` 列がある。曖昧さが原理的に無い。

**実物で両方の突合を走らせて比べた。**

| | 証券コード＋社名（暫定） | **法人番号** |
| --- | ---: | ---: |
| 突合できた社数 | 1,679社（89.9%） | **1,690社（90.5%）** |
| **誤った相手に紐づいた社数** | **29社（1.7%）** | **0社** |

有報1,867社のうち **EDINETコードリストから法人番号を引けなかった会社は0件**、同じ法人番号が2行以上ある会社も0件だった。

誤マッチ29社の内訳は、持株会社が子会社に紐づいたものが28社と、証券コードの誤登録が1社。

```
株式会社おきなわフィナンシャルグループ      → 株式会社 沖縄銀行
株式会社京都フィナンシャルグループ          → 株式会社 京都銀行
株式会社テレビ東京ホールディングス          → 株式会社テレビ東京
株式会社ニトリホールディングス              → 株式会社ニトリ
ハウス食品グループ本社株式会社              → ハウス食品株式会社
ハリマ化成グループ株式会社                  → ハリマ化成株式会社
ダイヤモンドエレクトリックホールディングス  → ダイヤゼブラ電機株式会社
阪急阪神ホールディングス株式会社            → 阪神電気鉄道株式会社（証券コードの誤登録）
（ほか21社）
```

**精度と網羅のトレードオフですらなかった。** 法人番号のほうが突合率も高い。

**持株会社が一致しないのは正しい挙動である。** 有報の提出者が持株会社で、女性活躍DBには事業子会社が別法人として登録されている場合、法人番号は一致しない。未突合177社は大和証券グループ本社・東京海上ホールディングス・野村ホールディングス・三井住友トラストグループ・フジ・メディア・ホールディングスが並び、単体従業員数の中央値は246人（全体は588人）だった。

**有報の平均年間給与が提出会社単体の数字である**（glossary「平均年間給与」）のと同じ理由で、残業時間も「その法人のもの」でなければならない。持株会社の行に子会社の残業時間を出すのは、単体従業員3,306人のキーエンスに連結12,784人ぶんの数字を出すのと同じ誤りになる。「本社のみ」バッジで扱ってきた問題そのものである。

## 結果

- **`ranking_unified_2026.csv` に `corporate_number` 列が増える。** `unified.py` の `HEADERS`、`pipeline/scripts/lib/csv.ts` の `HEADER` と `UnifiedRow` を更新する。`edinet_code` を足したとき（C0・ADR-0006）と同じ手順
- **`run.load_edinet_codelist()` が `提出者法人番号` を読むようになる。** いまは業種・上場区分・提出者名・証券コード・種別・資本金しか読んでいない
- **突合できない会社が177社出る。** その会社の企業詳細ページには「掲載なし」と出す（`docs/worklife/spec.md` AC-10）。節ごと消さない
- **突合率は年ごとに変わりうる。** 女性活躍DBへの掲載は任意で、企業がいつでも登録・更新できる。取り込みのたびに突合率をサマリーに出し、前年から大きく落ちたら気づける状態にする
- **法人番号を公開データとして画面に出すかは別の判断。** この ADR は突合キーとしての利用だけを決める

## 却下案

**証券コードで突合する。** 上のとおり自己申告で誤登録があり、3.5%の行にしか入っていない。誤りが2件見つかった時点で、キーとして使えないことが確定した。

**社名で突合し、曖昧なものだけ人手で解決する。** 1,867社に対して初回はやれるが、毎年の更新でこの作業が発生する。運営者は2026年10月から工数がほぼ取れない（`docs/product/product.md` の制約）ので、人手の解決を前提にした突合を運用に組み込めない。

**法人番号で引けなかった会社を社名でフォールバックする。** 着手前は「突合率は上がるが、上げたぶんがそのまま誤りのリスクになる」という見立てだった。**実測すると、上がりもしなかった。** 証券コード＋社名で拾えて法人番号で拾えない28社は全部が持株会社の誤マッチで、逆に法人番号だけで拾えた会社が39社あった。フォールバックは網羅を1社も増やさずに誤りだけを増やす。

有報1,867社すべてに法人番号が入っている以上、**フォールバックが発動する余地もない**（引けなかった会社が0件）。

**持株会社に、傘下の事業会社の値を出す。** 有報の平均年間給与と粒度が食い違う。ニトリホールディングスのページに株式会社ニトリの残業時間を出せば、同じページの年収（持株会社単体）と残業（事業会社）が別の集団の数字になる。証券コード＋社名の突合はこれを28社ぶん、黙ってやってしまっていた。

**法人番号を国税庁の法人番号公表サイトから別途取る。** EDINETコードリストに既に入っているので、依存先を1つ増やす理由がない。

# ADR-0008 企業ロゴの出典と再配布

状態: Accepted

日付: 2026-08-21

親 Issue: [#23](https://github.com/varmil/nenshu/issues/23)。施策は `docs/logo/`。

`docs/product/product.md` の制約「取得したデータを再配布してよいかの判断は運営者が行う」に該当する決定である。**判断は運営者が 2026-08-21 に行い、ここに記録する。**

## 文脈

社名の左にある頭文字マークをロゴに置き換えたい（Issue #23）。親 Issue には出典の候補として「OpenWork からのスクレイピング」「各企業wikiや公式サイト」が挙がっていた。

決めるべきことは3つある。**どこから取るか**、**自前でホストして再配布してよいか**、**どこまでの品質を載せるか**。いずれも一度公開すると引き返しにくい（1,000社ぶんの画像を配り始めた後で出典を変えると、URLとキャッシュを作り直すことになる）。

判断の材料として 2026-08-21 に実測した数値は `docs/logo/intent.md`「前提の確認」にある。要点は次の3つ。

- 法人番号（EDINETコード一覧の `提出者法人番号`）が1,867社すべてにあり、Wikidata の `P3225` でそのまま外部データに繋がる
- Commons のロゴは 522社（28%）ぶんあるが、**アスペクト比の中央値が 3.8:1 の横長ワードマーク**で、正方形の器には入らない
- 公式サイトから 128px 以上のアイコンが取れるのは、サイトを持つ会社の47%（全体の40%）

## 決定

### 1. 出典は Wikimedia Commons と当該企業の公式サイト

優先順位は Commons が先、無ければ公式サイトから取る。公式サイトからは**アイコン（`apple-touch-icon`・web app manifest の `icons`・`favicon`）だけでなく、ヘッダのロゴ画像と JSON-LD の `Organization.logo` も採る**——器が横長を許すようになったので（決定4）、ワードマークがそのまま使える。どちらも無ければロゴを持たない。

**OpenWork・OpenMoney からの取得は、運営者の指示（2026-08-21）で検討したが採れなかった。** 判断の根拠は規約の解釈ではなく、両サイトが**技術的なアクセス制御を実際に作動させている**ことである。

| サイト | 実測（2026-08-21） |
| --- | --- |
| OpenWork | 企業ページ自体は robots.txt で許可されており（禁止は検索系のみ）、`image.vorkers.com/resize/320x-/logo/company/…` にロゴがある。**しかし9社ぶんアクセスした時点で画像認証（CAPTCHA）に切り替わった。** その画面に「断続的な機械的なアクセス行為、コンテンツを一括ダウンロードする行為またはそれに類する行為も禁止」「損害賠償請求等の必要な措置（法的措置を含みます）」と明記されている |
| OpenMoney | 企業ページが AWS WAF の JS チャレンジで返る（`x-amzn-waf-action: challenge`・本文0バイト）。sitemap に3,394社ぶんの企業ページが載っているが、到達できない |

**900社ぶんとなると約1,800リクエストが必要で、続けるには CAPTCHA と WAF を突破する仕掛けを作ることになる。それは作らない。** アクセス制御の回避に当たるためで、規約の是非とは別の線である。

なお OpenWork は**証券コードを持っていない**（該当欄はユーザー編集式の wiki フィールドで、キーエンスでも空だった）。仮に到達できたとしても名寄せは社名の文字列一致に頼ることになり、別会社のロゴを載せる事故と隣り合わせだった。

**ランタイムで外部のロゴAPI（logo.dev 等）にホットリンクしない。** 読者のIPが第三者に渡り、「DBも外部APIも持たない」（product.md・ADR-0004）構成が崩れる。Clearbit の Logo API は2025年に終了しており、この種の無料サービスは寿命が読めない。ランニングコストをゼロに保つ制約とも、無料枠の変更リスクという形で衝突する。

### 2. 取得したロゴは自前でホストして配る

`web/public/logos/` に静的アセットとして置く。理由は3つ。

- 読者のブラウザから外部ドメインへのリクエストを出さない（プライバシーと、取得先サイトへの負荷の両方）
- 取得先の都合で画像が消えても表示が壊れない
- 品質の下限（決定3）を通すには、どのみち手元で実寸を検める必要がある

**再配布の根拠は出典ごとに違う。**

| 出典 | 根拠 |
| --- | --- |
| Commons | 自由ライセンスで公開されているもののみ（実測120件中107件がパブリックドメイン、残りは CC 系）。**CC ライセンスのものは作者・ライセンス名・元ファイルへのリンクを表示する** |
| 公式サイト | 当該企業のロゴを、当該企業を識別する目的でそのまま出す（商標の識別的な使用）。**加工しない** |

**ロゴが各社の商標であること、掲載が提携・推奨を示すものではないことを `/about` に明記する。**

### 3. 解像度の下限は設けない。実寸を記録しておき、見てから決める

**運営者の判断（2026-08-21）で、当初決めた「短辺128px未満は載せない」を撤回した。** 取れたものは一旦すべて載せ、**明らかにおかしいものを見てから頭文字マークに戻す**。欠損を最小限にすることを優先する。

下限を 128px に引くと到達率は40%（Commons と合わせて53%）に留まるが、**16px のファビコンまで許せば公式サイト側だけで74%に届く**（実測）。半分が空くことの見た目の損失のほうが、甘い画像が混ざることより大きいという判断である。

**代わりに、採った画像の実寸・出典・元URLを `logos.json` に必ず記録する。** これがあれば、後から「短辺◯px未満は頭文字に戻す」を**再取得なしで**決め直せる。閾値は運用の中で決める。

**下限を設けないことと、壊れたものを載せることは別である。** 1x1 の透明画像・全面が単色の画像・HTMLエラーページを画像として掴んだものは採らない（EDINET の 429 を `.zip` として保存した件と同じ失敗の形。CLAUDE.md）。

### 4. ロゴの器は正方形をやめ、横長のロゴが入る形にする

Commons のロゴの60%が 3.0:1 より横長で、正方形の器に入れると高さ10pxの帯になる。**器を正方形に保つと Commons は全体の3%しか寄与せず、出典として実質的に成立しない。**

器の寸法は L1 の design で決める。**満たすべきことは「社名の開始位置が揃う」「行の高さが変わらない」「360pxで横スクロールしない」の3つ**（`docs/logo/spec.md` AC-9・AC-10）。

これは `改善案.dc.html` が描く正方形の器から意図的に外れる決定である（U13 の「モックに合わせないと決めたもの」と同じ扱い）。

**器の形は Claude Design 上で決める**（運営者の指示・2026-08-21）。U11・U12・C2 でモックを読まずに実装してズレた（Issue #84）ので、L1 は `改善案.dc.html` を直接読み、必要なら新しいアートボードを起こしてから実装する。MCP は本セッションで接続済みであることを確認した。

## 結果

- ロゴが付く行と付かない行が混在する。**下限を外したので見込みは75〜85%**（当初の53%から上がった）。頭文字マークは**欠落ではなく意図した表示**として残る（元々そう設計してある）
- **画質にばらつきが出る。** 16px のファビコンを引き伸ばした行と、Commons の SVG の行が同じ列に並ぶ。実寸を `logos.json` に持つので、見てから閾値を引き直せる
- **ランキングの「操作でネットワークが発生しない」不変条件に、画像だけの例外が入る。** 絞り込み・並び替え・ページ送りで行が入れ替わればロゴ画像のリクエストが出る。E2E がリクエスト数を0で固定している5箇所を、文書・RSCペイロードだけを見る形に直す（`docs/logo/spec.md` AC-11）
- 年1回のデータ更新にロゴの再取得が1工程増える。リブランドは最大1年古いままになる
- `/about` にロゴの出典とライセンスの節が増える
- 画像は Worker を経由しない静的アセットとして配るので、Workers の CPU 予算には影響しない

## 代替案

- **公式サイトのファビコンだけで揃える（正方形を維持）。** 器を触らずに済むが、`/favicon.ico` しか無いサイトが多く、下限128pxを守ると到達率が40%まで落ちる。Commons の28%を丸ごと捨てることにもなる。
- **短辺128px の下限を維持する。** 当初はこちらを決定にしていたが、到達率が53%に留まる。運営者の判断で撤回した（決定3）。
- **横長ロゴを企業詳細ページだけで使い、ランキングは正方形のまま。** 器の規則が2つになり、同じ会社が場所によって違う見え方をする。`docs/logo/spec.md` 2.2 の「4箇所すべてで同じ規則」に反する。
- **ロゴを SVG のまま配る。** ファイルは小さく解像度も無限だが、SVG は外部参照とスクリプトを含みうる。1,600件を外部から取ってそのまま配るのは避け、ラスタライズする。

# ADR-0015: 有報の要約と AI 分析——分析セクションに限って評価を書き、材料を有報の外へ広げる

- 状態: 採用
- 日付: 2026-08-28
- 関連: [ADR-0010](0010-company-summary-sourcing.md)（会社説明文の出所と生成方針。**決定1「出所は事業の内容だけ」と決定2 の「評価語を書かない」を、分析セクションに限って上書きする。「モデルの一般知識から補わない」は上書きしない**）, [ADR-0008](0008-company-logo-sourcing.md)（外部サイトの叩き方。**そのまま引き継ぐ**）, [ADR-0012](0012-prerender-company-pages.md)（企業詳細の事前生成。**据え置き**——分析はビルド時に確定した文で、リクエスト時に生成しない）, [ADR-0006](0006-public-url-strategy.md)（公開URL。**据え置き**）, Issue [#214](https://github.com/varmil/nenshu/issues/214)（親）。Unit は C8（[#240](https://github.com/varmil/nenshu/issues/240)）・C9（[#241](https://github.com/varmil/nenshu/issues/241)）・C10（[#242](https://github.com/varmil/nenshu/issues/242)）。施策は `docs/company/`

## 背景

**有報には定量的・無機質な情報しか無く、定性的な意味付けが決定的に欠けている。** 企業詳細ページはいま、その欠けを引き継いでいる——金額・順位・偏差値・10年推移・稼ぐ力・残業と有給が並ぶが、**その会社がいまどういう状況にあるのかを言った文はどこにも無い。** C7（#161）が h1 直下に置いた説明文は「何をやっている会社か」に答えるもので、「いまどうなのか」には答えない。

**求職者にとって効くのはそこである**（`docs/company/intent.md`。マネタイズは転職マッチング）。年収が高いか低いかは表が示すが、**その水準が続きそうなのか、会社が伸びているのか畳んでいるのか**は、有報の本文を数万字読める人にしか分からない。

一方、この方針転換には **ADR-0010 の決定1・決定2 が正面から立ちはだかる。**

> 出所は有価証券報告書の「事業の内容」だけにする。
>
> **原文から導けない事実は書かない。** …**世間で知られている話をモデルの一般知識から補わない。評価語を書かない。**

**この3つは別々の線である。** ①出所を1つに絞る、②モデルの記憶から補わない、③評価語を書かない。ADR-0010 は3つをまとめて引いたが、**分析セクションで曲げる必要があるのは①と③で、②は曲げなくてよい。**

**この決定は不可逆である。** 2,961ページに主観と外部の出所を載せた後で「知ったふうな評価を出していた」となれば、根拠を全部公開していることを差別化に置いた立て方（`docs/ranking/spec.md` 2.）が崩れる。ADR-0010 が同じ危険を「入力を絞って出力を検める」で塞いだのに対し、**ここでは入力を広げるので、塞ぎ方を出力側に寄せる必要がある。**

判断の材料として 2026-08-27 に実測した値（#214）。

| | 値 |
| --- | --- |
| 使う4節の取得率 | **2,961 / 2,961社**（C8 で全社ぶんを実測） |
| 1社あたりの有報の原文 | 平均 21,005字（C6 の約29倍） |
| 「好調かどうかの一言」を実際に書いた社数 | 5社（性格の違う会社を選んだ） |
| その5例に含まれる算用数字 | **0〜2個** |
| 分析の材料になる数値のカバー率 | 平均年収の10年推移 100% / 稼ぐ力 99.9% / 定着 100% / 残業・有給 79.9% |
| 公式サイトのURLを持っている会社 | 2,690 / 2,961社（logo 施策の実測。Wikidata P856 ＋ gBizINFO） |

**5社とも違う語彙になった。** 段階評価（「好調」「安定」「不振」の3段など）を固定していたら、三陽商会の「本業は苦しい。最終利益は増えているが、これは保有株の売却益による」もファナックの「業績は堅いが、平均年収は10年で13%下がっている」も出せなかった。

## 決定

### 1. 2つのセクションに分け、規格を変える。ADR-0010 を覆すのは分析セクションだけ

企業詳細ページに **要約セクション**と **AI分析セクション**を置く。**ADR-0010 は要約セクションではそのまま効く。**

| | 要約セクション | AI分析セクション |
| --- | --- | --- |
| 出所 | 有報の4節だけ | 有報の4節＋同じページの数値＋**取得した外部の文書** |
| 書いてよいこと | 原文に**書いてある**事実 | 材料から**導ける**解釈 |
| 評価語 | **書かない** | **書く**（これが本体） |
| モデルの記憶から補う | 不可 | **不可**（ここは変わらない） |
| 出典の表示 | 有報とその節 | **参照した URL を画面に出す** |
| 機械ゲート | C6 のものを流用 | 別に作る（評価語は通す。**数値の個数に上限**・出典の有無・観点の網羅） |
| 検証パス | 「原文に**書いてあるか**」 | 「**渡した材料から導けるか**」 |

**分析が書いてよいのは、材料そのものではなく材料の読み方である。** 「営業利益が半減し、最終利益の増加は保有株の売却益による」は、原文の数字を突き合わせれば導ける。「業界の先行きは明るい」は、それを言っている文書が材料に無ければ導けない。

### 2. 材料は「取得した文書」に限る。モデルの記憶は材料にしない

分析が材料にしてよいのは次の3つで、**いずれも取ってきた実体がある**。

1. **有報の4節**（C8 が全社ぶん調達済み）
2. **同じページが既に表示している数値**——平均年収の10年推移・稼ぐ力とその推移・定着（平均在籍年数）・残業と有給
3. **その会社について Web から取得した文書**——公式サイト・ニュースリリース（自社ページでも PR TIMES 等の配信サービスでも）・採用求人（自社ページでも HRMOS・Indeed 等でも）・その他、検索で辿れる一次情報

**3 は積極的に使う。** 有報の無機質な情報を多面的に読み、求職者に分かりやすい形へ消化することがこのセクションの狙いなので、**有報だけに閉じると狙いに届かない**（運営者の判断・2026-08-28）。**配信サービスや求人サイトを理由に落とさない**——出所の格ではなく、**取れて出典を示せるかどうか**で見る。

**そのうえで、モデルの記憶から補ってはならない。** 世間で知られている話・報道の記憶・世評を、**取ってきた文書の裏付け無しに**書かない。これは ADR-0010 決定2 の唯一残る線であり、**分析セクションでも覆らない。**

**この線が要る理由は、検出できるかどうかにある。** 取ってきた文書は原文と突き合わせられるので、検証パス（決定1）がそのまま機能し、読者も出典を開いて確かめられる。**記憶にはその手がかりが1つも無い**——ADR-0010 が試作のキーエンスで踏んだ「原文と逆のことが書かれ、混ざったことを検出する手段が無い」型は、記憶に固有の性質である。

**数値は脇役。** 数値を並べることは目的ではない。主役は「その会社がいまどういう状況にあるか」という定性的な意味付けで、**分析に含めてよい算用数字の個数には上限を置く**（上限は C9 のパイロットで決める。暫定2個）。#214 の良い例5つに含まれる算用数字は0〜2個で、「半減」「増収増益」「2割」のように語で言えるものを語で言うと数値が要らなくなる。

### 3. 参照した URL を画面に出す

分析の近くに**参照した出典を並べる**。読者が開いて確かめられることが、材料を有報の外へ広げてよい前提になる。

**出所の信頼性は読者が評価してよい**（運営者の判断）。我々が「この配信サービスは載せる／載せない」と選別するより、**出典を示して読者に委ねるほうが素直**である——選別の基準そのものが我々の主観になり、しかもそれは画面に出ない。

**取り方は ADR-0008 の線をそのまま引き継ぐ。** ブラウザの UA への偽装をしない、ヘッドレスブラウザで取りに行かない、アクセス制御（画像認証・WAF のチャレンジ）を回避しない。403・503 は明示的な拒否として受け取り、その会社ではその材料を使わない。

**転載しない。** 材料から導いた解釈を自分の言葉で書くのであって、原文を長く写さない。

### 4. 読者が2つを見分けられることを要件にする

**この分け方が成り立つ前提は、読者が「事実の要約」と「主観的な分析」を見分けられることである。** UI の区別——見出し・地の色・断り書き——は装飾ではなく**要件**であり、満たせない見せ方は採らない。

具体は C10 が決めるが、**分析セクションには「これは AI による評価であって、有報に書いてある事実ではない」ことが読める断りを置く**。要約セクションには置かない（あちらは事実なので、同じ断りを付けると区別が消える）。

**同じ断りを1画面に2回置かない**（Issue #128 で「推定」について決めたのと同じ扱い）。セクションが2つ増えるぶん重複は起きやすくなるので、C10 は既存の断り（説明文の出典1行・実測値の見出しの決算期・推定の語）と突き合わせる。

### 5. C7 の説明文は残す。要約セクションの出所から「事業の内容」を外す

同じページに3種類の文が並ぶ（#214「決めるべきこと1」）。

| | 出所 | 役 |
| --- | --- | --- |
| 説明文（C7・実装済み） | 事業の内容 | **一目で分かる**（h1 直下・2〜3文） |
| 要約（C9・C10） | MD&A・リスク・課題・人的資本 | **読み込む** |
| 分析（C9・C10） | 同上＋数値＋外部の文書 | **意味付け** |

**説明文は消さない。** C3（#89）が空けた h1 直下を C7 が埋めた経緯があり、一等地の3行を「読み込む」文で置き換えると、社名の直後に数百字が来る。**代わりに、要約セクションの出所から「事業の内容」を外す**（`DescriptionOfBusinessTextBlock` は C5 のまま説明文だけが使う）。同じ原文から2つの文を作ると、1画面に同じ内容が2回出る。

### 6. 外部の材料は生成時に集める。事前調達の Unit を作らない

**C9 の生成セッションが検索して取りに行き、使った URL を出力に残す。** 全社ぶんを先に集めるクローラ（C11 のような Unit）は作らない。

- **何を探すべきかが会社によって違う。** 赤字なら構造改革の発表、増収なら新製品や増産の発表、人手が要る会社なら採用ページ——**先に「全社の公式サイトのトップを取る」と決めても当たりが薄い**
- **どのサービスに載るかも会社によって違う。** ニュースは自社ページか PR TIMES 等、求人は自社ページか HRMOS・Indeed 等。**URL の表を先に作れない**ので、検索で辿るほうが素直
- **再現性は URL を残すことで担保する。** 検証パスは、生成が挙げた URL を取りに行って「その文書から導けるか」を判定できる

**有報の4節だけは事前調達のまま**（C8・実装済み）。全社が必ず持ち、要素名で確実に引けるので、検索で辿る理由が無い。

### 7. 生成の主体と工程は C5〜C7 のものを引き継ぐ

**Anthropic API は使わない。生成は Claude Code のセッション（Max サブスクの枠）で回す**（ADR-0010 の 2026-08-26 の追記のまま）。工程も `plan → 生成 → 機械ゲート → 検証 → merge` をそのまま使う。

**要約と分析は1回の呼び出しで両方書かせる。** 有報の原文が C6 の約29倍あり、2回読ませると量が倍になる。**ただし機械ゲートと検証パスは規格ごとに分ける**（決定1）。

**書けない会社では、そのセクションを出さない。** C7 が178社で取った形と同じで、空の器・プレースホルダ・「準備中」を置かない。**材料の薄い会社の分析を無理に埋めない**——外部の文書が取れる量は会社によって大きく違い、埋めにいけば記憶から補うことになる（決定2 が禁じたもの）。

**【2026-08-28・運営者の判断で改めた】要約と分析は対で出す。片方だけのページを作らない。** 初版は「要約は書けるが分析は書けない会社が出てよい」としていたが、**読者から見て「事実はあるのに解釈が無い」ページに意味が無い**ため覆した。満たし方は**書き直して両方通す**のが本筋で、**それでも通らなければ残ったほうも落とす**。

**この「両方落とす」を残すことが、決定1 の検証パスを守っている。** 「必ず対にする」を絶対条件にすると、**通らない分析を通す圧力がそのまま検証パスに掛かる**——落とせるようにしておくことで、書き直しの回数に上限を置ける。**C9 のパイロットで落ちた2社は、どちらも1文を直せば通った**（材料は足りていて、言い過ぎていただけだった）ので、実際に効くのはほとんど書き直しのほうになる。

## 理由

**有報を「読める形にする」ことがこのサイトの立て方そのものだからである。** 数値については既にやっている——年齢補正・偏差値・順位・レーダーは、どれも生の開示をそのまま出さずに読める形へ変えたものだ。**文についてだけ「原文に書いてあることしか言わない」を守ると、有報の無機質さがそのまま読者に渡る。** 三陽商会の有報を素直に読むと「最終利益は増えた」で終わり、それが保有株の売却益だと気づくには営業利益・経常利益・純利益の動きを突き合わせる必要がある。**その突き合わせを代わりにやることが、ここで言う「意味付け」の中身である。**

**有報だけでは多面的にならない。** 有報は年1回・法定の書式で、書いてあるのは提出時点の会社の言い分に限られる。**求職者が知りたいことの多くはその外にある**——いまどんな人を募集しているか、直近に何を発表したか、事業のどこに人を割いているか。**公式サイト・リリース・求人はどれも会社自身が出している一次情報**で、有報と出所の性質は変わらない。

**「配信サービスだから信頼性が低い」は成り立たない。** PR TIMES に載ったリリースも HRMOS に載った求人も、**出しているのは会社自身**である。むしろ Wikipedia のような第三者の編集物より一次に近い。**そして出典 URL を示せば、信頼性の評価は読者ができる**（運営者の判断）。我々が出所を選別すると、その基準自体が画面に出ない主観になる。

**評価を書くことと、根拠を隠すことは別である。** CLAUDE.md の約束は「数値の出典と計算方法は必ずユーザーから見える場所に置く」「根拠を隠した推定値を表示しない」であって、「評価を書かない」ではない。分析セクションは**材料の在り処を全部画面に出す**——有報の節、同じページの数値、参照した URL。

**線を「記憶かどうか」に引いたのは、そこが検出可能性の境目だからである。** 出所の格（有報か／公式サイトか／配信サービスか）で引くと、どこに引いても恣意的になり、しかも**どちらの側にも検証できない記述が混ざりうる**。**取ってきた文書か記憶か**で引けば、前者は突き合わせられ後者は突き合わせられない、という機械的な違いに対応する。**C6 の二段構え（機械ゲート＋検証パス）が効くのは前者だけ**で、記憶を許した瞬間に検証パスは判定する対象を失う。

**語彙を固定しないと決められたのは、5社で実際に書いてみたからである。** 段階評価を先に決めていたら、ファナックの「業績は堅いが、平均年収は10年で13%下がっている」——求職者にとって最も効く食い違い——は「好調」の一語に潰れていた。

## 結果

- **`docs/company/spec.md` の 1.19・AC-25〜AC-30 と、`overview.md`・`intent.md`・`glossary.md` を同時に改訂する。** ADR-0010 の決定1・決定2 にも上書きの注記を置く
- **評価を含む文と、有報の外の出所を公開する最初の決定になる。** 誤りが見つかったときの直し方は、C6 と同じく「その会社をセクションごと落とす」だけになる。会社ごとの手動での上書きは持たない
- **生成の工程に Web の取得が入る。** C9 は既に約140セッションの見積りで、1社ごとに検索を挟めばさらに増える。**どこまで探すか（1社あたりの検索回数・取りに行くページ数）は C9 のパイロットで実測して決める**——ここを決めないと、量が会社ごとに青天井になる
- **出典リンクが2,961ページに載る。** 年1回の更新なので、**1年後にリンク切れになる出典が出る**（ニュースリリースは特に消えやすい）。**参照した日を添えるか、リンク切れをどう扱うかは C10 が決める**（未決事項）
- **分析の厚みが会社によって変わる。** 外部の文書が取れる量は上場の大手に偏る。**薄い会社は薄いままにする**——埋めにいけば記憶から補うことになる（決定2）
- **検証パスの判定が難しくなり、材料も増える。** C6 の「その文が原文に**書いてあるか**」は二値でぶれにくいが、分析の「その解釈が**渡した材料から導けるか**」は判定者によってぶれる。**対策は3つ**——観点ごとに根拠として使ってよい材料を紐づけること、**数値の裏付けを機械的に照合すること**（「10年で13%下がっている」なら `history.json` が支持するか確かめられる。C6 に無かった検査）、**挙がった URL を検証パスが実際に取りに行くこと**
- **失敗の型の表を2つ持つ。** C6 は `prompts/generate.md` に型①〜⑪を積み上げ、**番号を prompts 側に固定する**ことで回をまたいで比べられるようにした。**要約と分析は規格が違うので表を分ける**
- **目視レビューの枠を分析にも持つ。** C6 の型⑪（有報の記載作法をそのまま書く）は原文にあるので機械ゲートも検証パスも通し、**目視レビューだけが拾った**。分析では「導けるか」の判定がぶれるぶん、同じ枠がより効く
- **表示のペイロードは問題にならない見込み。** `/company/[id]` は静的アセットで、C7 の説明文（約116字）が +976 B だった。要約1,000字＋分析800字＋出典数件でも +10KB 程度。**`/` には出さない**ので `companies.json` の gzip 100KB 予算とも無関係で、**Worker バンドルにも入らない**
- **ページタイトルを年収寄りから変えるかは、この ADR では決めない**（#214 の未決事項のまま）

## 却下案

**現状維持（ADR-0010 をそのまま守り、評価も外部の出所も足さない）。** 一貫していて、検証も楽になる。**だが作れるのは原文の並べ替えだけで、読者の負担が減らない。** 有報が定量的な情報しか持たないことが問題なのに、その制約をそのまま出力に写すことになる。

**評価は書くが、材料は有報と同じページの数値に限る**（この ADR の初版・2026-08-28 午前）。検証が原文との照合だけで済み、出典も1つで済む。**だが多面的にならない。** 有報は年1回・法定の書式で、書いてあるのは提出時点の会社の言い分に限られる——いま何を募集し、直近に何を発表したかは1文字も無い。**「無機質な情報を多面的に消化する」という狙いに届かないので、運営者の判断で同日に覆した。**

**モデルの一般知識も材料にする。** 分析は最も厚く柔らかくなる。**だが混ざったことを検出する手段が無い**（ADR-0010 決定2 の却下案と同じ）。**評価を書けるようにしたうえで記憶まで許すと、C6 が作った二段構えのうち検証パスが判定する対象を失う**——「原文から導けるか」の「原文」が無くなる。読者も確かめられない。**取ってきた文書に限れば、広げても両方が生きる。**

**出所を格付けして選別する**（有報＞公式サイト＞配信サービス＞求人サイト、のように）。素朴には安全側に見える。**だが基準そのものが画面に出ない主観になる。** PR TIMES のリリースも HRMOS の求人も出しているのは会社自身で、第三者の編集物より一次に近い。**出典を示して読者に委ねるほうが、我々の選別を隠すより誠実である**（運営者の判断）。

**外部の材料を全社ぶん事前に集める Unit（C11）を作る。** 再現性が高く、量も管理できる。**だが何を探すべきかが会社によって違い、どのサービスに載るかも違う**ので、URL の表を先に作れない。**先に「全社の公式サイトのトップを取る」と決めても当たりが薄い**——logo 施策の実測でも、URL がどこにも無い会社が271社、届かない会社が183社ある。再現性は**使った URL を出力に残す**ことで足りる。

**段階評価（好調 / 安定 / 不振の3段など）を先に決め、一言はその語彙から選ばせる。** 検証が二値になり、集計もできる。**だが5社で書いた一言のうち、3段に潰れないものが4つあった**（三陽商会・ファナック・出前館・ジャパンディスプレイ）。**この機能の価値は、まさにその潰れない部分にある。** さらに段階評価はランキングやスコアに見え、`docs/worklife/` で「束ねる名前を付けない」と決めた線とも衝突する。

**1つのセクションにまとめ、評価語を含む文だけ地の色を変える。** 分量は減る。**だが読者が文単位で色を追うことになり、決定4 の「見分けられること」が実質守れない。** セクションで割るほうが、断り書きと出典の置き場所も1つで済む。

**リクエスト時に生成する（読者が押したら分析を作る）。** 常に最新の見立てになり、リンク切れも起きにくい。**だが ADR-0012（事前生成）と ADR-0004（DBも外部APIも持たない）の両方を覆すことになり、配信時に有料の外部APIを呼ぶ最初の機能になる。** `docs/product/product.md` の「ランニングコストをゼロに保つ」に正面から触れる。

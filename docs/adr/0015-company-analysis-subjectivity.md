# ADR-0015: 有報の要約と AI 分析——分析セクションに限って評価と推測を書き、材料を有報の外へ広げる

## 背景

**有報には定量的・無機質な情報しか無く、定性的な意味付けが決定的に欠けている。** 企業詳細ページはいま、その欠けを引き継いでいる——金額・順位・偏差値・10年推移・稼ぐ力・残業と有給が並ぶが、**その会社がいまどういう状況にあるのかを言った文はどこにも無い。** C7（#161）が h1 直下に置いた説明文は「何をやっている会社か」に答えるもので、「いまどうなのか」には答えない。

**求職者にとって効くのはそこである**（`docs/company/intent.md`。マネタイズは転職マッチング）。年収が高いか低いかは表が示すが、**その水準が続きそうなのか、会社が伸びているのか畳んでいるのか**は、有報の本文を数万字読める人にしか分からない。

一方、この方針転換には **ADR-0010 の決定1・決定2 が正面から立ちはだかる。**

> 出所は有価証券報告書の「事業の内容」だけにする。
>
> **原文から導けない事実は書かない。** …**世間で知られている話をモデルの一般知識から補わない。評価語を書かない。**

**この3つは別々の線である。** ①出所を1つに絞る、②モデルの記憶から補わない、③評価語を書かない。ADR-0010 は3つをまとめて引いたが、**分析セクションで曲げる必要があるのは①・②・③のすべてで、②は「具体的な数値」に限って残す**（下記・決定3）。

**この決定は不可逆である。** 2,961ページに主観と外部の出所を載せた後で「知ったふうな評価を出していた」となれば、根拠を全部公開していることを差別化に置いた立て方（`docs/ranking/spec.md` 2.）が崩れる。ADR-0010 が同じ危険を「入力を絞って出力を検める」で塞いだのに対し、**ここでは入力を広げるので、塞ぎ方を出力側に寄せる必要がある。**

判断の材料として 2026-08-27 に実測した値（#214）。

| | 値 |
| --- | --- |
| 使う4節の取得率 | **2,961 / 2,961社**（C8 で全社ぶんを実測） |
| 1社あたりの有報の原文 | 平均 21,005字（C6 の約29倍） |
| 「好調かどうかの一言」を実際に書いた社数 | 5社（性格の違う会社を選んだ） |
| その5例に含まれる算用数字 | **0〜2個** |
| 分析の材料になる数値のカバー率 | 平均年収の10年推移 100% / 稼ぐ力 99.9% / 定着 100% / 残業・有給 79.9% |
| 公式サイトのURLを持っている会社 | 2,690 / 2,961社（logo 施策の実測。Wikidata P856 ＋ gBizINFO） |

**5社とも違う語彙になった。** 段階評価（「好調」「安定」「不振」の3段など）を固定していたら、三陽商会の「本業は苦しい。最終利益は増えているが、これは保有株の売却益による」もファナックの「業績は堅いが、平均年収は10年で13%下がっている」も出せなかった。

**50回まわして分かった追加の背景（2026-09-01）**: C9 は回すたびに検証パスが落とした型を `prompts/generate.md` へ書き戻してきたが、積み上がった型のうち9つが「材料が述べていないことを書くな」という同じ系統だった（内訳が書かれていない影響を切り分けた／材料が述べていない因果を作った／材料が書いていないことを「無い」と断定した／1期の増減から趨勢を述べた／材料が持っていない比較を作った／会社が並べているものに重みを付けた／数字を評価する基準を材料の外から持ち込んだ／減収の要因を理由の書かれていない減益にも掛けた／並べられているものに包含関係を作った）。どれも「解釈するな」と言っているに等しく、1つずつは正しく見えても、近づいた先が要約だった。

**運営者が示した対照が一目でそれを示す。** `prompts/verify.md` は次の表を「落ちた文 → 直した形」として載せていたが、望まれているのは左側であり、しかもまだ弱い。

| verify.md が「落ちた文」として挙げていたもの | 実際に望まれている側 |
| --- | --- |
| 会計処理の変更を差し引いても縮小は続いている | **これ** |
| 労務費と資材価格の高騰が利益を削っている | **これ** |
| 上場も2024年11月と新しく | **これ** |
| 待遇がそろっている分だけ入り口の競争は厳しい | **これ** |

**4つとも、材料の数字を突き合わせれば読者が納得できる推測である。** そして4つとも、有報を数万字読める人なら自分で辿り着くが、そうでない人には届かない種類の話でもある。**「意味付け」と呼んだのはまさにこれで、実装の側が型を積むうちに、その狙いから離れていた。**

## 決定

### 1. 2つのセクションに分け、規格を変える。ADR-0010 を覆すのは分析セクションだけ

企業詳細ページに **要約セクション**と **AI分析セクション**を置く。**ADR-0010 は要約セクションではそのまま効く。**

| | 要約セクション | AI分析セクション |
| --- | --- | --- |
| 出所 | 有報の4節だけ | 有報の4節＋同じページの数値＋**取得した外部の文書**＋**モデルの一般知識**（具体的数値を除く） |
| 書いてよいこと | 原文に**書いてある**事実 | 材料から**推測できる**解釈・因果・評価・見通し・重み付け・比較・含意 |
| 評価語 | **書かない** | **書く**（これが本体） |
| モデルの記憶から補う | 不可 | **文脈・語の説明・相場観・一般的な理解は可。具体的な数値（金額・率・順位・シェア・従業員数）は不可** |
| 出典の表示 | 有報とその節 | **参照した URL を画面に出す**（使った場合） |
| 機械ゲート | C6 のものを流用 | 別に作る（評価語は通す。**数値の個数に上限**・出典の有無・観点の網羅） |
| 検証パス | 「原文に**書いてあるか**」 | 「**事実の誤りが無いか**」（6種類。下記・決定2） |

**分析が書いてよいのは、材料そのものではなく材料の読み方である。** 「営業利益が半減し、最終利益の増加は保有株の売却益による」は、原文の数字を突き合わせれば導ける。**因果・評価・見通し・重み付け・比較・含意は、材料が明示していなくても「そう読めるなら」書いてよい**——「労務費と資材価格の高騰が利益を削っている」は、材料が減益と労務費高騰を別々に書いていてもそう読めるなら書ける。「会計処理の変更を差し引いても縮小は続いている」は、内訳の金額が材料に無くても規模感から推測できるなら書ける。会社が複数の施策を並べていても、求職者にとって効くのがどれかを言ってよい。1期しか無くても「この流れが続くなら」と趨勢を語ってよい。

**「〜とみられる」「〜だろう」で逃げる必要はない。言い切ってよい。** 読者はこれが AI の分析だと分かって読む（決定4・C10 の要件）。

### 2. 落とす線は「事実の誤り」だけに引き直す。それ以外の推測は落とさない

**検証パスが `false` にしてよいのは、材料と食い違う記述だけである。**

| 落とす（事実の誤り） | 例 |
| --- | --- |
| **数値の向き**（型S1・A5） | 2,278 → 2,045 億円と減っているのに「上回った」 |
| **数値の幅**（型A8） | 9.0%増を「二桁の増益」 |
| **出来事の時点**（型A12） | 翌期の発売を当期の新作として書く |
| **区分**（型A10・A14・A16・型④） | セグメントの損益をその中の事業名で呼ぶ／別の節の出来事を移す |
| **材料の外の属性・出来事を事実として足す**（型A3） | 原文に無い工場・製品・資本関係、前期の大口案件の存在などを書く |
| **改善要因を悪化の中身として並べる**（型A13） | 増益要因を減益の説明に混ぜる |

**この6つは推測ではなく誤りである。** 読者が材料に当たれば違うと分かり、しかも「そう読める」の余地が無い。

**それ以外は落とさない。** 内訳の切り分け・因果の推測・重み付け・趨勢や比較や水準の語り・材料の外の文脈を持ち込むことは、分析については禁じない。**「言い過ぎ」「断定しすぎ」「材料は述べていない」は、それ単独では `false` の理由にならない**（`false` にするのは決定2の6類型に該当するときだけ）。検証パスの申告の仕組みは残す——落とさなかったが気になったものを添えることで、線の引き直しがまた要るときに気づける。

**推測の誤りと事実の誤りは、読者にとって同じものではない。** 「労務費の高騰が利益を削っている」が外れていても、読者は分析として読んでおり、材料を見れば自分で判断できる。「営業利益は増えた」が実際には減っていれば、それは嘘である。落とす線をここに引けば、踏み込みと正確さは両立する。

### 3. モデルの記憶と一般的な知識を使ってよい。ただし具体的な数値だけは材料にあるものに限る

**業界の文脈・語の説明・その会社が置かれている状況の一般的な理解・相場観・競合との位置関係・将来性の評価を、取ってきた文書の裏付け無しに書いてよい。主観的な評価・意味づけこそがこのセクションの本体であり、書くこと自体を推奨する。**

**ただし具体的な数値は材料にあるものだけ。** 記憶から金額・率・順位・シェア・従業員数を書かない。材料は次の3つで、**いずれも取ってきた実体がある**——①有報の4節（C8 が全社ぶん調達済み）、②同じページが既に表示している数値（平均年収の10年推移・稼ぐ力とその推移・定着・残業と有給）、③その会社について Web から取得した文書（公式サイト・ニュースリリース・採用求人。配信サービスや求人サイトも可、**出所の格ではなく取れて出典を示せるかで見る**）。

**この一線だけを残す理由は、害の形が違うことにある。** 記憶から書いた**文脈**が外れていても「そう読める話」の範囲に収まり、読者は分析として受け取る。**記憶から書いた数字は事実の顔をして出る**——読者はそれを有報の数値と区別できず、同じページの表と食い違えばサイトの立て方（根拠を全部画面に出す）そのものが崩れる。ADR-0010 が試作のキーエンスで踏んだ「原文と逆のことが書かれ、混ざったことを検出する手段が無い」型は、数字で起きたときにいちばん重い。

**外部の文書は引き続き積極的に使う。** 有報の無機質な情報を多面的に読み、求職者に分かりやすい形へ消化することがこのセクションの狙いなので、有報だけに閉じると狙いに届かない（運営者の判断・2026-08-28）。**配信サービスや求人サイトを理由に落とさない。使ったら URL を残す**——記憶で書いてよくなっても、取ってきたものは出典を示せるほうが読者に強い。**数値は脇役**——数値を並べることは目的ではなく、主役は「その会社がいまどういう状況にあるか」という定性的な意味付けで、分析に含めてよい算用数字の個数には上限を置く（暫定2個。「半減」「増収増益」「2割」のように語で言えるものを語で言うと数値が要らなくなる）。

### 4. 参照した URL を画面に出す

分析の近くに**参照した出典を並べる**（使った場合）。読者が開いて確かめられることが、材料を有報の外へ広げてよい前提になる。

**出所の信頼性は読者が評価してよい**（運営者の判断）。我々が「この配信サービスは載せる／載せない」と選別するより、出典を示して読者に委ねるほうが素直である——選別の基準そのものが我々の主観になり、しかもそれは画面に出ない。

**取り方は ADR-0008 の線をそのまま引き継ぐ。** ブラウザの UA への偽装をしない、ヘッドレスブラウザで取りに行かない、アクセス制御（画像認証・WAF のチャレンジ）を回避しない。403・503 は明示的な拒否として受け取り、その会社ではその材料を使わない。

**転載しない。** 材料から導いた解釈を自分の言葉で書くのであって、原文を長く写さない。

### 5. 読者が2つを見分けられることを要件にする

**この分け方が成り立つ前提は、読者が「事実の要約」と「主観的な分析」を見分けられることである。** UI の区別——見出し・地の色・断り書き——は装飾ではなく**要件**であり、満たせない見せ方は採らない。**推測を言い切るほど、これが AI の評価であると読者に分かることの重みが増す。**

具体は C10 が決めるが、**分析セクションには「これは AI による評価であって、有報に書いてある事実ではない」ことが読める断りを置く**。要約セクションには置かない（あちらは事実なので、同じ断りを付けると区別が消える）。

**同じ断りを1画面に2回置かない**（Issue #128 で「推定」について決めたのと同じ扱い）。セクションが2つ増えるぶん重複は起きやすくなるので、C10 は既存の断り（説明文の出典1行・実測値の見出しの決算期・推定の語）と突き合わせる。

### 6. C7 の説明文は残す。要約セクションの出所から「事業の内容」を外す

同じページに3種類の文が並ぶ（#214「決めるべきこと1」）。

| | 出所 | 役 |
| --- | --- | --- |
| 説明文（C7・実装済み） | 事業の内容 | **一目で分かる**（h1 直下・2〜3文） |
| 要約（C9・C10） | MD&A・リスク・課題・人的資本 | **読み込む** |
| 分析（C9・C10） | 同上＋数値＋外部の文書＋一般知識 | **意味付け** |

**説明文は消さない。** C3（#89）が空けた h1 直下を C7 が埋めた経緯があり、一等地の3行を「読み込む」文で置き換えると、社名の直後に数百字が来る。**代わりに、要約セクションの出所から「事業の内容」を外す**（`DescriptionOfBusinessTextBlock` は C5 のまま説明文だけが使う）。同じ原文から2つの文を作ると、1画面に同じ内容が2回出る。

### 7. 外部の材料は生成時に集める。事前調達の Unit を作らない

**C9 の生成セッションが検索して取りに行き、使った URL を出力に残す。** 全社ぶんを先に集めるクローラ（C11 のような Unit）は作らない。

- **何を探すべきかが会社によって違う。** 赤字なら構造改革の発表、増収なら新製品や増産の発表、人手が要る会社なら採用ページ——**先に「全社の公式サイトのトップを取る」と決めても当たりが薄い**
- **どのサービスに載るかも会社によって違う。** ニュースは自社ページか PR TIMES 等、求人は自社ページか HRMOS・Indeed 等。**URL の表を先に作れない**ので、検索で辿るほうが素直
- **再現性は URL を残すことで担保する。** 検証パスは、生成が挙げた URL を取りに行って「その文書から導けるか」を判定できる

**有報の4節だけは事前調達のまま**（C8・実装済み）。全社が必ず持ち、要素名で確実に引けるので、検索で辿る理由が無い。

### 8. 生成の主体と工程は C5〜C7 のものを引き継ぐ

**Anthropic API は使わない。生成は Claude Code のセッション（Max サブスクの枠）で回す**（ADR-0010 の 2026-08-26 の追記のまま）。工程も `plan → 生成 → 機械ゲート → 検証 → merge` をそのまま使う。

**要約と分析は1回の呼び出しで両方書かせる。** 有報の原文が C6 の約29倍あり、2回読ませると量が倍になる。**ただし機械ゲートと検証パスは規格ごとに分ける**（決定1）。

**書けない会社では、そのセクションを出さない。** C7 が178社で取った形と同じで、空の器・プレースホルダ・「準備中」を置かない。**材料の薄い会社の分析を無理に埋めない**——外部の文書が取れる量は会社によって大きく違い、それでも決定3の一般知識の範囲までは書けるので、実際に「埋められない」のは記憶でも埋められない具体的な数値だけである。

**要約と分析は対で出す。片方だけのページを作らない**（2026-08-28・運営者の判断で改めた）。初版は「要約は書けるが分析は書けない会社が出てよい」としていたが、読者から見て「事実はあるのに解釈が無い」ページに意味が無いため覆した。満たし方は**書き直して両方通す**のが本筋で、**それでも通らなければ残ったほうも落とす**。

**この「両方落とす」を残すことが、決定2の検証パスを守っている。** 「必ず対にする」を絶対条件にすると、通らない分析を通す圧力がそのまま検証パスに掛かる——落とせるようにしておくことで、書き直しの回数に上限を置ける。

## 理由

**有報を「読める形にする」ことがこのサイトの立て方そのものだからである。** 数値については既にやっている——年齢補正・偏差値・順位・レーダーは、どれも生の開示をそのまま出さずに読める形へ変えたものだ。**文についてだけ「原文に書いてあることしか言わない」を守ると、有報の無機質さがそのまま読者に渡る。** 三陽商会の有報を素直に読むと「最終利益は増えた」で終わり、それが保有株の売却益だと気づくには営業利益・経常利益・純利益の動きを突き合わせる必要がある。**その突き合わせを代わりにやることが、ここで言う「意味付け」の中身である。**

**有報だけでは多面的にならない。** 有報は年1回・法定の書式で、書いてあるのは提出時点の会社の言い分に限られる。**求職者が知りたいことの多くはその外にある**——いまどんな人を募集しているか、直近に何を発表したか、事業のどこに人を割いているか。公式サイト・リリース・求人はどれも会社自身が出している一次情報で、有報と出所の性質は変わらない。

**「配信サービスだから信頼性が低い」は成り立たない。** PR TIMES に載ったリリースも HRMOS に載った求人も、出しているのは会社自身である。むしろ Wikipedia のような第三者の編集物より一次に近い。そして出典 URL を示せば、信頼性の評価は読者ができる（運営者の判断）。我々が出所を選別すると、その基準自体が画面に出ない主観になる。

**評価を書くことと、根拠を隠すことは別である。** CLAUDE.md の約束は「数値の出典と計算方法は必ずユーザーから見える場所に置く」「根拠を隠した推定値を表示しない」であって、「評価を書かない」ではない。分析セクションは材料の在り処を全部画面に出す——有報の節、同じページの数値、参照した URL。

**線を「具体的な数値かどうか」に引いたのは、そこが検出可能性と実害の境目だからである。** 出所の格（有報か／公式サイトか／配信サービスか／記憶か）で全面的に引くと、記憶を許した瞬間に検証パスは判定する対象を失う。**ただし記憶で書いた文脈的な推測（因果・評価・見通し）は、読者が「そう読めるか」を材料と照らして自分で判定できる**ので、事実の誤り6類型に当たらない限り許容してよい。**記憶で書いた具体的な数値だけは、事実の顔をして出るのに検証しようがない**ので、そこだけ線を残した。

**規則を積む工程には、締まる方向にしか動かない癖がある。** 落ちた型を書き戻すのは C6 から続く C9 の中心的な仕組みで、実際に品質を上げてきた。**ただし落ちるのは常に「言い過ぎた」側で、「言い足りない」側は落ちない**——検証パスは材料と突き合わせるので、材料に近い文ほど通る。50回ぶんの書き戻しが一方向に効き続けた結果、分析が要約に近づいていた。決定2でその向きを引き直した。

**語彙を固定しないと決められたのは、5社で実際に書いてみたからである。** 段階評価を先に決めていたら、ファナックの「業績は堅いが、平均年収は10年で13%下がっている」——求職者にとって最も効く食い違い——は「好調」の一語に潰れていた。

## 結果

- **`docs/company/spec.md` の 1.19・AC-25〜AC-30 と、`overview.md`・`intent.md`・`glossary.md` を同時に改訂する。** ADR-0010 の決定1・決定2 にも上書きの注記を置く
- **評価と推測を含む文と、有報の外の出所・モデルの一般知識を公開する最初の決定になる。** 誤りが見つかったときの直し方は、C6 と同じく「その会社をセクションごと落とす」だけになる。会社ごとの手動での上書きは持たない
- **生成の工程に Web の取得が入る。** C9 は既に約140セッションの見積りで、1社ごとに検索を挟めばさらに増える。**探す量の上限は1社あたり検索2回・取得3ページ**（C9 のパイロットで実測して決めた）
- **出典リンクが2,961ページに載る。** 年1回の更新なので、1年後にリンク切れになる出典が出る（ニュースリリースは特に消えやすい）。**参照した日を添えるか、リンク切れをどう扱うかは C10 が決める**（未決事項）
- **分析の厚みが会社によって変わる。** 外部の文書が取れる量は上場の大手に偏るが、決定3の一般知識の範囲は材料の多寡によらず書けるので、要約ほどの薄さの差は出ない見込み
- **検証パスの判定対象を「材料に当たっているか」から「事実の誤りが無いか」の6類型に絞った。** 判定のぶれは減ったが、目視レビューの枠は引き続き要る——C6 の型⑪（有報の記載作法をそのまま書く）は機械ゲートも検証パスも通し、目視レビューだけが拾った
- **表示のペイロードは問題にならない見込み。** `/company/[id]` は静的アセットで、C7 の説明文（約116字）が +976 B だった。要約1,000字＋分析800字＋出典数件でも +10KB 程度。`/` には出さないので `companies.json` の gzip 100KB 予算とも無関係で、Worker バンドルにも入らない
- **ページタイトルを年収寄りから変えるかは、この ADR では決めない**（#214 の未決事項のまま）

## 却下した案

**現状維持（ADR-0010 をそのまま守り、評価も外部の出所も一般知識も足さない）。** 一貫していて、検証も楽になる。**だが作れるのは原文の並べ替えだけで、読者の負担が減らない。** 有報が定量的な情報しか持たないことが問題なのに、その制約をそのまま出力に写すことになる。

**評価は書くが、材料は有報と同じページの数値に限る**（この ADR の初版・2026-08-28 午前）。検証が原文との照合だけで済み、出典も1つで済む。**だが多面的にならない。** 有報は年1回・法定の書式で、書いてあるのは提出時点の会社の言い分に限られる——いま何を募集し、直近に何を発表したかは1文字も無い。「無機質な情報を多面的に消化する」という狙いに届かないので、運営者の判断で同日に覆した。

**評価は書くが記憶は一切許さず、材料から「導ける」ことだけに絞る**（この ADR の当初決定2・2026-08-28）。検証パスが「原文に書いてあるか」の延長で判定できて安全に見えた。**だが50回まわすと、検証パスが積んだ型のほとんどが「材料が述べていないことを書くな」という同じ系統になり、分析が要約と大差ないものになった**（運営者の指摘・2026-09-01）。因果・重み付け・趨勢の読みまで塞ぐと、この機能の狙いである「有報を読める形にする」に届かない。

**記憶も含めて数値まで全部許す。** 分析は最も厚く柔らかくなる。**だが同じページの表と食い違う数字が出たときに気づく手段が無い**（ADR-0010 決定2 の却下案と同じ）。記憶から書いた数字は事実の顔をして出るので、害の形が文脈的な推測とは違う。ここだけ線を残した。

**出所を格付けして選別する**（有報＞公式サイト＞配信サービス＞求人サイト、のように）。素朴には安全側に見える。**だが基準そのものが画面に出ない主観になる。** PR TIMES のリリースも HRMOS の求人も出しているのは会社自身で、第三者の編集物より一次に近い。出典を示して読者に委ねるほうが、我々の選別を隠すより誠実である（運営者の判断）。

**外部の材料を全社ぶん事前に集める Unit（C11）を作る。** 再現性が高く、量も管理できる。**だが何を探すべきかが会社によって違い、どのサービスに載るかも違う**ので、URL の表を先に作れない。先に「全社の公式サイトのトップを取る」と決めても当たりが薄い——logo 施策の実測でも、URL がどこにも無い会社が271社、届かない会社が183社ある。再現性は使った URL を出力に残すことで足りる。

**段階評価（好調 / 安定 / 不振の3段など）を先に決め、一言はその語彙から選ばせる。** 検証が二値になり、集計もできる。**だが5社で書いた一言のうち、3段に潰れないものが4つあった**（三陽商会・ファナック・出前館・ジャパンディスプレイ）。この機能の価値はまさにその潰れない部分にある。さらに段階評価はランキングやスコアに見え、`docs/worklife/` で「束ねる名前を付けない」と決めた線とも衝突する。

**1つのセクションにまとめ、評価語を含む文だけ地の色を変える。** 分量は減る。**だが読者が文単位で色を追うことになり、決定5 の「見分けられること」が実質守れない。** セクションで割るほうが、断り書きと出典の置き場所も1つで済む。

**リクエスト時に生成する（読者が押したら分析を作る）。** 常に最新の見立てになり、リンク切れも起きにくい。**だが ADR-0012（事前生成）と ADR-0004（DBも外部APIも持たない）の両方を覆すことになり、配信時に有料の外部APIを呼ぶ最初の機能になる。** `docs/product/product.md` の「ランニングコストをゼロに保つ」に正面から触れる。

**段階を作って「推測です」と印を付ける。** 文ごとに「事実／推測」を分けて表示する案。**分析セクション全体が推測であることは C10 が断る**ので、その中でさらに分けると、印の無い文が「事実」として読まれる——いま以上に危うい。

**型を全部消す。** 事実の誤り6種は、実際に50回のうちで繰り返し出た（型S1 は3回、型A12 は3回）。消せば同じ誤りが戻る。

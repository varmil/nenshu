# ADR-0015: 有報の要約と AI 分析——分析セクションに限って評価を書く

- 状態: 採用
- 日付: 2026-08-28
- 関連: [ADR-0010](0010-company-summary-sourcing.md)（会社説明文の出所と生成方針。**決定2「原文から導けない事実は書かない」を、分析セクションに限って上書きする**）, [ADR-0012](0012-prerender-company-pages.md)（企業詳細の事前生成。**据え置き**——分析はビルド時に確定した文で、リクエスト時に生成しない）, [ADR-0006](0006-public-url-strategy.md)（公開URL。**据え置き**）, Issue [#214](https://github.com/varmil/nenshu/issues/214)（親）。Unit は C8（[#240](https://github.com/varmil/nenshu/issues/240)）・C9（[#241](https://github.com/varmil/nenshu/issues/241)）・C10（[#242](https://github.com/varmil/nenshu/issues/242)）。施策は `docs/company/`

## 背景

**有報には定量的・無機質な情報しか無く、定性的な意味付けが決定的に欠けている。** 企業詳細ページはいま、その欠けを引き継いでいる——金額・順位・偏差値・10年推移・稼ぐ力・残業と有給が並ぶが、**その会社がいまどういう状況にあるのかを言った文はどこにも無い。** C7（#161）が h1 直下に置いた説明文は「何をやっている会社か」に答えるもので、「いまどうなのか」には答えない。

**求職者にとって効くのはそこである**（`docs/company/intent.md`。マネタイズは転職マッチング）。年収が高いか低いかは表が示すが、**その水準が続きそうなのか、会社が伸びているのか畳んでいるのか**は、有報の本文を数万字読める人にしか分からない。

一方、この方針転換には **ADR-0010 の決定2 が正面から立ちはだかる。**

> **原文から導けない事実は書かない。** …**世間で知られている話をモデルの一般知識から補わない。評価語を書かない。**

「評価語を書かない」を守ったまま「好調かどうかを言い切る」ことはできない。**どちらかを曲げる決定が要る。**

**この決定は不可逆である。** 2,961ページに主観を載せた後で「知ったふうな評価を出していた」となれば、根拠を全部公開していることを差別化に置いた立て方（`docs/ranking/spec.md` 2.）が崩れる。ADR-0010 が同じ危険を「入力を絞って出力を検める」で塞いだのに対し、**ここでは出力に評価が入ることを前提に、別の塞ぎ方を決める必要がある。**

判断の材料として 2026-08-27 に実測した値（#214）。

| | 値 |
| --- | --- |
| 使う4節の取得率（無作為60社） | **60 / 60（100%）** |
| 1社あたりの原文（中央） | 約14,400字（C6 の約20倍） |
| 「好調かどうかの一言」を実際に書いた社数 | 5社（性格の違う会社を選んだ） |
| その5例に含まれる算用数字 | **0〜2個** |
| 分析の材料になる数値のカバー率 | 平均年収の10年推移 100% / 稼ぐ力 99.9% / 定着 100% / 残業・有給 79.9% |

**5社とも違う語彙になった。** 段階評価（「好調」「安定」「不振」の3段など）を固定していたら、三陽商会の「本業は苦しい。最終利益は増えているが、これは保有株の売却益による」もファナックの「業績は堅いが、平均年収は10年で13%下がっている」も出せなかった。

## 決定

### 1. 2つのセクションに分け、規格を変える。ADR-0010 決定2 を覆すのは分析セクションだけ

企業詳細ページに **要約セクション**と **AI分析セクション**を置く。**ADR-0010 決定2 は要約セクションではそのまま効く。**

| | 要約セクション | AI分析セクション |
| --- | --- | --- |
| 書いてよいこと | 原文に**書いてある**事実 | 原文と数値から**導ける**解釈 |
| 評価語 | **書かない** | **書く**（これが本体） |
| 原文に無い事実 | 不可 | **不可**（ここは変わらない） |
| 機械ゲート | C6 のものを流用（社名・数値・評価語・原文に無い固有名詞） | 別に作る（評価語は通す。**数値の個数に上限**・原文に無い固有名詞・観点の網羅） |
| 検証パス | 「原文に**書いてあるか**」（C6 と同じ） | 「原文と渡した数値から**導けるか**」 |

**覆るのは「評価語を書かない」の1点だけである。** 「原文に無い事実を書かない」——モデルの一般知識・報道・株価・世評を材料にしない——は**両セクションで守る**。ADR-0010 が塞いだ経路（キーエンスの「自社工場を持たないファブレス体制」）は、分析セクションでも塞がったままになる。

**分析が書いてよいのは、材料そのものではなく材料の読み方である。** 「営業利益が半減し、最終利益の増加は保有株の売却益による」は、原文の数字を突き合わせれば導ける。「業界の先行きは明るい」は導けない。

### 2. 分析は同じページが持つ数値も材料にする。ただし数値は脇役

一言と分析の材料は原文（有報の節）だけに限らず、**同じページが既に表示している数値**——平均年収の10年推移（`history.json`）・稼ぐ力とその推移（`performance.json` / `profit-history.json`）・定着（`companies.json`）・残業と有給（`worklife.json`）——**も使ってよい。**

外部から数値を新しく引いてこない。**画面に出ている数字だけを材料にする**ので、読者は分析の根拠を同じページの中で突き合わせられる。

**ただし数値を並べることは目的ではない。** 有報が無機質なのは数値しか無いからで、それを短くしても読者の負担は減らない。**主役は定性的な意味付けで、数値はそれを裏づける脇役に置く。**

この線は**機械で落とせる**。上の5例に含まれる算用数字は0〜2個だった——「半減」「増収増益」「2割」のように語で言えるものを語で言うと、数値が要らなくなる。**分析の機械ゲートは「数値を含まない」ではなく「数値は N 個まで」にする**（N は C9 のパイロットで決める。暫定2）。

**この検査は C6 には無かった型である。** C6 の型②（重み付け）・型⑥（動詞や修飾語の共有）は規則を言い直しても減らず、対照表を置いて初めて落ちた。「数値を主役にしない」は同じ性質（原文が数値だらけなので手が伸びる）を持つが、**個数として機械で落とせるぶん扱いやすい。** 対照表は併せて置く（#214 に3組ある）。

### 3. 読者が2つを見分けられることを要件にする

**この分け方が成り立つ前提は、読者が「事実の要約」と「主観的な分析」を見分けられることである。** UI の区別——見出し・地の色・断り書き——は装飾ではなく**要件**であり、満たせない見せ方は採らない。

具体は C10 が決めるが、**分析セクションには「これは AI による評価であって、有報に書いてある事実ではない」ことが読める断りを置く**。要約セクションには置かない（あちらは事実なので、同じ断りを付けると区別が消える）。

**同じ断りを1画面に2回置かない**（Issue #128 で「推定」について決めたのと同じ扱い）。セクションが2つ増えるぶん重複は起きやすくなるので、C10 は既存の断り（説明文の出典1行・実測値の見出しの決算期・推定の語）と突き合わせる。

### 4. C7 の説明文は残す。要約セクションの出所から「事業の内容」を外す

同じページに3種類の文が並ぶ（#214「決めるべきこと1」）。

| | 出所 | 役 |
| --- | --- | --- |
| 説明文（C7・実装済み） | 事業の内容 | **一目で分かる**（h1 直下・2〜3文） |
| 要約（C9・C10） | MD&A・リスク・課題・人的資本 | **読み込む** |
| 分析（C9・C10） | 同上＋同じページの数値 | **意味付け** |

**説明文は消さない。** C3（#89）が空けた h1 直下を C7 が埋めた経緯があり、一等地の3行を「読み込む」文で置き換えると、社名の直後に数百字が来る。

**代わりに、要約セクションの出所から「事業の内容」を外す**（`DescriptionOfBusinessTextBlock` は C5 のまま説明文だけが使う）。同じ原文から2つの文を作ると、1画面に同じ内容が2回出る。

### 5. 生成の主体と工程は C5〜C7 のものを引き継ぐ

**Anthropic API は使わない。生成は Claude Code のセッション（Max サブスクの枠）で回す**（ADR-0010 の 2026-08-26 の追記のまま）。工程も `plan → 生成 → 機械ゲート → 検証 → merge` をそのまま使う。

**要約と分析は1回の呼び出しで両方書かせる。** 原文が C6 の約20倍あり、2回読ませると量が倍になる。**ただし機械ゲートと検証パスは規格ごとに分ける**（決定1）。

**書けない会社では、そのセクションを出さない。** C7 が178社で取った形と同じで、空の器・プレースホルダ・「準備中」を置かない。**要約は書けるが分析は書けない、という会社が出てよい**（規格が違うので、落ちる基準も別になる）。

## 理由

**有報を「読める形にする」ことがこのサイトの立て方そのものだからである。** 数値については既にやっている——年齢補正・偏差値・順位・レーダーは、どれも生の開示をそのまま出さずに読める形へ変えたものだ。**文についてだけ「原文に書いてあることしか言わない」を守ると、有報の無機質さがそのまま読者に渡る。** 三陽商会の有報を素直に読むと「最終利益は増えた」で終わり、それが保有株の売却益だと気づくには営業利益・経常利益・純利益の動きを突き合わせる必要がある。**その突き合わせを代わりにやることが、ここで言う「意味付け」の中身である。**

**評価を書くことと、根拠を隠すことは別である。** CLAUDE.md の約束は「数値の出典と計算方法は必ずユーザーから見える場所に置く」「根拠を隠した推定値を表示しない」であって、「評価を書かない」ではない。分析セクションは**材料を同じページの中に持つ**——原文の節は出典として示し、数値は同じページが表示している。読者は根拠を突き合わせられる。

**ADR-0010 が「評価語を書かない」と決めたのは、あの文脈では正しかった。** C6 が書いていたのは全角60〜130字の説明文で、そこに「高い収益性」が混ざれば、**支える材料を置く場所が無い**。分析セクションは数百字あり、評価の直後に根拠を書ける。**同じ規則を分量の違う2つの文に当てる理由が無い。**

**主観を入れなければ、この機能は作る意味が薄い。** 評価を避けた分析は「増収増益であり、リスクとして為替変動が挙げられている」のような、原文の並べ替えにしかならない。それは有報が既にやっていることで、読者の負担は減らない。

**語彙を固定しないと決められたのは、5社で実際に書いてみたからである。** 段階評価を先に決めていたら、ファナックの「業績は堅いが、平均年収は10年で13%下がっている」——求職者にとって最も効く食い違い——は「好調」の一語に潰れていた。

**数値を材料に入れるのも、同じ5社が示した。** ファナックの食い違いは**有報の文面だけでは言えない**。平均年収の10年推移はこのサイトが持っていて有報の当年の本文には無い、という非対称がここで効く。

## 結果

- **`docs/company/spec.md` に 1.19 と AC-24〜AC-29 を足し、`overview.md` の Unit 一覧に C8・C9・C10 を足す。** `intent.md` の「作らないもの」は ADR-0010 で既に外れている
- **`docs/product/glossary.md` に「要約」「分析」を足す。** 説明文（C7）と3語になるので、**サイト上でもドキュメント上でも呼び分ける**。C7 が「解説文」「紹介文」を使わないと決めたのと同じ扱い
- **評価を含む文を公開する最初の決定になる。** 誤りが見つかったときの直し方は、C6 と同じく「その会社をセクションごと落とす」だけになる。会社ごとの手動での上書きは持たない
- **検証パスの判定が難しくなる。** C6 の「その文が原文に**書いてあるか**」は二値でぶれにくいが、分析の「その解釈が原文から**導けるか**」は判定者によってぶれる。**対策は2つ**——観点ごとに「根拠として使ってよい節」を紐づけて検証パスにはその節だけを見せること、**数値の裏付けを機械的に照合すること**（「10年で13%下がっている」と書いたなら `history.json` が支持するか確かめられる。これは C6 に無かった検査で、分析だからこそ効く）
- **失敗の型の表を2つ持つ。** C6 は `prompts/generate.md` に型①〜⑪を積み上げ、**番号を prompts 側に固定する**ことで回をまたいで比べられるようにした。**要約と分析は規格が違うので表を分ける**——同じ番号が別の型を指すと、12回ぶんの積み上げが混ざる
- **目視レビューの枠を分析にも持つ。** C6 の型⑪（有報の記載作法をそのまま書く）は原文にあるので機械ゲートも検証パスも通し、**目視レビューだけが拾った**。分析では「導けるか」の判定がぶれるぶん、同じ枠がより効く
- **生成の量が制約になる。** 1社あたり約14,400字・全社で約4,270万字（C6 の約20倍）。C6 が12セッションだったので単純計算で約96回。**原文の切り方・使う節の数は C9 のパイロット（60社）で実測して決める**——上の5例は MD&A の冒頭1,500〜1,800字で一言が書けている
- **表示のペイロードは問題にならない見込み。** `/company/[id]` は静的アセットで、C7 の説明文（約116字）が +976 B だった。要約1,000字＋分析800字でも +10KB 程度。**`/` には出さない**ので `companies.json` の gzip 100KB 予算とも無関係で、**Worker バンドルにも入らない**（F1 以降、`/company/[id]` だけが読むデータはビルド時に消費される）
- **ページタイトルを年収寄りから変えるかは、この ADR では決めない**（#214 の未決事項のまま）。SEO の実測が要り、触るのは S2（#116）・U16（#135）が持つメタデータの出口になる

## 却下案

**現状維持（ADR-0010 決定2 をそのまま守り、評価を書かない）。** 一貫していて、検証も楽になる。**だが作れるのは原文の並べ替えだけで、読者の負担が減らない。** 有報が定量的な情報しか持たないことが問題なのに、その制約をそのまま出力に写すことになる。

**要約だけを作り、分析は作らない。** 危険は小さい。**だが #214 が問題にしているのは「定性的な意味付けが決定的に欠けている」ことで、要約はそこを埋めない。** 求職者が知りたい「この会社はいまどうなのか」に、評価抜きでは答えられない。

**1つのセクションにまとめ、評価語を含む文だけ地の色を変える。** 分量は減る。**だが読者が文単位で色を追うことになり、決定3 の「見分けられること」が実質守れない。** セクションで割るほうが、断り書きの置き場所も1つで済む。

**段階評価（好調 / 安定 / 不振の3段など）を先に決め、一言はその語彙から選ばせる。** 検証が二値になり、集計もできる。**だが5社で書いた一言のうち、3段に潰れないものが4つあった**（三陽商会の「本業は苦しいが最終利益は増えている」、ファナックの「業績は堅いが年収は下がっている」、出前館の「赤字は続くが規模を追う段階は終えた」、ジャパンディスプレイの「縮小しながら建て直している最中」）。**この機能の価値は、まさにその潰れない部分にある。** さらに段階評価はランキングやスコアに見え、`docs/worklife/` で「束ねる名前を付けない」と決めた線とも衝突する。

**分析の材料を原文だけに限る。** 出所が1つで済み、検証も原文との照合だけになる。**だがファナックの型——業績は堅いのに平均年収が10年で13%下がっている——が言えなくなる。** 求職者にとって最も効く食い違いが、有報の当年の本文には無いところで起きている。

**外部の情報（報道・株価・世評・モデルの一般知識）も材料にする。** 分析としては厚くなる。**だが混ざったことを検出する手段が無い**（ADR-0010 決定2 の却下案と同じ）。評価を書けるようにしたうえで材料まで広げると、**根拠を突き合わせられないものが2,961ページに載る。** 覆すのは規格の1点だけにする。

**リクエスト時に生成する（読者が押したら分析を作る）。** 常に最新の見立てになる。**だが ADR-0012（事前生成）と ADR-0004（DBも外部APIも持たない）の両方を覆すことになり、配信時に有料の外部APIを呼ぶ最初の機能になる。** `docs/product/product.md` の「ランニングコストをゼロに保つ」に正面から触れる。

# ADR-0017 企業ページの ID は一度振ったら変えない

状態: Accepted

日付: 2026-09-29

関連: [ADR-0006](0006-public-url-strategy.md)（公開URL。**決定2 の ID の決め方を、初めて振るときの規則に限る**）, [ADR-0018](0018-universe-entry-exit.md)（母集団の出入り）, 親 Issue [#868](https://github.com/varmil/nenshu/issues/868)。施策は `docs/refresh/`

## 文脈

企業ページの URL は `/company/[id]` で、ID は ADR-0006 決定2 のとおり「証券コードがあれば証券コード、無ければ EDINETコード」で決まる（`pipeline/scripts/lib/slug.ts` の `makeId`）。**ID はビルドのたびに、その時点の会社の属性から計算し直している。**

そのため、会社の属性が変わると URL が変わる。

- **上場。** 非上場で有報を出していた会社（ID は EDINETコード）が上場すると、証券コードが付いて ID が証券コードに変わる
- **上場廃止。** 上場廃止の後も有報を出し続ける会社で証券コードが EDINETコードリストから消えると、ID が EDINETコードに変わる。ADR-0006 が扱っているのは、上場廃止後も証券コードが残る2社（広栄化学・養命酒製造）だけだった

年1回の一括更新でも起きていたが、毎日の差分更新（refresh 施策）では、起きた日にそのまま公開される。

**一度公開した URL を変えると、積み上げた評価を捨てることになる**（ADR-0006「文脈」）。企業ページはすでに何ページもインデックスされている（運営者・2026-09-29）。

加えて、**証券コードは上場廃止の後に別の会社へ振り直されることがある**（未確認）。ADR-0018 で提出が途切れた会社のページを残すと決めたので、振り直された証券コードで新しい会社が載ると、ID がぶつかりうる。

## 決定

1. **ID は EDINETコードごとに1度だけ振り、以後は変えない。** 振った ID は更新台帳（`docs/refresh/spec.md` 1.1）に持ち、ビルドはそこから引く。上場・上場廃止で証券コードが付いたり消えたりしても、URL は変わらない
2. **2026-09-29 時点で公開している全社の ID は、そのまま台帳に写す。** 証券コード 2,819社・EDINETコード 142社の URL は1つも変わらない
3. **新しく振るときの規則は ADR-0006 決定2 のまま。** 証券コードがあれば証券コード、無ければ EDINETコード
4. **ID がぶつかったら、後から来た会社を EDINETコードにする。** 先に公開していたページの URL を守る
5. 振った ID を変えるのは、この ADR を改めるときだけにする

## 理由

- **URL を変えないことを優先する**（運営者の判断・2026-09-29）。KPI は自然検索からのセッション数で（`docs/ranking/intent.md`）、URL が変わると評価も外部からのリンクも失う
- **失うものは小さい。** 上場した会社が EDINETコードの URL のまま残り、上場会社の URL の形がそろわなくなる。しかし ADR-0006 は、URL の読みやすさが検索順位に与える影響は小さいと判断している（却下案「日本語スラッグ」「読み仮名データを調達してローマ字スラッグにする」）
- **EDINETコードは年をまたいで変わらない**（ADR-0006）ので、台帳の鍵にそのまま使える

## 結果

- `makeId` は、台帳に無い会社（新しく載る会社）に ID を振るときだけ使う。それ以外は台帳から引く（refresh の D2）
- **ビルドは ID のぶつかりを検める。** 同じ ID が2社に振られていたら落とす
- glossary の「企業ID」に「一度振ったら変えない」を書き足す
- 上場した会社の URL が EDINETコードのまま残る。証券コードで URL を推測したアクセスは 404 になる（サイト内のリンクと sitemap はすべて台帳の ID から作るので、サイト内で壊れるリンクは無い）

## 却下案

**上場・上場廃止のたびに ID を付け替え、古い URL から新しい URL へ 301 を張る。** URL の形は「上場会社なら証券コード」にそろう。採らなかったのは、リダイレクトの表が会社の出来事のたびに増え続けるうえ、**証券コードが別の会社に振り直されると、古い URL をどちらに向けるかが決まらない**ため。守りたいのは URL の不変で、形のそろい方ではない。

**全社の ID を EDINETコードにそろえる。** 規則は1つで済む。採らなかったのは、いま公開している証券コードの2,819社の URL がすべて変わり、インデックスされたページの評価を捨てることになるため。

# ADR-0005 若い側の推定は22歳を業種平均に固定した2点モデルで出す

状態: Accepted
日付: 2026-08-18

ADR-0003 の推定式を、目標年齢が平均年齢より下の範囲について supersede する。配信方式（カーブを配ってブラウザで計算する）と、`companies.json` / `curves.json` の形は ADR-0003 のまま変わらない。

## 文脈

ADR-0003 の式は全年齢で次のとおりだった。

```
推定年収(目標年齢) = 平均年間給与 × カーブ[業種](目標年齢) ÷ カーブ[業種](平均年齢)
```

これは書き換えると `推定年収(t) = カーブ(t) × 倍率`、ただし `倍率 = 平均年間給与 ÷ カーブ(平均年齢)` になる。つまり実質**「その会社の産業平均に対する倍率は何歳でも同じ」**と仮定している。

1,867社で倍率を実測すると、中央値1.22倍・上位10%で1.64倍・最大はキーエンスの4.32倍で、2倍超が49社ある。産業計の25歳は382万円なので、倍率をそのまま掛けると若年側が破綻する。

| 会社 | 平均年間給与（平均年齢） | 旧式の25歳推定 |
| --- | ---: | ---: |
| キーエンス | 2,178万円（35.0歳） | 1,642万円 |
| 三菱商事 | 2,113万円（42.3歳） | 1,491万円 |
| トヨタ自動車 | 1,006万円（40.5歳） | 694万円 |

現実には、会社ごとの給与の差は若いうちは小さく、年次や等級を重ねて開いていく。倍率を一定と置くと**倍率の大きい会社ほど若年側が過大**になる。中央値付近（1.2倍）では誤差が小さく、歪みは高給企業に集中する。

実装にバグは無い（U0のテストが1,867社全件でCSVとの一致を固定している）。壊れているのはモデルの仮定であり、`docs/ranking/intent.md` H1 が「知りたいのは順位ではなく金額」と置いている以上、金額が2倍ずれるのは軽くない。

## 決定

**目標年齢がその会社の平均年齢より下のとき、その会社の賃金カーブが2点を通ると置き、間を業種カーブの形でつなぐ。**

```
C(a) = カーブ[業種](a)

目標年齢 ≦ 平均年齢:
  推定年収 = C(22) + (平均年間給与 − C(22)) × (C(目標年齢) − C(22)) ÷ (C(平均年齢) − C(22))

目標年齢 > 平均年齢:
  推定年収 = 平均年間給与 × C(目標年齢) ÷ C(平均年齢)     ← ADR-0003 のまま
```

2点は「22歳＝その業種の22歳の平均水準」と「平均年齢＝その会社の実測の平均年間給与」。22歳はカーブの起点（`agePoints[0]`）をそのまま使う。

**平均年齢より上は旧式のまま残す。** 「初任給は業種内で圧縮されている」に相当する根拠が高年齢側には無く、手を入れると根拠の無いパラメータを置くことになる。この非対称は残った限界として `/about` に明記する。

`平均年間給与 ≦ C(22)` の会社（実データで1社）と `C(平均年齢) − C(22) ≦ 0` のときは2点を結べないので、旧式にフォールバックする。

## 結果

| 会社 | 25歳 旧→新 | 30歳 旧→新 |
| --- | ---: | ---: |
| キーエンス | 1,642 → **788万円** | 1,912 → 1,487万円 |
| 三菱商事 | 1,491 → **711万円** | 1,707 → 1,199万円 |
| トヨタ自動車 | 694 → **466万円** | 809 → 664万円 |
| ソニーグループ | 779 → **486万円** | 907 → 713万円 |
| 全社中央値 | 469 → 410万円 | 549 → 513万円 |

中央値の動きは小さく、歪みが集中していた高給企業だけが大きく下がる。診断と一致する。

**同業種内の順位不変が部分的に崩れる。** 旧式では補正倍率が業種ごとの共通因子になり、同業種内の並び順は目標年齢によらず完全に不変だった。新式でも「同じ業種・同じ平均年齢」の2社なら不変（両社に同じアフィン変換が掛かる）だが、平均年齢が違えば入れ替わりうる。実測すると同業種ペアの **1.7%**（1,685/96,469）。上位50社の重なりは25歳時点と60歳時点で41社→39社になる。

`docs/ranking/intent.md` の「既知の限界」と `/about` の該当セクション、`spec.md` AC-2 をこの実測値に合わせる。**売り文句を増やす方向に書き換えない。**

**カーブの単位を揃える必要が出た。** 旧式はカーブの比しか取らないので `curves.json` の千円のままで答えが合っていた。新式はカーブの値を給与と足し引きするため、円に揃えないと1,000倍ずれる。`curveValuesInYen` を通す。

**CSV の `salary35` / `factor` / `rank_adj` 列は旧式の派生値として取り残される。** web側はこれらを読んでいない（`build-data.ts` は `avgSalary` / `avgAge` / `industry` しか使わない）。`pipeline/scripts/build-data.test.ts` の照合テストは旧式のまま残し、役割を「データ取り込みの検証」と書き換えた。Python側の式の追随は次回のデータ再生成とセットで行う（Issue #46）。

## 却下案

**標準労働者カーブへの差し替え** — Issue #42 で「本命候補」としていた案。e-Stat の令和7年 標準労働者 第1表（`statInfId=000040421138`、17産業 × 学歴 × 年齢各歳15〜65）を実際に取得し、大卒・男女計・企業規模計で17産業ぶんのカーブを組んで1,867社を再計算して確かめた。

| | 25歳 旧→標準労働者 | 60歳 旧→標準労働者 |
| --- | ---: | ---: |
| キーエンス | 1,642 → 1,505万円 | 2,213 → **2,849万円** |
| 三菱商事 | 1,491 → 1,213万円 | 1,962 → **2,686万円** |
| 中央値 | 469 → 380万円 | 640 → 722万円 |

**若年側の改善はわずかで、60歳側は大幅に悪化する。** 標準労働者（学校卒業後すぐ入社し同一企業に継続勤務している大卒）のカーブは産業計で22歳311万円→57歳1,057万円と急に立ち上がり、そこに4倍の倍率を掛けると破綻する。**倍率一定の仮定が残る限り、カーブの差し替えでは直らない。** 2点モデルと組み合わせても25歳の中央値は410万円 vs 402万円でほぼ変わらず、Excelパースを新たに書くコストに見合わない。

副次的に判明したこと: e-Stat の**API（DBビュー）で取れるのは2023年（令和5年）まで**で、統計表 `0003425893`・`0003447178` とも時間軸は2020〜2023。令和6年・令和7年はファイル（Excel）にしかない。「令和7年データへの更新」は別途Excelパースを書く話になる。

**22歳に部分的な倍率を認める（`C(22) × (1 + (倍率 − 1) × α)`）** — 商社やキーエンスのように初任給の時点で業種平均より高い会社は実在するので、そのほうが実態には近い。しかし α を決める根拠になるデータが無償では見つからず、置けば「根拠を隠した推定値を表示しない」（CLAUDE.md）に反する。業種平均を素直に使い、**そのぶん若い側が低めに出ることを `/about` に書く**。

**就職四季報（約1,300社の25歳・30歳・35歳の大卒総合職賃金）** — 構造的には理想だが有償・要商用ライセンス。

**推定をやめて実測値だけを出す** — `docs/ranking/intent.md` の差別化要因そのものを捨てることになる。既存の平均年収ランキングとの違いが無くなる。

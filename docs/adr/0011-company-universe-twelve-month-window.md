# ADR-0011 掲載企業の母集団は「直近12か月に有報を出した内国法人」にする

状態: Accepted
日付: 2026-08-24

## 文脈

いま載っているのは1,867社で、この集合は `pipeline/salary/unified.py` の `build()` が直書きしている取得の窓から決まる。

```python
rows, curve_table = run.build(0, "年収", date(2026, 6, 1), date(2026, 7, 10), include_unlisted=True)
```

**6月1日〜7月10日は3月期決算の有報提出のピークで、それ以外の決算期の会社は1社も入らない。** 実際、掲載1,867社の決算期は1,865社が3月期・2社が4月期になる（`docs/site-chrome/spec.md` 5.3）。

**この窓は MVP の scope として意図的に置かれ、`/about`「対象範囲」と `docs/product/product.md`「データの前提」に開示されている。** 隠していたわけではない。決めるのは、この scope を続けるかどうかになる。

親 Issue [#22](https://github.com/varmil/nenshu/issues/22) が「有報に載っているが OpenReport に載っていない企業があれば追加したい（4,000社以上あるはず？）」と問うている。**実測すると、その見立ては正しかった。**

**この決定は実質的に不可逆である。** 一度公開した企業ページのURLは変えない・消さないという約束がある（`docs/product/product.md`「一度公開したURLは変えない」）。1,095社ぶんのページを公開したあとで「やはり3月期だけにする」と戻すことはできない。

## 決定

**母集団を「直近12か月に有価証券報告書（`docTypeCode=120`）を提出した内国法人・組合」にする。**

- **窓は取得を回す日から遡って12か月。** 決算期に貼り付いた窓を使わない
- **1社1件に寄せるキーは EDINETコード。** 証券コードではない（ADR-0006 と同じ理由）
- **同じ会社の書類が窓の中に複数あるときは、期末（`periodEnd`）が新しいほうを採る。** 期末が同じなら `docID` が大きいほう（訂正報告は後勝ち）
- **外国法人・組合と外国政府等は落とす**（`提出者種別 == "内国法人・組合"` だけを残す）
- **掲載の条件（単体従業員100人以上・平均年齢20〜65歳・平均年間給与100万円超）は変えない**

## 理由

**決算期は読者に関係のない属性である。** 転職検討者がキヤノンを探して0件を見たとき、そこにあるのは「キヤノンは有報を出していない」でも「まだ集めていない」でもなく、**サイトの取得の窓が3月期に貼り付いている**という、読者からは見えない理由になる。載せる／載せないの線が読者に説明できないものになっている。

**実測した。** EDINET API の書類一覧を直近12か月（2025-08-25〜2026-08-24・平日261日）ぶん取り、`docTypeCode=120` を数えた。

| | 件数 |
| --- | ---: |
| 有報の提出件数（取下げ除く） | 10,657件 |
| EDINETコードでユニークにした社数 | 4,528社 |
| **うち内国法人・組合** | **4,132社** |
| 平均年間給与が取れた | 4,014社 |
| 平均年齢20〜65歳・平均年間給与100万円超 | 4,011社 |
| **単体従業員100人以上（＝掲載できる社数）** | **2,962社** |
| うち現行CSVに載っている | 1,867社 |
| **新しく載る会社** | **1,095社** |

**親 Issue の見立て（4,000社以上）は、有報の提出社数としては当たっていて、掲載社数としては外れる。** 1,049社が単体従業員100人未満で落ちる（数人しかいない持株会社・REIT・小型株。日本マクドナルドホールディングスは単体2人）。**掲載は 1,867社 → 2,962社（1.59倍）**、上場2,800・非上場162、「本社のみ」バッジは173社から244社になる。**いま載っている1,867社は1社も落ちない。**

**欠けているのは無名の会社ではない。**

```
日本たばこ産業（JT）                    12月期
キヤノン                                12月期
楽天グループ                            12月期
花王                                    12月期
キリンホールディングス／アサヒグループホールディングス  12月期
資生堂／ブリヂストン／中外製薬          12月期
すかいらーくホールディングス            12月期
セブン＆アイ・ホールディングス／イオン   2月期
しまむら                                 2月期
サイバーエージェント                     9月期
ファーストリテイリング                   8月期
良品計画                                 8月期
日本オラクル                             5月期
```

**指名検索の的がそのまま抜けている。** この施策の North Star KPI は自然検索からの月間セッション数で（`docs/ranking/intent.md`）、いま sitemap に載る1,910 URL のうち1,867件が企業ページになる（ADR-0006・U8）。**掲載が 2,962社（1.59倍）になれば、検索に当たる面もほぼそのぶん増える。** 「会社名 年収」は年齢別・業種別のクエリより意図が強い。

**取得コストは許容範囲だった。** 4,132件の有報CSVの取得は並列3で36分（実測）。年1回の更新でこれが走る。運営者の工数がほぼ取れなくなる2026年10月以降でも、コマンド1つで完結する。

**12か月にする理由。** 有報は事業年度ごとに1回出る。12か月の窓なら、決算期がいつであっても各社ちょうど1回入る。**暦年（1/1〜12/31）にしないのは、年の途中で回したときに窓の後半が空になるため**——8月に回せば9月以降に提出する会社（6月期・7月期）が落ちる。**窓を置かず「各社の最新の有報」にしないのは、上場廃止・合併で提出をやめた会社が何年も残るため**。12か月の窓は「いまも有報を出している」という条件そのものになる。

**期末で寄せる理由。** いまの実装は上場側も非上場側も「後に見つかったものが勝つ」で1件に潰しており、**どれが残るかが走査順に依存する**。窓を12か月に広げると、これが会社を落とす。**同じ年に有報を複数出す会社が実在する**——りそな銀行と三井住友信託銀行は窓の中にそれぞれ4件あり、期末で選び直す前は**「従業員の状況」を持たない書類が残ってこの2社が母集団から消えていた**（実測）。**提出が遅れて、窓の中に前の期の有報しか無い会社もある**（ニデック 6594・2025-03-31期）。期末で決めれば走査順に依存しない。

**外国法人を落とす理由。** 窓の中に外国法人・組合が200社と外国政府等が28社いる。転職先ではない。`run.unlisted_docs()` が非上場側で既に使っている線を、上場側にも同じように当てるだけになる。

**掲載条件を変えない理由。** `MIN_EMPLOYEES = 100` は「数人しかいない持株会社が上位を埋めるとランキングとして読めなくなる」ための線で、決算期の話とは独立している。**社数を目標にしてここを緩めると、載っている数字の意味が薄まる。** 4,132社は窓を外した結果であって目標ではない。

## 結果

- **`/` の初回ロードは予算に収まる（実測）。** gzip 63,654 B → **90,724 B** で、`docs/ranking/spec.md` 3.「gzip 後 100KB 以内」の 90.7%。**着手前の見込み（4,000社で137KB・予算超過）は外れていた。** ただし余白は 9.3KB しか残らないので、ペイロード方式の入れ替え（ADR-0012・Unit E0）は続けて入れる。**拡大の前提条件にはしない**
- **`docs/ranking/spec.md` の AC-1 が成り立たなくなる。** 1位がキーエンス（2,178万円）からヒューリック（2,295万円・12月期・単体234人）に変わる。Ｍ＆Ａキャピタルパートナーズ（2,266万円・9月期）も上に来る。**受け入れ基準と E2E を書き換える**——1位が変わるほどの入れ替えがテストを通ったまま入るほうがまずい
- **「従業員の状況」本文からの読み取りが上位に出る。** `source == "textblock"` の会社が103社から139社になり、**そのうち1社（株式会社山田クラブ２１）が読み違いのまま3位に来る**（`231(13)57.309.822,360,598` を「勤続9.8／2,236万円」と読むか「勤続9.82／236万円」と読むかが1書類の中では決まらない。CLAUDE.md の既知の問題）。**年をまたいで選び直す仕組みはタグ由来の値を基準にするので、どの年もタグを持たないこの会社では効かない。** 上位30社は目視で確かめてから公開する
- **`unlisted_docs()` の寄せ方を直さないと会社が消える。** EDINETコードごとに「後に見つかったものが勝つ」で潰しているため、**同じ年に有報を複数出す会社**（りそな銀行・三井住友信託銀行はそれぞれ窓の中に4件ある）で従業員の状況を持たない書類が残る。**期末で選び直す前は、この2社が母集団から消えていた**（実測）
- **決算期を1つで代表できなくなる。** `build-data.ts` の `dominantFiscalPeriod()` は代表が過半に届かないと例外で止まるが、**3月期は 1,881/2,962 = 63.5% で過半を超えるので落ちない。** 1,081社の決算期が違うまま「2026年3月期」と名乗ることになる。**落ちないほうが危ない**ので、site-chrome の S3 を改訂する（Unit E1）
- **派生データが母集団に追随する必要がある。** ロゴ（`logo`）・10年推移（`timeseries`）・働きやすさ指標（`worklife`）はすべて母集団を単位に作ってある。**新規社ぶんは追随するまで空になる**（Unit E3・E4・E5）。10年推移は 1,095社×10年で約1万件の追加取得になる
- **`stats.json` が gzip 39,922 B → 68,515 B になる**（実測）。`/` は母集団統計だけを抜いて渡す（1KB未満）のでページのペイロードには効かないが、**Worker のモジュール評価では全部が読まれる**。CPU 超過（Issue #118）と同じ側の負荷になる
- **`pipeline/salary/` の取得側が変わる。** `unified.build()` の窓、`edinet.annual_reports()` の寄せ方とキー、内国法人への絞り込み
- **`/about`「対象範囲」と `docs/product/product.md`「データの前提」の文言が変わる。** 窓の日付（`web/lib/data/period.ts` の `filingWindowLabel`）は「6月1日〜7月10日」ではなくなる
- **sitemap は自動で増える**（`lib/seo/`）。URLの形は変わらないので ADR-0006 の改訂は要らない
- **同じ表に並ぶ会社の決算期が15か月ずれる。** 3月期と4月期で既に1か月ずれてはいるが、12月期を含めると差が広がる。**平均年間給与は事業年度の値なので、景気や賃上げの局面では時点差がそのまま数字の差になる。** これは注記で扱う（Unit E1・E2）

## 却下案

**窓を6月1日〜7月10日のまま置く（現状維持）。** 掲載条件として `/about` に開示済みであり、嘘ではない。しかし**読者に説明できない線**である以上、開示しても読者の役には立たない。JT もキヤノンも楽天も引けないランキングは、「有価証券報告書ベースの平均年収ランキング」として名乗っている範囲を満たしていない。

**窓を暦年（1/1〜12/31）にする。** `timeseries` 施策の `warm_lists.py` が既にこの窓で書類一覧を温めている。しかし**年の途中で回すと窓の後半が空になる**——8月に回せば、9月以降に提出する会社（6月期・7月期の決算）が母集団から落ちる。書類一覧のキャッシュを暦年で温めることと、母集団を暦年の窓で切ることは別の話になる。

**窓を置かず、EDINETコードごとに最新の有報を採る。** 上場廃止・合併・解散で提出をやめた会社が、最後に出した有報の数字のまま何年も残る。**「いまその会社に転職できるか」と無関係な行が増えていく**。12か月の窓はこの条件をそのまま表している。

**上場企業だけにする。** 非上場の有報提出会社109社（みずほ銀行・三井住友銀行・東京海上日動など）は、この施策の差別化そのものになっている（`docs/ranking/intent.md`「非上場の事業会社を含むこと」）。持株会社の数字しか載せない既存ランキングとの差がここにある。

**フィルタを緩めて社数を4,000社に寄せる。** 単体従業員100人未満を入れれば社数は増えるが、増えるのは数人の持株会社の行になる。**社数は結果であって目標ではない。**

**外国法人・組合も載せる。** 200社いるが、日本の転職市場の対象ではない。外国法人の有報は日本語での従業員の状況の記載も揃わない。

**母集団を段階的に広げる（まず12月期だけ足す等）。** 決算期の順に足していくと、「いま何が載っていて何が載っていないか」の説明が更新のたびに変わる。**読者に説明できない線を、説明できない別の線に置き換えるだけになる。** 取得コスト（36分）は一度に全部やれる大きさなので、分ける理由がない。

# plan.md — W3 区分ごとに公表している指標を先頭の区分で図に載せる

Issue: [#802](https://github.com/varmil/nenshu/issues/802) ／ 親: [#185](https://github.com/varmil/nenshu/issues/185)
参照: `docs/worklife/spec.md` 2.2b・AC-13・AC-15・AC-17 ／ `docs/worklife/overview.md` の W3 ／ `docs/performance/company-radar/design.md`

着手前の段取り。出来上がりの構造は `design.md` にある。

## 前提の確認

**取り込み（`worklife_2026.csv`）は作り直さない。** 変えるのは「区分の並びから1点を選ぶ規則」だけで、CSV にも `worklife.json` にも区分は登録順のまま入っている。作り直すのは `radar.json`（順位と母集団）だけになる。

## 手順

1. **対象と先頭の区分を数える。** 全体値が無く値のある区分が2つ以上ある会社を有給・残業それぞれで数え、先頭の区分の名前を並べる。先頭の値が落とされていて2番目から取る会社があるかも見る
2. **全体値とのずれを測る。** 全体値と2つ以上の区分を両方持つ会社で「先頭の区分 − 全体値」を取り、先頭で代用したときに順位がどちらへどれだけ動くかの目安にする
3. **方針を運営者に諮る。** 区分名での振り分けをしないこと、断りに区分名を入れることを実測と一緒に出す（済み）
4. **代表値の規則を直す**（`radar.ts` の `representative`）。pipeline と web が同じ関数を import しているので、ここを直せば順位と図の頂点が一緒に動く
5. **`radar.json` を作り直し、母集団の変化を控える。** 他のデータファイルが動いていないことを差分で確かめる
6. **表示側を直す**（`pageData.ts` → `CompanyDetail` → `OverviewSection`）。「区分別」の文言を消し、断りの1文を条件付きで出す
7. **テストを直す。** 「区分別」を固定していたテストは新しい規則に**書き換える**（消さない）。規則と文の組み立ては Unit テスト、画面に出る・出ないは E2E で固定する
8. **検証の順序**は web の Unit テスト → pipeline の Unit テスト → 型・lint → E2E → 本番ビルドで HTML の前後比較。**E2E はデータを作り直した後**に回す
9. spec.md の 2.2b・AC-13 を改め AC-17 を足し、design.md・P1 の design.md・CLAUDE.md を直す

## 確認すること

- **順位を書き写している既存のテスト**がどこにあるか（母集団が変わるので `1,264社中` のような文字列が落ちる）
- 断りの1文が**モバイル幅で横スクロールを出さない**か（区分名は会社が登録した文字列で、長いものがある）
- 島の props に載る量。区分名のぶんだけ増え、該当しない会社では増えないこと

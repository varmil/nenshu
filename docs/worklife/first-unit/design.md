# design.md — W3 区分ごとに公表している指標を先頭の区分で図に載せる

Issue: [#802](https://github.com/varmil/nenshu/issues/802) ／ 親: [#185](https://github.com/varmil/nenshu/issues/185)
参照: `docs/worklife/spec.md` 2.2b・AC-13・AC-15・AC-17 ／ `docs/performance/company-radar/design.md` ／ W2 の `docs/worklife/outlier-handling/design.md`

全体値が無く、雇用管理区分を2つ以上登録している会社（有給222社・残業112社）の**レーダーの点を、区分の並びの先頭の値で打つ。** W2 の「区分別」の表記はやめ、どの区分の値かを**該当する会社にだけ**図の下で断る。

---

## 代表値の規則

`web/features/company/lib/radar.ts` の `representative(all, units)` が1点を決める。**pipeline（`build-data.ts` の順位）と web（`pageData.ts` の図の値）が同じ関数を import する**ので、ここを変えると順位と頂点が一緒に動く。

| 入力 | 値 | `pickedUnit` | 残業 | 有給 |
| --- | --- | --- | ---: | ---: |
| 全体値がある | 全体値 | `null` | 1,366社 | 552社 |
| 全体値が無く、値のある区分が1つ | その区分の値 | `null`（選んでいない） | 47社 | 712社 |
| 全体値が無く、値のある区分が2つ以上 | **先頭の区分の値** | **その区分名** | 112社 | 222社 |
| どちらも無い | `null`（掲載なし） | `null` | 1,436社 | 1,475社 |

**全体値があれば、区分がいくつあっても全体値で打つ。断りは出さない**（区分から選んでいないため）。残業で全体値と2つ以上の区分を両方持つ会社は503社ある——ソフトバンクグループ（9984）は全体 9.9h と 正社員 10.0h・契約社員等 4.0h、住友商事（8053）は全体 9.8h と2区分。住友商事は有給のほうが全体値の無い2区分なので、断りは有給の1軸ぶんだけ出る。**残業の全体値は節では「公表する範囲」の名前で出る**（`対象正社員`・`その他`・`基幹的な職種`。W1 の `withAll`）ので、節の先頭の行のラベルは「全体」とは限らない。

**図の値はどの会社でも節の先頭の行と同じになる。** 全2,961社のビルド成果物で、図の残業・有給の値と節の先頭の行、断りの有無と区分名を `worklife_2026.csv` と突き合わせて不一致0件だった（表の社数はそのときの内訳）。

**「先頭」は値のある区分のうち最初のもの。** 節（W1 の `unitRows`）も値の無い区分を飛ばして並べるので、**節の先頭の行と常に一致する。** いまのデータでは、先頭の区分の値が W2 で落とされていて2番目から取る会社は0社。

**区分名で振り分けない。** 先頭が管理職（有給10社・残業2社）・男性（有給9社）・部門や職種（有給35社・残業29社）の会社もそのまま使う。名前で飛ばす判定は spec 2.2b が禁じた「区分名を分類する」ことになる——W2 が 0 の残業を区分名で残し分けなかったのと同じ線。**代わりに区分名を画面に書く。**

**平均しない**（spec 1.4）。単純平均は人数の重みが無いぶん実際の全体値とずれる。

`representativeValue` は `representative` の値だけを返す薄いラッパで、順位を決めるだけの `build-data.ts` が使う。

## 区分名の流れ

```
worklife.json ──decodeWorklife──▶ WorklifeRecord（区分は登録順）
                                        │
                     pageData.radarFor ─┤ representative(all, units)
                                        ▼
                 RadarAxisInput { value, rank, population, pickedUnit? }   ← 島の props
                                        │
                  CompanyDetail ── buildRadarAxes
                                        ▼
                 RadarAxis { …, pickedUnit: "正社員" | "" }
                                        │
                OverviewSection ── unitPickNote(axes)
                                        ▼
                     図の下の説明文の末尾に1文（該当しなければ何も出さない）
```

- **`RadarAxisInput.pickedUnit` は選んだときだけキーを持つ。** この入力は島の props として HTML の属性に直列化されるので、全軸に `null` を並べると該当しない会社（有給・残業とも9割以上）のページまで重くなる
- **区分名は `worklife.ts` の `unitLabel` を通す。** 節の行の名前と同じ関数（名前の無い区分は「全体」）。断りは節の行を名指しするので、1文字でもずれると突き合わせられない
- **`RadarAxis.pickedUnit` は掲載なしの軸では空文字。** `subLabel`・`note` と同じ扱い

### 断りの文

**`unitPickNote` が組む。ビューに持たせない**——文をビューに載せると同じ文が props と本文の2か所に出る（W2・#224 の残業の注記と同じ扱い）。props に載るのは区分名だけになる。

| 該当する軸 | 文 |
| --- | --- |
| 1つ（ラクスの有給） | 有給は雇用管理区分ごとの公表で全体の値が無いため、先頭の区分「正社員」の値で点を打っています。区分ごとの値は下の節にあります。 |
| 2つ（オルガノ） | 有給・残業は雇用管理区分ごとの公表で全体の値が無いため、先頭の区分の値で点を打っています（有給は「管理職」、残業は「総合職」）。区分ごとの値は下の節にあります。 |
| 無し | 出さない |

- **軸の呼び名は「有給」「残業」。** 図のラベル（`有給の取得`・`残業時間`）より短くする。1文の中で2回出るため
- **置き場所は既存の説明文の末尾。** 同じ `<p>` の中で「公表の無い指標は頂点を打たず、残りの点で閉じています。」の後ろに続ける。図の描き方の断りをまとめて読める位置
- **リストの行には区分名を入れない。** 値の列は 13px・76px 固定で長い区分名が入らず、行に区分名を添えるのは P1 の2巡目に運営者の指示で外している
- **区分がちょうど1つの会社には出さない。** 選んでいない（登録された値が1つしか無い）ので、W2 までと同じ扱い。キーエンスの有給（正社員 38.8%）がこれに当たる

## 「区分別」の表記を消した

`buildRadarAxes` の `valueText` は `掲載なし` / 実数 の2通りに戻った。値が無い軸は、本当に何も公表していない軸だけになる。

W2 が「区分別」を入れた理由は「節には値が出ているのに図だけ掲載なしになり、公表していない会社と見分けが付かない」だった。**点を打つようになったので、見分ける必要そのものが無くなった。** 一方で W2 の形には2つの問題が残っていた。

1. **図から軸が1本欠けていた。** 有給222社・残業112社で、5角形が4角形になっていた
2. **「区分別」の断りが全社のページに出ていた。** 当てはまるのは320社（有給222社・残業112社、両方に当たる14社を重ねない）で、三菱商事（8058）のようにどちらの軸も当てはまらない会社でも読まされた（運営者の指摘。これが W3 のきっかけ）

## 実測

### 先頭の区分

`worklife_2026.csv`（2,367行）で、全体値が無く値のある区分が2つ以上ある会社。分け方は区分名からの目安。

| 先頭の区分 | 有給 222社 | 残業 112社 |
| --- | ---: | ---: |
| 全体に相当（全労働者・全従業員・対象とする労働者すべて 等） | 17 | 1 |
| 正社員・総合職 | 151 | 80 |
| 管理職 | 10 | 2 |
| 性別（男性が先） | 9 | 0 |
| 部門・職種 | 35 | 29 |

**有給の17社は全体の値を区分の欄に入れているだけ**なので、W2 までより正しい値が図に出る（ローム「対象とする労働者すべて」84.2・清水建設「全従業員」65.3 など）。

### 全体値とのずれ

全体値と2つ以上の区分を**両方**登録している会社で「先頭の区分 − 全体値」を取った。

| | 社数 | 中央値 | 四分位 |
| --- | ---: | ---: | --- |
| 有給 | 124 | −1.5pt | −5.9〜0.0 |
| 残業 | 503 | +0.2h | 0.0〜+2.3 |

どちらも先頭の区分のほうが少し不利な向き（有給は低く、残業は長く出る）。全体値が中央値の会社に当てはめると、有給で上位50%の位置が57%あたりまで下がる程度で、残業はほぼ動かない。

### 母集団

| | W2 | W3 |
| --- | ---: | ---: |
| 有給 | 1,264社 | **1,486社**（+222） |
| 残業 | 1,413社 | **1,525社**（+112） |

**この Unit と関係の無い会社の順位も動く。** キーエンスの有給は `1,264社中1,245位` → `1,486社中1,461位`。動いたのは `radar.json` だけで、他のデータファイルは1バイトも変わっていない。

### 断りが出るページ

ビルド成果物（`dist/client/company/*.html`）を数えると、**2,961ページ中320ページ**に断りが出る。うち14ページ（オルガノ・東光電気工事ほか）は2軸ぶんの文。

### ページの重さ

同じ手順（`npm run build` の成果物の raw バイト数）で前後を比べた。

| | 前 | 後 | 差 |
| --- | ---: | ---: | ---: |
| `/company/8058`（三菱商事。該当しない） | 152,574 B | 152,310 B | **−264 B** |
| `/company/6861`（キーエンス。該当しない） | 146,411 B | 146,145 B | **−266 B** |
| `/company/6758`（ソニーグループ。該当しない） | 152,465 B | 152,200 B | **−265 B** |
| `/company/3923`（ラクス。有給の1軸） | 149,220 B | 149,284 B | **+64 B** |
| `/company/6368`（オルガノ。2軸） | 154,548 B | 154,815 B | **+267 B** |
| `/company/7743`（シード。2軸） | 149,677 B | 149,950 B | **+273 B** |

**該当しない2,641ページは約265 B 軽くなった。** 全社に出ていた「区分別」の1文と、島の props に4つずつ並んでいた `byUnit: false` が消えたぶん。**該当するページは断りの1文と `pickedUnit`（区分名）のぶんだけ増える。** `/` は `radar.json` も `worklife.json` も読まないので変わらない。

## テスト

- **`radar.test.ts`** — `representative` の4通り（先頭を選ぶ・管理職でも飛ばさない・選んでいないときは区分名を返さない・値の無い区分を飛ばす）、`buildRadarAxes` が「区分別」を出さないこと、`unitPickNote` の0・1・2軸
- **`worklife.test.ts`** — `unitLabel` が節の行の名前と一致すること
- **`build-data.test.ts`** — 母集団（1,486・1,525）と、新日本空調の有給が軸に乗ること。**W2 までの「軸に乗せない」テストは書き換えた**（消していない）
- **`e2e/company-radar.spec.ts`** — ラクスで5つの頂点と `88.0%`・`1,486社中100位` が出て「区分別」がどこにも無いこと、断りがラクス・オルガノにだけ出て三菱商事・キーエンスには出ないこと、JS 実行前の HTML に断りがあること、390px で横スクロールが出ないこと

## 公開後に直したもの

### 欠測軸の断りも該当する会社にだけ出す

図の下の「公表の無い指標は頂点を打たず、残りの点で閉じています。」も、**頂点を打たなかった軸がある会社にだけ出す**ようにした（`radar.ts` の `missingAxisNote`。運営者の指摘）。W3 の時点では Issue #802 の非対象として全社に出したままにしていて、5軸すべてに頂点がある会社（トヨタ自動車・三菱商事など）でも読まされた。

- 出るのは **2,961ページ中1,803ページ**、出なくなったのは1,158ページ
- 判定は `RadarAxis.position === null`。**先頭の区分で点を打った軸は欠けていない扱い**になる
- 稼ぐ力の2文（分子と分母の範囲）は全社に出たまま。稼ぐ力の軸は2,959社にあり、無い2社のために分ける理由が無い

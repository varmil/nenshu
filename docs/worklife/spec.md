# spec.md — 働きやすさ指標

対象面: user-web（ユーザー画面）

親 Issue: #148 ／ Unit: W0 #149・W1 #150

厚生労働省「女性の活躍推進企業データベース」から**平均残業時間・年次有給休暇の取得率・男女の賃金の差異**を取り込み、企業詳細ページ `/company/[id]` に出す。用語は `docs/product/glossary.md` に従う。突合の方式は ADR-0009 に従う。

数値はすべて `4e6b3d07-99_20260820_utf8_bom.zip`（2026-08-20 生成・全件版）での実測値。

---

## 1. データ

### 1.1 出典と取得

厚生労働省「女性の活躍推進企業データベース」オープンデータ（https://positive-ryouritsu.mhlw.go.jp/positivedb/opendata/ ）の全件版。CSV・UTF-8・ZIP 圧縮で、BOM 有りと無しの2種類が配られている。

**BOM 無しの版を読む。** BOM 有りは Excel 向けで、法人番号が数値として解釈され先頭の0が落ちうる。

**取得は自動化しない。手元に置いた ZIP を読む。** ダウンロードURLに `4e6b3d07-` のような UUID が入っていて固定できない。更新は年1回（有報の再取得と同時）を既定とし、**ファイル名・sha256・取得日を manifest に残す**。

**再配布の可否は運営者が判断する**（`docs/product/product.md` の制約）。このデータベースには独自の「オープンデータ利用規約」がある。

### 1.2 突合

**法人番号（13桁）で内部結合する。ADR-0009。**

- 有報側 — `ranking_unified_2026.csv` に `corporate_number` 列を足す。値は EDINETコードリスト（`Edinetcode.zip`）の `提出者法人番号`
- 女性活躍DB側 — 2列目の `法人番号`

**証券コードと社名では突合しない**（理由は ADR-0009）。**一致しない会社は「データ無し」として扱い、子会社や同名の別会社で代用しない。**

同じ法人番号が複数行にある場合は**最終更新日が新しい行**を採る。**突合できた1,690社の中には該当が1件も無かった**が、女性活躍DB全体では7件あるので保険として規則を置く。

### 1.3 取り込む項目

| 女性活躍DB の列 | 取り込む形 |
| --- | --- |
| 6. 一月当たりの労働者の平均残業時間 — 公表する範囲 / 平均残業時間(時間) | 全体値とそのスコープ |
| 7. 雇用管理区分ごとの一月当たりの労働者の平均残業時間 — 区分1〜5 | 区分名と値の組（最大5） |
| 8.(1) 年次有給休暇の取得率 — 対象労働者(%) | 全体値 |
| 8.(2) 年次有給休暇の取得率(区) — 区分1〜5 | 区分名と値の組（最大5） |
| 14. 男女の賃金の差異 1/2/3 — 全労働者 / うち正規雇用労働者 / うち非正規雇用労働者(%) | 3つの値 |
| 14. 男女の賃金の差異 注釈・説明 | 自由記述（718社） |
| 14. 対象期間 | 文字列（`2025年4月1日～2026年3月31日` 等） |
| 16. データ集計時点 | 文字列（`2026年3月時点` 等） |
| データの最終更新日 | 文字列 |

**236列のうちこれ以外は取り込まない**（intent.md「作らないもの」）。

**列は名前の完全一致で検証してから読む。** 厚労省が列を足したときに黙って添字がずれると、別の指標を残業時間として出す。`parseUnifiedCsv` と同じく、想定と違えば例外で落とす。

**列名には重複がある**（`-女性(%)` 等が5回繰り返される）。**`DictReader` 相当の名前引きを使わず、位置で読む。**

### 1.4 値の扱い

**欠測と 0 を分ける。** 「未登録」と「残業0時間」は別物で、`null` と `0` として区別する。

**雇用管理区分は畳まない。** 区分名と値の組をそのまま持つ。**平均して1つの値にしない**——区分は自由記述で、「正社員」と「派遣社員」と「アルバイト」が同じ列に並ぶ。

**異常値の扱いを個別に決める。**

| 実測された値 | 扱い |
| --- | --- |
| 平均残業時間 `-16.8`（1社） | **落とす。** 負の残業時間は入力ミス以外にありえない |
| 平均残業時間 `0`（全体値10社・区分別128セル） | **落とす**（W2 で追加）。下の「0 の扱い」 |
| 有給取得率 `0`（1社） | **落とす**（W2 で追加）。残業と同じ理由 |
| 有給取得率の全体値が `100` ちょうどで、区分別がすべてそれ未満（4社） | **全体値だけ落とし、区分別を残す**（W2 で追加）。下の「100% ちょうど」 |
| 有給取得率 100超（7社。小松製作所103.0 ほか） | **残す。** 前年繰越分の消化で100%を超えるのは正しい |
| 男女の賃金の差異 638.6（1社） | **残す。** 少人数区分の外れ値だが値としては正しい |
| `-`（非正規で51社） | 欠測として `null` |

**落とした値は件数と会社名をビルド時のサマリーに出す。** 黙って消さない。件数が3桁になったので**理由ごとにまとめて**出す。

**0 の扱い**（W2・Issue #185）。~~欠測と 0 を分ける~~ → **0 は落とす。** 「1か月あたりの平均残業時間」が 0 になるのは対象者が1年間まったく残業していないときだけで、**未記入を 0 で埋めたのか本当に 0 なのかを我々は区別できない**。実測では自社の中で矛盾している会社がある（花王は全体15.4hなのに区分5件すべて0.0、東洋エンジニアリングは全体0.0なのに総合職8.0h）。残業の軸は小さいほど上位なので、残すとその会社が図の最上位に出る。**代償として、パート・嘱託の本物の 0.0 も一緒に消える**（商船三井の嘱託社員ほか）。**取り込み時点で落とす**——節・レーダー・順位のすべてで同じ扱いになる。**区分の行そのものは残す**（値だけ空にする）——その会社が自社をどう切っているかは 2.2b のとおり情報である。

**100% ちょうど**（W2・Issue #185）。有給取得率の全体値が **100 ちょうど、かつ区分別の値がすべて 100 未満**なら、その全体値を落とす。実測でこの条件を満たす4社（ソニーグループ 100 / 全体 63.7、富士電機 100 / 正社員 78.1、ＩＭＶ 100 / 社員 67.0 ほか2区分、極東貿易 100 / 正社員 60.2）は**いずれも自社の登録した区分別の値がその 100 を否定している**。列の見出しが `8.(1)年次有給休暇の取得率-対象労働者(%)` で「対象労働者の割合」とも読めるため、100 は「対象は全労働者（100%）」の意味で書かれたとみられる。**100 ちょうど以外は判定しない**——98.8 / 34.5 のような怪しい組み合わせは他にもあるが、どちらが正しいかを決める根拠が無い。**全体値が区分の範囲外にあること自体は矛盾ではない**（区分は全労働者を覆っているとは限らない。実測で残業50社・有給33社）。

### 1.5 出力

`pipeline/data/worklife_2026.csv`（突合済み・1社1行）を中間成果物としてコミットし、`build-data.ts` が `web/public/data/worklife.json` を作る。

**`worklife.json` は `/company/[id]` だけが import する。`app/page.tsx` からは読まない**——トップページのHTML（gzip 64KB・Issue #22）を1バイトも増やさないため。

**表現は `companies.json` と同じ文字列プール＋フラットな配列にする。** 入れ子の構造にすると起動時のオブジェクト生成が増える（Node 22 での実測: 入れ子 697KB で 30.8ms、フラット 250KB で 12.5ms。`companies.json` は 133KB で 6.2ms）。区分名は重複が多く（「正社員」「総合職」「契約社員」が上位）、プール化すると1,300語ほどに収まる。

## 2. 表示（企業詳細ページ）

### 2.1 置き場所

`/company/[id]` に「働きやすさ」の節を1つ足す。**推移（timeseries）と同じ扱いで、表示基準（実測値 / 年齢そろえ）とは独立に出す**——年齢補正を通さない値なので、年齢スイッチでも表示基準スイッチでも変わらない。

### 2.2 平均残業時間

全体値がある会社は `◯◯.◯時間 / 月` と、その**公表する範囲**（`対象正社員` / `その他` / `基幹的な職種`）を添える。

雇用管理区分ごとの値がある会社は、**区分名と値を並べて出す**（三菱商事なら 総合職14.1時間・一般職3.3時間・嘱託その他3.2時間・派遣社員5.6時間の4区分）。全体値と区分別の両方がある会社は両方出す。

**総合職と派遣社員を平均した数字には意味がない**——これが「区分を畳まない」（1.4）の具体例になる。

**定義の注記を1つ置く**（Issue #224）。女性活躍データベースの算式は「各月の対象労働者の（法定時間外労働＋法定休日労働）の総時間数の合計 ÷ 対象労働者数」で、**起点が法定労働時間（1日8時間・週40時間）にある**。会社が自社サイトに出す数値は**所定労働時間**を起点にした所定外の労働時間であることが多く、所定が8時間より短いぶんが構造的に落ちる。さらに算式には**管理監督者（労基法41条）と事業場外みなし労働時間制の適用者（38条の2）を除外する但し書き**がある。

- 実測 — 三菱商事（8058）は所定が1日7時間15分（標準 9:15〜17:30・休憩1時間）で、自社公表の 31.0時間／月 に対してデータベースの値は全体10.5時間・総合職14.1時間。差 0.75時間／日 × 月20日 ≒ 15時間／月 がほぼそのまま説明になる（31.0 − 15 ≒ 16 ≒ 総合職14.1）。三井物産でも同じ構図（自社開示 27.6時間／月）
- **注記は全体値と雇用管理区分ごとの値の両方にかかる位置に1つだけ置く。区分ごとに繰り返さない**——同じ文が5回並ぶと、区分によって定義が違うように見える
- **値が1つも無い会社（「掲載なし」）には置かない**——何の定義かが画面に無い
- **有給取得率・男女の賃金の差異には置かない**（Issue #224 の対象外）

### 2.2b 雇用管理区分は会社が登録した名前のまま出す

**正規化しない。こちらで分類を発明しない。代表の1区分を選んで残りを捨てない。並び順も登録順のまま。**

**区分の切り口は会社ごとに違い、それ自体が読者にとっての情報になる。**

| 切り口 | 会社 | 区分 |
| --- | --- | --- |
| 雇用形態 | 三菱商事（8058） | 総合職 / 一般職 / 嘱託その他 / 派遣社員 |
| 雇用形態 | 商船三井（9104） | 総合職(事務) / 総合職(技術) / 一般職 / 契約社員(フルタイム) / 嘱託社員(フルタイム) |
| 職能 | 新日本空調（1952） | 営業・管理系 / 技術系 |
| 職能 | 大気社（1979） | 正社員技術系 / 正社員事務系 |
| 組織・機能 | みずほ銀行（E03532） | カンパニー / ユニット / グループ / 無期契約フルタイム / 無期契約パートタイム |
| 組織・機能 | ドリームインキュベータ（4310） | BP部門 / CA部門 |

**1つの会社の中でも切り口が混ざる。** みずほ銀行は「カンパニー / ユニット / グループ」という組織階層と「無期契約フルタイム / パートタイム」という雇用形態を同じ並びに置いている。軸を1本に決められるという前提そのものが成り立たない。

**区分名は1,548社で1,009種類ある**（上位は 正社員605 / 総合職136 / 契約社員112 / 一般職70 / 対象とする労働者すべて59。あとは裾が長い）。統一する土台が無い。

「正社員」と「全社員」と「対象とする労働者すべて」を同じものにしない。「正規/非正規」のような軸に振り分けない。**その会社が自社をどう切っているかは、残業時間そのものと同じくらい読者の役に立つ。**

### 2.3 年次有給休暇の取得率

全体値がある会社は `◯◯.◯%`。区分ごとの値がある会社は区分名と並べて出す。

**100%を超える値をそのまま出す。** 丸めない。繰越分の消化で超えることを注記する。

### 2.4 男女の賃金の差異

全労働者・うち正規雇用労働者・うち非正規雇用労働者の3つを出す。

**値の意味を必ず併記する** ——`女性の平均賃金 ÷ 男性の平均賃金 × 100`。100未満は女性のほうが低いことを示す。

**数字だけを単独で置かない。** 差異の主因が職種構成や勤続年数の差であることが多い旨の共通の注記を添える。**会社が注釈・説明を登録している場合（718社）はそれも出す。**

### 2.5 出典と時点

節の中に必ず置く。

- 出典 — 厚生労働省「女性の活躍推進企業データベース」
- **企業の自己申告値であり、有価証券報告書のような監査を経ていない**こと
- その会社の**データ集計時点**（`2026年3月時点` 等）と、賃金の差異の**対象期間**
- 有報の決算期（`2026年3月期`）とは**別の時点**であること

**「推定」の語は使わない。** 推定値ではない。**「実測値」とも呼ばない**——`docs/product/glossary.md` の「実測値」は有報の平均年間給与を指す語で、意味が衝突する。**「自己申告値」と呼ぶ。**

### 2.6 データが無いとき

**節ごと消さない。** 3指標のいずれも無い会社（突合できた1,690社のうち142社と、未突合177社を合わせて全1,867社中319社）にも節は出し、**掲載が無いことと、その理由（データベースへの掲載は任意）を書く。**

3つのうち一部だけ無い会社も同じで、**無い指標は「掲載なし」と出す**。項目を消すと「残業が少ない会社」と見分けがつかない。

### 2.7 対象外

**所定労働時間による補正**（Issue #224）。所定労働時間は有価証券報告書にも女性活躍DBにも入っておらず、全社ぶんを一次情報から埋められない。埋められない以上、補正値は推定値になる——**「根拠を隠した推定値を表示しない」**（CLAUDE.md「開発上の約束」）に反する。**所定労働時間の推定・取り込みもしない。自社サイトの公表値との併記もしない**（全社ぶんの調達手段が無い）。代わりに 2.2 の注記で定義を明示する。

**雇用管理区分の正規化・分類の発明**（2.2b）、働きやすさランキング、順位・偏差値・スコア、総合評価、女性活躍DBの他の項目（管理職の女性比率・育児休業取得率・えるぼし認定等）、若者雇用促進総合サイトのデータ。いずれも `docs/worklife/intent.md`「作らないもの」を参照。

**ランキングページには出さない**（Issue #22）。

## 3. 非機能要件

**配信** — 企業詳細ページと同じフルSSR（ADR-0004）。エッジキャッシュを効かせる。

**データ量** — `worklife.json` の gzip サイズに上限を置き、`build-data.ts` で超過したらビルドを落とす（`companies.json` の100KB制限と同じ扱い）。**トップページのペイロードは1バイトも増やさない。**

**計算量** — リクエスト時の処理は当該1社ぶんの引き当てだけにする。全社の集計をリクエストごとに回さない（Workers Free の CPU 10ms/リクエスト制約）。

**起動コスト** — `worklife.json` の import による起動時間の増分を実物の Worker で測り、`docs/worklife/<unit>/design.md` に残す。**着手前の実測では初回リクエストが +約20ms、定常リクエストは変化なし**（アイソレートごとに1回しか払わない。`docs/worklife/overview.md`）。DuckDB・D1 は使わない（1,690行の読み取り専用データに DB を持ち込まない。将来 Issue #22 の規模で再検討する）。

**対応環境** — モバイルを主とする。横スクロールを発生させない。雇用管理区分が5つある会社でも、**長い区分名**（`技術系　無期雇用（フルタイム）` のような16文字級が実在する）でも崩れないこと。

**SEO** — 数値はすべて初期HTMLに含める。

**アクセシビリティ** — 区分別の値は表として読み上げられる形にする。

## 4. 受け入れ基準

### AC-1 突合

```gherkin
Given pipeline/data/ranking_unified_2026.csv に corporate_number 列がある
When 女性活躍DBの全件CSVと法人番号で内部結合する
Then 1,690社が突合できる
And 1,867社すべてに法人番号が入っている（EDINETコードリストから引けなかった会社が0件）
And 突合率・指標ごとの記入率がサマリーに出力される
```

```gherkin
Given 阪急阪神ホールディングス株式会社（証券コード 9042）
When 突合する
Then 阪神電気鉄道株式会社の行が紐づかない
```

```gherkin
Given 株式会社ニトリホールディングス（持株会社）
When 突合する
Then データ無しになる
And 株式会社ニトリ（子会社）の値が代用されない
```

証券コードと社名で突合すると **29社が誤った相手に紐づく**（うち28社が持株会社→子会社）。法人番号では0件になる。

### AC-2 列の検証

```gherkin
Given 女性活躍DBのCSVの列見出しが想定と1つでも違う
When 取り込みを実行する
Then 例外で停止する
And 読み進めない
```

### AC-3 値の扱い

```gherkin
Given ビジネスエンジニアリング株式会社の平均残業時間が -16.8 である
When 取り込む
Then その値は落とされる
And 落とした件数と会社名がサマリーに出る
```

```gherkin
Given 株式会社小松製作所の有給休暇取得率が 103.0 である
When 取り込む
Then 103.0 のまま残る
```

```gherkin
Given 三菱商事株式会社の雇用管理区分ごとの残業時間が 総合職14.1 / 一般職3.3 である
When 取り込む
Then 2つの組がそのまま保持される
And 平均された1つの値になっていない
```

```gherkin
Given 株式会社野村総合研究所の平均残業時間が 全体0 / 総合職0 / 事務職0 である
When 取り込む
Then 3つの値はすべて落とされる
And 「総合職」「事務職」という区分の行そのものは残る
```

```gherkin

```

```gherkin
Then 100 はそのまま残る（矛盾の証拠が無いため）
```

### AC-4 出力


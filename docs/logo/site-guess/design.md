# design.md — L2 英字社名からの公式サイト推定を測る

Issue: [#243](https://github.com/varmil/nenshu/issues/243)（親: [#23](https://github.com/varmil/nenshu/issues/23)）

## 結論: 入れない

**英字社名から推定したドメインを、ロゴの調達に使わない。** 実測した precision は **0.908 [0.849, 0.945]** で、着手前に置いた条件 0.99 に**区間の上限でも届かない**。

**残った誤りは規則を締めても消えない型である。** 日本には同じ社名の会社が普通に複数あり、**社名が一致することがそのまま誤りの原因**になる——「やまびこ」に対して長野県岡谷市の**やまびこの森**、「サンメッセ」に対して宮崎の**サンメッセ日南**、「アルペン」に対して**アルペンチーズケーキ**、「プラッツ」に対して**有限会社プラッツ**（長野県のウェブ制作会社）。

これを入れると、**271社のうち推定できた会社の約1割で、別の会社のロゴを企業ページに出す**ことになる。ADR-0008 決定1 と #220（クレスコに X のロゴが出ていた）が扱ってきた事故そのものである。

## 測ったもの

### 母集団と標本

**271社の正解URLを知らないことがそもそもの問題**なので、**すでにURLが分かっている会社で測った**。URLを知らないふりをして推定し、既知のURLと突き合わせる——手作業のラベル付けなしに両方の指標が出る。

正解のある会社2,490社から**無作為500社**（乱数の種 `20260828`。`measure-site-guess.ts` に固定してあり、同じ標本を再現できる）。

**この集団は偏っている。** Wikidata にURLが載っている会社は有名・老舗が多く、社名とドメインが一致しやすい。**測った recall は上限**として読むこと。

### 1回目 — 規則を締める前

| | 値 |
| --- | --- |
| 推定できた | 243社 |
| recall（ホスト完全一致） | 0.240 [0.205, 0.279] |
| precision（同上） | 0.494 [0.432, 0.556] |

**この数字は precision を過小に測っている。** 不一致123社のうち**51社は登録名が同じで TLD やサブドメインが違うだけ**（`tosoh.com` / `tosoh.co.jp`）で、実際はその会社のサイトである。**Wikidata 側のURLが古いことすらある**——芝浦機械は正解が `toshiba-machine.co.jp` で推定した `shibaura-machine.com` のほうが正しく、アステラス製薬は**正解が `web.archive.org`** だった。

**それでも本物の誤りが2種類あった。**

- **ドメイン売却のパーキングページ。** `hugedomains.com` が5件・`forsale.dynadot.com` が1件。`<社名>.com is for sale` と書くので社名が一致してしまう
- **同じ英単語を持つ海外企業。** ワークマン → `hachettebookgroup.com`（Workman Publishing を抱える）、ルネサンス → `renaissance.com`、エイチ・アイ・エス → `his.com`、サンコー → `sanko.com.tr`

### 検証の規則を1回だけ締めた

**作り直しは1回まで**（plan の「打ち切る条件」）。2回目からは規則を標本に合わせているだけになる。締めたのは筋の通る2点。

- **推定に使ったドメイン名を照合の前に取り除く**（`stripHost`）。**ドメイン名の再掲は、その会社のサイトである証拠にならない**
- **和文社名の一致を必須にし、英字名だけでは通さない。** 日本の上場企業の公式サイトなら、和文社名が `<title>` かコピーライトに出る

### 2回目 — 規則を締めた後

| | 値 |
| --- | --- |
| 推定できた | 141社 |
| recall（ホスト完全一致） | 0.214 [0.180, 0.252] |
| precision（同上） | 0.759 [0.682, 0.822] |

**パーキングページと海外の同名企業は1件も残らなかった。** 締めた2点はどちらも効いている。

### 不一致34件を目で見て正した

ホスト完全一致は「同じ会社の別ドメイン」を誤りに数えるので、**34件すべての推定先の `<title>` を見て仕分けた。**

| | 件数 |
| --- | ---: |
| **同じ会社の別ドメイン・関連サイト** | **21** |
| **同名の別会社** | **13** |

同じ会社だったもの: 東ソー `tosoh.co.jp`、ワークマン `workman.jp`（公式オンラインストア）、キヤノン `canon.jp`、リコー `ricoh.co.jp`、日産 `nissan.co.jp`、はてな `hatena.co.jp`、湖池屋 `koike-ya.com`、グリーHD `gree.co.jp`、アステリア `jp.asteria.com`、ノーリツ `noritz.co.jp`、竹内製作所 `takeuchi-mfg.co.jp`、タカミヤ `takamiya.co.jp` ほか。**ナイルは正解が `r-blog.nyle.co.jp`（ブログ）で、推定した `nyle.co.jp` のほうが正しい。**

別会社だったもの: やまびこ → **やまびこの森**（長野県岡谷市）、サンメッセ → **サンメッセ日南**、アルペン → **アルペンチーズケーキ**、中村屋 → **開発ツールの中村屋**、プラッツ → **有限会社プラッツ**、西部技研 → **西部技研工業**、スポーツフィールド → **フィットネス&クア スポーツフィールド**、シルバーライフ → **ビルメンテナンスのシルバーライフ**、石川製作所 → **板金加工の石川製作所**、セリア → **セリアコーポレーション**、ジャパンマテリアル・マツモト・東急（`p.tokyu.jp` はグループのモバイルサービスで本体ではない）。

### 目視で正した値

| | 値 |
| --- | --- |
| **precision** | **0.908 [0.849, 0.945]** |
| recall | 0.256 [0.220, 0.296] |

**条件は precision ≥ 0.99。区間の上限 0.945 でも届かない。**

## なぜ締め直しても届かないか

**残る13件は「同名の別会社」で、社名の一致で切り分けられない。** 検証が見ているのは「このページに社名が出るか」で、同名の別会社のページには**当然その社名が出る**。規則を厳しくするほど recall だけが落ちて precision は上がらない。

**届かせるには社名以外の一致が要る**——法人番号・本店所在地・証券コードのどれか。しかしこれらは**トップページには載らず、会社概要のページにしかない**。1社あたり数ページを辿ることになり、**推定の当たりを確かめるためだけに取得を数倍にする**。得られるのは211社の上限に対して recall 0.26＝**50社ほど**で、割に合わない。

## 残したもの・残さなかったもの

**`guess.ts` と `measure-site-guess.ts` は残す。** `build-logos.ts` の経路には入っていない（`ogp` と違って `LogoSource` にも増やしていない）ので、本番のロゴ調達には一切影響しない。**残すのは、同じ案を思いついた人が測り直さずに済むため**——数字だけを文書に書いても、条件を変えて測り直したくなったときに道具が無ければ結局作り直しになる。

**`PINNED` には1社も足していない。** 推定の結果を成果物に流し込んでいない。

## この測定で分かった副産物

**Wikidata の P856 は当てにならないことがある。** アステラス製薬は `web.archive.org`、ナイルはブログのURL、芝浦機械は社名変更前の `toshiba-machine.co.jp` が残っていた。**いま出ているロゴが「その会社の現在のサイト」から取れているとは限らない**ことになるが、**ロゴそのものは目視で確かめてきた**（#221・#234・#238）ので、表示されているものが間違っているわけではない。

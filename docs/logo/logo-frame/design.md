## ディレクトリ

```
web/features/logo/
  components/
    CompanyLogo.tsx        器。ロゴか頭文字かをここで分ける
    LogoIdsProvider.tsx     ロゴを持つIDの集合を配るコンテキスト
```

**`features/ranking/components/CompanyLogoMark.tsx` は廃止して `features/logo/` に移した。** ランキング・企業詳細の両方が使う共有物で、`logo` は独立した施策（`docs/logo/`）だからである。`design-system/` には昇格させない——企業IDという企業ドメインの語彙に依存する（`AgeSwitch` と同じ理由。`docs/company/company-page/design.md`）。

## 器の寸法

| 使う場所 | `size` | 寸法 | モックの元の寸法 |
| --- | --- | --- | --- |
| ランキングの表（`md` 以上） | `default` | **88 × 50** | 40 × 40（アートボード 4a） |
| ランキングの表（`md` 未満、DOM 上は残るが不可視） | `default` | 48 × 38 | 40 × 40 |
| モバイルのランキング行 | `row` | **68 × 48** | 40 × 40（アートボード 2a） |
| 近傍5社 | `sm` | 48 × 38 | 40 × 40 |
| 企業詳細の見出し | `lg` | **136 × 62** | 62 × 62（アートボード 4b） |

**高さはモックのまま、幅だけ広げた。** 高さを変えると行の縦のリズムが変わり、U13・C3 で合わせたレイアウト全体に波及する。

**ランキングの表（PC）だけは例外で、40px → 50px にした**（運営者の指示・Issue #128）。この行では行の高さを決めているのが器そのもの（社名＋meta 行は36px前後）なので、縦のリズムは動くが、隣の列は削られない。**器を高くすると `object-contain` の余地が縦に増えるぶんロゴが大きく見える**——横長のワードマークは幅で頭打ちになるが、正方形付近の230社はここで効く。値は `e2e/logo.spec.ts` の「ロゴの器の高さが50px」で固定してある。

**幅は場所ごとに違ってよい**（spec 2.2）。揃えるのは**収め方**——`object-contain` で収め、拡大しない、切らない——のほうである。OpenWork・OpenMoney も同じ扱いで、ロゴ自体は正方形に揃えず表示箇所ごとの器に収めている（2026-08-21 に確認）。

### モバイルを48pxに留めた理由（実測）

360px 幅では、器を広げたぶんが meta 行から削られる。**器を広げる前から meta 行は切れていた**ので、切れ方の悪化だけを見た。

| 器の幅 | meta 行のはみ出し | 切れている要素 |
| ---: | ---: | ---: |
| 38px（元） | 10px | 25 |
| 48px（採用） | 18px | — |
| 56px | 28px | 36 |
| 64px | 28px超 | 36 |

56px 以上にすると「平均42.3歳 ・ 4,456人」の**従業員数が丸ごと消える**。48px なら末尾の数桁が欠ける程度で収まる。48×38 に 3.7:1 のワードマークを入れると 48×13 になり、読める大きさではない——**モバイルでのロゴは色と形の目印**と割り切っている。

**この制約は Issue #119（アートボード 2a）で外れた。** 上の表が測っているのは「社名・meta・年収バーを右の1列に縦積みしていた行」で、器を広げたぶんがそのまま meta 行の幅から引かれていた。行を4カラム（順位 / ロゴ / 社名＋meta / 金額ブロック）に割り、**meta を平均年齢だけに落として従業員数を先に削った**ことで、削られる相手そのものが無くなった。器は `size="row"` の **68 × 48** になっている（`docs/ranking/ranking-mock-alignment/design.md` の4巡目）。行の高さもこの48pxが決めるので、社名の長さによらず等間隔に並ぶ。`sm`・`default`・`lg` の寸法は変えていない。

## ロゴの有無をどう配るか

**`logos.json` はクライアントに渡さない**（gzip 41.7KB。`/` の予算は 75,000B）。渡すのは**ロゴがあるかどうかだけ**である。

```
app/page.tsx（サーバー・モジュール読み込み時に1度）
  buildLogoMask(companies.rows, logos.byId)  →  "1101011…"（1,867文字）
        ↓ HTML に埋まる（raw 1.9KB・gzip 約250B）
  <LogoIdsProvider rows={rows} mask={mask}>
        ↓ クライアントで1度だけ開く
  Set<企業ID>
        ↓
  <CompanyLogo id={…} />   ← useHasLogo(id)
```

**縦横比は渡さない。器の寸法が固定で中身は `object-contain` なので、画像が届いてもレイアウトは動かない**（AC-12）。当初は縦横比を渡す前提で spec を書いていたが、器を固定した時点で不要になった。

**`app/page.tsx` はリクエストごとに描画される**（`ƒ (Dynamic)`）ので、マスクはモジュールの読み込み時に1度だけ作る。

企業詳細ページは**マスクを送らない**。出るのは自身と9基準ぶんの近傍5社＝多くても46社で、1,867文字を送るほうが大きい。`logoIdsOnPage(view)` がその画面に出るIDだけを選ぶ。

## ダークモードでロゴが沈む問題

ロゴは透明背景で、**濃い色のワードマークをダークの地に置くと読めない**（実測）。色を反転させる加工は採らない——商標をそのままの形で出すと決めてある（ADR-0008 決定1）。

そこで**器の側に明るい面を敷く**。トークンを1つ足した。

```css
:root { --logo-surface: oklch(1 0 0); }        /* 白 */
.dark { --logo-surface: oklch(0.93 0.002 197.1); } /* わずかに落とす */
```

**ダークだけ少し暗くしているのは、白のままだと1ページに30枚並んで眩しいため。** 生の `bg-white` は書かない（CLAUDE.md「色は tokens.css の CSS 変数だけを使う」）。

E2E は、この面がどちらのモードでも十分明るいことを固定している。**`getComputedStyle` は `lab()` を返す**（トークンが oklch のため）ので、数値を素で読まずキャンバスに描いて sRGB に開いてから測る。

## 頭文字マーク

ロゴを持たない231社はこれまでどおり。**破線の枠は変えていない**——「意図した空き」として既に設計されているもので、ロゴが載る行と並んでも欠落には見えない（実機で確認）。

器の幅が広がったぶん、頭文字マークも横長になる。1文字が中央に置かれる形になるが、**列が揃うこと**（AC-9）を優先した。

## E2E の「リクエスト数0」を緩める

`e2e/network.ts` の `collectPageRequests(page)` に寄せた。**`resourceType() === "image"` のリクエストだけを数えない。**

```
9箇所 / 6ファイル（ranking-refresh 4・ranking-basis・ranking-url-sync・
ranking-pagination・company-page・company-refresh・theme）
```

見たいのは「操作でページ（HTML・RSCペイロード）を取り直していないこと」で（`docs/ranking/spec.md` AC-7）、ロゴを `loading="lazy"` で後から読むことはこれに反しない。**緩め方を1か所に閉じたのは、次に誰かが同じ検査を書くときに素の `page.on("request")` を書き足せてしまうため。**

## /about の帰属表示

`attributionCredits` が `attr: true` のものだけを拾う（**44社**）。パブリックドメインの397社は並べない——帰属を求めていないものまで並べると、本当に帰属が要る44件が埋もれる。

出典そのもの（Commons 441社・公式サイト 1,195社）と、**ロゴが各社の商標であること**は節の本文に書く。

`/about` は静的ページなので、`logos.json` はビルド時に消費されクライアントには渡らない。

## 実測（2026-08-21）

| ページ | L1前 | L1後 | 差 |
| --- | ---: | ---: | ---: |
| `/` | 62,565 B | **63,095 B** | +530 B（予算 75,000B） |
| `/about` | 11,454 B | 20,431 B | +8,977 B（44件の帰属表示） |
| `/company/[id]` | 13,689 B | 13,917 B | +228 B |

いずれも gzip・`next start` に対する実測。**`/` の増分が530Bで済んだのはマスクだけを渡しているため**で、`logos.json` を渡していれば予算を超えていた。

ロゴ画像は1枚あたり平均5.5KB。`web/public/_headers` で `/logos/*` に1週間のキャッシュを設定してある（L0）。

## モックに合わせなかったもの

| モック（`改善案.dc.html`） | 実装 | 理由 |
| --- | --- | --- |
| ロゴ枠は正方形（40×40・62×62） | 横長（88×50・136×62） | 実データの縦横比の中央値が3.69で、正方形付近は1,636社中230社だけ。40px角に入れると高さ11pxの帯になる（ADR-0008 決定4） |
| 枠の中は社名の頭文字 | ロゴがあれば画像 | モックはロゴを持たない前提で描かれている |
| 枠は破線・地は `--muted` | ロゴのときは実線・地は `--logo-surface` | 破線は「意図した空き」の表現。実物が入る枠に破線を残すと未完成に見える |

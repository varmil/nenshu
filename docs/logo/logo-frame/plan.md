# plan.md — L1 ロゴの器と表示

Issue: [#110](https://github.com/varmil/nenshu/issues/110)（親: [#23](https://github.com/varmil/nenshu/issues/23)）
仕様: `docs/logo/spec.md` 2.（AC-7〜AC-14）／決定: `docs/adr/0008-company-logo-sourcing.md`

着手前の段取り。出来上がりの構造は `design.md` にある。

## 順序

### 1. モックの実寸を取る

1. **`改善案.dc.html` を Claude Design から直接読む。** U11・U12・C2 でモックを読まずに実装してズレた（#84）ことの再発防止。MCP が繋がっていることを先に確かめる
2. アートボード 4a・5c・4b のロゴ枠の実寸（幅・高さ・角丸）を測る。**ここが器の出発点**で、変えるのは幅だけにする

### 2. データの渡し方を決める

3. `logos.json`（gzip 41.7KB）を**クライアントに丸ごと渡さない**方法を決める。`/` の予算は 75,000B で、現状の余裕はわずか
4. 渡す前と後で `/` のHTMLサイズを測り、差分を記録する

### 3. 器を作る

5. ロゴと頭文字マークを**1つのコンポーネント**にまとめ、4箇所（表・カード・企業詳細の見出し・近傍5社）から同じ規則で使う
6. **ダークモードで濃いロゴが沈む問題**を先に片付ける。色を反転させる加工はしない（ADR-0008 決定1）ので、器の側で対処する
7. 生の色を書かない。必要ならトークンを足す（CLAUDE.md）

### 4. 実物で見る

8. dev サーバーを立て、**PC・モバイル・ライト・ダークの4通り**を実際に見る。ロゴは1,636社ぶん実在するので、モックではなく本物の混在状態で判断する
9. **社名や meta 行が切れていないかを測る。** 器を広げたぶんは本文から取る形になるため、どこが削れるかを数値で見る

### 5. テスト

10. 単体テスト: マスクの作り方と開き方、帰属表示の絞り込み、頭文字
11. E2E: AC-7〜AC-14。**ロゴと頭文字が同じページに混在していることを検査の前提として確かめる**——片方しか出ていないページで「揃っている」と言っても何も見ていない
12. **既存の「リクエスト数0」を画像だけ緩める。** 5ファイル9箇所が当たる。緩め方は1か所に閉じる

### 6. 出典

13. `/about` にロゴの出典とライセンスの節を足す（AC-14）。帰属が要るものだけを並べる

## 検証の順序

**器の寸法は最後まで動かす前提で進める。** 先に配線（データの渡し方・コンポーネントの差し替え）を終え、寸法は実物を見ながら決める。寸法を先に固定すると、社名が切れるのを見つけたときに配線ごとやり直すことになる。

モバイル360pxが一番きつい。**器を広げる前の状態でも meta 行が切れていること**を先に測っておき、「元から切れていた」のか「広げたから切れた」のかを区別できるようにする。

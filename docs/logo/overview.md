## 実施順序

```
（C0 完了済み）─→ L0 ─→ L1
```

**L0 と L1 を1つの Unit にしない。** L0 は外部への1,600件の取得を含み、実行に時間がかかるうえ再実行の条件が違う（年1回）。L1 はブラウザで見て決める作業で、L0 の成果物が手元にあることが前提になる。1つの PR にすると、取得の失敗とレイアウトの崩れが同じ差分に混ざる。

**L0 だけをマージしても表示は変わらない。** これは T0（10年推移の取得）と同じ形で、既存の Unit テスト・E2E が緑のままであることが L0 の完了条件の一部になる。

## L0 ロゴの調達パイプライン

spec.md の 1.（調達）すべて。法人番号 → Wikidata → Commons／公式サイト → 正規化 → `logos.json` と `web/public/logos/` を出すところまで。

### 事前に確認済みの数値

着手前に実測した（`docs/logo/intent.md`「前提の確認」）。

- 法人番号は1,867社すべてにある（EDINETコード一覧の `提出者法人番号`）
- Wikidata に到達: 1,656社／公式サイトURL: 1,604社／Commons のロゴ: 522社
- 公式サイトから 128px 以上のアイコンが取れるのは、サイトを持つ会社の47%
- 合わせての到達率は約53%（約990社）

### この Unit で決めること

- 配信する画像の形式と正規化の規則（透明背景・余白の詰め方・ラスタライズの倍率）
- `logos.json` の形（`/` のペイロード予算 AC-13 に収まる形で、行を描く前に縦横比が分かること）
- 取得の並列数と、失敗・429 の扱い（EDINET で踏んだ「エラーが200で返る」型の失敗を繰り返さない）
- Commons のライセンス情報をどこまで持つか

### 非対象

表示の変更。`CompanyLogoMark` はこの Unit では触らない。

## L1 ロゴの器と表示

spec.md の 2.（表示）すべて。

### この Unit で決めること

- **器の寸法。** 中央値 3.8:1 の横長ロゴと 1:1 のアイコンが同じ列に収まり、社名の開始位置が揃い、360px で横スクロールが出ない形（AC-9・AC-10）
- `CompanyLogoMark` を「ロゴ or 頭文字」を切り替える1つのコンポーネントにするか、器と中身を分けるか
- 遅延読み込みの境界と、E2E の「リクエスト数0」をどう画像だけ緩めるか（AC-11。5ファイルが影響する）
- `/about` のロゴ出典の節（AC-14）

### モックとの関係

**`改善案.dc.html` は正方形の器を描いている。** L1 はここから意図的に外れる——モックはロゴを持たない前提の頭文字マークとして描かれたもので、実データ（横長が60%）と合わない。**U13 の「モックに合わせないと決めたもの」の対照表と同じ扱いで design.md に残す。**

## 共有コンポーネント

**`CompanyLogoMark`（`features/ranking/components/`）。** ランキングの表・カード、企業詳細の見出し、近傍5社の4箇所が使う。L1 はこれを作り直す。

**`design-system/` には昇格させない。** `AgeSwitch` と同じ理由で、企業ドメインの語彙（企業ID・ロゴの索引）に依存する（`docs/company/company-page/design.md`）。

## 対象外

OpenWork 等の第三者サイトからの取得、ランタイムでの外部ロゴAPI、ロゴの加工、ロゴでの検索・絞り込み、211社ぶんの手作業収集。いずれも `docs/logo/intent.md`「作らないもの」を参照。

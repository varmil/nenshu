# spec.md — 企業ロゴ

対象面: user-web（ユーザー画面）… `docs/product/product.md` の面一覧に対応

`docs/logo/intent.md` の狙いを、何を作るか（WHAT）と満たすべき条件に落とす。用語は `docs/product/glossary.md` に従う。再配布の可否は `docs/adr/0008-company-logo-sourcing.md`（運営者の判断）に従う。

## 1. 調達（パイプライン）

### 1.1 どこから取るか

2つの出典を、この優先順位で使う。

| 優先 | 出典 | 取り方 | 見込み |
| --- | --- | --- | ---: |
| 1 | **Wikimedia Commons のロゴ** | 法人番号（P3225）で Wikidata の項目を引き、`P154 logo image` の画像を取る | 522社 |
| 2 | **公式サイトのアイコン** | 同じ項目の `P856 公式ウェブサイト` を起点に、`apple-touch-icon`・`sizes` 付きの `<link rel=icon>`・web app manifest の `icons`・`/apple-touch-icon.png`・`/favicon.ico` を辿る | 約750社 |

**Commons を先に見る。** ライセンスが明示されており、81%が SVG で解像度の心配が無い。

どちらも取れない会社は**ロゴを持たない**。頭文字マーク（`CompanyLogoMark`）のままにする。

**OpenWork をはじめとする第三者サイトからは取らない**（intent.md「作らないもの」）。

### 1.2 名寄せ

**法人番号を経由する。** EDINETコード一覧（`Edinetcode.zip`）の `提出者法人番号` → Wikidata `P3225` → 項目。1,867社すべてが法人番号を持つ（実測）。

社名の文字列一致では引かない。「株式会社◯◯」の表記揺れと同名他社で誤爆する。

出力のキーは**企業ID**（証券コード／EDINETコード。ADR-0006）。`companies.json` の `id` と一致させる。

### 1.3 品質の下限

**下限を割るものは採らない。** 載せないほうが、ぼやけたものを載せるより良い（intent.md H3）。

| 種別 | 下限 |
| --- | --- |
| ベクタ（SVG） | 制限なし。ただしラスタライズして配信する |
| ラスタ（PNG・ICO・JPEG・WebP） | **短辺 128px 以上** |

`/favicon.ico` の 16px・32px はここで落ちる。ICO は内包する最大サイズで判定する。

**中身も検める。** 1x1 の透明画像・全面が単色の画像・HTMLエラーページを画像として掴んだものは採らない（EDINET の 429 を `.zip` として保存した件と同じ失敗の形。CLAUDE.md）。

### 1.4 出力

- 画像: `web/public/logos/` 以下に**企業IDで引ける静的ファイル**として置く。形式は1つに統一する（SVG をそのまま配らない——外部参照とスクリプトを含みうるため）
- 索引: `web/public/data/logos.json`。企業IDから「ロゴの有無・器に必要な縦横比・出典・ライセンス・帰属先」が引ける

**縦横比は索引に持つ。** 描く前に器の寸法が決まらないとレイアウトが動く（1.7 AC-12）。

### 1.5 ライセンスと商標

**CC ライセンスのロゴは帰属表示が要る。** 実測では120件中12件が CC 系（BY-SA 4.0 / BY-SA 3.0 / BY 2.5 / CC0）。作者名・ライセンス名・ファイルへのリンクを、**読者が辿れる場所**に置く。

**商標であることを明記する。** ロゴは各社の商標であり、掲載は当該企業を識別するためであって、提携・推奨を示すものではない旨を書く。

**公式サイト由来のロゴには帰属表示の相手がいない。** 出典が当該企業自身であることを書く。

### 1.6 再取得

**年1回、有報の再取得と同じ回で回す。** 既に取得済みのロゴはキャッシュから使い、差分だけ取る。

**取得先の負荷を抑える。** 1,600件の外部サイトを叩くので、並列数を絞り、`User-Agent` に連絡先を入れる。

### 1.7 受け入れ基準（調達）

#### AC-1 名寄せ

```gherkin
Given EDINETコード一覧と ranking_unified_2026.csv がある
When 法人番号で Wikidata の項目を引く
Then 1,600社以上が項目に到達する
And 到達しなかった会社は「ロゴなし」として記録される
And 社名の文字列一致で引いた会社が1社も無い
```

#### AC-2 品質の下限

```gherkin
Given logos.json に載っている全ロゴ
Then ラスタ由来のものはすべて元画像の短辺が128px以上である
And 1x1・単色・画像でないファイルが1件も混ざっていない
```

#### AC-3 到達率

```gherkin
Given 調達を1周した後
Then ロゴを持つ会社が900社以上ある
And 到達率が logos.json のメタ情報に記録されている
```

実測にもとづく見込みは約53%（約990社）。**900社を下回ったら調達側が壊れている。**

#### AC-4 ライセンスの記録

```gherkin
Given Commons 由来のロゴ
Then ライセンス名・作者・元ファイルのURLが logos.json に入っている
And パブリックドメイン以外のものは帰属表示の対象として印が付いている
```

#### AC-5 出力の整合

```gherkin
Given logos.json
Then すべてのキーが companies.json の id に存在する
And すべてのエントリに対応する画像ファイルが web/public/logos/ にある
And 逆に、logos.json に無い画像ファイルが残っていない
```

#### AC-6 容量

```gherkin
Given web/public/logos/ 以下
Then 1ファイルが20KB以下である
And 合計が10MB以下である
```

## 2. 表示

### 2.1 器

**横長のロゴと正方形のロゴが同じ器に収まること。** Commons のロゴは中央値 3.8:1、公式サイトのアイコンは 1:1 で、両方が同じ列に並ぶ。

満たすべき条件は次の3つ。

- **行の左端と社名の開始位置が、ロゴの有無・形にかかわらず揃う**
- **ロゴの有無で行の高さが変わらない**
- **モバイル360pxで横スクロールが出ない**（U13 で潰した回帰。`docs/ranking/ranking-mock-alignment/design.md`）

器の寸法そのものは design で決める（L1）。

### 2.2 出す場所

| 場所 | 現状 |
| --- | --- |
| ランキングの表（PC） | `CompanyLogoMark`（40px 角） |
| ランキングのカード（モバイル） | 同上（38px 角） |
| 企業詳細ページの見出し | 同上（60px 角） |
| 企業詳細の「水準が近い会社」 | 同上 |

**4箇所すべてで同じ規則にする。** 場所ごとに出典や下限を変えない。

### 2.3 ロゴが無いとき

**現行の頭文字マークをそのまま使う。** 破線の枠は「意図した空き」として既に設計されているもので、これを変える必要は無い。

**「ロゴなし」を欠落として見せない。** 灰色の四角・壊れた画像アイコン・代替テキストの露出をしない。

### 2.4 読み上げ

ロゴは**装飾**として扱う。社名は同じ行にテキストとして必ずあるので、画像に社名を重ねて読み上げさせない（頭文字マークが `aria-hidden` なのと同じ扱い）。

### 2.5 出典の表示

`/about` に**ロゴの出典とライセンス**の節を置く。1.5 の3点（Commons 由来の帰属、公式サイト由来の出典、商標の注記）を満たす。

### 2.6 受け入れ基準（表示）

#### AC-7 ロゴのある行

```gherkin
Given ロゴを持つ会社の行
Then 頭文字マークではなくロゴ画像が表示される
And 画像が器からはみ出さず、引き伸ばされていない
```

#### AC-8 ロゴの無い行

```gherkin
Given ロゴを持たない会社の行
Then 現行の頭文字マークが表示される
And 壊れた画像・空の器・代替テキストの文字列が見えない
```

#### AC-9 列の揃い

```gherkin
Given 横長のロゴ・正方形のロゴ・頭文字マークが混在する100行
Then すべての行で社名の開始位置が同じである
And すべての行の高さが同じである
```

#### AC-10 モバイル

```gherkin
Given 360px 幅でランキングを開く
Then 横スクロールが発生しない
And 社名が読める幅を保っている
```

#### AC-11 操作でHTMLを取りに行かない

```gherkin
Given ランキングを開いている
When 絞り込み・並び替え・ページ送りを操作する
Then 文書・RSCペイロードのリクエストが発生しない
And 発生するリクエストがあればロゴ画像だけである
```

**既存の「リクエスト数0」を画像だけ緩める。** 主旨は「操作でページを取り直さない」ことであって、画像の遅延読み込みはこれに反しない（intent.md）。

#### AC-12 レイアウトが動かない

```gherkin
Given ランキングを開く
When ロゴ画像の読み込みが完了する
Then 行の高さと社名の位置が読み込み前後で変わらない
```

#### AC-13 ペイロード

```gherkin
Given トップページ（/）のHTML
Then gzip後のサイズが 75,000 バイト以下である
```

現状 71,671 バイト（CLAUDE.md）。**索引を丸ごと埋め込む余裕は無い。**

#### AC-14 出典

```gherkin
Given /about
Then ロゴの出典とライセンスの節がある
And CC ライセンスのロゴについて作者とライセンス名が読める
And ロゴが各社の商標である旨が書かれている
```

## 3. 非機能要件

**リクエスト時の計算を増やさない。** ロゴの索引はビルド時に確定させ、サーバーでは当該行ぶんを引くだけにする（Workers Free の CPU 10ms/リクエスト制約）。

**画像は Worker を経由しない。** `_next/static/*` と同じく静的アセットとして配る（`public/_headers` でキャッシュを設定する）。

**折り返しより下のロゴは遅延読み込みする。** 1ページ100行ぶんの画像を初期表示で取りに行かない。

## 4. 未決事項

- **到達率を上げる追加の出典。** Wikidata に項目が無い211社に届く手段は現状無い。読者の反応を見てから考える。
- **リブランドの検知。** 年1回の再取得で追う。それより速く追う仕組みは持たない。

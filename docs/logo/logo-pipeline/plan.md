# plan.md — L0 ロゴの調達パイプライン

Issue: [#109](https://github.com/varmil/nenshu/issues/109)（親: [#23](https://github.com/varmil/nenshu/issues/23)）
仕様: `docs/logo/spec.md` 1.（AC-1〜AC-6）／決定: `docs/adr/0008-company-logo-sourcing.md`

着手前の段取りだけを書く。出来上がりの構造は `design.md` にある。

## 順序

### 1. 名寄せの土台を作る

1. `pipeline/salary/Edinetcode.zip` を展開し、EDINETコード → 法人番号 の対応を作る
2. `ranking_unified_2026.csv` の1,867社に当て、**全社に法人番号が付くことを確かめる**（実測では欠損0。ここが欠けたら以降が全部ずれる）
3. 企業ID（`makeId`）を付けて、以降のキーにする

### 2. 外部の索引を引く（画像はまだ取らない）

4. Wikidata に SPARQL で300件ずつ問い合わせ、法人番号（P3225）から **項目・ロゴ（P154）・公式サイト（P856）** を得る
5. **URLが取れなかった会社だけ** gBizINFO に法人番号で問い合わせ、`company_url` を得る。**深いパスで返ることがあるのでオリジンに正規化する**
6. ここまでの結果をキャッシュに書く。**以降の工程を何度やり直しても、この2つのAPIを叩き直さない**

### 3. 候補を集める

7. Commons のロゴがある会社は、Commons API で**実寸・ライセンス・作者・原寸URL**を取る
8. 公式サイトのHTMLを取り、候補を4種類に分けて集める（JSON-LD の `Organization.logo` / ヘッダの `logo` を含む `<img>` / `<link rel=icon>` と manifest の `icons` / `/apple-touch-icon.png` と `/favicon.ico`）
9. **HTMLを取る時点で相手のサーバーに負荷をかけない。** 並列を絞り、`User-Agent` に連絡先を入れ、1社あたりのリクエストを数件に抑える

### 4. 実体を取って検める

10. 優先順（Commons → 構造化データ → ヘッダ → アイコン）に候補を1つずつ取り、**中身を検めて**採否を決める
11. **検めるのは「画像として読めるか」だけ**にする。解像度では落とさない（ADR-0008 決定3）。1x1・単色・画像でないものは落とす
12. 採ったものは生バイトのままキャッシュに置く。**取り直しは工程5以降だけで済むようにする**

### 5. 正規化して出す

13. すべて同じ形式にそろえる（SVG はここでラスタライズする）
14. `web/public/logos/` に企業IDで書き、`web/public/data/logos.json` に索引を書く
15. **元画像の実寸・出典・元URL・ライセンスを索引に残す**（後から閾値を決め直すため）

### 6. 検証

16. AC-1〜AC-6 を検証する関数を通す。**到達率が1,400社を下回ったら失敗として止める**
17. 出典の内訳を出力して記録する（Commons / 構造化データ / ヘッダ / アイコン）
18. `web` の既存テストと E2E を回し、緑のままであることを確かめる（表示は変えていないので変化があってはいけない）

## 検証の順序

**単体テストを先に書く。** ネットワークに出る部分と、集めた候補から1つ選ぶ部分を分け、後者はHTMLの断片を固定値として持たせて回す。1,867社を1周させるのは30〜40分かかるので、**選び方の間違いを1周ごとに直すやり方を取らない。**

1周目を回した後に見るのは次の3つ。

- 到達率と出典の内訳（AC-3）
- **採ったのに小さいもの・横長すぎるものの分布**（L1 で器を決めるときの入力になる）
- 落ちた会社の理由の内訳（URLが無い／HTMLが取れない／候補が無い／画像が壊れている）

## この Unit で触らないもの

`web/` の表示側。`CompanyLogoMark` も `app/` も変更しない。**差分が `pipeline/`・`web/public/`・`docs/` に閉じていることを、PRを出す前に確かめる。**

## 秘密情報

gBizINFO の API トークンは**リポジトリに入れない**。既存の `salary/.edinet_key`・`.estat_key` と同じ形で、gitignore 済みのファイルから読む。トークンが無い環境では、その工程だけを飛ばして動くようにする（147社ぶんのURLが埋まらないだけで、他は同じ結果になる）。

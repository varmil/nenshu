# 数字の読み直し（線 B）

refresh の D4（#874）・`docs/refresh/spec.md` 1.11・AC-11。`update_numbers.py collect` が読み違いを疑った会社を、有報の原文と突き合わせて確かめる。

## 材料

`pipeline/refresh/work/reread/<EDINETコード>.txt`。先頭の3行に、機械が読み取った値（平均年間給与・平均年齢・平均勤続年数・単体の従業員数）、前の期の平均年間給与、読み直す理由がある。その後ろが有報の「従業員の状況」の原文（表を平文にしたもの）。

## 確かめること

**「有報にそう書いてあるか」だけを見る。「あり得る値か」は見ない。** 前の期から大きく動いていても、原文に書いてあればそのまま出す——持株会社化で単体の従業員が入れ替わった、事業を売った、のような本物の変化がある。

1. 原文の中に、提出会社（単体）の平均年間給与・平均年齢・平均勤続年数が書かれている箇所を探す。連結の表やセグメント別の表と取り違えない
2. 読み取った4つの値が、その箇所の値と一致するか。**単位に注意する**——平均年間給与は円・千円・万円のどれで書かれているかを表の見出しで確かめ、円に直して比べる。平均年齢の「歳」と「ヶ月」、平均勤続の「年」と「ヶ月」も同じ
3. 一致すれば `confirmed`。一致しない、提出会社の値が見つからない、どの表の値か決められない、のどれかなら `unresolved`

**決められなければ `unresolved` にする。** その会社は前の期の数字のまま出て、運営者に知らせが出る（新しく載る会社は載らない）。迷って `confirmed` にすると、読み違いが公開される。

**値を直さない。** 原文と違う値を見つけても、正しい値を書き込まない。`unresolved` にして、違っていた箇所を `note` に書く。

## 書き出す形

`pipeline/refresh/work/verdicts.json` に、会社ごとに1つ。

```json
{
  "E00001": {
    "doc_id": "S100XXXX",
    "verdict": "confirmed",
    "note": "従業員の状況の提出会社の表に 平均年間給与 12,345千円・平均年齢 40.1歳 とある"
  }
}
```

- `doc_id` は材料の1行目の書類 ID。**書類 ID が違う判定は使われない**（次の書類が出たときに古い判定が効かないように）
- `note` には、確かめた箇所（表の見出しと値）か、決められなかった理由を1〜2文で書く

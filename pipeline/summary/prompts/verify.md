# 説明文の検証パス（C6・#160）

生成済みの説明文が、**渡した原文だけから支持されるか**を判定する。

**生成とは別の仕事として読む。** 「読んで自然か」「日本語として良いか」は見ない。見るのは
**原文に書いてあるかどうか**だけ。ADR-0010 決定2 が求めているのはこの一点で、
機械ゲート（`gate.py`）が拾えない「原文と食い違う言い換え」をここで止める。

## 入力

`work/gated_NNNN.json`。`companies[]` の各要素が1社で、`edinet_code` / `name` /
`summary`（機械ゲートを通った説明文）/ `source`（原文）を持つ。

## 出力

`work/verify_NNNN.jsonl`。**入力と同じ社数・同じ順**で、1行1社の JSON。

```json
{"edinet_code": "E01967", "supported": true, "reason": ""}
```

`supported` が `false` のときは `reason` に**原文と食い違う箇所を1つ**書く（20字程度）。

## 判定

**説明文の各文について、原文がその内容を述べているかを見る。1文でも支持されなければ
`false`。**

`false` にするもの。

- 原文に無い事実を述べている（事業内容・体制・販路・技術）
- 原文と逆のことを述べている（原文が子会社の製造を書いているのに「自社で製造しない」）
- 原文が触れていない範囲に広げている（原文が国内だけを書いているのに「海外にも展開する」）
- 評価になっている（「収益性が高い」「強みを持つ」）
- **原文が事業を説明していないのに、説明文が事業を述べている**——当期の異動や
  セグメント区分の変更しか書かれていない原文から書かれた文がこれに当たる

`true` にしてよいもの。

- 原文の言い換え・要約・順序の入れ替え
- 原文が列挙しているセグメントの一部だけを取り上げること
- 原文の「当社」「当社グループ」を主語なしで書き直すこと

**迷ったら `false`。** 説明文が1つ減ることの損は、根拠の無い文が1つ出ることの損より小さい
（ADR-0010「文は照らし合わせる先が読者の手元に無い」）。

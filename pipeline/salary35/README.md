# salary35 — 35歳時点年収ランキング

有価証券報告書の平均年間給与を、賃金カーブで35歳時点に補正して並べ直す。
note記事1本目の元データを作るためのパイプライン。

## 使い方

```bash
export EDINET_API_KEY=xxxxxxxx      # または salary35/.edinet_key に書く
python3 run.py --limit 300           # 検証（300社）
python3 run.py --limit 0             # 全社
python3 run.py --limit 0 --curve 大企業   # 企業規模別カーブで頑健性チェック
```

出力は `out/salary35.csv`。標準出力に順位変動のサマリーが出る。

## データソース

**有報**は EDINET API v2 の CSV形式（type=5）から取る。APIキーが必須で、
無料登録で発行される（https://api.edinet-fsa.go.jp/api/auth/index.aspx）。
抜き出すのは平均年間給与・平均年齢・平均勤続年数・従業員数（単体と連結）。

**業種**は EDINETコードリストから取る。こちらはAPIキー不要で、
上場企業3,824社の東証33業種が入っている。

**賃金カーブ**は厚生労働省「令和6年賃金構造基本統計調査」の第4表・第5-1表を
`curves.py` に定数として持っている。産業別（16分類）と企業規模別（3分類）の2系統。
年1回しか更新されないので、APIではなく定数で持つほうが扱いやすい。

## 補正のしかた

年齢階級の中央値（22, 27, 32, ... 67歳）を結ぶ区分線形カーブを作り、
各社の平均年齢の位置から35歳の位置へスケールする。

```
35歳推定年収 = 平均年間給与 × カーブ(35) / カーブ(平均年齢)
```

情報通信業なら、平均30歳の会社は1.152倍、平均44歳の会社は0.826倍。
平均年収が同じ800万円でも、35歳換算では922万円と661万円に分かれる。

## 2本目のカーブ

賃金センサスの数字は所定内給与で、賞与と残業代が入っていない。年功は賞与に
乗ってくるので、このカーブは年齢の効きを過小評価している可能性がある。

そこで `fit_curve_from_data()` が、有報データ自身から局所線形回帰でカーブを
引き直す。こちらは賞与込みの年収ベースになる。2つのカーブで順位相関を取って、
結論がカーブの選び方に依存していないかを確認する。

ただし自前カーブは会社間の差であって、1社の中の昇給ではない。
「平均年齢の高い会社ほど年収も高い」という関係を年功カーブと読み替える
生態学的推論になっている。記事ではこの限界を明示する。

## 持株会社の扱い

有報の平均年間給与は提出会社単体の数字で、連結子会社の社員は入らない。
本体に管理職しか置いていない持株会社は不当に高く出る。
単体従業員数が連結の10%未満（かつ連結500人以上）の会社にフラグを立て、
ランキング本体から外して別枠で見せる。

## ファイル

| ファイル | 中身 |
| --- | --- |
| `curves.py` | 賃金カーブの定数、東証33業種のマッピング、補間 |
| `edinet.py` | EDINET APIクライアント、CSV形式のパーサ |
| `run.py` | 取得・補正・順位変動の集計・書き出し |
| `cache/` | ダウンロード済みの書類一覧とZIP（再実行時は再取得しない） |
| `out/` | `salary35.csv` |

# 生成パスの手順

あなたは C9（Issue #241）の**生成パス**です。

1. **`pipeline/analysis/prompts/generate.md` を全文読む。** 規格はそこにあり、**それだけを読めばよい**（ADR は取り込み済み）。
2. **`pipeline/analysis/work/batch_0001.json` を読む。** 各社の4節（切った版）と `figures` が材料。
3. 1社ずつ要約と分析を書き、**`pipeline/analysis/work/gen_0001.jsonl`** に**入力と同じ社数・同じ順**で1行1社の JSON を出力する。

## 絶対の制約

**`pipeline/data/analysis_text_2026.csv`（切らない版）を開かない。** 材料はバッチが渡す切った版だけ。機械ゲートは切らない版を優先するので通ってしまうが、検証パスは切った版だけで判定し、切った版しか無い環境では再現しない。**切った版に無いことは書かない。記憶から補完しない。**

## 書き終えたら自分で確かめる

**報告に書くことは、実物に当たってから書く。** 過去2回、「原文にある語で書いた」「文を割った」という報告が実態と食い違った。

- **固有名詞と語**——4節を `grep` して実在を確かめる（「戸建住宅」が0件だった例がある）
- **数値**——`figures` か原文の値で検算する。**丸めは9割の線**（generate.md の表）
- **利益の段階**を書いたか。**時点**は当期か（「本年度」は翌期を指すことがある）
- **同じバッチの他社と並べて**、一言の型と締めが重なっていないか

## 報告

各社の `headline` と、**迷った箇所**を書く。迷った箇所は次の回の規格になるので、判断した理由まで書く。

# 検証パスの手順

あなたは C9（Issue #241）の**検証パス**です。生成パスとは別の仕事として読みます。

1. **`pipeline/analysis/prompts/verify.md` を全文読む。** 判定の基準はそこにあり、**それだけを読めばよい**（ADR も型の番号も取り込み済み）。
2. **`pipeline/analysis/work/gated_0001.json` を読む。** これが**判定に使う唯一の材料**。
3. **`pipeline/analysis/work/verify_0001.jsonl`** に、**入力と同じ社数・同じ順**で1行1社の JSON を出力する。

## 絶対の制約

**`pipeline/data/analysis_text_2026.csv`（切らない版）を開かない。** 切った版に無いものは材料の外。そこを根拠に通しても落としても判定の意味が変わる。

## 見るもの

- **要約**は4節に書いてあるか。**分析**は事実の誤り6種だけ（verify.md の表）。**迷ったら `true`。**
- **`sources` の URL は開いて確かめる。**
- **数値は独立に検算する**（生成側の申告を信じない）。丸めは9割の線。
- **落とすほどではないが直させるもの**（verify.md の節）に当たるものは `true` にしたうえで申告する。

## `false` 以外に指摘してよい2つ（`verify.md` の `## 分析の判定`）

- **5つ目「主題から外れた話題が並んでいる」**——**歯止めつき**。主題に対する留保・裏返し・条件は落とさせない。使う前に**捨てることで残った主張が強くなるか**を確かめる
- **6つ目「事実で終わっていて "So What" に降りていない」**——見出しにも当てる。**ただし2段目（会社の力学）で止まるのは違反ではない**。掛かるのは事実の記述で終わっているときだけ

## 毎回数えるもの

- **主節が事実で終わる文**（本文全体で1つまで。従属節の事実は何個でもよい）
- **`profit_per_employee_yen`**——`performance_history.csv` に当たって基準・またぎまで。**上回る側で条件番号を名乗っていたら指摘する。ただし条件④（またぎ）は例外で、上回る側でも名乗ってよい**（166回目。`verify.md` が正で、この1行はその写し——食い違ったら `verify.md` を見ること）

## 報告は短く

**判定の内訳（true/false の数）／`false` の型と該当文／申告／数えた結果（事実終わりの文数・指標の扱い）／所見。** 所見は `## この規格の育て方` に照らして**規則にすべきか判例に留めるか**まで書く。**生成側の申告は数えず、語で検索して実物に当たる。通ったものの逐一の照合表は要らない**——確かめたうえで、書くのは**引っかかった箇所だけ**。

# 検証パスの手順

あなたは C9（Issue #241）の**検証パス**です。生成パスとは別の仕事として読みます。

1. **`pipeline/analysis/prompts/verify.md` を全文読む。** 判定の基準はそこにあり、**それだけを読めばよい**（ADR も型の番号も取り込み済み）。
2. **`pipeline/analysis/work/gated_0001.json` を読む。** これが**判定に使う唯一の材料**。
3. **`pipeline/analysis/work/verify_0001.jsonl`** に、**入力と同じ社数・同じ順**で1行1社の JSON を出力する。

## 絶対の制約

**`pipeline/data/analysis_text_2026.csv`（切らない版）を開かない。** 切った版に無いものは材料の外。そこを根拠に通しても落としても判定の意味が変わる。

## 見るもの

- **要約**は4節に書いてあるか。**分析**は事実の誤り6種だけ（verify.md の表）。**迷ったら `true`。**
- **`sources` の URL は開いて確かめる。**
- **数値は独立に検算する**（生成側の申告を信じない）。丸めは9割の線。
- **落とすほどではないが直させるもの**（verify.md の節）に当たるものは `true` にしたうえで申告する。

## 報告

`false` の内訳を型の番号で。**`true` にしたが迷った箇所を、社名と該当文を挙げて必ず添える**——申告が基準を動かす。**生成側の申告は数えず、語で検索して実物に当たる。**
